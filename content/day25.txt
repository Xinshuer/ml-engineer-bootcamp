@@ concept
title: 上线后要看的几个数
--- body
模型上线之后，每天都有人问：「它还好吗？」回答这个问题，要看两类数。

**服务健不健康**（和普通的网站后台一样）：

- **延迟**（latency）：一个请求从进来到返回用了多久。看分位数 p50 / p95 / p99（第 22 天学过），不要只看平均值：平均值会被少数特别慢的请求拉高，又把它们藏了起来。
- **错误率**：失败的请求占多少。5xx（服务端出错）和超时都算；4xx（用户传了坏数据）通常单独看。
- **吞吐量**（throughput）：每秒处理多少个请求（req/s）。进来的比处理完的多，队列就会越排越长。
- **饱和度**：GPU 利用率、显存、排队的请求数。GPU 一直 100%、队列还在涨，说明容量不够了。
- **成本**：每 1000 个请求花多少钱（今天最后一张卡片）。

**模型对不对**：上面这些全是绿的，模型也可能在悄悄变差。比如来了一批新用户，输入的数据和训练时不一样了，服务照样按时返回，只是答案错了。真实标签（这笔贷款到底有没有违约、这笔交易是不是欺诈）往往要几天甚至几周才回来，所以要先盯住**输入的分布**和**预测的分布**（后面几张卡片）。

下面用 10 秒的请求日志，算出面板上的几个数。
--- code
latency_ms = torch.tensor([21., 19, 25, 22, 480, 20, 23, 18, 2000, 24, 22, 19])
status = torch.tensor([200, 200, 200, 200, 200, 200, 200, 200, 504, 200, 500, 200])
seconds = 10                                         # 这 12 个请求是 10 秒内进来的
gpu_util = torch.tensor([0.62, 0.71, 0.68, 0.66])    # 每 2.5 秒采一次

print("吞吐量:", len(latency_ms) / seconds, "req/s")
print("错误率:", round((status >= 500).float().mean().item(), 3))
print("平均延迟:", round(latency_ms.mean().item(), 1), "ms   <- 被两个慢请求拉高了")
q = torch.quantile(latency_ms, torch.tensor([0.5, 0.95]))
print("p50, p95:", [round(v, 1) for v in q.tolist()], "ms")
print("GPU 利用率:", round(gpu_util.mean().item(), 3))

@@ concept
title: PSI：输入的分布变了多少
--- body
**漂移**（drift）：线上数据的分布，慢慢变得和训练数据不一样。比如训练时用户的平均年龄是 35 岁，一次推广之后来了一大批 20 岁的用户。模型没见过这样的数据，预测就可能变差，而服务本身一个错都不报。

PSI（Population Stability Index，群体稳定性指数）是最常用的漂移指标，在金融风控里用了几十年。一次看一个特征（输入的一列）：

1. **用训练数据定分箱边界**：取训练数据的 10%、20%、…、90% 分位数，一共 9 个边界，切出 10 个箱。这样每个箱里正好有 10% 的训练数据。
2. 数一数：训练数据在每个箱里占多少（e，expected），线上数据在每个箱里占多少（a，actual）。
3. PSI = Σ (a − e) × ln(a / e)，对 10 个箱求和。两边一样时每一项都是 0；差得越多，PSI 越大。

几个细节：

- 边界**只能来自训练数据**，而且要和模型一起存下来，线上数据用同一套边界去数。如果用线上数据自己的分位数分箱，每个箱永远是 10%，PSI 永远接近 0（今天有一道改错题就是它）。
- 线上的值超出训练时的范围，也要算进最两边的箱。`torch.bucketize(x, edges)` 正好这样做：比第一个边界小的进 0 号箱，比最后一个边界大的进 9 号箱。
- `torch.bincount(idx, minlength=10)` 数每个箱有几个。一定要写 minlength：否则最后几个箱是空的时，结果会变短。
- 某个箱里线上一个数据都没有，a = 0，ln(0) 是负无穷。所以先把比例夹到一个很小的数：`clamp_min(1e-4)`。
- 常用的经验阈值：PSI < 0.1 基本没变；0.1 到 0.25 有变化，要留意；> 0.25 变化很大，要查原因。
--- code
torch.manual_seed(0)
train = torch.randn(5000)                                          # 训练时的一个特征
edges = torch.quantile(train, torch.linspace(0, 1, 11))[1:-1]      # 9 个边界 -> 10 个箱
print("边界:", [round(v, 2) for v in edges.tolist()])

def shares(x):
    return torch.bincount(torch.bucketize(x, edges), minlength=10) / len(x)

e = shares(train).clamp_min(1e-4)
print("训练数据每个箱:", [round(v, 3) for v in e.tolist()])

for name, live in [("没变", torch.randn(2000)),
                   ("均值 +0.3", torch.randn(2000) + 0.3),
                   ("均值 +1.0", torch.randn(2000) + 1.0)]:
    a = shares(live).clamp_min(1e-4)
    psi = ((a - e) * torch.log(a / e)).sum().item()
    print(f"{name:8s} PSI = {psi:.3f}")

@@ concept
title: KS 统计量：两条累积曲线的最大距离
--- body
PSI 要先分箱，箱怎么分会影响结果。KS 统计量（Kolmogorov–Smirnov）不用分箱。

先认识**经验累积分布**（ECDF）：F(x) = 数据里「≤ x」的值占多少。比如数据是 [1, 2, 3, 4]：F(0) = 0，F(2) = 2/4 = 0.5，F(10) = 1。x 从小往大走，F 从 0 一格一格涨到 1，画出来是一条台阶线。

两份数据各有一条台阶线。**KS 统计量 = 两条线在竖直方向上的最大距离**：

- 0 表示两份数据的分布一模一样；1 表示完全分开（一份的所有值都比另一份的小）。
- 最大距离一定出现在某个数据点上，所以只要在「两份数据合在一起的所有值」上各算一次就够了。

用 PyTorch 算 F：先 `torch.sort` 排好序，再 `torch.searchsorted(排好序的 a, points, right=True)`。它返回 a 里有几个值 ≤ points（right=True 把相等的也数进去），除以 len(a) 就是 F(points)。

PSI 和 KS 怎么选：两个都常用。PSI 有行业里惯用的阈值；KS 不用分箱，结果总在 0 到 1 之间，好理解。scipy 的 `ks_2samp` 还会给一个 p 值，但线上数据量很大时，一点点差别都会「显著」，所以监控里一般直接给 KS 的值设阈值。今天不用 scipy，自己写。
--- code
a = torch.tensor([1., 2., 3., 4.])
b = torch.tensor([3., 4., 5., 6.])
points = torch.cat([a, b]).sort().values          # 排序只是为了打印好看
Fa = torch.searchsorted(a, points, right=True) / len(a)     # a、b 已经排好序
Fb = torch.searchsorted(b, points, right=True) / len(b)
print("x   :", points.tolist())
print("F_a :", Fa.tolist())
print("F_b :", Fb.tolist())
print("KS  :", (Fa - Fb).abs().max().item())

torch.manual_seed(0)
train = torch.randn(3000).sort().values
live = (torch.randn(1000) + 0.5).sort().values
pts = torch.cat([train, live])
d = (torch.searchsorted(train, pts, right=True) / len(train)
     - torch.searchsorted(live, pts, right=True) / len(live)).abs().max()
print("均值偏移 0.5 时的 KS:", round(d.item(), 3))

@@ concept
title: 预测漂移：标签没回来，先看预测
--- body
监控模型最直接的办法，是算线上的准确率。可是真实标签（label）常常要等很久：贷款要几个月后才知道会不会违约，欺诈要等用户申诉。等标签回来，损失已经造成了。

**预测漂移**（prediction drift）：不看标签，只看模型**输出**的分布有没有变。模型的每个预测我们马上就知道，所以它是实时的。

- 分类模型：看每个类别被预测的比例。上线第一周预测为「欺诈」的是 2%，今天是 9%：要么欺诈真的变多了，要么输入变了、模型开始乱判。两种情况都值得有人去看。
- 也可以看平均置信度（softmax 最大值的平均）有没有明显下降。

类别本身就是「箱」，不用再分箱：

- 比例：`torch.bincount(pred, minlength=num_classes) / len(pred)`。一定要写 minlength：今天某个类一次都没出现时，bincount 返回的结果会变短，和训练时对不上。
- 然后套 PSI 的公式：Σ (a − e) × ln(a / e)，同样先 `clamp_min(eps)`。

输入漂移和预测漂移互相补充：输入变了，预测不一定变（模型可能不在乎那个特征）；预测变了，一定值得查。
--- code
ref_pred = torch.repeat_interleave(torch.arange(3), torch.tensor([700, 250, 50]))    # 上线第一周的预测
live_pred = torch.repeat_interleave(torch.arange(3), torch.tensor([450, 250, 300]))  # 今天的预测
print("ref_pred 的开头:", ref_pred[:5].tolist(), " 长度", len(ref_pred))

e = torch.bincount(ref_pred, minlength=3) / len(ref_pred)
a = torch.bincount(live_pred, minlength=3) / len(live_pred)
print("第一周:", [round(v, 3) for v in e.tolist()])
print("今天:  ", [round(v, 3) for v in a.tolist()])
a, e = a.clamp_min(1e-4), e.clamp_min(1e-4)
print("预测的 PSI:", round(((a - e) * torch.log(a / e)).sum().item(), 3))

only_0_and_1 = torch.tensor([0, 1, 1, 0])
print("不写 minlength:", torch.bincount(only_0_and_1).tolist())
print("写了 minlength:", torch.bincount(only_0_and_1, minlength=3).tolist())

@@ concept
title: 报警规则：滚动窗口 + 最少样本数
--- body
报警要做到两件事：出事时**快**响，没出事时**别**响。半夜被没意义的报警叫醒几次之后，大家就开始无视报警了。

**滚动窗口**（rolling window）：只看最近一段时间（比如最近 5 分钟）的请求。

- 不能用「从上线到现在」的累计错误率：服务跑了一周，错误率 0.5%；刚刚 5 分钟错误率 30%，累计值只从 0.5% 变成 0.51% 左右，谁也发现不了。
- 窗口太短，数字跳得厉害；太长，出事后要很久才响。几分钟是常见的选择。

**最少样本数**（minimum count）：窗口里的请求太少，错误率没有意义。凌晨 3 点，1 分钟里只有 2 个请求，1 个失败，错误率 50%，但这很可能只是某个用户传了坏数据。所以规则写成：**请求数 ≥ min_count，并且错误率 > 阈值**，才报警。

实现：用 `collections.deque`（两头都能快速进出的队列）按时间顺序存 (时间, 是不是错误)。新请求从右边 `append` 进来；每次检查时，先把左边太旧的（时间 ≤ now − window_s）`popleft` 扔掉，剩下的就是窗口里的。扔掉旧请求还有一个好处：服务连着跑几个月，内存也不会一直涨。

真实的系统（比如 Prometheus 的报警规则）还常加一条「连续 N 分钟都超过阈值才报」，以及「报过之后一段时间内不重复报」。思路一样。
--- code
from collections import deque

window_s, threshold, min_count = 60, 0.05, 20
events = deque()                                        # (t 秒, 是不是错误)，旧的在左边

def check(now):
    while events and events[0][0] <= now - window_s:   # 太旧的，从左边扔掉
        events.popleft()
    n = len(events)
    errors = sum(1 for _, is_error in events if is_error)
    rate = errors / n if n else 0.0
    return n, round(rate, 3), n >= min_count and rate > threshold

events.extend([(3, True), (41, False)])                 # 凌晨：1 分钟里只有 2 个请求
print("凌晨 3 点 (请求数, 错误率, 报警):", check(now=50))

for t in range(100, 160):                               # 白天：每秒 1 个请求，每 5 个失败 1 个
    events.append((t, t % 5 == 0))
print("白天出事 (请求数, 错误率, 报警):", check(now=160))
print("deque 里还剩:", len(events), "个请求（凌晨那 2 个已经扔掉了）")

@@ concept
title: 影子流量：新模型先陪跑
--- body
新模型在离线测试集上更好，不代表上线后也更好：线上的数据、流量、各种奇怪的输入，测试集里不一定有。

**影子流量**（shadow traffic，也叫 shadow mode）：每个线上请求，同时发一份给新模型（影子），但**用户拿到的永远是旧模型（prod）的答案**。影子的结果只记下来，拿去和 prod 比。

- 对用户零风险：影子答错了、变慢了、崩了，用户都感觉不到。
- 能拿到真实流量上的数：两个模型的**分歧率**（disagreement rate，预测不一样的比例），影子的延迟和出错次数。
- 分歧率高不一定是坏事（也许新模型改对了），但它告诉你「换上新模型会改变多少用户的结果」，还能把分歧的样本挑出来给人看。

两条铁律：

1. 影子出错，必须被 `try/except` 接住、记一笔，然后照常返回 prod 的答案。**绝不能**因为影子让用户看到错误。
2. prod 自己出错，要照常报错（这是正常的错误处理），不能被影子的 try/except 顺手吞掉。所以 try 只包住影子的那一行。

真实系统里，影子通常在后台线程或者另一个服务里异步地跑，这样也不会拖慢响应。今天的练习为了简单，同步调用。
--- code
torch.manual_seed(0)
prod = nn.Linear(4, 3)
shadow = nn.Linear(4, 3)
shadow.load_state_dict(prod.state_dict())
with torch.no_grad():
    shadow.weight.add_(0.05 * torch.randn(3, 4))     # 「新模型」：和 prod 有点不一样

x = torch.randn(1000, 4)                             # 1000 个线上请求
with torch.inference_mode():
    p = prod(x).argmax(dim=-1)                       # 用户拿到的
    s = shadow(x).argmax(dim=-1)                     # 只记下来
print("预测不一样的行数:", int((p != s).sum()))
print("分歧率:", round((p != s).float().mean().item(), 3))

def broken(x):
    raise RuntimeError("CUDA out of memory（模拟）")

try:
    broken(x)
except Exception as e:
    print("影子出错，记一笔:", type(e).__name__, "-> 用户照样拿到 prod 的答案，shape", tuple(p.shape))

@@ concept
title: 金丝雀和 A/B：样本不够别下结论
--- body
**金丝雀发布**（canary release）：新版本先只接一小部分真实流量（比如 5%），其余还走旧版本（叫基线，baseline）。比较两边的错误率和延迟：没问题就逐步加到 100%，有问题就回滚。名字来自矿工带进矿井的金丝雀：它先出事，人就来得及撤。

**A/B 测试**和它很像，目的不同：两个版本各分一部分用户，跑够事先定好的时间，比较业务指标（点击率、转化率），决定哪个更好。

两者都会撞上同一个问题：**样本太少，差别可能只是运气。**一个真实错误率为 p 的服务，看 n 个请求算出来的错误率会上下晃，晃动的大小叫**标准误差**（standard error，SE）：

SE = sqrt(p × (1 − p) / n)

p = 2%、n = 50 时，SE ≈ 2 个百分点：一个真实错误率 2% 的模型，看起来是 4% 一点也不奇怪。n 变成 100 倍，SE 只缩小到 1/10（因为有根号）。

所以决策规则分三档：

1. 任何一边的请求数 < min_n（事先定好）：**wait**，继续收集，不下结论。
2. 金丝雀的错误率比基线高出 z 倍以上的标准误差（常用 z = 2）：**rollback**。两边合起来的标准误差是 se = sqrt(p_b(1 − p_b)/n_b + p_c(1 − p_c)/n_c)，b 是基线，c 是金丝雀。
3. 否则：**promote**（继续放量）。

下面的代码模拟 2000 次金丝雀：新旧模型**完全一样**，真实错误率都是 2%。每次只看 n 个请求，有多少次金丝雀「看起来」错误率 ≥ 4%？
--- code
torch.manual_seed(0)
p = 0.02
for n in [50, 500, 5000]:
    errors = torch.binomial(torch.full((2000,), float(n)), torch.full((2000,), p))  # 2000 次金丝雀各有几个失败
    looks_bad = (errors / n >= 0.04).float().mean().item()
    se = math.sqrt(p * (1 - p) / n)
    print(f"n={n:5d}  SE={se:.4f}  看起来 >= 4% 的比例: {looks_bad:.3f}")

@@ concept
title: 每 1000 个请求花多少钱
--- body
老板会问：「这个模型一个月花多少钱？值不值？」工程师要能算出**每 1000 个请求的成本**（cost per 1k requests）。

GPU 按小时收钱，不管它忙不忙。所以：

- 每小时实际处理的请求数 = 满载时每秒的吞吐量 × 3600 × 平均利用率
- 每个请求的成本 = GPU 每小时的价格 ÷ 每小时处理的请求数
- 每 1000 个请求的成本 = 每个请求的成本 × 1000

两个杠杆：

- **吞吐量**：批处理（第 22 天）、int8 / fp16（第 21 天）能让同一张卡每秒处理更多请求，成本按比例下降。
- **利用率**：流量白天高、夜里低。按高峰准备的 GPU，夜里大多在空转，钱照样付。平均利用率 25%，成本就是满载时的 4 倍。自动扩缩容（按流量增减机器）就是为了提高利用率。

生成式模型常说「每 1000 个 token 的成本」，算法一样，把请求数换成 token 数。

下面的价格是假设的，只用来演示怎么算。
--- code
price = 2.00                                         # 假设：一张 GPU 每小时 2 美元
for name, rps, util in [("batch=1,  利用率 100%", 40, 1.0),
                        ("batch=1,  利用率 25%", 40, 0.25),
                        ("batch=16, 利用率 25%", 400, 0.25)]:
    per_hour = rps * 3600 * util                     # 每小时实际处理的请求数
    cost = price / per_hour * 1000
    print(f"{name}   每 1000 个请求 ${cost:.4f}")

title: 从请求日志算面板上的数
level: 1
cards: 上线后要看的几个数
--- context
监控面板上的每个数，都是从一行行请求日志算出来的。自己算一遍，才知道「平均延迟 125 ms」这种数为什么会骗人。
--- prompt
10 个请求，5 秒内进来。写出这段代码打印的 4 行。
--- code
latency_ms = [12, 15, 11, 240, 14, 13, 16, 12, 15, 900]
status = [200, 200, 200, 500, 200, 200, 200, 200, 200, 504]
seconds = 5

print(len(latency_ms) / seconds)                        # 吞吐量 req/s
print(sum(s >= 500 for s in status) / len(status))      # 错误率
print(sum(latency_ms) / len(latency_ms))                # 平均延迟
print(sorted(latency_ms)[len(latency_ms) // 2])         # 排好序后，正中间那个

def psi(ref, live, bins=10, eps=1e-4):
    edges = torch.quantile(ref, torch.linspace(0, 1, bins + 1))[1:-1]     # 边界只来自训练数据
    e = torch.bincount(torch.bucketize(ref, edges), minlength=bins) / len(ref)
    a = torch.bincount(torch.bucketize(live, edges), minlength=bins) / len(live)
    e, a = e.clamp_min(eps), a.clamp_min(eps)                            # 空箱不会变成 log(0)
    return float(((a - e) * torch.log(a / e)).sum())

def ks_statistic(a, b):
    a = torch.sort(a).values                   # searchsorted 要求排好序
    b = torch.sort(b).values
    points = torch.cat([a, b])                 # 最大距离一定出现在某个数据点上
    cdf_a = torch.searchsorted(a, points, right=True) / len(a)    # a 里 <= 每个位置的比例
    cdf_b = torch.searchsorted(b, points, right=True) / len(b)
    return float((cdf_a - cdf_b).abs().max())

    return torch.bincount(pred, minlength=num_classes) / len(pred)     # minlength：没出现的类也占一个位置


def prediction_psi(ref_pred, live_pred, num_classes, eps=1e-4):
    e = class_shares(ref_pred, num_classes).clamp_min(eps)
    a = class_shares(live_pred, num_classes).clamp_min(eps)
    return float(((a - e) * torch.log(a / e)).sum())

from collections import deque

class ErrorRateAlert:
    def __init__(self, window_s=300, threshold=0.05, min_count=50):
        self.window_s = window_s
        self.threshold = threshold
        self.min_count = min_count
        self.events = deque()

    def record(self, t, is_error):
        self.events.append((t, bool(is_error)))

    def firing(self, now):
        while self.events and self.events[0][0] <= now - self.window_s:   # 窗口外的，从左边扔掉
            self.events.popleft()
        n = len(self.events)
        if n == 0 or n < self.min_count:                                 # 样本太少，不下结论
            return False
        errors = sum(1 for _, is_error in self.events if is_error)
        return errors / n > self.threshold

def serve_with_shadow(x, prod, shadow, stats):
    with torch.inference_mode():
        pred = prod(x).argmax(dim=-1)          # 用户拿到的答案：只来自 prod。prod 出错就照常抛出
        try:
            other = shadow(x).argmax(dim=-1)   # try 只包住影子
        except Exception:
            stats["shadow_errors"] += 1        # 记一笔，但不影响用户
        else:
            stats["rows"] += len(x)
            stats["disagree"] += int((pred != other).sum())
    return pred


def disagreement_rate(stats):
    if stats["rows"] == 0:
        return None
    return stats["disagree"] / stats["rows"]

def canary_decision(base_errors, base_n, canary_errors, canary_n, min_n=1000, z=2.0):
    if base_n < min_n or canary_n < min_n:
        return "wait"                                       # 样本不够，不下结论
    p_base = base_errors / base_n
    p_canary = canary_errors / canary_n
    se = math.sqrt(p_base * (1 - p_base) / base_n + p_canary * (1 - p_canary) / canary_n)
    if p_canary - p_base > z * se:                          # 差得比噪声大得多，才算真的更差
        return "rollback"
    return "promote"

def psi(ref, live, bins=10, eps=1e-4):
    edges = torch.quantile(ref, torch.linspace(0, 1, bins + 1))[1:-1]
    e = torch.bincount(torch.bucketize(ref, edges), minlength=bins) / len(ref)
    a = torch.bincount(torch.bucketize(live, edges), minlength=bins) / len(live)
    e, a = e.clamp_min(eps), a.clamp_min(eps)
    return float(((a - e) * torch.log(a / e)).sum())

from collections import deque

class ErrorRateAlert:
    def __init__(self, window_s=300, threshold=0.05, min_count=50):
        self.window_s = window_s
        self.threshold = threshold
        self.min_count = min_count
        self.events = deque()

    def record(self, t, is_error):
        self.events.append((t, bool(is_error)))

    def firing(self, now):
        while self.events and self.events[0][0] <= now - self.window_s:
            self.events.popleft()
        n = len(self.events)
        if n == 0 or n < self.min_count:
            return False
        errors = sum(1 for _, is_error in self.events if is_error)
        return errors / n > self.threshold
