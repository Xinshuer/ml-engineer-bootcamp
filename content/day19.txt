@@ concept
title: 一个张量占多少字节
--- body
显存和内存都按字节算。一个张量占的字节数 = 元素个数 × 每个元素的字节数，写成代码是 `t.numel() * t.element_size()`，也可以直接用 `t.nbytes`。

常见 dtype 每个元素的字节数：

- float32（fp32）：4
- bfloat16（bf16）、float16（fp16）：2
- int8：1
- int64（也叫 long，比如分类标签）：8

一个模型占的内存 = **参数**（parameters）+ **buffer**。buffer 是模型里「要跟着模型保存、跟着 `.to(device)` 一起搬，但不训练」的张量，比如 BatchNorm 的 `running_mean` 和 `running_var`。用 `model.parameters()` 和 `model.buffers()` 分别遍历它们。

两个容易算错的地方：

- 冻结的参数（`requires_grad=False`）只是不训练，照样占内存。
- 共享的权重只占一份内存。比如很多语言模型的输入 embedding 和输出层用同一个矩阵。`model.parameters()` 会自动去重，`model.state_dict()` 却会把它列两次。
--- code
for dt in [torch.float32, torch.bfloat16, torch.int64]:
    print(dt, "每个元素", torch.zeros(1, dtype=dt).element_size(), "字节")

model = nn.Sequential(nn.Linear(512, 512), nn.BatchNorm1d(512))
for name, t in model.named_parameters():
    print("参数  ", name, tuple(t.shape), t.dtype, t.numel() * t.element_size(), "字节")
for name, t in model.named_buffers():
    print("buffer", name, tuple(t.shape), t.dtype, t.numel() * t.element_size(), "字节")

emb = nn.Embedding(100, 16)
head = nn.Linear(16, 100, bias=False)
head.weight = emb.weight                     # 输出层和 embedding 共用同一个矩阵
tied = nn.ModuleDict({"emb": emb, "head": head})
print("parameters() 里有", len(list(tied.parameters())), "个张量；state_dict() 里有", len(tied.state_dict()), "个")

@@ concept
title: 训练显存的四大块
--- body
训练时，GPU 显存主要花在四个地方：

1. **权重**（weights）：每个参数一个数。
2. **梯度**（gradients）：`backward()` 之后，每个参数都有一个同样大小的 `.grad`。
3. **优化器状态**：Adam 给每个参数存两个数，一阶动量 m 和二阶动量 v，通常是 fp32，各 4 字节。SGD 什么都不存，带 momentum 的 SGD 存一个。
4. **激活值**（activations）：前向时为反向保存的中间结果。它随 batch 和序列长度变化，下一张卡片专门讲。

前三块只和参数个数有关。按「每个参数几个字节」来记：

- fp32 训练 + Adam：权重 4 + 梯度 4 + Adam 8 = **16 字节**
- 混合精度 + Adam：bf16 权重 2 + bf16 梯度 2 + fp32 主权重 4 + Adam 8 = **还是 16 字节**
- 纯 bf16（权重、梯度、Adam 状态全是 bf16）：2 + 2 + 4 = **8 字节**

主权重（master weights）是混合精度训练额外留的一份 fp32 权重。优化器在它上面做更新，因为 bf16 太粗，很小的更新会被舍入成 0。所以混合精度省的主要是激活和计算时间，不是这三块。（PyTorch 自带的 `torch.autocast` 做法不同：权重和梯度一直是 fp32，只在计算时临时转成 bf16。合起来同样是 4 + 4 + 8 = 16 字节。）

拿一个 7B（70 亿参数）的模型算一算。本课为了好算，1 GB 按 10⁹ 字节：

- 只推理，bf16 权重：7×10⁹ × 2 = 14 GB
- fp32 + Adam 全量训练：7×10⁹ × 16 = 112 GB。激活还没算，一张 80 GB 的卡已经放不下了。

这就是大模型微调要用 LoRA（第 6 天）、把这些状态分到多张卡上（ZeRO / FSDP）或者用 8-bit 优化器的原因。（显卡上标的「24 GB」其实是 24×2³⁰ ≈ 25.8×10⁹ 字节，估算时这 7% 可以忽略。）
--- code
model = nn.Linear(1000, 1000)
opt = torch.optim.Adam(model.parameters())
model(torch.randn(8, 1000)).sum().backward()
opt.step()                                   # 第一次 step 时，Adam 才创建 m 和 v

w = sum(p.nbytes for p in model.parameters())
g = sum(p.grad.nbytes for p in model.parameters())
s = sum(v.nbytes for st in opt.state.values() for k, v in st.items() if k != "step")
print("权重", w, " 梯度", g, " Adam 状态", s, "字节")   # 1 : 1 : 2

n = 7_000_000_000
for name, per_param in [("fp32 + Adam", 4 + 4 + 8), ("混合精度 + Adam", 2 + 2 + 4 + 8), ("纯 bf16 + Adam", 2 + 2 + 4)]:
    print(f"7B {name}: 每个参数 {per_param} 字节 -> {n * per_param / 1e9:.0f} GB（不含激活）")

@@ concept
title: 激活值：随 batch 和长度一起涨
--- body
前向时，很多层要把输入或输出存下来，反向算梯度时要用。比如 `y = x @ W`，求 W 的梯度要用到 x。这些为反向存下的中间结果，就是激活值。

激活和参数个数无关，和「这一次喂进去多少数据」成正比：batch 翻倍，激活翻倍；序列长度翻倍，激活至少翻倍（普通 attention 还要存 T×T 的分数矩阵，涨得更快）。

粗略估算 Transformer：每一层前向时大约要存十几个 (batch, seq, hidden) 大小的张量（attention 和 MLP 里的各种中间结果）。本课按 16 个算：

```
每个样本的激活 ≈ seq × hidden × 层数 × 16 × 每个数的字节
```

例子：24 层、hidden 2048、seq 2048、bf16（2 字节）。每个样本的激活约 3.2 GB。这个模型大约 12 亿参数，混合精度 + Adam 的前三块按 16 字节/参数算约 19.3 GB。一张 24 GB 的卡只剩约 4.7 GB 给激活，micro-batch 只能开到 1。想开大 batch，可以用梯度累积（第 17 天）、激活检查点（后面的卡片），或者缩短序列。

没有 GPU 也能「量」激活：`torch.autograd.graph.saved_tensors_hooks` 让你在 autograd 每存一个张量时都被通知一次。下面的 `saved_bytes` 把这些张量的字节数加起来：同一块内存只算一次；`skip` 里的张量（比如模型参数）本来就在内存里，不算。后面几道题的测试也用这个函数。
--- code
def act_bytes_per_sample(seq, hidden, n_layers, bytes_per_value, tensors_per_layer=16):
    return seq * hidden * n_layers * tensors_per_layer * bytes_per_value

per = act_bytes_per_sample(2048, 2048, 24, 2)
print(f"每个样本 {per / 1e9:.2f} GB；batch=8 要 {8 * per / 1e9:.1f} GB")

def saved_bytes(fn, *args, skip=()):
    skip_ptrs = {t.untyped_storage().data_ptr() for t in skip}
    seen = {}
    def pack(t):                              # autograd 每为反向存一个张量，就调用一次 pack
        s = t.untyped_storage()
        if s.data_ptr() not in skip_ptrs:
            seen[s.data_ptr()] = s.nbytes()   # 同一块内存只记一次
        return t
    with torch.autograd.graph.saved_tensors_hooks(pack, lambda t: t):
        out = fn(*args)
    return out, sum(seen.values())

mlp = nn.Sequential(nn.Linear(64, 256), nn.GELU(), nn.Linear(256, 64))
for batch in (8, 16, 32):
    _, n = saved_bytes(mlp, torch.randn(batch, 64), skip=mlp.parameters())
    print(f"batch={batch:2d}: 为反向存了 {n} 字节")

title: 泄漏：存下来的 loss 拖着整张图
--- body
一个需要梯度的张量（比如 loss）身上挂着 `grad_fn`。顺着它能找到整张计算图，图里又存着前向的激活值。只要你还拿着这个张量，这些东西就都活着。

经典的写法：

```
losses.append(loss)      # 存的是 tensor，连着计算图
total += loss            # total 也变成带图的 tensor，每一步都接到同一条链上
```

- 如果这一步没有做 `backward()`（比如验证循环，或者只是记录一下），整张图连同所有激活都留在显存里，几个 batch 就 OOM（显存不够）。
- 就算做了 `backward()`（它会释放图里存的激活），图的节点还在；`total += loss` 把每一步的图串成一条越来越长的链，内存慢慢往上涨。

改法：要记一个数，就存数。`loss.item()` 返回一个 Python float，和计算图没有任何关系。要留一个张量（比如预测结果）时，用 `.detach()`，通常再加 `.cpu()` 挪出显存。（在 GPU 上，`.item()` 要等 GPU 算完才能拿到数，所以记日志时可以每 N 步才调用一次。）

怎么看显存：`nvidia-smi` 显示的是 PyTorch **预留**的显存。PyTorch 有一个缓存分配器（caching allocator）：张量释放后，那块显存先留在 PyTorch 手里，下次直接复用，不还给显卡驱动。所以：

- `torch.cuda.memory_allocated()`：张量真正占着的显存
- `torch.cuda.max_memory_allocated()`：到目前为止的峰值
- `torch.cuda.memory_reserved()`：PyTorch 预留的总量，接近 nvidia-smi 里的数

下面的代码没有 GPU 也能看到泄漏：`weakref.ref(h)` 是一个「弱引用」，它不会让 h 活着。循环结束后，如果弱引用还能拿到 h，说明有别的东西（计算图）还抓着它。
--- code
import weakref

torch.manual_seed(0)
model = nn.Sequential(nn.Linear(4, 256), nn.ReLU(), nn.Linear(256, 1))

def run(keep_tensor):
    alive, kept = [], []
    for _ in range(3):
        h = model[1](model[0](torch.randn(64, 4)))   # 中间激活，(64, 256)
        alive.append(weakref.ref(h))
        loss = model[2](h).pow(2).mean()              # 没有 backward，比如只是记录一下
        kept.append(loss if keep_tensor else loss.item())
        del h, loss
    return [r() is not None for r in alive], kept[0]

print("append(loss)       激活还活着吗:", run(True))
print("append(loss.item()) 激活还活着吗:", run(False))

@@ concept
title: 推理时别建图：no_grad 和 inference_mode
--- body
默认情况下，只要有一个输入需要梯度（模型参数都需要），PyTorch 就会一边算一边建计算图、存激活。推理和验证根本不做反向，这些都是白占显存、白花时间。

- `with torch.no_grad():` 里算出来的张量 `requires_grad=False`，没有 `grad_fn`，也不存激活。
- `with torch.inference_mode():` 更彻底，还省掉了一些内部记账，所以稍快一点。代价是：它产生的「推理张量」以后不能再参与需要梯度的计算，否则报错。
- 两个都能当装饰器用：在函数上面写 `@torch.no_grad()` 或 `@torch.inference_mode()`。

注意：它们管的是「在 with 块里做的计算」，不会改动模型参数的 `requires_grad`。出了 with 块，用同一个模型算出来的结果又会带上计算图。

还有，`model.eval()` 是另一回事（第 18 天）：它切换 dropout 和 BatchNorm 的行为，不管建不建图。推理时两个都要。
--- code
lin = nn.Linear(4, 2)
x = torch.randn(3, 4)

y = lin(x)
print("默认:           requires_grad =", y.requires_grad, " 有 grad_fn:", y.grad_fn is not None)
with torch.no_grad():
    y = lin(x)
print("no_grad:        requires_grad =", y.requires_grad, " 有 grad_fn:", y.grad_fn is not None)
with torch.inference_mode():
    y = lin(x)
print("inference_mode: requires_grad =", y.requires_grad, " is_inference =", y.is_inference())
print("参数本身:       lin.weight.requires_grad =", lin.weight.requires_grad)

try:
    lin(y).sum().backward()        # 拿推理张量去参与训练
except RuntimeError as e:
    print("报错:", str(e).split(".")[0])

title: 计时：预热、同步、取中位数
--- body
「这个改动让模型快了多少」要靠计时回答。常见的错法有三种：

1. **不预热**。第一次调用往往特别慢：要分配显存，cuDNN 要挑算法，`torch.compile` 要编译。所以先空跑几次（warm-up，预热），这几次不计时。
2. **不同步**。GPU 是异步的：`y = model(x)` 只是把任务排进队列就立刻返回，GPU 还在后台算。不等它算完就读时间，量到的只是「排队」的时间。所以读开始时间之前、读结束时间之前，都要调用 `torch.cuda.synchronize()`，等 GPU 把队列里的活干完。开始前那一次，是为了不把之前没干完的活（比如预热）算到这一次头上。
3. **只跑一次，或者取平均**。每次的时间都会抖（别的程序、系统调度）。要跑很多次，取**中位数**（median，排好序后中间那个）。偶尔一次特别慢，不会把中位数带偏；平均数却会被它拉高。

读时间用 `time.perf_counter()`，它是专门测时间间隔的高精度时钟。`time.time()` 是日历时间，精度差，还可能被系统校时改掉。

下面先用一个「假 GPU」演示第 2 点：`launch` 只排队，`sync` 才让时钟往前走。这里没有真实时间流逝，所以每次运行结果都一样。
--- code
import statistics, time

class FakeGPU:
    def __init__(self):
        self.now, self.pending = 0.0, 0.0
    def launch(self, seconds):        # 像一个 CUDA kernel：排进队列，马上返回
        self.pending += seconds
    def sync(self):                   # 像 torch.cuda.synchronize()：等队列清空
        self.now += self.pending
        self.pending = 0.0
    def clock(self):
        return self.now

gpu = FakeGPU()
t0 = gpu.clock(); gpu.launch(0.010); t1 = gpu.clock()
print(f"不 sync:          {t1 - t0:.3f} s   只量到了排队")
t0 = gpu.clock(); gpu.launch(0.010); gpu.sync(); t1 = gpu.clock()
print(f"只在结束前 sync:  {t1 - t0:.3f} s   上一次没干完的 10 ms 也算进来了")
gpu.sync(); t0 = gpu.clock(); gpu.launch(0.010); gpu.sync(); t1 = gpu.clock()
print(f"前后都 sync:      {t1 - t0:.3f} s   对了")

times = [0.010, 0.011, 0.250, 0.010, 0.012]     # 有一次被别的程序打断了
print("平均:", round(statistics.mean(times), 4), " 中位数:", statistics.median(times))

x = torch.randn(256, 256)
for _ in range(3):                  # 预热
    x @ x
ts = []
for _ in range(20):
    t0 = time.perf_counter()
    x @ x
    ts.append(time.perf_counter() - t0)
print(f"本机 CPU 上 256x256 矩阵乘：中位数 {statistics.median(ts) * 1e3:.3f} ms")

title: 激活检查点：用计算换显存
ref: day19
--- body
激活检查点（activation checkpointing，也叫 gradient checkpointing）：前向时，一个 block 内部的中间结果都不存，只存这个 block 的输入；反向时，用这个输入把 block 重新算一遍，拿到需要的中间结果，再算梯度。

- 省了：每个 block 只剩一个输入张量，激活大约从每层十几份降到一份。
- 花了：每个 block 的前向要多算一遍，大约多三分之一的计算量。
- 没变：输出和梯度。它只是换了一种算法省显存，数学上完全一样。

写法：

```
from torch.utils.checkpoint import checkpoint
x = checkpoint(block, x, use_reentrant=False)   # 代替 x = block(x)
```

一定要写 `use_reentrant=False`。旧的 `use_reentrant=True` 有个坑：如果传进去的张量都不需要梯度（比如第一层的输入就是数据），这一段里的参数就拿不到梯度，backward 甚至直接报错。不写这个参数时，现在的 PyTorch 会给一个警告，用的还是旧的 True。

block 里有 dropout 也没关系：checkpoint 默认会记下随机数状态，重算时用同一个 dropout mask，梯度完全一样。

下面的代码用卡片「激活值：随 batch 和长度一起涨」里的 `saved_bytes` 量一量。
--- code
from torch.utils.checkpoint import checkpoint

torch.manual_seed(0)
blocks = nn.ModuleList([nn.Sequential(nn.Linear(64, 256), nn.GELU(), nn.Linear(256, 64)) for _ in range(4)])
x = torch.randn(32, 64)

def plain(x):
    for b in blocks:
        x = b(x)
    return x

def ckpt(x):
    for b in blocks:
        x = checkpoint(b, x, use_reentrant=False)
    return x

grads = []
for f in (plain, ckpt):
    blocks.zero_grad()
    out, n = saved_bytes(f, x, skip=blocks.parameters())
    out.pow(2).mean().backward()
    grads.append([p.grad.clone() for p in blocks.parameters()])
    print(f"{f.__name__:5s}: 为反向存了 {n:6d} 字节")
print("梯度完全一样:", all(torch.equal(a, b) for a, b in zip(*grads)))

title: DataLoader worker 和 torch.compile 重编译
--- body
### DataLoader

`num_workers=0` 时，读数据和预处理都在主进程里做，这段时间 GPU 在干等。设成 `num_workers=4` 这类值，就会开几个子进程（worker）并行准备后面的 batch。

- Windows 和 macOS 用 spawn 方式启动 worker：每个 worker 是一个全新的 Python，它会先重新 import 你的脚本。脚本顶层的代码会在每个 worker 里再跑一遍。如果顶层就在建 DataLoader、开始训练，worker 又会去开 worker，Python 直接报 RuntimeError。所以训练代码要放进函数，用 `if __name__ == "__main__":` 保护起来。
- Dataset 类要写在能被 import 的 .py 文件里。在 Jupyter 里定义的类，spawn 出来的 worker 找不到。
- `pin_memory=True`：把 batch 放进「锁页内存」，往 GPU 拷贝更快，还能配合 `.to("cuda", non_blocking=True)` 一边拷贝一边计算。
- `persistent_workers=True`：一个 epoch 结束后不关 worker，下个 epoch 不用重新启动（Windows 上启动很慢）。

```
def main():
    loader = DataLoader(ds, batch_size=32, num_workers=4, pin_memory=True, persistent_workers=True)
    for x, y in loader:
        ...

if __name__ == "__main__":
    main()
```

### torch.compile

第一次调用时，`torch.compile` 按这次输入的形状，把模型编译成更快的代码。这一步可能要几秒到几十秒。之后形状一样就直接复用。形状变了会触发重新编译（recompile）。默认设置下，第二个不同的形状出现时，PyTorch 会把变化的那一维改成「动态」再编译一次，之后的新长度一般都能复用。如果写了 `dynamic=False`，每个新形状都要编译一次，编到上限（这个版本是 8 次）以后就不再编译，退回普通的慢速执行。

上线时的做法：启动时用几种典型形状预热；或者把输入 pad 到几个固定长度（比如 64、128、256，叫「分桶」）。想知道为什么重编译，设置环境变量 `TORCH_LOGS=recompiles`。

下面的代码打印本机启动 worker 的方式，再用一个「只计数、不真编译」的 backend 数一数编译了几次。
--- code
import multiprocessing
print("本机启动 worker 的方式:", multiprocessing.get_start_method())

compiles = []
def counting_backend(gm, example_inputs):
    compiles.append(1)
    return gm.forward                          # 不真的编译，照原样执行

for dynamic in (None, False):
    compiles.clear()
    torch._dynamo.reset()                      # 清掉之前的编译记录，多次运行结果才一样
    f = torch.compile(lambda x: (x * 2).sum(), backend=counting_backend, dynamic=dynamic)
    for n in [4, 4, 5, 6, 7, 4]:
        f(torch.ones(n))
    print(f"dynamic={dynamic}: 长度 4,4,5,6,7,4 一共编译了 {len(compiles)} 次")

PER_PARAM = {           # weights, grads, master, adam
    "fp32": (4, 4, 0, 8),
    "mixed": (2, 2, 4, 8),
    "bf16": (2, 2, 0, 4),
}

def train_state_bytes(n_params, precision):
    if precision not in PER_PARAM:
        raise ValueError(precision)
    w, g, m, a = PER_PARAM[precision]
    out = {"weights": n_params * w, "grads": n_params * g, "master": n_params * m, "adam": n_params * a}
    out["total"] = sum(out.values())
    return out

def max_micro_batch(gpu_bytes, static_bytes, seq, hidden, n_layers, bytes_per_value, tensors_per_layer=16):
    per_sample = seq * hidden * n_layers * tensors_per_layer * bytes_per_value
    free = gpu_bytes - static_bytes
    if free <= 0:
        return 0
    return free // per_sample

import statistics
import time

def benchmark(fn, warmup=3, runs=10, clock=time.perf_counter, sync=None):
    for _ in range(warmup):
        fn()
    times = []
    for _ in range(runs):
        if sync is not None:
            sync()               # 先等之前的活（比如预热）干完
        t0 = clock()
        fn()
        if sync is not None:
            sync()               # 等这一次真的算完
        times.append(clock() - t0)
    return statistics.median(times)

from torch.utils.checkpoint import checkpoint

def forward_checkpointed(blocks, x):
    for b in blocks:
        x = checkpoint(b, x, use_reentrant=False)
    return x
--- tests
def _blocks():
    seed(0)
    return nn.ModuleList([nn.Sequential(nn.Linear(16, 64), nn.GELU(), nn.Dropout(0.1), nn.Linear(64, 16))
                          for _ in range(4)])

def _plain(blocks, x):
    for b in blocks:
        x = b(x)
    return x

def _grads(f, blocks, x):
    blocks.zero_grad()
    seed(1)                          # 同一个随机种子 -> 同样的 dropout mask
    f(blocks, x).pow(2).mean().backward()
    return [None if p.grad is None else p.grad.clone() for p in blocks.parameters()]

--- context
同一个训练脚本，在 Linux 服务器上好好的，拿到 Windows 电脑上一开 num_workers 就崩。原因是两边启动子进程的方式不一样。
--- prompt
你在 Windows 上运行 `train.py`。文件顶层直接写着下面几行，没有函数，也没有 `if __name__ == "__main__":`：

```
ds = MyDataset("data/")

for x, y in loader:
    train_step(x, y)
```

会发生什么？
--- options
- 正常运行，4 个 worker 并行读数据，比 `num_workers=0` 快
- 报 RuntimeError：每个 worker 是一个新启动的 Python，会重新执行 train.py 的顶层代码，于是又去建 DataLoader、又要开 worker；Python 发现「进程还没启动完就要开新进程」，直接报错
- PyTorch 发现是 Windows，自动退回 `num_workers=0`，只打印一条警告
- 不报错，但每个 batch 会被读 4 遍，训练结果不对
answer: 2
--- explain
Windows 上 Python 用 spawn 启动子进程：新进程先 import 你的主脚本（这时它的 `__name__` 是 `"__mp_main__"`，不是 `"__main__"`），再接活。没有保护的顶层代码会在每个 worker 里重跑，worker 又去开 worker。Python 会报 RuntimeError（「An attempt has been made to start a new process before the current process has finished its bootstrapping phase」），主进程接着报「DataLoader worker (pid ...) exited unexpectedly」。改法：训练代码放进 `main()`，文件最后写 `if __name__ == "__main__": main()`。Linux 上，Python 3.13 及以前默认用 fork（直接复制当前进程，不重新执行脚本），所以同一个脚本在服务器上常常没事。
--- hints
- Windows 上的子进程不是「复制」出来的，而是从头启动一个新的 Python。
- 新的 Python 要先 import 你的脚本。脚本顶层的那几行会怎么样？

- 默认设置下，PyTorch 看到某一维变过一次，就会把它当成「会变的」维度。

PER_PARAM = {           # weights, grads, master, adam
    "fp32": (4, 4, 0, 8),
    "mixed": (2, 2, 4, 8),
    "bf16": (2, 2, 0, 4),

def train_state_bytes(n_params, precision):
