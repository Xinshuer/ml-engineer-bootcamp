@@ concept
title: 字符级 tokenizer：字和数字互相转换
--- body
模型只认识数字，不认识文字。tokenizer（分词器）做两件事：把文字切成一小块一小块（每块叫一个 token），再把每个 token 换成一个整数，叫 token id。

最简单的切法是一个字符一个 token：

1. 把语料里出现过的字符去重再排序：`sorted(set(text))`。排序是为了每次建出来的表都一样。
2. 给每个字符一个编号。建两个字典：`stoi`（string to int，字符 → id）和 `itos`（int to string，id → 字符）。
3. `encode`：字符串 → id 列表。`decode`：id 列表 → 字符串。

词表大小 `vocab_size`（常写成 V）就是不同字符的个数。下面的 "hello world" 有 8 个不同字符（空格也算），V = 8。nanoGPT 用的莎士比亚语料有 65 个不同字符，V = 65。

一个 tokenizer 最基本的要求是能「往返」：`decode(encode(s)) == s`。

小坑：模型输出的 id 常常是 tensor 里的数。tensor 不能直接当字典的键去查（会报 KeyError），decode 时先用 `int(i)` 转成 Python 整数。
--- code
text = "hello world"
chars = sorted(set(text))
stoi = {c: i for i, c in enumerate(chars)}
itos = {i: c for c, i in stoi.items()}
print("词表:", chars)
print("V =", len(chars))
ids = [stoi[c] for c in "hello"]
print("encode('hello') ->", ids)
print("decode ->", "".join(itos[i] for i in ids))
t = torch.tensor(ids)
print("从 tensor decode ->", "".join(itos[int(i)] for i in t))

@@ concept
title: BPE 与压缩率
ref: day3
--- body
字符级 tokenizer 太「碎」：一句话要很多 token，模型要处理的序列就很长。GPT 系列用的是 BPE（Byte Pair Encoding，字节对编码）。它从最小的单位开始（GPT-2 从 256 个字节开始），反复做三步：

1. 数一数所有相邻的两个 token（叫一个 pair）各出现几次。
2. 把出现次数最多的 pair 合并成一个新 token，比如 `"t","h"` → `"th"`，加进词表。
3. 拿合并后的序列回到第 1 步。

GPT-2 一共合并了 50000 次：256 个字节 + 50000 个合并出来的 token + 1 个特殊 token `<|endoftext|>`，词表就是 50257。

合并时从左往右扫。一个位置合并过了，就跳过这两个 token，它们不能再参与这一轮合并。所以 `["a","a","a"]` 合并 `("a","a")` 得到 `["aa", "a"]`，不是两个 `"aa"`。但数 pair 时重叠也算：`["a","a","a"]` 里 `("a","a")` 出现 2 次（位置 0-1 和 1-2）。

### 压缩率

压缩率 = 字符数 ÷ token 数，也就是平均一个 token 装几个字符。数越大，这个 tokenizer 对这段文字越「省」。字符级 tokenizer 的压缩率正好是 1；每合并一次，token 变少，压缩率变大。

token 数为什么要紧：API 按 token 收费，上下文窗口按 token 算长度，训练和生成的时间也按 token 算。

为什么中文常常更「贵」：GPT-2 这类 BPE 从 UTF-8 字节开始合并。一个英文字母是 1 个字节，一个常用汉字是 3 个字节（「你」是 228, 189, 160）。合并规则主要是从英文语料里学来的，很多汉字没被合并过，一个字常常要占不止一个 token。

下面的代码里，`merge_pair` 是今天 d3-02 要你自己写的函数，这里先用参考实现看效果。
--- code
from collections import Counter

text = "the cat and the hat"
tokens = list(text)
print("开始:", len(tokens), "个 token")
for step in range(4):
    counts = Counter(zip(tokens, tokens[1:]))      # 相邻 pair 计数
    best = max(counts, key=counts.get)             # 出现最多的 pair
    tokens = merge_pair(tokens, best)
    print(f"合并 {best}（出现 {counts[best]} 次）-> {len(tokens)} 个 token，压缩率 {len(text) / len(tokens):.2f}")
print(tokens)
print("'你' 的 UTF-8 字节:", list("你".encode("utf-8")))

@@ concept
title: get_batch：x 和 y 错开一位
--- body
语言模型的任务是「预测下一个 token」。训练时，整段语料就是一长串 token id（一个 1D tensor `data`）。每一步从里面随机切出 batch_size 段（记作 B），每段长 block_size（上下文长度，记作 T）：

- `x = data[i : i+T]` 是输入。
- `y = data[i+1 : i+1+T]` 是答案，也就是 x 往右挪一位。

这样 `y[t]` 正好是 `x[t]` 的下一个 token。一段长 T 的 x，一次给模型出了 T 道「猜下一个」的题：看到前 1 个猜第 2 个，看到前 2 个猜第 3 个……

起点 i 能取多大？y 的最后一个元素是 `data[i+T]`，它必须存在，所以 `i + T <= len(data) - 1`，也就是 i 最大是 `len(data) - T - 1`。`torch.randint(high, (B,))` 生成 0 到 high-1 的整数（不含 high），所以写 `torch.randint(len(data) - T, (B,))`。把 B 段用 `torch.stack` 叠起来，x 和 y 的形状都是 `(B, T)`。

想让随机起点可以复现，就建一个 `g = torch.Generator().manual_seed(0)`，再传 `generator=g` 给 `torch.randint`：同一个种子，同一批起点。

dtype 必须是 int64（`torch.long`）：embedding 层（按 id 查表、把 id 换成向量的层）和 `cross_entropy` 的标签都只收整数。

三个常见错误：

- y 忘了右移（y 和 x 一样）：不报错。模型只要「抄输入」就能答对，loss 很快掉到接近 0，但生成出来的全是垃圾。
- 起点上界写成 `len(data)`：切到末尾时切片变短，`torch.stack` 报错。而且是偶尔才报错，最难查。
- 转成了 float：embedding 直接报错。
--- code
data = torch.arange(10, 20)          # 假装这是 10 个 token id
T = 4
i = 3
x = data[i:i + T]
y = data[i + 1:i + 1 + T]
print("x =", x.tolist())
print("y =", y.tolist())
for t in range(T):
    print(f"看到 {x[:t + 1].tolist()} -> 该猜 {y[t].item()}")
print("起点 i 最大:", len(data) - T - 1)
g = torch.Generator().manual_seed(0)
print("随机起点:", torch.randint(len(data) - T, (5,), generator=g).tolist())
g = torch.Generator().manual_seed(0)
print("同一个种子再来:", torch.randint(len(data) - T, (5,), generator=g).tolist())

@@ concept
title: 大语料：uint16 的 .bin 文件和 np.memmap
--- body
真实语料有几十 GB，读不进内存。nanoGPT 的做法分两步：

1. 预处理时，把所有 token id 一次写成一个二进制文件：`np.asarray(ids, dtype=np.uint16).tofile(path)`。文件里只有数字，没有任何表头。
2. 训练时用 `np.memmap(path, dtype=np.uint16, mode="r")` 打开。memmap（内存映射）用起来像一个 numpy 数组，但数据还留在磁盘上：你切哪一段，操作系统才读哪一段。

为什么用 uint16：它表示 0 到 65535 的整数，每个只占 2 字节。GPT-2 的词表是 50257，装得下。比 int64（8 字节）省 4 倍磁盘。1000 个 token 就是 2000 字节。

几个要记住的点：

- `.bin` 文件不记录 dtype。读的时候 dtype 必须和写的时候一样，不然读出来全是错的数（下面的代码故意用 uint8 读了一次）。
- `mode="r"` 是只读，防止训练代码不小心改坏语料。
- 词表超过 65536（比如 10 万词的 tokenizer）就不能用 uint16，要用 uint32。装不下的数如果来自 Python list，numpy 会报 OverflowError；如果来自 int64 的 numpy 数组（比如用 `astype` 转），不会报错，会悄悄变成别的数。
- 送进模型前，把切出来的一段转成 int64 tensor：`torch.from_numpy(m[i:i+T].astype(np.int64))`。
--- code
import os, tempfile
import numpy as np

with tempfile.TemporaryDirectory(ignore_cleanup_errors=True) as d:
    path = os.path.join(d, "train.bin")
    np.asarray([5, 50256, 7, 8], dtype=np.uint16).tofile(path)
    print("文件大小:", os.path.getsize(path), "字节")       # 4 个 token × 2 字节
    m = np.memmap(path, dtype=np.uint16, mode="r")
    print(type(m).__name__, m.dtype, len(m), m.tolist())
    x = torch.from_numpy(m[1:3].astype(np.int64))
    print(x, x.dtype)
    wrong = np.memmap(path, dtype=np.uint8, mode="r")
    print("用 uint8 去读:", wrong.tolist())
    del m, wrong                                          # 关掉文件，临时目录才删得掉

@@ concept
title: bigram 计数与 ln(V) 基线
--- body
bigram（二元）模型是最简单的语言模型：只看当前这一个 token，猜下一个。它的全部「参数」就是一张 V×V 的计数表 C：`C[i, j]` 是「i 后面紧跟着 j」出现的次数。把每一行除以这一行的和，就变成「i 后面是 j 的概率」。

一段 N 个 token 的序列有 N-1 个相邻对。不写 Python 循环也能数完：

1. 把每一对 (i, j) 编成一个数：`i * V + j`。它在 0 到 V*V-1 之间，不同的对编出来的数一定不同。
2. `torch.bincount(flat, minlength=V * V)` 数出每个数出现几次。`minlength` 保证结果长度正好是 V*V（最大的几个 pair 没出现也不会变短）。
3. `.reshape(V, V)` 变回表格。

### ln(V) 基线

一个什么都没学的模型，对 V 个词给一样的概率 1/V。交叉熵是「正确答案概率的负对数」，所以它的 loss = -ln(1/V) = ln(V)。

- V = 65（莎士比亚字符）：ln 65 ≈ 4.17
- V = 50257（GPT-2）：ln 50257 ≈ 10.82

用法：刚初始化时，loss 应该在 ln(V) 附近。训练很久还在 ln(V) 附近，说明模型什么都没学到，多半是代码有 bug（比如忘了 `optimizer.step()`，或者学习率是 0）。
--- code
ids = torch.tensor([0, 1, 0, 1, 2])
V = 3
flat = ids[:-1] * V + ids[1:]            # 每一对 (i, j) 编成 i*V + j
print("相邻对的编码:", flat.tolist())
counts = torch.bincount(flat, minlength=V * V)
print("每个编码出现几次:", counts.tolist())
print(counts.reshape(V, V))

logits = torch.zeros(4, 65)              # 4 个位置，65 个词，分数全一样 = 均匀瞎猜
y = torch.tensor([3, 10, 0, 64])
print("瞎猜的 loss:", round(F.cross_entropy(logits, y).item(), 4), "  ln(65) =", round(math.log(65), 4))

@@ concept
title: padding、attention mask 和 position ids
--- body
一个 batch 里的句子长短不一，但 tensor 必须是整齐的矩形。办法是 padding（补齐）：短的句子在右边补上 `pad_id`，补到最长那句的长度 Tmax。

补完要同时给出三样东西，形状都是 `(B, Tmax)`，dtype 都是 int64：

- `ids`：补齐后的 token id。
- `attention mask`：真实 token 是 1，补上去的位置是 0。attention 靠它忽略 pad。
- `position ids`：每个 token 在自己那句话里是第几个，从 0 开始，只数真实 token。pad 位置填 0（反正会被 mask 掉）。

为什么不能省：没有 mask，真实 token 会去「看」pad，结果就被 pad 污染了；同一句话放进 pad 多的 batch 和 pad 少的 batch，输出会不一样。

下面的代码用了两个不写循环的小技巧：`torch.arange(Tmax) < lengths[:, None]` 一次比出整个 mask；`(mask.cumsum(-1) - 1) * mask` 从 mask 算出 position ids。练习里用 for 循环逐句填也完全可以。
--- code
seqs = [[4, 5], [6, 7, 8, 9]]
B, Tmax = len(seqs), max(len(s) for s in seqs)
ids = torch.full((B, Tmax), 0, dtype=torch.long)     # 先全部填 pad_id = 0
ids[0, :2] = torch.tensor(seqs[0])                    # 第 0 句的前 2 个位置
ids[1, :4] = torch.tensor(seqs[1])
print(ids)
lengths = torch.tensor([len(s) for s in seqs])
mask = (torch.arange(Tmax) < lengths[:, None]).long()
print(mask)
pos = (mask.cumsum(-1) - 1) * mask
print(pos)

@@ concept
title: 把 mask 变成 -inf 加性偏置
--- body
attention 先算分数 scores，形状 `(B, nh, T, T)`（nh 是头数），再对最后一维做 softmax 得到权重。要让 pad 位置的权重变成 0，做法是在 softmax 之前，给 pad 位置的分数加上 -inf：

- exp(-inf) = 0，所以 softmax 后这个位置的权重正好是 0。其余位置的权重重新分配，加起来还是 1。
- 真实位置加 0，分数不变。

所以偏置 bias 在真实位是 0.0，在 pad 位是 -inf。形状做成 `(B, 1, 1, T)`：第一维对应每句话；两个 1 让它广播到所有头、所有查询位置；最后的 T 对应「被看的那个位置」（key）。

写法：`torch.zeros(B, 1, 1, T).masked_fill(mask[:, None, None, :] == 0, float("-inf"))`。`masked_fill(cond, v)` 把 cond 为 True 的位置换成 v；`mask[:, None, None, :]` 在中间插入两个长度为 1 的维度。

坑：不能写 `(1 - mask) * float("-inf")`。真实位上算的是 `0 * -inf`，浮点规定结果是 nan（不是数）。nan 一进 softmax，整行都变成 nan。
--- code
mask = torch.tensor([[1, 1, 0]])                      # 第 3 个位置是 pad
bias = torch.zeros(1, 1, 1, 3).masked_fill(mask[:, None, None, :] == 0, float("-inf"))
print(bias)
scores = torch.tensor([[[[2.0, 1.0, 5.0]]]])
print("不加偏置:", scores.softmax(-1))
print("加了偏置:", (scores + bias).softmax(-1))

@@ concept
title: 一个训练 step 里的全部 shape
--- body
以 GPT-2 small 为例：B = 8（batch 大小），T = 256（block_size），V = 50257（词表大小），C = 768（每个 token 向量的宽度）。一个训练 step 里的张量依次是：

1. `x`、`y`：`(B, T)` = `(8, 256)`，int64。
2. `tok_emb = wte(x)`：`wte = nn.Embedding(V, C)` 是一张 V 行 C 列的表，每个 id 查出一行，所以在后面加一维 C：`(8, 256, 768)`。
3. `pos = torch.arange(T)` 是 `(T,)`；`pos_emb = wpe(pos)` 是 `(T, C)` = `(256, 768)`。`tok_emb + pos_emb` 靠广播，还是 `(B, T, C)`。
4. 每个 Transformer block 进出形状都不变：`(8, 256, 768)`。
5. `logits = lm_head(hidden)`：`lm_head = nn.Linear(C, V)` 只改最后一维，`(8, 256, 50257)`，每个位置给 V 个词各打一个分。
6. `F.cross_entropy` 要 `(N, V)` 的 logits 和 `(N,)` 的标签，所以 `logits.view(-1, V)` 是 `(2048, 50257)`，`y.view(-1)` 是 `(2048,)`，N = B*T = 2048。
7. `loss` 是标量（只有一个数的 tensor），shape 是空 tuple `()`。

logits 是这一步里最大的张量：8 × 256 × 50257 ≈ 1.03 亿个数，fp32 下约 412 MB。

下面用很小的数字真的跑一遍，每个 shape 都打印出来。
--- code
torch.manual_seed(0)
B, T, V, C = 2, 5, 11, 8
wte = nn.Embedding(V, C)
wpe = nn.Embedding(T, C)
lm_head = nn.Linear(C, V, bias=False)
x = torch.randint(0, V, (B, T))
y = torch.randint(0, V, (B, T))
tok_emb = wte(x)
pos_emb = wpe(torch.arange(T))
h = tok_emb + pos_emb                 # (B, T, C) + (T, C) 广播
logits = lm_head(h)
loss = F.cross_entropy(logits.view(-1, V), y.view(-1))
for name, t in [("x", x), ("tok_emb", tok_emb), ("pos_emb", pos_emb), ("h", h), ("logits", logits),
                ("logits.view(-1, V)", logits.view(-1, V)), ("y.view(-1)", y.view(-1)), ("loss", loss)]:
    print(f"{name:20s} {tuple(t.shape)}")
print("刚初始化的 loss =", round(loss.item(), 3), "  ln(V) =", round(math.log(V), 3))

title: CharTokenizer 往返
level: 1
cards: 字符级 tokenizer：字和数字互相转换
targets: CharTokenizer
ref: day3
--- context
每个语言模型的第一步都是 tokenizer。字符级 tokenizer 只要 20 行，却有完整的 encode / decode 接口；nanoGPT 训练莎士比亚用的就是它，面试也常让你当场写一个。
--- prompt
写一个 `CharTokenizer` 类：

- `CharTokenizer(text)`：用 `sorted(set(text))` 建词表（排好序，每次建出来都一样）。
- `tok.vocab_size`：词表大小，也就是 text 里不同字符的个数。
- `tok.encode(s)`：字符串 → `list[int]`，每个字符换成它的 id。
- `tok.decode(ids)`：id 列表 → 字符串。ids 可以是 Python 的 int 列表，也可以是一个 1D tensor。

要求：`decode(encode(s)) == s`；id 都在 0 到 `vocab_size - 1` 之间；同一个字符永远是同一个 id。

例子：`CharTokenizer("hello world")` 的 `vocab_size` 是 8；空格排在最前面，id 是 0；`encode("hello")` 是 `[3, 2, 4, 4, 5]`。
--- starter
class CharTokenizer:
    """用法:
        tok = CharTokenizer("hello world")
        tok.vocab_size      -> 去重后的字符数
        tok.encode("hell")  -> [int, int, int, int]
        tok.decode([...])   -> "hell"
    """

    def __init__(self, text):
        raise todo()

    def encode(self, s):
        raise todo()

    def decode(self, ids):
        raise todo()
--- solution
class CharTokenizer:
    def __init__(self, text):
        chars = sorted(set(text))
        self.itos = {i: c for i, c in enumerate(chars)}
        self.stoi = {c: i for i, c in self.itos.items()}
        self.vocab_size = len(chars)

    def encode(self, s):
        return [self.stoi[c] for c in s]

    def decode(self, ids):
        return "".join(self.itos[int(i)] for i in ids)
--- tests
@check("CharTokenizer 往返")
def t01():
    txt = "the quick brown fox jumps over the lazy dog"
    tok = CharTokenizer(txt)
    true(tok.vocab_size == len(set(txt)), f"vocab_size 不对: 你的是 {tok.vocab_size}，这段文字里有 {len(set(txt))} 个不同字符")
    ids = tok.encode("quick fox")
    true(isinstance(ids, list) and all(isinstance(i, int) for i in ids), "encode 要返回 Python int 组成的 list")
    true(tok.decode(ids) == "quick fox", f"往返不一致: decode(encode('quick fox')) 得到 {tok.decode(ids)!r}")
    same = tok.encode("the the")
    true(same[0] == same[4] and same[1] == same[5], "同一个字符要映射到同一个 id")
    true(tok.encode(" ") == [0] and tok.decode([tok.vocab_size - 1]) == "z",
         "词表要按字典序排：空格最小（id 0），'z' 最大 —— 用 sorted(set(text)) 建表")
    true(min(ids) >= 0 and max(ids) < tok.vocab_size, "id 越界了：必须在 0 到 vocab_size-1 之间")
    try:
        back = tok.decode(torch.tensor(ids))
    except KeyError:
        back = None
    true(back == "quick fox", "decode 也要能处理 tensor：tensor 里的数不能直接当字典的键，先用 int(i) 转一下")
--- hints
- 在 `__init__` 里建两个字典：`stoi`（字符 → id）和 `itos`（id → 字符）。`enumerate(sorted(set(text)))` 会同时给你编号和字符。
- encode 用列表推导式：`[self.stoi[c] for c in s]`。decode 用 `"".join(...)` 把字符拼回字符串。
- decode 里写 `self.itos[int(i)]`：`int()` 让 tensor 里的数也能当字典的键。

    """tokens: list[str]。统计所有相邻二元组出现次数。
    ["a","b","a","b","c"] -> {("a","b"): 2, ("b","a"): 1, ("b","c"): 1}
    """
    raise todo()

def merge_pair(tokens, pair):
    """把 tokens 里所有连续出现的 pair 合并成一个 token（字符串拼接）。
    从左往右扫，合并过的位置不再参与下一次合并。
    (["a","b","a","b"], ("a","b")) -> ["ab", "ab"]
    """
    raise todo()
--- solution
def pair_counts(tokens):
    c = {}
    for a, b in zip(tokens, tokens[1:]):
        c[(a, b)] = c.get((a, b), 0) + 1
    return c

def merge_pair(tokens, pair):
    out, i = [], 0
    while i < len(tokens):
        if i + 1 < len(tokens) and (tokens[i], tokens[i + 1]) == pair:
            out.append(tokens[i] + tokens[i + 1])
            i += 2                      # 跳过两个，重叠的 pair 不会被重复合并
        else:
            out.append(tokens[i])
            i += 1
    return out

    随机取 batch_size 个起点 i，返回:

--- solution
def get_batch(data, batch_size, block_size, generator=None):
    # 上界是 len-block_size，这样最大起点 i = len-block_size-1，y 的末位刚好是 len-1
    hi = len(data) - block_size
    ix = torch.randint(hi, (batch_size,), generator=generator)
    x = torch.stack([data[i:i + block_size] for i in ix]).long()
    y = torch.stack([data[i + 1:i + 1 + block_size] for i in ix]).long()
    return x, y

--- starter
def bigram_counts(ids, vocab_size):
    """ids: 1D LongTensor。返回 (V, V) 的计数矩阵 C，C[i, j] = i 后面紧跟 j 的次数。

--- solution
def bigram_counts(ids, vocab_size):
    flat = ids[:-1].long() * vocab_size + ids[1:].long()
    return torch.bincount(flat, minlength=vocab_size ** 2).reshape(vocab_size, vocab_size).float()

def mask_to_bias(attn_mask):

def pad_batch(seqs, pad_id=0):
    B, Tmax = len(seqs), max(len(s) for s in seqs)
    ids = torch.full((B, Tmax), pad_id, dtype=torch.long)
    mask = torch.zeros(B, Tmax, dtype=torch.long)

        pos[i, :L] = torch.arange(L)
    return ids, mask, pos
