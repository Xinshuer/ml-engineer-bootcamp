@@ concept
title: 上线前的推理检查单
ref: day21
--- body
同一个模型，训练时和上线时要换一种跑法。上线（推理，inference）之前，先过这张检查单：

1. **`model.eval()`**：切到推理模式。Dropout 不再随机丢值；BatchNorm 改用训练时攒下的统计量（`running_mean` / `running_var`），也不再更新它们。忘了这一步，同一个输入两次预测，结果都不一样。
2. **`with torch.inference_mode():`**：告诉 PyTorch 不用记计算图（计算图是给 backward 求梯度用的）。省内存，也更快。输出的 `requires_grad` 是 False。
3. **预处理和训练时一模一样**：同样的归一化统计量、同样版本的 tokenizer（第 18 天细讲）。

今天的题目都用这个小模型 `Net`，它已经在隐藏的准备代码里定义好了：

```
class Net(nn.Module):              # 8 个特征 -> 3 类
    def __init__(self, hidden=16, p_drop=0.5):
        super().__init__()
        self.fc1 = nn.Linear(8, hidden)
        self.bn = nn.BatchNorm1d(hidden)
        self.drop = nn.Dropout(p_drop)
        self.fc2 = nn.Linear(hidden, 3)

    def forward(self, x):
        return self.fc2(self.drop(F.relu(self.bn(self.fc1(x)))))
```

`trained_net()` 返回一个「训练过」的 Net：BatchNorm 的统计量已经攒好了，模型还处在 train 模式，就像刚训练完一样。

下面的代码里，`num_batches_tracked` 数的是 BatchNorm 在 train 模式下被更新了几次。
--- code
torch.manual_seed(0)
net = trained_net()               # train 模式
x = torch.randn(3, 8)

print("train 模式，两次结果一样吗:", torch.equal(net(x), net(x)))
print("BatchNorm 被更新了几次:", net.bn.num_batches_tracked.item())

net.eval()
with torch.inference_mode():
    a, b = net(x), net(x)
print("eval 模式，两次结果一样吗:", torch.equal(a, b))
print("BatchNorm 被更新了几次:", net.bn.num_batches_tracked.item())
print("输出要梯度吗:", a.requires_grad)

@@ concept
title: 导出：把 Python 模型变成一张固定的图
ref: day21
--- body
训练时用 PyTorch 很方便，但上线的机器上不一定有 Python 和 PyTorch：可能是一个 C++ 服务、一部手机，或者专门的推理引擎（onnxruntime、TensorRT）。所以要先把模型「导出（export）」成一张计算图：一串固定的运算，每一步算什么、形状多大，都写在里面。

`torch.export.export(model, (x,))` 是这样工作的：

1. 拿你给的示例输入 `x`，把 `forward` 跑一遍。
2. 一边跑，一边把每个张量运算（linear、relu……）记下来。记下来的就是图。
3. Python 自己的东西不进图：`print` 只在导出时跑那一次；`for` 循环被展开（循环 3 次，图里就有 3 份运算）；`if self.use_relu:` 这种看 Python 变量的判断，导出时就定好走哪边。

两个要记住的后果：

- 图里的形状默认是**固定的**：用 `(2, 4)` 的示例导出，图就只认 `(2, 4)`。怎么让 batch 维可变，见「动态 batch 维」那张卡。
- 导出时模型处在什么模式，图就记下什么行为。用 `torch.export` 在 train 模式下导出，图里的 Dropout 是开着的（下面代码的最后两行）。所以导出前一定先 `model.eval()`。`torch.onnx.export` 发现模型在 train 模式，也会警告：`Exporting a model while it is in training mode`。

第一次调用 `torch.export` 要 1～2 秒（在加载东西），之后就快了。
--- code
class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(4, 4)

    def forward(self, x):
        print("forward 在跑，x 的形状:", tuple(x.shape))
        for _ in range(3):                    # Python 循环：导出时展开成 3 份
            x = torch.relu(self.fc(x))
        return x

ep = torch.export.export(Tiny(), (torch.randn(2, 4),))
print("图里的运算:", [n.target.__name__ for n in ep.graph.nodes if n.op == "call_function"])

net = Net()
for mode in ("train", "eval"):
    getattr(net, mode)()                      # 就是 net.train() 或 net.eval()
    ep = torch.export.export(net, (torch.randn(2, 8),))
    drop = [n.args[2] for n in ep.graph.nodes if n.op == "call_function" and "dropout" in n.target.__name__]
    print(mode, "模式导出，图里的 Dropout 开着吗:", drop)

title: 导出成 ONNX，再用 onnxruntime 对拍
ref: day21
--- body
ONNX 是一种通用的模型文件格式：一个 `.onnx` 文件里存着计算图和权重。onnxruntime 是专门跑 ONNX 文件的推理引擎，不需要 PyTorch，CPU、GPU 都能跑。

导出（`dynamo=True` 表示用新的导出器：先用 `torch.export` 抓图，再翻译成 ONNX）：

```
model.eval()
prog = torch.onnx.export(model, (example,), dynamo=True, verbose=False)
prog.save(path)                    # 写成 .onnx 文件
```

- 第二个参数是**元组**：`(example,)`，逗号不能少。
- `verbose=False` 关掉导出过程的进度信息。
- 返回的 `prog` 是一个 `ONNXProgram`，`.save(path)` 把它写成文件。今天的文件都写进 `tempfile.TemporaryDirectory()` 建的临时文件夹，用完自动删掉。
- 导出一次要 1～3 秒。

用 onnxruntime 跑：

```
sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
name = sess.get_inputs()[0].name              # 输入叫什么，从文件里读
out = sess.run(None, {name: x.numpy()})[0]    # None = 要所有输出；返回一个列表
```

onnxruntime 吃 numpy 数组，吐 numpy 数组。

**导出之后一定要对拍**：同一个输入，PyTorch 和 onnxruntime 各跑一遍，看最大误差 `np.abs(a - b).max()`。两边不会完全相等：不同的库做加法的顺序不同，而浮点数的 `(a + b) + c` 和 `a + (b + c)` 可能差最后一位。fp32 下误差在 1e-7～1e-5 很正常，一般用 1e-4 当容差。误差到了 1e-2 甚至更大，就是真 bug：导出的权重不对、PyTorch 这边忘了 `eval()`、预处理不一样……
--- code
import os, tempfile
import numpy as np
import onnxruntime as ort

torch.manual_seed(0)
net = trained_net().eval()
x = torch.randn(2, 8)
prog = torch.onnx.export(net, (x,), dynamo=True, verbose=False)

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "net.onnx")
    prog.save(path)
    print("文件大小:", os.path.getsize(path), "字节")
    sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
    inp = sess.get_inputs()[0]
    print("输入:", inp.name, inp.shape)
    got = sess.run(None, {inp.name: x.numpy()})[0]
    del sess                                  # 先关掉 session，临时文件夹才好删

with torch.inference_mode():
    want = net(x).numpy()
print("onnxruntime 第 1 行:", got.round(4)[0])
print("PyTorch    第 1 行:", want.round(4)[0])
print("最大误差:", np.abs(got - want).max())

@@ concept
title: 动态 batch 维：说清楚哪一维会变
ref: day21
--- body
上一张卡用 `(2, 8)` 的示例导出，文件里输入的形状是 `[2, 8]`：只认 batch = 2。喂它 5 个样本，onnxruntime 会报错：

```
INVALID_ARGUMENT : Got invalid dimensions for input: x for the following indices
 index: 0 Got: 5 Expected: 2
```

上线时每次请求的样本数都不一样。所以导出时要说清楚：第 0 维（batch）是可变的。

```
prog = torch.onnx.export(
    model, (example,), dynamo=True, verbose=False,
    input_names=["x"], output_names=["logits"],     # 文件里输入、输出的名字
    dynamic_shapes={"x": {0: "batch"}},             # 参数 x 的第 0 维可变，名字叫 batch
)
```

- `dynamic_shapes` 的 key 是 **forward 的参数名**。`Net.forward(self, x)` 的参数叫 `x`；`nn.Sequential` 的参数叫 `input`，写错了会报 `its top-level keys must be the arg names`。也可以不写名字，按位置写成元组：`dynamic_shapes=({0: "batch"},)`。
- `input_names` / `output_names` 是存进文件里的名字。不写的话，输入默认用参数名，输出名是自动起的（比如 `linear_1`），调用的人不好用。
- 导出后，输入的形状变成 `['batch', 8]`：字符串表示这一维可变。
- 导出后用几个不同的 batch 大小（1、中等、很大）各对拍一次。
--- code
import os, tempfile
import numpy as np
import onnxruntime as ort

torch.manual_seed(0)
net = trained_net().eval()
prog = torch.onnx.export(net, (torch.randn(2, 8),), dynamo=True, verbose=False,
                         input_names=["x"], output_names=["logits"],
                         dynamic_shapes={"x": {0: "batch"}})

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "net.onnx")
    prog.save(path)
    sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
    print("输入:", sess.get_inputs()[0].name, sess.get_inputs()[0].shape)
    print("输出:", sess.get_outputs()[0].name, sess.get_outputs()[0].shape)
    for b in (1, 7, 64):
        x = torch.randn(b, 8)
        got = sess.run(None, {"x": x.numpy()})[0]
        with torch.inference_mode():
            diff = np.abs(got - net(x).numpy()).max()
        print(f"batch = {b}: 输出形状 {got.shape}，最大误差 {diff:.1e}")
    del sess

title: 导出失败头号原因：对张量的值写 Python if
ref: day21
--- body
导出时 forward 只跑一遍，图里只记张量运算。Python 的 `if` 必须当场决定走哪边：

- `if x.shape[1] != 8:`、`if self.use_relu:`：导出时就知道答案（形状、Python 变量），没问题。走了哪边，就记哪边。
- `if x.mean() > 0:`：答案取决于**输入的值**。今天的输入走这边，明天的输入可能走那边。一张固定的图装不下这种 Python 分支，导出直接失败：

```
GuardOnDataDependentSymNode: Could not guard on data-dependent expression Eq(u0, 1)
```

「data-dependent」就是「取决于数据的值」。用 `torch.onnx.export(dynamo=True)` 时，这个错误被包在 `TorchExportError: Failed to export the model with torch.export. This is step 1/3 ...` 里面，真正的原因写在下面的 `Exception summary`。

一行一行处理数据的 `for row in x:` 里面如果有 `if row.sum() > 0:`，也是同样的问题。

**修法：两条路都算出来，再用 `torch.where` 按条件挑。** `torch.where(cond, a, b)`：cond 为 True 的位置取 a，否则取 b。它是普通的张量运算，能进图。cond 的形状可以比 a、b 小，会自动广播（broadcast）：

- 整个输入一个条件：`torch.where(x.mean() > 0, x * 2, -x)`
- 每一行一个条件：`n = x.norm(dim=1, keepdim=True)`，形状 `(B, 1)`；`torch.where(n > 1, x / n, x)` 对每一行分别挑。

有些分支有现成的运算可以代替：`x.clamp(max=10)`、`torch.maximum(x, y)`、`F.relu(x)`。

下面的代码用了准备代码里的小工具 `export_error(model, x)`：它安静地调用 `torch.export.export`，成功返回 None，失败返回一行原因。
--- code
class Bad(nn.Module):
    def forward(self, x):
        if x.mean() > 0:                      # 要看 x 的值才知道走哪边
            return x * 2
        return -x

class Good(nn.Module):
    def forward(self, x):
        return torch.where(x.mean() > 0, x * 2, -x)   # 两边都算，按条件挑

x = torch.randn(3, 4)
print("Bad :", export_error(Bad(), x))
print("Good:", export_error(Good(), x))       # None = 导出成功
for inp in (x.abs(), -x.abs()):               # 两个分支各试一次
    print("结果一样吗:", torch.equal(Bad()(inp), Good()(inp)))

title: int8 量化：1 个字节存一个权重
--- body
fp32 的权重，每个数占 4 个字节。量化（quantization）就是改用更少的字节来存。int8 是 -128～127 的整数，只占 1 个字节。

怎么把小数变成整数（对称量化）：

```
scale = max(|w|) / 127                   # 最大的 |w| 对应 127
q = round(w / scale)，限制在 [-127, 127]  # 存成 int8
w ≈ q * scale                            # 用的时候乘回来（反量化）
```

- 存的是 `q`（每个数 1 字节）和 `scale`（一个小数）。权重大约小 4 倍。
- 四舍五入带来误差：每个数最多差 `scale / 2`。
- 比 `scale / 2` 还小的权重，会直接变成 0。
- 整个矩阵只用一个 scale（per-tensor）时，一个特别大的数会把 scale 撑大，其他小数就只能用到很少几个整数，误差变大（下面代码的第 2 行）。所以实际上常常每一行（每个输出通道）各用一个 scale（per-channel）。

「动态（dynamic）量化」的「动态」说的是激活值（每一层的输入）：权重提前量化好，存成 int8；激活值每次推理时才看这一批数据的范围，当场量化。所以它不需要额外的校准数据，一行代码就能用。PyTorch 的动态量化只在 CPU 上跑，主要替换 `nn.Linear`（下一张卡）。
--- code
w = torch.tensor([[0.50, -0.20, 0.01],
                  [0.02, 0.03, -0.04]])
scale = w.abs().max() / 127                  # 整个矩阵一个 scale
q = torch.round(w / scale).clamp(-127, 127).to(torch.int8)
w_back = q.float() * scale                   # 反量化

print("scale:", round(scale.item(), 5))
print("q:", q.tolist(), q.dtype)
print("误差都 <= scale / 2 吗:", bool(((w - w_back).abs() <= scale / 2 + 1e-7).all()))
print("第 2 行原来:", [round(v, 4) for v in w[1].tolist()])
print("第 2 行还原:", [round(v, 4) for v in w_back[1].tolist()])

title: 动态量化的账：大小、精度、速度
ref: day21
--- body
PyTorch 一行代码就能把模型里所有的 `nn.Linear` 换成 int8 版本：

```
q = torch.ao.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)
```

- 返回一个**新模型**，原模型不变（它内部先复制一份）。
- `{nn.Linear}`：只替换这些类型的层。
- 新模型里的层，打印出来是 `DynamicQuantizedLinear`。

量化不是白送的。上线前把三笔账都算一遍：

1. **大小**：量「存下来有多大」。把 `state_dict` 用 `torch.save` 存进内存里的 `io.BytesIO()`，看写了多少字节。**不能数 `parameters()`**：量化后的权重被打包成特殊的格式，不再是 `nn.Parameter`，`parameters()` 里什么都没有。
2. **精度**：同一批输入，比较两个模型的输出。最大误差是一个参考；更实用的是「预测类别（argmax）一致的比例」。真实项目里，要在验证集上把指标（准确率等）重新算一遍。
3. **速度**：取决于 CPU 型号、计算后端和 batch 大小。有的机器上快不少，有的机器上反而更慢。一定要在上线用的那台机器上测（先预热，测很多次取中位数，第 19 天讲过）。

在 GPU 上跑大语言模型时，常用的是别的量化方法（只量化权重的 int8 / int4，比如 bitsandbytes、GPTQ、AWQ）。道理一样：用更少的字节存权重，换来一点精度损失。

下面的 `make_mlp()` 来自准备代码：`Linear(256, 512) -> ReLU -> Linear(512, 10)`。
--- code
import io, time

torch.manual_seed(0)
model = make_mlp().eval()
q = torch.ao.quantization.quantize_dynamic(model, {nn.Linear}, dtype=torch.qint8)
print(q[0])

def size_bytes(m):
    buf = io.BytesIO()
    torch.save(m.state_dict(), buf)
    return buf.getbuffer().nbytes

print("parameters() 里的数:", sum(p.numel() for p in model.parameters()), "->", sum(p.numel() for p in q.parameters()))
print("存下来的字节数:", size_bytes(model), "->", size_bytes(q))

x = torch.randn(256, 256)
with torch.inference_mode():
    a, b = model(x), q(x)
print("最大误差:", round((a - b).abs().max().item(), 4))
print("argmax 一致的比例:", (a.argmax(1) == b.argmax(1)).float().mean().item())

def median_ms(m, n=30):
    ts = []
    with torch.inference_mode():
        for i in range(n + 5):
            t0 = time.perf_counter()
            m(x)
            if i >= 5:                        # 前 5 次是预热，不算
                ts.append(time.perf_counter() - t0)
    return sorted(ts)[n // 2] * 1000

print(f"fp32 {median_ms(model):.2f} ms，int8 {median_ms(q):.2f} ms（每台机器都不一样）")

title: fp16 和 bf16 推理
ref: day21
--- body
另一种压缩：每个数用 2 个字节（半精度）代替 4 个字节。显存和带宽省一半，在支持的 GPU 上还快得多（用上了 Tensor Core）。半精度有两种：

- **fp16**：最大只能表示 65504。更大的数变成 `inf`，再往后算就是 `nan`。好处是有效数字多一些（3 位多）。
- **bf16**：能表示的范围和 fp32 一样大（最大约 3.4e38），不容易溢出。代价是有效数字只有 2～3 位：70000 会变成 70144，1.001 会变成 1.0。

怎么选：较新的 NVIDIA GPU（A100、RTX 30 系列及以后）优先用 bf16，大语言模型基本都用它。用 fp16 要小心溢出：注意力分数、很大的激活值，都可能超过 65504。

怎么用：`model.to(torch.bfloat16)`，**输入也要转**：`x.to(torch.bfloat16)`。只转了模型、没转输入，会报 `mat1 and mat2 must have the same dtype`。也可以用 `torch.autocast`，让 PyTorch 自动挑哪些运算用半精度。

和 fp32 对比时，容差要放宽：bf16 的误差常在 1e-3～1e-2。精度和容差的细节，第 18 天讲过。
--- code
for dt in (torch.float32, torch.float16, torch.bfloat16):
    fi = torch.finfo(dt)
    print(f"{str(dt):15} 每个数 {torch.tensor([], dtype=dt).element_size()} 字节，最大 {fi.max:.3g}，精度 eps {fi.eps:.3g}")

big = torch.tensor([70000.0, 1.001])
print("fp16:", big.half().tolist())
print("bf16:", big.bfloat16().tolist())

torch.manual_seed(0)
net = trained_net().eval()
x = torch.randn(4, 8)
with torch.inference_mode():
    want = net(x)
    out = net.to(torch.bfloat16)(x.to(torch.bfloat16))
print(f"bf16 输出: {out.dtype}，和 fp32 的最大误差: {(out.float() - want).abs().max().item():.4f}")

def predict(model, x):

import numpy as np
import onnxruntime as ort

def verify_export(model, path, example, batch_sizes=(1, 4, 16), tol=1e-4):
    model.eval()
    sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
    name = sess.get_inputs()[0].name
    worst = 0.0
    for b in batch_sizes:
        x = torch.randn(b, *example.shape[1:])
        with torch.inference_mode():
            want = model(x).numpy()
        got = sess.run(None, {name: x.numpy()})[0]
        worst = max(worst, float(np.abs(got - want).max()))
    if worst > tol:
        raise AssertionError(f"ONNX 和 PyTorch 的最大误差 {worst:.2e} 超过了容差 {tol}")
    return worst

    def __init__(self, max_norm=1.0):
        super().__init__()
        self.max_norm = max_norm

    def forward(self, x):                     # x: (B, D)
        rows = []

class ClipNorm(nn.Module):
    def __init__(self, max_norm=1.0):
        super().__init__()
        self.max_norm = max_norm

    def forward(self, x):                     # x: (B, D)
        n = x.norm(dim=1, keepdim=True)       # (B, 1)：每一行的长度
        return torch.where(n > self.max_norm, x * (self.max_norm / n), x)

写 `quantize_int8(w)`，对 `(out, in)` 的权重矩阵做对称 int8 量化，**每一行一个 scale**：

- `scale`：每一行最大的 |w| 除以 127，形状 `(out, 1)`（用 `amax(dim=1, keepdim=True)`）。再 `clamp_min(1e-8)`，这样全 0 的行不会除以 0

- 返回 `(q, scale)`

    """w: (out, in) 小数 -> (q: (out, in) int8, scale: (out, 1) 小数)，每行一个 scale。"""

def quantize_int8(w):
    scale = (w.abs().amax(dim=1, keepdim=True) / 127).clamp_min(1e-8)   # (out, 1)
    q = torch.round(w / scale).clamp(-127, 127).to(torch.int8)
    return q, scale

import numpy as np
import onnxruntime as ort

def verify_export(model, path, example, batch_sizes=(1, 4, 16), tol=1e-4):
    model.eval()
    sess = ort.InferenceSession(path, providers=["CPUExecutionProvider"])
    name = sess.get_inputs()[0].name
    worst = 0.0
    for b in batch_sizes:
        x = torch.randn(b, *example.shape[1:])
        with torch.inference_mode():
            want = model(x).numpy()
        got = sess.run(None, {name: x.numpy()})[0]
        worst = max(worst, float(np.abs(got - want).max()))
    if worst > tol:
        raise AssertionError(f"ONNX 和 PyTorch 的最大误差 {worst:.2e} 超过了容差 {tol}")
    return worst
