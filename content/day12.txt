@@ concept
title: TTS 流水线：文字 → mel → 波形
--- body
TTS（text-to-speech，文字转语音）模型一般分成两段：**声学模型**把文字变成 mel 频谱（Day 11 讲过：每一帧是一个 n_mels 维的向量），**vocoder**（声码器，比如 HiFi-GAN）再把 mel 变成波形。

一句 20 个字的话，数据的 shape 一路是这样变的（B = batch 大小）：

1. 文本 token id：(B, 20)。每个字符或音素（phoneme，发音的最小单位）一个整数。
2. 文本编码器输出：(B, 20, C)。每个字一个 C 维向量。
3. duration（时长）：(B, 20)。每个字要念几帧 mel。
4. length regulator 之后：(B, Tm, C)。按 duration 把每个字的向量复制几份，Tm = duration 之和。
5. 解码器输出的 mel：(B, Tm, n_mels)。
6. vocoder 输出的波形：(B, Tm × hop)。每帧 mel 对应 hop 个采样点。

难点在第 4 步：文字只有 20 个，mel 却有上百帧，两边怎么对齐？有两种主流做法：

- **自回归（autoregressive）**，比如 Tacotron 2：解码器一帧一帧地生成 mel，每一步用 attention 自己去找「现在念到哪个字了」。它不知道总共要多少帧，所以每一步还要预测一个 **stop token**（要不要停）。
- **非自回归**，比如 FastSpeech 2：先用一个小网络预测每个字的 duration，再用 length regulator 把文本拉长到 mel 的长度。总帧数 = duration 之和，所有帧可以**并行**一次生成，不需要 stop token。训练用的 duration 标签来自强制对齐工具（比如 Montreal Forced Aligner）。

下面的例子用最简单的层代替真正的网络，只看 shape。
--- code
torch.manual_seed(0)
B, Tt, C, n_mels, hop = 2, 5, 16, 80, 256
ids = torch.randint(0, 40, (B, Tt))          # 2 句话，每句 5 个字
h = nn.Embedding(40, C)(ids)                 # 文本编码器（这里只用一层 Embedding 代替）
dur = torch.full((B, Tt), 3)                 # 假设每个字都念 3 帧
h_long = h.repeat_interleave(3, dim=1)       # length regulator：每个字复制 3 份
mel = nn.Linear(C, n_mels)(h_long)           # 解码器（这里只用一层 Linear 代替）
n_samples = mel.size(1) * hop                # vocoder：每帧变成 hop 个采样点
print("文本 id        ", tuple(ids.shape))
print("编码器输出     ", tuple(h.shape))
print("duration       ", tuple(dur.shape))
print("length reg 后  ", tuple(h_long.shape))
print("mel            ", tuple(mel.shape))
print("波形           ", (B, n_samples), f"约 {n_samples / 22050:.2f} 秒 @22050Hz")

@@ concept
title: length regulator：按 duration 复制
--- body
length regulator（长度调节器）是 FastSpeech 系列的核心，做的事情非常简单：第 i 个字的 duration 是 d，就把它的特征向量复制 d 份。

PyTorch 里一个函数就够了：`x.repeat_interleave(repeats, dim=0)`。`repeats` 是一个整数张量，第 i 个元素重复 `repeats[i]` 次。

- duration 是 0 的字直接消失，一帧都不占。标点、不发音的符号就是这样处理的。
- duration 必须是整数，而且不能是负数，否则会报错。
- 想念得慢一点？把 duration 都乘 1.2 再取整就行。FastSpeech 的语速控制就是这么做的。

batch 里每句话的总帧数不一样，所以要一句一句地复制，再把短的右边补 0，拼成一个 (B, Tm, C) 的张量。`x.new_zeros(...)` 会建一个和 x 同 dtype、同 device 的全 0 张量。
--- code
x = torch.tensor([[10., 11.], [20., 21.], [30., 31.]])   # 3 个字，每个字 C=2
d = torch.tensor([2, 0, 3])
print(x.repeat_interleave(d, dim=0))    # 第 2 个字 (20, 21) 消失了

# batch：两句话的总帧数分别是 2 和 5，短的补 0
xb = torch.ones(2, 2, 1)
db = torch.tensor([[1, 1], [3, 2]])
outs = [xb[b].repeat_interleave(db[b], dim=0) for b in range(2)]
print([o.size(0) for o in outs])
out = xb.new_zeros(2, 5, 1)
for b, o in enumerate(outs):
    out[b, :o.size(0)] = o
print(out[..., 0])

@@ concept
title: 对齐：边界、帧归属、对齐矩阵
--- body
同一份 duration，有三种常用的看法。以 duration = [2, 0, 3] 为例：

1. **边界**：每个字占哪一段帧，写成左闭右开的 [起始帧, 结束帧)，包含起始帧，不包含结束帧。结束帧就是 duration 的累加和 `cumsum`：[2, 2, 5]；起始帧 = 结束帧 − duration：[0, 2, 2]。第 1 个字是 [2, 2)，长度为 0。
2. **帧归属**：每一帧属于哪个字。把字的下标 [0, 1, 2] 按 duration 重复：[0, 0, 2, 2, 2]。
3. **对齐矩阵**：(帧数, 字数) 的 0/1 矩阵，`A[f, i] = 1` 表示第 f 帧来自第 i 个字。每行恰好一个 1，每列的和等于这个字的 duration。

对齐一定是**单调**的：帧往后走，字的下标只能不变或者变大，不会倒回去（人说话不会倒着念）。把矩阵画出来，就是一条从左上到右下、不回头的阶梯。训练 TTS 时大家最爱看的「对齐图」就是它：阶梯断了、跳了、回头了，说明模型在漏字或者重复字。

给矩阵一次放好很多个 1，可以用两个下标张量：`A[rows, cols] = 1.0` 会把 (rows[k], cols[k]) 这些位置都设成 1。
--- code
d = torch.tensor([2, 0, 3])
ends = d.cumsum(0)
starts = ends - d
print(torch.stack([starts, ends], dim=-1))   # 每行 [起始帧, 结束帧)

idx = torch.arange(3).repeat_interleave(d)   # 每一帧属于哪个字
print(idx)

A = torch.zeros(5, 3)
A[torch.arange(5), idx] = 1.0                # 第 f 行的 1 放在第 idx[f] 列
print(A)
print(A.sum(0))                              # 每列的和 = duration

@@ concept
title: teacher forcing：输入右移一位
--- body
自回归解码器（比如 Tacotron 2 的）生成第 t 帧时，要看前面已经生成的第 0 到 t−1 帧。

**推理**时只能一帧一帧地来。**训练**时我们手里有完整的真实 mel，于是直接把真实的前一帧当输入喂进去，这叫 **teacher forcing**（老师带着走）。这样整个序列可以一次算完，训练快得多。

具体做法：把目标 mel 在时间维上**右移一位**，开头补一个全 0 的 **go 帧**（「开始」信号），最后一帧目标被挤掉。目标是 [a, b, c] 时，输入是 [0, a, b]：第 0 步看到 go 帧、要预测 a；第 1 步看到 a、要预测 b。

这和 Day 4 语言模型的「输入是 x[:-1]，标签是 x[1:]」是同一个思路。

如果忘了右移，直接把目标本身当输入，第 t 步就能看到第 t 帧的答案，模型只要学会「抄」。结果是训练 loss 低得出奇，一到推理（没有答案可抄）就只会输出一团糊。
--- code
mel = torch.arange(1, 7.).reshape(1, 3, 2)   # 目标：3 帧，每帧 2 个 mel 值
go = torch.zeros_like(mel[:, :1])            # (1, 1, 2) 的全 0 go 帧
dec_in = torch.cat([go, mel[:, :-1]], dim=1)
print("目标:\n", mel[0])
print("解码器输入:\n", dec_in[0])            # 整体往下挪了一行

@@ concept
title: stop token 与自回归解码循环
--- body
自回归模型不知道一句话该念多少帧，所以每一步除了输出一帧 mel，还输出一个 **stop logit**（一个没过 sigmoid 的分数）。`sigmoid(stop_logit)` 是「该停了」的概率，超过阈值（常用 0.5）就停。

**训练标签**：每个样本一行 0/1，只有最后一个有效帧（下标 `length − 1`）是 1，其余都是 0。它用 BCE（二分类交叉熵）训练，所以标签要是 float。注意正负样本极不平衡：200 帧的句子只有 1 个 1，所以有的实现会给正样本加权（`BCEWithLogitsLoss` 的 `pos_weight`）。

**推理循环**的零件：

- 一开始只有 go 帧：`prev` 是 (1, 1, n_mels)。
- 每一步，解码器看 `prev`，输出新的一帧 (1, n_mels) 和 stop logit。
- 新帧要先 `unsqueeze(1)` 变成 (1, 1, n_mels)，再用 `torch.cat(..., dim=1)` 接到 `prev` 后面，下一步才能看到它。
- 生成的帧放进一个 Python 列表，最后用 `torch.stack(frames, dim=1)` 叠成 (1, T, n_mels)。
- 一定要有最大步数 `max_steps`：模型没学好时可能永远不说停，没有上限，服务就卡死了。
- 推理时用 `@torch.no_grad()`，不记录梯度，省显存。
--- code
lengths = torch.tensor([3, 5])
pos = torch.arange(5)
stop = (pos[None, :] == (lengths - 1)[:, None]).float()   # 比较下标：只有 length-1 的位置是 1
print(stop)

prev = torch.zeros(1, 1, 2)            # 只有 go 帧
new = torch.tensor([[0.5, 0.7]])       # 这一步生成的一帧：(1, n_mels)
prev = torch.cat([prev, new.unsqueeze(1)], dim=1)
print(prev.shape)                      # 接上以后是 2 帧

frames = [new, new * 2, new * 3]
print(torch.stack(frames, dim=1).shape)

for logit in [-3.0, 0.0, 2.0]:
    p = torch.sigmoid(torch.tensor(logit)).item()
    print(logit, round(p, 3), "停" if p > 0.5 else "继续")

@@ concept
title: 带 mask 的 loss：pad 不算分
--- body
一个 batch 里句子长短不一，mel 帧数也不一样。为了拼成一个张量，短的在右边补了 pad（Day 11 讲过）。pad 帧不是真实的声音，**不能**算进 loss，否则：

- 模型会花力气去拟合一堆没有意义的值；
- loss 的大小会随 pad 多少而变，同一个模型换个 batch 组合 loss 就不一样。

做法分三步：

1. 由真实长度造 mask：`torch.arange(T)[None, :] < lengths[:, None]`，得到 (B, T)，有效帧是 True。
2. mask 只有 (B, T)，误差是 (B, T, n_mels)。`mask.unsqueeze(-1)` 变成 (B, T, 1)，乘的时候会自动广播到每个 mel 维。
3. 平均时，分母是**真正参与计算的元素个数** = 有效帧数 × n_mels，而不是全部元素个数。

`F.l1_loss(pred, target)` 默认对所有位置求平均，pad 也算进去了，所以这里不能直接用它。
--- code
lengths = torch.tensor([4, 2])
mask = torch.arange(4)[None, :] < lengths[:, None]
print(mask.long())

pred = torch.zeros(2, 4, 3)
target = torch.ones(2, 4, 3)
target[1, 2:] = 50.0                  # 第 2 个样本的 pad 区域里是垃圾值
print("不带 mask:", F.l1_loss(pred, target).item())

m = mask.unsqueeze(-1).float()        # (2, 4, 1)
print("带 mask:  ", ((pred - target).abs() * m).sum().item() / (m.sum().item() * 3))

@@ concept
title: duration 在 log 域回归
--- body
FastSpeech 2 的 duration 预测器输出的不是帧数本身，而是 **log 域**的值。为什么？

duration 的分布是**长尾**的：大部分音素 3–10 帧，但句末停顿可能有 40 帧以上。直接对帧数做 MSE，少数长停顿的误差（比如差 20 帧，平方就是 400）会压过所有正常音素。取 log 以后，数值被压到大约 0 到 4 之间，每个音素的误差差不多一样重要。

- **训练**：目标是 `log(d + 1)`。要 +1，因为 duration 可以是 0，而 log(0) = −∞。整数张量要先 `.float()` 才能取 log。loss 只在有效的文本位上算（pad 位不算，和上一张卡片一样）。
- **推理**：逆变换 `exp(预测) − 1`，四舍五入成整数，负数变成 0（`clamp(min=0)`），最后转 int64（`.long()`）。不 clamp 的话，负的 duration 会让 `repeat_interleave` 直接报错。
- **总帧数**：推理时每句话要生成多少帧 mel = 有效文本位上 duration 之和。pad 位的预测值是随便输出的，要用 mask 清零再加。

PyTorch 也有 `torch.log1p(x)` = log(1 + x) 和 `torch.expm1(x)` = exp(x) − 1，意思一样。
--- code
d = torch.tensor([0, 1, 3, 10, 40])
t = torch.log(d.float() + 1)
print(t)                                                   # 0 到 3.7 之间
print((t.exp() - 1).round().clamp(min=0).long())           # 变回来
print((torch.tensor([-0.3, 0.2, 1.5]).exp() - 1).round().clamp(min=0).long())
try:
    torch.arange(3).repeat_interleave(torch.tensor([1, -1, 2]))
except RuntimeError as e:
    print("负的 duration:", e)

--- context
FastSpeech 2 这类非自回归 TTS 的核心就是这一步：文本只有 20 个字，mel 却有 160 帧，要把每个字的特征按 duration 复制，两边的长度才对得上。调语速也是在这里改 duration。
--- prompt
写 `length_regulator(x, durations, max_len=None)`。

- `x`：(B, Tt, C)，文本侧特征（Tt = 文本长度，C = 通道数）
- `durations`：(B, Tt) 的 int64，第 b 句第 i 个字占几帧 mel
- 返回 (B, Tm, C)：每个字的特征向量按 duration 重复；duration 为 0 的字直接跳过
- Tm：传了 `max_len` 就等于 `max_len`（太长的截掉，不够的补 0）；没传就等于这个 batch 里 duration 之和的最大值
- 总帧数不到 Tm 的句子，右边补 0

例：3 个字的特征是 [1], [2], [3]，durations = [2, 0, 3] → [1, 1, 3, 3, 3]。

可以用 `repeat_interleave`；batch 维用 Python 循环就行。
--- starter
def length_regulator(x, durations, max_len=None):
    """x: (B, Tt, C)   durations: (B, Tt) int64
    -> (B, Tm, C)，Tm = max_len 或 batch 里 duration 之和的最大值；不够的右边补 0。
    """
    raise todo()
--- solution
def length_regulator(x, durations, max_len=None):
    outs = [x[b].repeat_interleave(durations[b], dim=0) for b in range(x.size(0))]
    Tm = max_len or max(o.size(0) for o in outs)
    out = x.new_zeros(x.size(0), Tm, x.size(2))
    for b, o in enumerate(outs):
        n = min(o.size(0), Tm)
        out[b, :n] = o[:n]
    return out

--- context
训练用的 duration 通常来自强制对齐工具（比如 Montreal Forced Aligner）。拿到以后，常要换算成「哪几帧属于哪个音素」：按音素求平均音高和能量、切出某个字的音频、画图检查对齐，都要用到。
--- prompt
写两个函数。都只处理一句话，没有 batch 维。

1. `duration_to_boundaries(durations)`：(Tt,) → (Tt, 2)。第 i 行是第 i 个字的 [起始帧, 结束帧)，左闭右开：包含起始帧，不包含结束帧。例：[2, 0, 3] → [[0, 2], [2, 2], [2, 5]]（duration 为 0 的字起止相同）。
2. `frame_to_text_index(durations, n_frames)`：返回 (n_frames,)，第 f 个数是「第 f 帧属于第几个字」。例：[2, 0, 3]，n_frames=5 → [0, 0, 2, 2, 2]。`n_frames` 不会超过 duration 之和；比它小时只保留前 `n_frames` 个。
--- starter
def duration_to_boundaries(durations):
    """(Tt,) -> (Tt, 2)，每行 [起始帧, 结束帧)。
    [2, 0, 3] -> [[0, 2], [2, 2], [2, 5]]
    """
    raise todo()

def frame_to_text_index(durations, n_frames):
    """-> (n_frames,)，每一帧属于第几个字。
    [2, 0, 3], 5 -> [0, 0, 2, 2, 2]
    """
    raise todo()
--- solution
def duration_to_boundaries(durations):
    ends = durations.cumsum(0)
    starts = ends - durations
    return torch.stack([starts, ends], dim=-1)

def frame_to_text_index(durations, n_frames):
    idx = torch.arange(durations.numel(), device=durations.device).repeat_interleave(durations)
    return idx[:n_frames]
--- tests
@check("边界和帧归属")
def t02():
    d = torch.tensor([2, 0, 3])
    eq(duration_to_boundaries(d), torch.tensor([[0, 2], [2, 2], [2, 5]]),
       msg="结束帧是 duration 的累加和，起始帧 = 结束帧 - duration")
    eq(frame_to_text_index(d, 5), torch.tensor([0, 0, 2, 2, 2]),
       msg="duration=0 的字（下标 1）不应该出现")

    idx = frame_to_text_index(torch.tensor([1, 2, 1, 3]), 7)

--- hints
- 结束帧就是 duration 的累加和：`durations.cumsum(0)`；起始帧 = 结束帧 − duration。
- 用 `torch.stack([starts, ends], dim=-1)` 拼成 (Tt, 2)。
- 帧归属：把字的下标 `torch.arange(Tt)` 按 duration 重复（`.repeat_interleave(durations)`），再切 `[:n_frames]`。

--- starter
def masked_mel_loss(pred, target, mask):
    """pred/target: (B, T, n_mels)   mask: (B, T)，有效帧是 1。
    只在有效帧上算 L1，分母是「有效帧数 × n_mels」。

def masked_mel_loss(pred, target, mask):
    m = mask.unsqueeze(-1).to(pred.dtype)
    return ((pred - target).abs() * m).sum() / (m.sum() * pred.size(-1))

--- solution
def duration_loss(log_pred, target_dur, mask):
    tgt = torch.log(target_dur.float() + 1)
    m = mask.to(log_pred.dtype)
    return (((log_pred - tgt) ** 2) * m).sum() / m.sum()

def duration_from_log(log_pred):
    return (log_pred.exp() - 1).round().clamp(min=0).long()

`step_fn` 是解码器的一步，由测试提供：
- 输入 `prev`：(1, t, n_mels)，到目前为止的所有帧。第一帧是全 0 的 go 帧，所以第一次调用时 t = 1

def ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5):
    """step_fn(prev) -> (mel_next, stop_logit)
       prev: (1, t, n_mels)，第一帧是全 0 的 go 帧
       mel_next: (1, n_mels)   stop_logit: (1,)
    返回 (1, T, n_mels)，不含 go 帧。
    """
    raise todo()
--- solution
@torch.no_grad()
def ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5):
    prev = torch.zeros(1, 1, n_mels)          # go 帧
    frames = []
    for _ in range(max_steps):
        mel_next, stop_logit = step_fn(prev)
        frames.append(mel_next)
        prev = torch.cat([prev, mel_next.unsqueeze(1)], dim=1)
        if torch.sigmoid(stop_logit).item() > stop_thresh:
            break
    return torch.stack(frames, dim=1)

同一份 duration 有三种写法：每个字几帧、累加出来的边界、每一帧属于谁。读 TTS 代码、查对齐问题时要在它们之间来回换算，先在脑子里算熟。

--- code
d = torch.tensor([3, 1, 0, 2])
print(d.cumsum(0).tolist())
print(torch.arange(4).repeat_interleave(d).tolist())
print(int(d.sum()) * 256)
--- explain
`cumsum` 是每个字的结束帧：3、3+1=4、4+0=4、4+2=6，所以是 [3, 4, 4, 6]。

`repeat_interleave`：下标 0 重复 3 次，1 重复 1 次，2 重复 0 次（消失），3 重复 2 次，得到 [0, 0, 0, 1, 3, 3]。下标 2 没有出现：duration 为 0 的字一帧都不占。

--- hints
- 累加和：每个位置是「到这里为止所有数的和」。
- duration 为 0 的那个下标，在第二行里一次都不出现。

--- context
带 mask 的 loss 最容易错在分母上：忘了 mask，或者只除以有效帧数、忘了乘 n_mels，数值都会偏。loss 的数值不对，不同实验之间就没法比。
--- prompt
不要运行，写出这段代码打印的三行。
--- code
pred = torch.zeros(1, 4, 2)
target = torch.ones(1, 4, 2)
target[0, 3] = 9.0                                   # 第 3 帧是 pad
m = torch.tensor([[1., 1., 1., 0.]]).unsqueeze(-1)   # (1, 4, 1)
err = (pred - target).abs()
print(err.mean().item())
print((err * m).sum().item() / m.sum().item())
print((err * m).sum().item() / (m.sum().item() * 2))
--- explain
误差 `err` 一共 4 × 2 = 8 个数：前 3 帧是 1（6 个），pad 帧是 9（2 个），总和 6 + 18 = 24。

1. 不带 mask：24 ÷ 8 = 3.0。pad 的垃圾值把 loss 拉高了。
2. 带 mask，但分母只数了帧：有效误差之和是 6，`m.sum()` 是 3（帧数），6 ÷ 3 = 2.0。每帧有 2 个 mel 值，分母少乘了 n_mels。
3. 正确：6 ÷ (3 × 2) = 1.0，和「每个有效位置误差都是 1」一致。
--- hints
- 先算出 `err` 里的每个数：前 3 帧是多少？第 3 帧（pad）是多少？
- `m` 的 shape 是 (1, 4, 1)，`m.sum()` 数的是帧，不是元素。

「训练指标很好，一推理就崩」是自回归模型最典型的症状之一。能从症状倒推出原因，面试和实际排错都用得上。
--- prompt
你在训练一个 Tacotron 风格的自回归 TTS 模型。训练集上的 mel loss 很快就降到接近 0，比论文里好得多；可一到推理（一帧一帧自己生成），出来的 mel 就是一团糊。最可能的原因是哪个？
--- options
- 学习率太小了
- 解码器的输入直接用了目标 mel 本身，没有右移：第 t 步能看到第 t 帧的答案，模型只学会了抄
- stop token 的标签放在了最后一个有效帧上
- mel loss 用了 L1，而不是 MSE
answer: 2
--- explain
训练 loss 好得不正常、推理却崩掉，典型原因就是训练时偷看了答案。输入没有右移时，第 t 步的输入就是第 t 帧的目标，模型只要把输入抄到输出，loss 当然接近 0。推理时没有答案可抄，它就什么都不会。

- 学习率太小，loss 会降得慢，不会「很快降到接近 0」。
- stop 标签放在最后一个有效帧上，本来就是对的。
- L1 和 MSE 都能用来训练 mel（Tacotron 2 论文用 MSE，FastSpeech 2 用 L1），换 loss 不会造成这种症状。

- 训练 loss 比论文还好很多，本身就可疑：模型是不是拿到了不该拿的信息？
- 想想第 t 步的解码器输入应该是第几帧。

--- context
「FastSpeech 和 Tacotron 有什么区别？」是语音方向面试的经典问题。答案要落到具体机制上：长度由谁决定、能不能并行、需不需要 stop token。
--- prompt
关于 FastSpeech 2（预测 duration + length regulator）和 Tacotron 2（自回归 + attention），下面哪一句是对的？
--- options
- FastSpeech 2 一帧一帧地生成 mel，所以需要 stop token 决定什么时候停
- FastSpeech 2 的输出帧数等于 duration 之和，所有帧可以并行生成；对齐由 duration 决定，一定是单调的，不容易漏字或重复字
- Tacotron 2 训练时也需要每个字的 duration 标签
- 两者训练时都要把解码器输入右移一位、开头补 go 帧
answer: 2
--- explain
FastSpeech 2 先预测每个字的 duration，length regulator 按它把文本拉长，总帧数 = duration 之和，所有帧并行生成。对齐是按顺序复制出来的，天然单调，不会像 attention 那样跳过或者重复某个字。

- 一帧一帧生成、需要 stop token 的是 Tacotron 2。
- Tacotron 2 用 attention 自己学对齐，不需要 duration 标签；需要外部 duration（比如 Montreal Forced Aligner 给的）的是 FastSpeech 2。
- 右移 + go 帧是自回归解码器的 teacher forcing。FastSpeech 2 的解码器不看前面生成的帧，不需要右移。
--- hints
- 哪个模型事先就知道总共要生成多少帧？

def length_regulator(x, durations, max_len=None):
    outs = [x[b].repeat_interleave(durations[b], dim=0) for b in range(x.size(0))]
    Tm = max_len or max(o.size(0) for o in outs)
    out = x.new_zeros(x.size(0), Tm, x.size(2))
    for b, o in enumerate(outs):
        n = min(o.size(0), Tm)
        out[b, :n] = o[:n]
    return out

--- prompt
写 `ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5)`，`@torch.no_grad()` 已经加好了。

- `step_fn(prev)` 返回 `(mel_next, stop_logit)`：`prev` 是 (1, t, n_mels)，第一帧是全 0 的 go 帧（第一次调用时 t = 1）；`mel_next` 是 (1, n_mels)；`stop_logit` 是 (1,)

- 返回 (1, T, n_mels)：生成的所有帧，不含 go 帧，含触发停止的那一帧

--- solution
@torch.no_grad()
def ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5):
    prev = torch.zeros(1, 1, n_mels)          # go 帧
    frames = []
    for _ in range(max_steps):
        mel_next, stop_logit = step_fn(prev)
        frames.append(mel_next)
        prev = torch.cat([prev, mel_next.unsqueeze(1)], dim=1)
        if torch.sigmoid(stop_logit).item() > stop_thresh:
            break
    return torch.stack(frames, dim=1)
