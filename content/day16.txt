title: 读懂 PyTorch 报错：最后一行 + 你代码的最后一帧
error_demo: yes
--- body
报错时 Python 会打印一长串 traceback（调用记录：谁调用了谁，一层一层往下，最近的一层在最下面）。不用从头读，只看两处：

1. **最后一行**：错误类型 + 说明。形状、设备、dtype 的错几乎都是 `RuntimeError`，有用的信息在冒号后面。
2. **你自己代码的最后一帧**：从下往上找，第一个 `File "..."` 是你自己文件的那一段。它指出是你的哪一行把「错的东西」交给了 PyTorch。

把这张卡片代码里的模型写成一个 net.py 文件（开头有 import，没有那行 print），在终端里运行，会看到下面这个 traceback（路径缩短了，删掉了 `~~~^^^` 标记行）：

```
Traceback (most recent call last):
  File "net.py", line 17, in <module>
    out = model(torch.randn(4, 8))
  File ".../torch/nn/modules/module.py", line 1778, in _wrapped_call_impl
    return self._call_impl(*args, **kwargs)
  File ".../torch/nn/modules/module.py", line 1789, in _call_impl
    return forward_call(*args, **kwargs)
  File "net.py", line 13, in forward
    return self.fc2(h)
  File ".../torch/nn/modules/module.py", line 1778, in _wrapped_call_impl
    return self._call_impl(*args, **kwargs)
  File ".../torch/nn/modules/module.py", line 1789, in _call_impl
    return forward_call(*args, **kwargs)
  File ".../torch/nn/modules/linear.py", line 134, in forward
    return F.linear(input, self.weight, self.bias)
RuntimeError: mat1 and mat2 shapes cannot be multiplied (4x10 and 12x3)
```

- 最后一行：`mat1` 是进入这层 Linear 的输入，4 行 10 列（4 个样本，每个 10 个特征）。`mat2` 是这层的权重（转置后），12 行 3 列。矩阵乘法要求中间两个数相等：10 ≠ 12。
- 你代码的最后一帧：net.py 第 13 行 `return self.fc2(h)`。所以是 fc2 要 12 个输入特征，实际只来了 10 个。
- 中间的 `module.py`、`linear.py` 是 PyTorch 内部在转手，先跳过。

这张卡片的代码会真的报这个错，点「运行」看看。页面只显示你代码里的帧和最后一行。

常见报错里的关键词：
- `mat1 and mat2 shapes cannot be multiplied`：Linear 的 in_features 和输入的最后一维不一样。
- `The size of tensor a (3) must match the size of tensor b (4) at non-singleton dimension 1`：两个张量逐元素运算，第 1 维一个是 3、一个是 4，又都不是 1，没法广播。
- `view size is not compatible with input tensor's size and stride`：对不连续的张量用了 view（见「view、reshape 和 contiguous」）。
- `Expected all tensors to be on the same device`：一个在 GPU，一个在 CPU。
- `mat1 and mat2 must have the same dtype, but got Double and Float`：float64 的输入进了 float32 的模型。
- `expected target dtype to be Long or Byte, but got Float`：cross_entropy 的标签不是整数。
--- code
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 10)
        self.fc2 = nn.Linear(12, 3)   # 写错了：fc1 只输出 10 个特征

    def forward(self, x):
        h = torch.relu(self.fc1(x))
        print("进 fc2 之前 h 的 shape:", tuple(h.shape))
        return self.fc2(h)


model = Net()
out = model(torch.randn(4, 8))

@@ concept
title: 不报错的广播：(B,) 和 (B, 1)
--- body
广播（broadcasting）：两个 shape 不同的张量做逐元素运算时，PyTorch 会自动把它们「撑」成同一个 shape。规则是从最右边一维开始对齐，每一对维度要么相等，要么其中一个是 1（缺的维度当成 1）。

这很方便，也很危险。最经典的坑：

- 回归模型最后一层是 `nn.Linear(..., 1)`，输出 `pred` 的 shape 是 (B, 1)。
- 标签 `target` 的 shape 是 (B,)。
- `pred - target`：两边右对齐，(B,) 被当成 (1, B)，结果是 **(B, B)**。第 i 行第 j 列是 pred_i − target_j。
- 再 `.mean()` 一下，还是一个标量。不报错，loss 照样下降，只是算的是错的东西：模型最后只能学到「所有标签的平均值」。

卡片代码的例子里，预测**完全正确**，错的写法却算出 loss = 2.5。

怎么防：
- 算 loss 之前让两边 shape 一样：`pred.squeeze(-1)` 或 `target.unsqueeze(-1)`。用 `squeeze(-1)`，不要用不带参数的 `squeeze()`：B = 1 时 `squeeze()` 会把 batch 那一维也挤掉。
- 加一行断言：`assert pred.shape == target.shape, (pred.shape, target.shape)`。
- 更进一步：把期望的 shape 写成规格，比如 "B,T,C"。同一个字母在所有张量里必须是同一个数，写数字的维度必须正好是那个数。
- `F.mse_loss` 遇到这种情况会打一条 UserWarning（很容易淹没在日志里）；手写的 `((pred - target) ** 2).mean()` 连警告都没有。
--- code
pred = torch.tensor([[1.0], [2.0], [3.0], [4.0]])   # (4, 1)：Linear(..., 1) 的输出
target = torch.tensor([1.0, 2.0, 3.0, 4.0])         # (4,)：标签
diff = pred - target
print("pred - target 的 shape:", tuple(diff.shape))
print(diff)
print("错的 loss:", (diff ** 2).mean().item())
print("对的 loss:", ((pred.squeeze(-1) - target) ** 2).mean().item())

@@ concept
title: view、reshape 和 contiguous
--- body
一个张量 = 一块内存 + shape + stride（步长：沿某一维走一步，要在内存里跳过几个元素）。

- `torch.arange(6).view(2, 3)` 的 stride 是 (3, 1)：换一行跳 3 个，换一列跳 1 个。这叫 contiguous（连续）：一行一行从左往右读，正好就是内存里的顺序。
- `.t()`、`.transpose()`、`.permute()` **不搬数据**，只交换 stride。转置之后 stride 是 (1, 3)，不再连续。
- `view` 也不搬数据，只是换一种方式读同一块内存。张量不连续时，很多 view 做不到，就报 `view size is not compatible with input tensor's size and stride`。
- `reshape`：能 view 就 view，不能就复制一份。`.contiguous()`：复制成一个连续的新张量（本来就连续就什么都不做）。

所以这个报错的修法是 `x.contiguous().view(...)`，或者直接 `x.reshape(...)`。

**更危险的是不报错的那种。** reshape 和 view 永远按「逻辑顺序」（一行一行）读元素，**不会**帮你调换维度。想把 (B, C, H, W) 变成 (B, H*W, C)，直接写 `reshape(B, H*W, C)` 不会报错，但每个位置装的都是错位的数。调换维度要用 transpose / permute；reshape 只负责把**相邻**的维度合并或拆开。
--- code
x = torch.arange(6).view(2, 3)
print(x.tolist(), "stride", x.stride(), "连续?", x.is_contiguous())
t = x.t()                       # (3, 2)，没有搬数据
print(t.tolist(), "stride", t.stride(), "连续?", t.is_contiguous())
try:
    t.view(6)
except RuntimeError as e:
    print("t.view(6) 报错:", e)
print("t.reshape(6):", t.reshape(6).tolist())
print("t.contiguous().view(6):", t.contiguous().view(6).tolist())
print("x.reshape(3, 2):", x.reshape(3, 2).tolist(), " 不等于转置", t.tolist())

title: 设备：新建的张量要跟着输入走
--- body
一次运算里的张量必须在同一个设备（device）上：都在 CPU，或者都在同一块 GPU（比如 `cuda:0`）。模型的参数、输入，还有 forward 里**临时新建**的张量，都算。

最常见的 bug：forward 里的 `torch.arange(T)`、`torch.zeros(...)`、`torch.ones(...)` 没写 device，于是永远建在 CPU 上。在只有 CPU 的笔记本上一切正常，一上 GPU 服务器就报 `Expected all tensors to be on the same device, but found at least two devices, cuda:0 and cpu!`。

修法：让新张量「跟着输入走」。
- `torch.arange(T, device=x.device)`
- `torch.zeros(B, T, device=x.device, dtype=x.dtype)`，或者更短的 `x.new_zeros(B, T)`、`torch.zeros_like(x)`
- 已经存在的张量：`other.to(x.device)`

不要写死 `.cuda()`：没有 GPU 的机器会直接报错；`.cuda()` 默认去当前的 GPU（通常是 `cuda:0`），模型放在 `cuda:1` 上时又对不上。

一个例外：0 维的 CPU 张量（比如 `torch.tensor(2.0)`）可以直接和 GPU 张量运算，PyTorch 把它当成普通数字。

**没有 GPU 怎么测？** 用 meta 设备。它是一个「假设备」：张量只有 shape 和 dtype，没有真实数据，所以在哪台机器上都能用。CPU 张量和 meta 张量混在一起，会报同一类错：`Tensor on device cpu is not on the expected device meta!`。今天有几道题的检查就是这么测的。
--- code
def add_positions(x):                   # x: (B, T)
    pos = torch.arange(x.shape[1])      # bug：没写 device，永远在 CPU 上
    return x + pos

def add_positions_fixed(x):
    pos = torch.arange(x.shape[1], device=x.device)
    return x + pos

x = torch.zeros(2, 5, device="meta")    # 假装这是 GPU 上的输入
for fn in (add_positions, add_positions_fixed):
    try:
        out = fn(x)
        print(fn.__name__, "OK:", out.device, tuple(out.shape))
    except RuntimeError as e:
        print(fn.__name__, "报错:", e)

@@ concept
title: register_buffer：跟着模块一起搬家
--- body
`model.to("cuda")`、`model.cuda()`、`model.double()`、`model.half()` 只处理模块「认识」的张量：
- 参数：`nn.Parameter`，会被优化器更新（比如 Linear 的 weight）。
- buffer：用 `self.register_buffer("名字", 张量)` 登记过的张量。不参与训练，但跟着模块走：换设备、换 dtype、存进 `state_dict`。

普通属性 `self.mask = torch.tril(...)` 模块**看不见**。模型搬到 GPU，它还留在 CPU，forward 一用就报设备错。每次在 forward 里现建一个也不好：默认建在 CPU、float32，还白白重复计算。

所以固定的辅助张量（因果 mask、位置编码表、归一化用的均值和方差）都在 `__init__` 里建一次，用 `register_buffer` 登记。加 `persistent=False` 表示「不存进 state_dict」：它随时能重新算出来，不存能让 checkpoint 小一点，max_len 改了也不会加载失败。

**没有 GPU 怎么测「会不会跟着走」？** 换 dtype。`.double()` 和 `.to("cuda")` 走的是模块里同一段代码（`Module._apply`）：buffer 会从 float32 变成 float64，普通属性不变。注意 `.double()`、`.half()` 只改浮点张量，bool 和整数的 buffer 保持原来的 dtype（但换设备时照样跟着走）。
--- code
class M(nn.Module):
    def __init__(self):
        super().__init__()
        self.lin = nn.Linear(3, 3)
        self.plain = torch.ones(3)                                    # 普通属性：模块不知道它
        self.register_buffer("buf", torch.ones(3))                    # buffer：跟着走
        self.register_buffer("tmp", torch.ones(3), persistent=False)  # 跟着走，但不存

m = M().double()
print("lin.weight:", m.lin.weight.dtype)
print("buf:       ", m.buf.dtype)
print("tmp:       ", m.tmp.dtype)
print("plain:     ", m.plain.dtype, " <- 没变")
print("buffers:   ", [name for name, _ in m.named_buffers()])
print("state_dict:", list(m.state_dict().keys()))
m = m.to("meta")
print("to(meta) 之后: buf 在", m.buf.device, "，plain 在", m.plain.device)

@@ concept
title: dtype：long 标签、numpy 的 float64、整数除法
--- body
dtype（数据类型）决定张量里每个数怎么存。三个最常见的坑：

**1. numpy 默认是 float64。** PyTorch 默认的浮点是 float32，模型参数也是 float32。`torch.from_numpy(a)` 和 `torch.tensor(a)` 都会保留 float64，喂进模型就报 `mat1 and mat2 must have the same dtype, but got Double and Float`。修法：`.float()`。逐元素运算倒是不报错：float32 + float64 会被悄悄「提升」成 float64，内存翻倍。

**2. 类别标签必须是 long（int64）。** `F.cross_entropy` 的标签、`nn.Embedding` 的 token id、用来索引的下标，都要是整数。标签写成 float 会报 `expected target dtype to be Long or Byte, but got Float`。反过来，回归任务（MSE）的目标要是 float。

**3. 整数除法。** Python 的 `//` 是整除：`3 // 4 == 0`。用 `correct // total` 算准确率，除非全对，结果永远是 0。要用 `/`。PyTorch 里整数张量用 `/` 会得到浮点（真除法），`//` 才是整除。整数张量不能直接 `.mean()`（报 `mean(): could not infer output dtype`），先 `.float()`。

另外：`pred == y` 是 bool 张量，`.sum()` 之后变成 int64。
--- code
import numpy as np

a = np.array([0.5, 1.5])
print("numpy:", a.dtype, "-> torch.from_numpy:", torch.from_numpy(a).dtype)
print("torch.tensor([1, 2]):", torch.tensor([1, 2]).dtype)
print("torch.tensor([1.0, 2.0]):", torch.tensor([1.0, 2.0]).dtype)
try:
    nn.Linear(2, 1)(torch.from_numpy(a).view(1, 2))
except RuntimeError as e:
    print("float64 进 Linear:", e)
try:
    F.cross_entropy(torch.randn(2, 3), torch.tensor([0.0, 2.0]))
except RuntimeError as e:
    print("float 标签:", e)
correct, total = 3, 4
print("3 // 4 =", correct // total, "   3 / 4 =", correct / total)
y = torch.tensor([7, 8])
print("整数张量 / 2:", y / 2, "   // 2:", y // 2)

title: forward hook：让每一层报出输出 shape
--- body
模型一报 shape 错，最想知道的就是：**每一层输出的 shape 到底是多少**。一层层手动加 print 很麻烦。forward hook（钩子）不用改模型代码就能做到。

- `handle = layer.register_forward_hook(fn)`：之后 layer 每跑完一次 forward，就调用一次 `fn(module, inputs, output)`。`inputs` 是一个 tuple（这一层收到的所有输入），`output` 是这一层的输出。
- `handle.remove()`：把钩子取下来。忘了取，它会一直挂着，之后每次 forward 都会触发。
- `model.named_modules()`：依次给出 `(名字, 模块)`，包括整个模型自己（名字是空字符串 `''`）和中间的容器（比如 `nn.Sequential`）。嵌套的名字用点连起来，比如 `'2.0'`、`'enc.0'`。
- 只想看「真正干活的层」：挑叶子模块，也就是没有子模块的模块：`len(list(m.children())) == 0`。
- 同一个模块可以被调用好几次（比如一个 `nn.ReLU` 用了两次），它的钩子也就触发好几次。

用完一定要取下钩子，就算 forward 中途报错也要取。写法是 try / finally，`finally` 里的代码不管有没有报错都会执行：

```
handles = [...]
try:
    model(x)
finally:
    for h in handles:
        h.remove()
```

如果还想在报错时继续往下走，就在中间加一段 `except Exception as e:`，把错误存起来，而不是让它抛出去。

模型崩溃时，最后打印出来的那一层就是「最后一个成功跑完的层」，崩的是它后面那一层。

算卷积层的输出边长：`(输入 + 2·padding − kernel) // stride + 1`。
--- code
model = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Sequential(nn.Linear(8, 8), nn.Tanh()), nn.Linear(8, 2))

for name, mod in model.named_modules():
    leaf = len(list(mod.children())) == 0
    print(repr(name), type(mod).__name__, "叶子" if leaf else "容器")

def show(module, inputs, output):
    print("  ", type(module).__name__, tuple(inputs[0].shape), "->", tuple(output.shape))

handles = [m.register_forward_hook(show) for m in model.modules() if len(list(m.children())) == 0]
try:
    model(torch.randn(5, 4))
finally:
    for h in handles:
        h.remove()
print("钩子取下以后再跑一次，不再打印：")
model(torch.randn(5, 4))

@@ concept
title: 嵌套的 batch：递归走一遍 dict / list / tuple
--- body
真实项目里的 batch 很少只是一个张量。DataLoader 给出来的常常是这样的：

```
{"input_ids": (B, T) long, "attention_mask": (B, T) bool,
 "pixels": (B, 3, H, W) float, "meta": {"lengths": [...], "ids": ("a", "b")}}
```

要把它整个搬到 GPU，或者打印出每个张量的 shape，就要「走遍」这个嵌套结构。这是递归（函数调用它自己）的经典用法：
- 是张量：处理它，返回结果。
- 是 dict：对每个 value 递归，key 不变，拼回一个 dict。
- 是 list / tuple：对每个元素递归，拼回**同一种**容器（tuple 还是 tuple）。
- 其他东西（字符串、数字、None）：原样返回。

判断类型用 `isinstance(obj, torch.Tensor)`、`isinstance(obj, dict)`、`isinstance(obj, (list, tuple))`。`type(obj)(...)` 能用原来的容器类型再造一个：`type((1, 2))([3, 4])` 得到 `(3, 4)`。

换 dtype 时要小心：只有浮点张量（`t.is_floating_point()` 为 True）才该转成 float16、float64 之类。token id 和标签是 long，mask 是 bool，把它们也转成浮点，下游的 Embedding 和 cross_entropy 就会报错。
--- code
def describe(obj):
    """把嵌套 batch 里的每个张量换成一句说明，其余原样保留。"""
    if isinstance(obj, torch.Tensor):
        kind = "浮点" if obj.is_floating_point() else "非浮点"
        return f"{tuple(obj.shape)} {obj.dtype} {kind}"
    if isinstance(obj, dict):
        return {k: describe(v) for k, v in obj.items()}
    if isinstance(obj, (list, tuple)):
        return type(obj)(describe(v) for v in obj)
    return obj

batch = {
    "input_ids": torch.randint(0, 100, (2, 6)),
    "attention_mask": torch.ones(2, 6, dtype=torch.bool),
    "pixels": torch.randn(2, 3, 8, 8),
    "meta": {"lengths": [6, 4], "ids": ("a", "b")},
}
for key, value in describe(batch).items():
    print(key, "->", value)

def assert_shape(x, spec, sizes):
    """检查 x.shape 符合 spec（比如 "B,T,C"）：符合就返回 x，否则 raise ValueError。
    sizes: dict，名字 -> 大小。第一次见到时记下，之后必须一致。"""
    dims = [d.strip() for d in spec.split(",")]
    shape = tuple(x.shape)
    if len(dims) != len(shape):
        raise ValueError(f"shape {shape} 不符合 {spec!r}：应该有 {len(dims)} 维，实际 {len(shape)} 维")
    for i, (d, n) in enumerate(zip(dims, shape)):
        if d.isdigit():
            if n != int(d):
                raise ValueError(f"shape {shape} 不符合 {spec!r}：第 {i} 维应为 {d}，实际是 {n}")
        elif d in sizes and sizes[d] != n:
            raise ValueError(f"shape {shape} 不符合 {spec!r}：{d} 之前是 {sizes[d]}，这里是 {n}")
        else:
            sizes[d] = n
    return x

class CausalMask(nn.Module):
    def __init__(self, max_len):
        super().__init__()
        self.max_len = max_len
        bias = torch.triu(torch.full((max_len, max_len), float("-inf")), diagonal=1)
        self.register_buffer("bias", bias, persistent=False)   # 跟着 .to() / .double() 走

    def forward(self, scores):                     # scores: (B, T, T)
        T = scores.shape[-1]
        return scores + self.bias[:T, :T]

def move_to(batch, device, float_dtype=None):
    """把嵌套 batch 里的每个张量搬到 device；给了 float_dtype 时只转换浮点张量。"""
    if isinstance(batch, torch.Tensor):
        if float_dtype is not None and batch.is_floating_point():
            return batch.to(device=device, dtype=float_dtype)
        return batch.to(device)
    if isinstance(batch, dict):
        return {k: move_to(v, device, float_dtype) for k, v in batch.items()}
    if isinstance(batch, (list, tuple)):
        return type(batch)(move_to(v, device, float_dtype) for v in batch)
    return batch

def trace_shapes(model, x):
    """跑一次 model(x)，返回 (records, error)。
    records: [(name, shape), ...]，叶子模块的输出 shape，按运行顺序
    error: 正常时是 None；forward 报错时是那个异常对象
    返回前取下所有 hook。"""
    names = {mod: name for name, mod in model.named_modules()}
    records = []

    def hook(module, inputs, output):
        records.append((names[module], tuple(output.shape)))

    handles = [m.register_forward_hook(hook) for m in model.modules() if len(list(m.children())) == 0]
    error = None
    try:
        model(x)
    except Exception as e:          # 接住，作为结果返回
        error = e
    finally:
        for h in handles:           # 成功、失败都要取下
            h.remove()
    return records, error

--- solution
def move_to(batch, device, float_dtype=None):
    if isinstance(batch, torch.Tensor):
        if float_dtype is not None and batch.is_floating_point():
            return batch.to(device=device, dtype=float_dtype)
        return batch.to(device)
    if isinstance(batch, dict):
        return {k: move_to(v, device, float_dtype) for k, v in batch.items()}
    if isinstance(batch, (list, tuple)):
        return type(batch)(move_to(v, device, float_dtype) for v in batch)
    return batch
