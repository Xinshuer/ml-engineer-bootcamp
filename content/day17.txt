@@ concept
title: train() 和 eval()：Dropout 和 BatchNorm 会变
--- body
有两种常见的层，训练和推理时的行为不一样。`model.train()` 和 `model.eval()` 就是切换它们的开关，会自动作用到所有子模块。

- **Dropout**：train 模式下，每个数以概率 p 被置 0，活下来的数乘以 1/(1-p)，让平均值不变。eval 模式下它什么都不做。
- **BatchNorm**：train 模式下，用「当前这个 batch」的均值和方差做归一化，顺手更新 `running_mean` / `running_var`（一路累积下来的统计量）。eval 模式下，改用这两个存下来的统计量。

所以预测时忘了 `model.eval()`，代码不会报错，但是：

1. 同一个输入预测两次，结果不一样（Dropout 在随机丢）。
2. 一个样本的预测，会随同 batch 的其他样本变化（BatchNorm 用的是 batch 的统计量）。
3. 每预测一次，BatchNorm 的 running 统计量就被改一次。`torch.no_grad()` 拦不住：它只管梯度，不管模式。

记住：**`no_grad` 和 `eval()` 是两件事，推理时两个都要。** 反过来，训练循环里做完评估，要用 `model.train()` 切回来，不然后面的训练就没有 Dropout 了。
--- code
torch.manual_seed(0)
model = nn.Sequential(nn.Linear(4, 8), nn.BatchNorm1d(8), nn.Dropout(0.5), nn.Linear(8, 2))
x = torch.randn(6, 4)
with torch.no_grad():
    model.train()
    print("train 模式，预测两次一样吗:", torch.equal(model(x), model(x)))
    print("running_mean 被悄悄改了:", model[1].running_mean[:3])
    model.eval()
    print("eval 模式，预测两次一样吗:", torch.equal(model(x), model(x)))
    print("eval 模式，前 2 个样本单独算 == 放在 batch 里算:", torch.allclose(model(x[:2]), model(x)[:2]))

@@ concept
title: 数据泄漏：统计量只能来自训练集
--- body
数据泄漏（data leakage）：测试集的信息偷偷流进了训练过程。结果是评估分数比上线后的真实表现好，而你不知道。

最常见的一种：标准化（减均值、除标准差）时，均值和标准差是在「全部数据」上算的，算完才切分训练集和测试集。这样测试集的数值参与了训练数据的变换。

正确顺序：

1. 先切分：训练集、测试集分开。
2. 只在训练集上算 `mean` 和 `std`（这叫「拟合」统计量）。
3. 用这同一组 `mean` / `std` 去变换训练集、测试集，以及上线后的每一个请求。

一个简单的检查（这就是一个不变量测试）：**只改测试集，训练集变换后的结果必须一模一样。** 变了，就说明有泄漏。

tokenizer 的词表、特征选择、去重也是同一个道理：只能在训练集上「学」。

下面的例子里，测试集的分布偏了。泄漏版把这个偏移藏掉了一半：评估时看起来只偏了 1.74 个标准差，上线后模型面对的其实是 3.39 个。
--- code
torch.manual_seed(0)
train = torch.randn(100, 1) + 5.0      # 训练集：均值约 5
test = torch.randn(20, 1) + 8.0        # 测试集：分布偏了，均值约 8
both = torch.cat([train, test])
print(f"用全部数据算的均值: {both.mean().item():.2f}")
print(f"只用训练集算的均值: {train.mean().item():.2f}")
leaky = ((test - both.mean()) / both.std()).mean().item()
clean = ((test - train.mean()) / train.std()).mean().item()
print(f"测试集标准化后的均值，泄漏版: {leaky:.2f}")
print(f"测试集标准化后的均值，正确版: {clean:.2f}  <- 上线后模型看到的是这个")

@@ concept
title: next-token 标签要错开一位
--- body
语言模型的任务：看到位置 0..t 的 token，猜位置 t+1 的 token。所以输入和标签要**错开一位**：

- `inputs = tokens[:, :-1]`（去掉最后一个）
- `targets = tokens[:, 1:]`（去掉第一个）

模型在位置 t 的输出 `logits[:, t]`，和 `targets[:, t]` 比，也就是原序列的第 t+1 个 token。

忘了错开会怎样？标签就是模型已经看到的当前 token。模型只要学会「复读」，loss 就几乎是 0。训练曲线漂亮极了，生成的文本却一团乱。**loss 好得不真实，本身就是 bug 信号。**

另一种错法是方向错反了（`inputs = tokens[:, 1:]`，`targets = tokens[:, :-1]`），变成了「看后面猜前面」。

算 `F.cross_entropy` 前，要把 (B, T, V) 的 logits 摊平成 (B·T, V)，标签摊平成 (B·T,)。切片后的张量内存不一定连续，用 `.reshape`，不用 `.view`（第 16 天讲过）。
--- code
tokens = torch.tensor([[5, 6, 7, 8, 9]])
inputs, targets = tokens[:, :-1], tokens[:, 1:]
print("inputs :", inputs.tolist())
print("targets:", targets.tolist())
for t in range(inputs.shape[1]):
    print(f"看到 {inputs[0, :t + 1].tolist()} -> 要猜 {targets[0, t].item()}")

@@ concept
title: padding 不能算进平均
--- body
一个 batch 里的句子长短不一。短的要在后面补 padding（填充用的假 token），才能拼成一个 (B, T) 的张量。再配一个 mask：1 表示真 token，0 表示 padding。

padding 不是数据。loss、平均池化（mean pooling）、准确率，都只能在真 token 上算。正确写法：

```
masked_mean = (x * mask).sum() / mask.sum()
```

常见错法：先 `x * mask` 把 padding 置 0，再 `.mean()`。分子对了，分母却是「所有位置」的个数。后果：padding 越多，loss 看起来越小。换一个 batch 大小，或者按长度分桶，loss 就莫名其妙地变了。

用 `F.cross_entropy` 还有一条路：把 padding 位置的 target 设成 -100。它的默认参数 `ignore_index=-100` 会跳过这些位置，分母也只数真 token。

检查方法（又一个不变量）：**多补几列 padding，loss 必须完全不变。**
--- code
loss = torch.tensor([[2.0, 1.0, 3.0, 0.0, 0.0],
                     [4.0, 0.0, 0.0, 0.0, 0.0]])   # 每个位置的 loss（padding 处已经是 0）
mask = torch.tensor([[1., 1., 1., 0., 0.],
                     [1., 0., 0., 0., 0.]])
print("错误 (loss*mask).mean()          =", (loss * mask).mean().item())
print("正确 (loss*mask).sum()/mask.sum() =", ((loss * mask).sum() / mask.sum()).item())
wide_loss = torch.cat([loss, torch.zeros(2, 5)], 1)     # 再补 5 列 padding
wide_mask = torch.cat([mask, torch.zeros(2, 5)], 1)
print("多补 5 列后，错误写法 =", (wide_loss * wide_mask).mean().item())
print("多补 5 列后，正确写法 =", ((wide_loss * wide_mask).sum() / wide_mask.sum()).item())

@@ concept
title: 梯度累积要按样本数加权
--- body
显存装不下大 batch 时，可以把它切成几个小 batch（micro-batch）。每个小 batch 都 `backward()`，梯度会**自动累加**到 `.grad` 上，最后只 `step()` 一次。这叫梯度累积（gradient accumulation）。

坑就在「累加」上。每个小 batch 的 loss 已经是它自己的平均值，K 个梯度加起来，就是大 batch 梯度的 **K 倍**。

- 小 batch 一样大：每个 loss 除以 K。
- 小 batch 不一样大（最后一个常常更小）：每个 loss 乘以 `len(xb) / N`，N 是总样本数。只除以 K 的话，小 batch 里的样本权重会偏大。

这个 bug 为什么能藏很久？用 Adam 时几乎看不出来：Adam 会按梯度的大小自动缩放，梯度整体大 K 倍，更新几乎一样。但是用 SGD 时步子大了 K 倍；梯度裁剪（clip）的阈值不再对；日志里的 loss 也大了 K 倍。

检查方法（和参考对比）：**累积出来的梯度 == 直接在大 batch 上算的梯度。**
--- code
torch.manual_seed(0)
x, y = torch.randn(8, 3), torch.randn(8, 1)
m = nn.Linear(3, 1)
F.mse_loss(m(x), y).backward()
full = m.weight.grad.clone()                  # 大 batch 的梯度（参考答案）
m.zero_grad()
for xb, yb in zip(x.split(2), y.split(2)):    # 4 个小 batch，每个 2 条
    F.mse_loss(m(xb), yb).backward()          # 没有加权
print("没加权：是大 batch 梯度的", (m.weight.grad / full).round(decimals=3).tolist(), "倍")
m.zero_grad()
for xb, yb in zip(x.split(2), y.split(2)):
    (F.mse_loss(m(xb), yb) * len(xb) / len(x)).backward()
print("按样本数加权后，和大 batch 一样:", torch.allclose(m.weight.grad, full))

@@ concept
title: weight decay 不该压在 1 维参数上
--- body
weight decay：每一步都把参数往 0 拉一点（AdamW 里大约是 `p = p - lr * wd * p`），防止权重矩阵变得太大。

但有两类参数不该往 0 拉：

- **bias**：只是整体平移，拉向 0 起不到正则化的作用。
- **LayerNorm / RMSNorm 的 weight**（缩放系数）：初始值是 1。被拉向 0，等于把这一层的输出越压越小。

它们有一个共同点：都是 1 维的（`p.ndim == 1`）。权重矩阵、embedding 都是 2 维的。所以标准做法是按维数分成两组，交给优化器的 param groups（参数组：每组可以有自己的超参数）：

```
decay    = [p for p in model.parameters() if p.ndim >= 2]
no_decay = [p for p in model.parameters() if p.ndim < 2]
opt = torch.optim.AdamW([{"params": decay, "weight_decay": 0.1},
                         {"params": no_decay, "weight_decay": 0.0}], lr=3e-4)
```

按名字过滤（`"bias" in name`）很常见，但会漏掉 LayerNorm 的 weight：它的名字是 `norm.weight` 这种，里面没有 bias。
--- code
torch.manual_seed(0)
net = nn.Sequential(nn.Linear(4, 4), nn.LayerNorm(4))
for name, p in net.named_parameters():
    print(f"{name:9s} ndim={p.ndim}  ->", "decay" if p.ndim >= 2 else "不 decay")
opt = torch.optim.AdamW(net.parameters(), lr=0.1, weight_decay=0.1)   # 反面教材：全部 decay
for _ in range(10):
    for p in net.parameters():
        p.grad = torch.zeros_like(p)          # 梯度是 0，只剩 weight decay 在起作用
    opt.step()
print("10 步后 LayerNorm 的 weight:", net[1].weight.data)

@@ concept
title: 学习率调度器每一步都要 step
--- body
学习率调度器（scheduler）按「`scheduler.step()` 被调用了几次」来决定当前学习率。warmup（开头几百步把学习率从很小慢慢升上去）、cosine 这些常用调度，都是按**优化器的步数**设计的。

所以它的位置在内层循环里，紧跟在 `optimizer.step()` 后面：

```
for x, y in loader:
    loss = ...
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    scheduler.step()      # 每一步一次
```

两种常见错法，都不报错：

- 放在 epoch 循环里：一个 epoch 才走一步。warmup 本来 1000 步结束，结果要 1000 个 epoch，学习率一直很小，loss 降得慢得离谱。
- 放在 `optimizer.step()` 前面：整个计划提前一步，第一步的学习率被跳过。PyTorch 只打印一条 warning。

检查方法：把每一步实际用的学习率记下来（`optimizer.param_groups[0]["lr"]`），和你设计的计划逐项对比。
--- code
def used_lrs(per_step):
    m = nn.Linear(2, 1)
    opt = torch.optim.SGD(m.parameters(), lr=0.1)
    sched = torch.optim.lr_scheduler.LambdaLR(opt, lambda s: min(1.0, (s + 1) / 4))  # 4 步 warmup
    used = []
    for epoch in range(2):
        for step in range(3):
            used.append(round(opt.param_groups[0]["lr"], 4))
            opt.step()
            if per_step:
                sched.step()
        if not per_step:
            sched.step()
    return used

print("每步 step 一次:      ", used_lrs(True))
print("每个 epoch step 一次:", used_lrs(False))

@@ concept
title: 不变量测试：让不报错的 bug 现身
ref: day17
--- body
不报错的 bug 最贵：代码能跑，loss 也在降，只是结果悄悄差了一截。可能要训练好几天才发现。

办法是写**不变量测试**（invariant test）：找一个「不管输入是什么都必须成立」的性质，用随机输入去验证它。今天用到这几个：

- **因果性**：改掉位置 t 之后的输入，位置 0..t 的输出不能变。抓 attention mask 写错、卷积偷看下一个位置。
- **批内独立**：把 batch 拆成两半分别算，结果要和整个 batch 一起算一样。抓忘了 `eval()` 的 BatchNorm、softmax 的 dim 写成 0。
- **padding 不变**：多补几列 padding，loss 不变。抓 padding 被算进平均。
- **只改测试集，训练数据不变**：抓数据泄漏。
- **和参考实现对比**：梯度累积 vs 大 batch；手写 attention vs `F.scaled_dot_product_attention`。
- **在一个 batch 上过拟合**（第 15 天）：loss 降不到接近 0，有 bug；loss 一下子就到 0，也要怀疑（比如标签没错位）。

写这类测试有两个细节。第一，先 `model.eval()`，否则 Dropout 的随机性会让「应该不变」的输出也在变。第二，比较浮点数用 `torch.allclose(a, b, atol=1e-5)`，不用 `==`。

下面的代码只在一个位置上做因果性检查。`CumMean`（位置 t 输出前 t+1 个输入的平均）和 `TinyAttention`（单头 attention，`mask="none"` 表示没加 mask）是今天准备好的小模型。练习里你会把它写成对每个位置都检查的工具。
--- code
torch.manual_seed(0)
x = torch.randn(1, 6, 8)
x2 = x.clone()
x2[:, 4:] = torch.randn(1, 2, 8)          # 只改位置 4、5，也就是「未来」
for name, m in [("CumMean", CumMean()), ("没加 mask 的 attention", TinyAttention(8, mask="none"))]:
    m.eval()
    with torch.no_grad():
        same = torch.allclose(m(x)[:, :4], m(x2)[:, :4], atol=1e-5)
    print(f"{name}: 前 4 个位置的输出没变 = {same}")

type: predict
title: Dropout 在 train 和 eval 下各输出什么
level: 1
cards: train() 和 eval()：Dropout 和 BatchNorm 会变
--- context
「同一个输入，每次预测结果都不一样」是新手最常问的问题之一，原因几乎总是忘了 `model.eval()`。先亲眼看看 Dropout 在两种模式下各做了什么。
--- prompt
读下面的代码，写出它打印的两行。

提示：`p=0.5` 的 Dropout 在 train 模式下，没被置 0 的数会乘以 1/(1-p)。
--- code
torch.manual_seed(0)
drop = nn.Dropout(p=0.5)
x = torch.ones(4)
drop.eval()
print(drop(x).tolist())
drop.train()
print(sorted(set(drop(x).tolist())))
--- explain
第一行：eval 模式下 Dropout 什么都不做，输出等于输入，`[1.0, 1.0, 1.0, 1.0]`。

第二行：train 模式下，每个数有一半的概率变成 0，没变成 0 的乘以 1/(1-0.5) = 2，这样平均值还是 1。`set` 去掉重复，`sorted` 排好序，得到 `[0.0, 2.0]`（这个种子下两种值都出现了）。

所以推理时忘了 `eval()`，模型里一部分神经元会被随机关掉，预测自然每次都不一样。
--- hints
- eval 模式下的 Dropout 是「直通」的：输入是什么，输出就是什么。
- train 模式下，每个 1.0 要么变成 0，要么变成 1.0 / (1 - 0.5)。

@@ item d17-02
type: fix
title: 预测时忘了 model.eval()
level: 1
cards: train() 和 eval()：Dropout 和 BatchNorm 会变
targets: predict
ref: day17
--- context
线上服务里，同一张图请求两次给出两个不同的答案；一个用户的结果随同一批请求里别人的数据变化。这些都是真实发生过的事故，原因常常只是少了一行 `model.eval()`。
--- prompt
`predict(model, x)` 把 x（形状 (B, 8)）交给一个分类模型，返回每个样本 3 个类别的概率，形状 (B, 3)。模型来自 `make_classifier()`，里面有 BatchNorm 和 Dropout。

它已经用了 `torch.no_grad()`，能跑，也不报错。但测试发现了三个问题：

1. 同一个输入预测两次，结果不一样。
2. 一个样本的预测结果，会随同 batch 的其他样本变化。
3. 每预测一次，BatchNorm 的 `running_mean` 就被改一次。

修好 `predict`，让这三个问题都消失。
--- starter
def predict(model, x):
    """x: (B, 8) -> 概率 (B, 3)"""
    with torch.no_grad():
        logits = model(x)
    return logits.softmax(-1)
--- solution
def predict(model, x):
    """x: (B, 8) -> 概率 (B, 3)"""
    model.eval()                     # Dropout 关掉，BatchNorm 改用存下来的统计量
    with torch.no_grad():
        logits = model(x)
    return logits.softmax(-1)
--- tests
@check("同一个输入预测两次，结果一样")
def _():
    model = make_classifier()
    model.train()                    # 刚训练完，模型还在 train 模式
    x = torch.randn(16, 8)
    p1 = predict(model, x)
    p2 = predict(model, x)
    eq(p2, p1, tol=1e-6, msg="两次预测不一样：Dropout 还开着，每次随机关掉一半神经元。")

@check("一个样本的预测不受同 batch 其他样本影响")
def _():
    model = make_classifier()
    model.train()
    x = torch.randn(16, 8)
    whole = predict(model, x)[:4]
    part = predict(model, x[:4])
    eq(part, whole, tol=1e-5, msg="同样 4 个样本，单独预测和混在 16 个样本里预测，结果不同。train 模式的 BatchNorm 用的是「这个 batch」的均值和方差。")

@check("预测不会偷偷改掉 BatchNorm 的统计量")
def _():
    model = make_classifier()
    model.train()
    before = model[1].running_mean.clone()
    predict(model, torch.randn(16, 8) + 3.0)
    eq(model[1].running_mean, before, tol=0.0, msg="预测完 running_mean 变了：train 模式下 BatchNorm 每次 forward 都会更新它，torch.no_grad() 也拦不住。")
--- hints
- `torch.no_grad()` 只管「记不记录梯度」，不管层的行为。
- Dropout 和 BatchNorm 的行为由模型的「模式」决定。预测时应该在哪个模式？
- 在 `with torch.no_grad():` 前面加一行 `model.eval()`。

@@ item d17-03
type: fix
title: 评估完忘了切回 train()
level: 2
cards: train() 和 eval()：Dropout 和 BatchNorm 会变
targets: fit
ref: day17
--- context
训练中途评估一次，然后忘了切回 train 模式，后面几万步训练就都没有 Dropout 了。模型更容易过拟合，但日志里什么异常都看不到。
--- prompt
`fit(model, train_batches, val_batch, eval_every=2)` 在 `train_batches` 上训练（SGD，lr=0.1，MSE loss），每 `eval_every` 步在 `val_batch` 上评估一次，返回验证 loss 的列表。

def train_with_warmup(model, batches, epochs, lr=0.1, warmup=8):
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    sched = torch.optim.lr_scheduler.LambdaLR(opt, lambda s: min(1.0, (s + 1) / warmup))
    used = []
    for epoch in range(epochs):
        for x, y in batches:
            loss = F.mse_loss(model(x), y)
            opt.zero_grad()
            loss.backward()
            used.append(opt.param_groups[0]["lr"])
            opt.step()
        sched.step()
    return used

def train_with_warmup(model, batches, epochs, lr=0.1, warmup=8):
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    sched = torch.optim.lr_scheduler.LambdaLR(opt, lambda s: min(1.0, (s + 1) / warmup))
    used = []
    for epoch in range(epochs):
        for x, y in batches:
            loss = F.mse_loss(model(x), y)
            opt.zero_grad()
            loss.backward()
            used.append(opt.param_groups[0]["lr"])
            opt.step()
            sched.step()             # 每一步一次，紧跟在 opt.step() 后面
    return used
--- tests

    batches = [(torch.randn(5, 2), torch.randn(5, 1)) for _ in range(4)]
    return train_with_warmup(model, batches, epochs=3, lr=0.1, warmup=8)

def check_causal(model, x):
    model.eval()                                  # 关掉 Dropout，不然输出本来就在变
    with torch.no_grad():
        base = model(x)
        for t in range(x.shape[1] - 1):
            x2 = x.clone()

                return False                      # 过去的输出变了：偷看了未来
    return True

def check_batch_independent(f, x):
    """f: (B, ...) -> (B, ...)   x: (B, ...)
    两半分开算、再拼起来 == 整个 batch 一起算 -> True，否则 False。"""

def check_batch_independent(f, x):
    h = x.shape[0] // 2
    with torch.no_grad():
        whole = f(x)                                   # 整个 batch 一起算
        parts = torch.cat([f(x[:h]), f(x[h:])])        # 拆成两半分别算
    return torch.allclose(parts, whole, atol=1e-5)

def masked_lm_loss(logits, targets, mask):
    V = logits.size(-1)
    loss = F.cross_entropy(logits.reshape(-1, V), targets.reshape(-1), reduction="none")
    mask = mask.reshape(-1).to(loss.dtype)
    return (loss * mask).sum() / mask.sum()      # 分母只数真 token

    targets = torch.randint(0, V, (B, T)) * mask.long()       # padding 位置的 target 是 0
    return logits, targets, mask
