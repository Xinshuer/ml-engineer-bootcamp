@@ concept
title: 波形和采样率：一秒有多少个数
--- body
一段音频在电脑里就是一串数字，叫 **波形**（waveform）。每个数记录某一瞬间声音的振动位置，范围大约在 -1 到 1 之间。

**采样率**（sample rate，简写 sr）= 每秒记录多少个数。16kHz 就是每秒 16000 个数。

- 采样点数 = 秒数 × sr，取整。16kHz 下 2 秒 → 32000 个点
- 秒数 = 采样点数 ÷ sr。48000 个点 @16kHz → 3.0 秒
- 一条单声道音频的 shape 是 `(T,)`，一个 batch 是 `(B, T)`

常见采样率：语音识别常用 16kHz；TTS 和音频 codec 常用 22.05kHz 或 24kHz；音乐 CD 是 44.1kHz。

模型一般不直接看每个采样点，而是把波形切成一帧一帧（frame）。相邻两帧的起点差多少个点，叫 **hop**（步长）。所以：

- 每秒多少帧（帧率）= sr ÷ hop
- 16kHz、hop=160 → 每秒 100 帧（Whisper 就是这么设的）

帧率就像 LLM 里「一个 token 大约几个字」：它决定了一段音频变成多长的序列，也就决定了模型要算多久。
--- code
sr = 16000
seconds = 2.5
T = int(seconds * sr)
wav = torch.zeros(T)                  # 2.5 秒的静音
print("shape:", tuple(wav.shape))
print("时长:", wav.numel() / sr, "秒")

for sr_, hop in [(16000, 160), (22050, 256), (24000, 300)]:
    print(f"sr={sr_}, hop={hop}: 每秒 {sr_ / hop:.1f} 帧")

@@ concept
title: 峰值归一化：把音量拉齐
--- body
不同录音的音量差很多：有人贴着麦克风说话，**峰值**（绝对值最大的那个采样点）接近 1；有人离得远，峰值只有 0.05。喂给模型之前，常见做法是先把音量拉到同一个水平。

**峰值归一化**（peak normalization）：整条波形乘同一个数，让峰值正好等于目标值，比如 0.95。

- 峰值 = `wav.abs().max()`（要取绝对值，负数也算）
- 结果 = `wav * (target / peak)`
- 所有点乘同一个数，波形的「形状」不变，只是音量变了
- 目标用 0.95 而不是 1.0，是留一点余量：后面的处理如果把数值推过 1，就会削波（clipping），听起来是爆音

坑：全是 0 的静音片段，峰值是 0。`0.95 / 0` 是 inf，`0 * inf` 是 nan。数据集里混进一条静音文件，就能让训练出现 nan。所以峰值为 0 时要原样返回。
--- code
wav = torch.tensor([0.05, -0.2, 0.1])
peak = wav.abs().max()
print("峰值:", round(peak.item(), 3))
out = wav * (0.95 / peak)
print("归一化后:", [round(v, 4) for v in out.tolist()])
print("新峰值:", round(out.abs().max().item(), 4))

silence = torch.zeros(3)
print("静音也直接除:", (silence * (0.95 / silence.abs().max())).tolist())

@@ concept
title: 分帧：用 unfold 把波形切成一段一段
--- body
声音一直在变，但在 20～60 毫秒这么短的时间里，可以看成基本不变。所以处理音频的第一步通常是 **分帧**：一个长度为 `size` 的窗口在波形上滑动，每次往前挪 `step` 个点（这个 step 就是 hop）。

`wav.unfold(0, size, step)` 一步做完：在第 0 维上，每隔 `step` 个点取一段长度为 `size` 的片段，排成一个新维度。

- 输入 `(T,)` → 输出 `(帧数, size)`
- 第 i 帧是 `wav[i*step : i*step + size]`
- 帧数 = `(T - size) // step + 1`，最后凑不满一帧的尾巴丢掉
- 返回的是 view（视图）：不复制数据，所以很快；写 Python 循环一帧帧切，长音频上会慢很多

例子：T=8、size=3、step=2 → (8 - 3) // 2 + 1 = 3 帧，起点是 0、2、4，最后的 7 被丢掉。

记住这个帧数公式：它就是下一张卡里 STFT 在 `center=False` 时的帧数。
--- code
wav = torch.arange(8.)
frames = wav.unfold(0, 3, 2)
print(frames)
print("帧数公式:", (8 - 3) // 2 + 1)

big = torch.randn(16000).unfold(0, 400, 160)   # 16kHz: 25 毫秒一帧, 10 毫秒一跳
print(tuple(big.shape), "=", (16000 - 400) // 160 + 1, "帧")

@@ concept
title: STFT：频点数和帧数
--- body
分帧之后，对每一帧做一次 FFT（快速傅里叶变换），就知道这一帧里「每个频率有多强」。所有帧排在一起，就是 **STFT**（短时傅里叶变换）。`torch.stft` 一步做完分帧、加窗、FFT。

三个参数：

- `n_fft`：每帧多少个点，比如 1024
- `hop_length`：相邻两帧差多少个点，比如 256
- `window`：每帧先乘一个窗函数，把帧的两头压到 0，常用 `torch.hann_window(n_fft)`

输出 shape 是 `(频点数, 帧数)`；输入带 batch 时是 `(B, 频点数, 帧数)`。

- **频点数** = `n_fft // 2 + 1`。每个频点宽 `sr / n_fft` Hz，第 k 个频点对应 `k * sr / n_fft` Hz
- **帧数，center=True**（默认）：两头各补 `n_fft // 2` 个点再分帧，帧数 = `T // hop + 1`
- **帧数，center=False**：不补，和 unfold 一样，帧数 = `(T - n_fft) // hop + 1`

例子：T=16000、n_fft=512、hop=128 → 频点数 257，center=True 时 126 帧，center=False 时 122 帧。注意 center=True 时帧数和 n_fft 无关，只看 hop。

要加 `return_complex=True`，输出是复数张量（`complex64`）。每个复数的模 `.abs()` 就是这个频率有多强，得到 **幅度谱**（magnitude spectrogram），它是普通的实数张量。
--- code
sr = 16000
t = torch.arange(sr) / sr                      # 1 秒的时间轴
tone = torch.sin(2 * math.pi * 1000 * t)       # 1000 Hz 的纯音
n_fft, hop = 512, 128
spec = torch.stft(tone, n_fft, hop, window=torch.hann_window(n_fft), return_complex=True)
print("复数谱:", tuple(spec.shape), spec.dtype)
mag = spec.abs()
print("幅度谱:", tuple(mag.shape), mag.dtype)
print("第 60 帧最强的频点:", mag[:, 60].argmax().item(), " 理论值 1000 * 512 / 16000 =", 1000 * n_fft / sr)

nc = torch.stft(tone, n_fft, hop, window=torch.hann_window(n_fft), return_complex=True, center=False)
print("center=False:", tuple(nc.shape))

@@ concept
title: 幅度和相位：幅度谱丢掉了什么
--- body
STFT 输出的每个格子是一个复数 `a + bi`。把它想成平面上的一支箭头：

- **幅度**（magnitude）= 箭头的长度 = `z.abs()` = √(a² + b²)。表示这个频率有多强，永远 ≥ 0
- **相位**（phase）= 箭头的角度 = `z.angle()`。表示这个频率的波在这一帧里「从哪里开始」
- `z.real` 只是实部 a，既不是幅度也不是相位，还可能是负数。想要幅度却写成 `.real`，是很常见的 bug

幅度 + 相位 = 完整信息。`torch.polar(幅度, 相位)` 能把复数拼回来，再用 `torch.istft`（STFT 的逆运算）变回波形，误差几乎为 0。

可是 mel 谱、log-mel 都只从幅度算出来，相位被扔掉了。下面的实验把相位全设成 0 再重建：相对误差大约是 1.0，也就是误差和原信号本身一样大，波形面目全非。所以 TTS 模型预测出 mel 谱之后，还需要一个 **vocoder**（声码器）把相位「猜」回来，才能得到能播放的波形（Day 12 会用到）。
--- code
torch.manual_seed(1)
wav = torch.randn(4096)
win = torch.hann_window(512)
spec = torch.stft(wav, 512, 128, window=win, return_complex=True)
mag, phase = spec.abs(), spec.angle()
print("spec:", tuple(spec.shape), spec.dtype)

z = torch.tensor(-3 + 4j)
print("一个格子 -3+4j: real =", z.real.item(), " abs =", z.abs().item())

def rel_err(x):
    return (((x - wav) ** 2).mean() / (wav ** 2).mean()).item()

full = torch.istft(torch.polar(mag, phase), 512, 128, window=win, length=4096)
print(f"幅度 + 相位重建, 相对误差: {rel_err(full):.1e}")

no_phase = torch.istft(mag.to(torch.complex64), 512, 128, window=win, length=4096)
print(f"只用幅度 (相位全 0) 重建, 相对误差: {rel_err(no_phase):.2f}")

@@ concept
title: mel 刻度和 mel 滤波器组
--- body
人耳对低频的变化很敏感：100 Hz 和 200 Hz 听起来差很多；7900 Hz 和 8000 Hz 却几乎听不出区别。**mel 刻度** 把 Hz 换成「听起来的距离」：

`mel = 2595 * log10(1 + f / 700)`

- 0 Hz → 0 mel，1000 Hz → 大约 1000 mel
- 100→200 Hz 差 133 mel；7900→8000 Hz 只差 13 mel
- 低频被「拉开」，高频被「挤紧」

**mel 滤波器组**（mel filterbank）是一个矩阵 `fb`，shape `(n_mels, n_freq)`，比如 `(80, 513)`。每一行是一个三角形的滤波器。80 个三角形在 mel 刻度上等间距排开，换回 Hz 看：低频的三角形又窄又密，高频的又宽又稀。

把 513 个频点压成 80 个 mel 频带，只要一次矩阵乘法：

- `fb @ mag`：`(80, 513) @ (513, 63)` → `(80, 63)`
- mag 带 batch 时：`(80, 513) @ (B, 513, 63)` → `(B, 80, 63)`，`@` 会自动广播

实际项目里 fb 用现成函数生成（`torchaudio.functional.melscale_fbanks` 或 `librosa.filters.mel`）。注意方向：librosa 返回的和这里一样是 `(n_mels, n_freq)`，torchaudio 返回的却是转置 `(n_freq, n_mels)`，要先 `.T` 再 `fb @ mag`。下面手写一个，看清它长什么样。
--- code
def hz_to_mel(f):
    return 2595 * math.log10(1 + f / 700)

for f in [100, 200, 1000, 7900, 8000]:
    print(f, "Hz ->", round(hz_to_mel(f)), "mel")

sr, n_fft, n_mels = 16000, 1024, 80
edges_mel = torch.linspace(0, hz_to_mel(sr / 2), n_mels + 2)   # mel 上等间距
edges_hz = 700 * (10 ** (edges_mel / 2595) - 1)                # 换回 Hz
freqs = torch.linspace(0, sr / 2, n_fft // 2 + 1)              # 513 个频点各自的 Hz
fb = torch.zeros(n_mels, freqs.numel())
for i in range(n_mels):
    lo, mid, hi = edges_hz[i], edges_hz[i + 1], edges_hz[i + 2]
    rise = (freqs - lo) / (mid - lo)
    fall = (hi - freqs) / (hi - mid)
    fb[i] = torch.clamp(torch.minimum(rise, fall), min=0)      # 三角形

print("fb:", tuple(fb.shape))
print("第 0 个滤波器盖住几个频点:", (fb[0] > 0).sum().item())
print("第 79 个滤波器盖住几个频点:", (fb[79] > 0).sum().item())
mag = torch.rand(2, 513, 63)
print("fb @ mag:", tuple((fb @ mag).shape))

@@ concept
title: log-mel：取 log，再加 eps
--- body
mel 谱里的数值跨度很大：安静处可能是 0.001，响的地方可能是 1000，差了一百万倍。直接喂给神经网络，大数会压倒一切。而且人耳对响度的感觉本来就接近对数：能量翻 10 倍，听起来只是「响了一档」。

所以几乎所有语音模型都用 **log-mel**：对 mel 取 log。取完 log，一百万倍的差距只剩 13.8。

坑：完全静音的地方 mel = 0，`log(0) = -inf`。一个 -inf 进了网络，loss 就变成 nan。所以要加一个很小的数 **eps**：

`log_mel = log(fb @ mag + eps)`，常用 eps = 1e-5。

加了 eps，完全静音 = log(1e-5) ≈ -11.5。这就是 log-mel 的「静音地板」。后面补 padding 时用的 -11.5 就是从这里来的。

完整链路：波形 `(T,)` → 幅度谱 `(n_freq, 帧数)` → `fb @` → mel `(n_mels, 帧数)` → `log(· + eps)` → log-mel `(n_mels, 帧数)`。
--- code
mel = torch.tensor([0.0, 0.001, 1.0, 1000.0])
print("不加 eps:", [round(v, 2) for v in torch.log(mel).tolist()])
print("加 eps  :", [round(v, 2) for v in torch.log(mel + 1e-5).tolist()])
print("静音地板 log(1e-5) =", round(math.log(1e-5), 2))
print("最大 / 最小 (线性):", 1000.0 / 0.001)
print("最大 - 最小 (log)  :", round(math.log(1000.0) - math.log(0.001), 1))

@@ concept
title: 进模型之前：通道维、padding 和 mask
--- body
**mel 谱就是一张单通道的图**：高 = n_mels，宽 = 帧数。图像模型要的输入是 `(B, C, H, W)`，所以 `(B, n_mels, 帧数)` 只要在第 1 维加一个通道维：`mel.unsqueeze(1)` → `(B, 1, n_mels, 帧数)`。然后 Day 8 用过的 `nn.Conv2d` 原样能用。

**变长**：一个 batch 里的音频长短不一，帧数各不相同，但张量必须是规整的长方体。做法和文本的 padding 一样：

- 找出最长的帧数 Tmax，建一个 `(B, n_mels, Tmax)` 的张量，全部先填成 pad 值
- 把每条 mel 拷到左边，右边剩下的就是 padding
- pad 值用 -11.5（log-mel 的静音地板），而不是 0：log-mel 里的 0 表示能量为 1，是「有声音」
- 再做一个 **mask**，shape `(B, Tmax)`：真实帧是 1，padding 帧是 0。之后算 loss、做 attention 时靠它忽略 padding

`F.pad(x, (左, 右), value=v)` 能在最后一维的两边补值；`arange < lengths` 能一次做出整个 mask。

下面的代码用 0.5 秒、n_fft=512、hop=128、n_mels=64 走一遍整条 shape 链。
--- code
wav = torch.randn(8000)                         # 0.5 秒, 16kHz
mag = torch.stft(wav, 512, 128, window=torch.hann_window(512), return_complex=True).abs()
fb = torch.rand(64, 257)                        # 假的滤波器组, 只看 shape
log_mel = torch.log(fb @ mag + 1e-5)
x = log_mel.unsqueeze(0).unsqueeze(0)           # 加 batch 维和通道维
print(tuple(wav.shape), "->", tuple(mag.shape), "->", tuple(log_mel.shape), "->", tuple(x.shape))
print("Conv2d 输出:", tuple(nn.Conv2d(1, 8, 3, padding=1)(x).shape))

short = torch.zeros(2, 3)                       # 一条 3 帧的 mel (n_mels=2)
print(F.pad(short, (0, 5 - 3), value=-11.5))    # 右边补 2 帧
lengths = torch.tensor([3, 5])
print((torch.arange(5)[None, :] < lengths[:, None]).long())

写 `n_frames(n_sample, n_fft, hop_length, center=True)`，返回 `torch.stft` 会产生的帧数（int）。不许调用 `torch.stft`，用公式算。

--- options
- 几乎一样：相位只影响音色的细节
- 面目全非：相对误差很大，因为相位决定了各个频率分量怎么叠加

--- solution
def pad_mels(mels, pad_value=-11.5):
    B = len(mels)
    n_mels = mels[0].size(0)
    Tmax = max(m.size(1) for m in mels)
    batch = torch.full((B, n_mels, Tmax), pad_value)
    mask = torch.zeros(B, Tmax, dtype=torch.long)
    for i, m in enumerate(mels):
        T = m.size(1)
        batch[i, :, :T] = m
        mask[i, :T] = 1
    return batch, mask

def pad_mels(mels, pad_value=-11.5):
    B = len(mels)
    n_mels = mels[0].size(0)
    Tmax = max(m.size(1) for m in mels)
    batch = torch.full((B, n_mels, Tmax), pad_value)
    mask = torch.zeros(B, Tmax, dtype=torch.long)
    for i, m in enumerate(mels):
        T = m.size(1)
        batch[i, :, :T] = m
        mask[i, :T] = 1
    return batch, mask
