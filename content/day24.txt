@@ concept
title: 一次实验要记下的六样东西
--- body
三个月后，有人问你：「线上那个模型是怎么训出来的？能再训一个一样的吗？」答不上来，这个模型就没法修，也没法改，更说不清它为什么好。

所以每次训练结束，都要留一份**实验记录**（run record）。它要回答一个问题：用同样的东西，能不能再得到同样的结果？至少要记六样：

1. **config**：所有超参数（学习率、batch size、epoch 数、模型大小……）。
2. **git commit**：代码的版本，一串 40 个字符的十六进制数（`git rev-parse HEAD` 打印的就是它）。如果还有没提交的改动（working tree 是 dirty 的），这个 commit 就不等于你跑的代码。要么先提交，要么把 diff 一起存下来。
3. **数据指纹**：数据文件内容的 sha256（下一张卡讲）。文件名没变，内容可能早就被人改过。
4. **seed**：随机种子。
5. **库版本**：Python、torch、numpy 的版本。升级 torch 之后结果变了，是常有的事。
6. **metrics**：这次训练的结果（val_loss、val_acc……）。

再加一个 `run_id`，给这次实验起个名字。整份记录存成一个 JSON 文件，和 checkpoint 放在一起。

今天的练习里，git commit 是当作字符串传进来的，不用真的去跑 git。
--- code
import platform
import numpy as np

record = {
    "run_id": "run-01",
    "config": {"lr": 0.001, "batch_size": 32, "epochs": 10},
    "git_commit": "3f9a2c1d0b7e4f6a8c5d2e1f0a9b8c7d6e5f4a3b",
    "data_fingerprint": "（下一张卡讲怎么算）",
    "seed": 42,
    "versions": {"python": platform.python_version(), "torch": torch.__version__, "numpy": np.__version__},
    "metrics": {"val_loss": 0.47, "val_acc": 0.842},
}
for key, value in record.items():
    print(f"{key:17s}", value)
print("git commit 有", len(record["git_commit"]), "个字符")

@@ concept
title: 数据指纹：用 sha256 认出同一份数据
--- body
sha256 是一种**哈希函数**：把任意多的字节变成一个 64 个字符的十六进制字符串（叫哈希值）。它有两个性质，正好拿来当数据的「指纹」：

- 同样的字节，永远得到同样的哈希值。换台机器、换个文件名都一样。
- 字节哪怕只改了一个，哈希值就完全变了。

Python 自带 `hashlib`：

```
h = hashlib.sha256()
h.update(b"some bytes")    # 可以分好几次 update，结果和一次喂进去一样
h.hexdigest()              # 64 个字符
```

读文件要用二进制模式 `"rb"`（哈希算的是字节），而且分块读，比如每次 1 MB。这样 10 GB 的文件也不用一次装进内存。

一份数据常常是好几个文件，怎么合成一个指纹？直接按顺序把内容拼起来算，有个问题：`os.listdir` 返回文件的顺序，在不同机器上可能不一样。同一份数据，就会得到不同的指纹。

办法：**先给每个文件单独算哈希，把这些哈希排好序，用换行连起来，再算一次 sha256。** 这样文件的顺序、文件名、放在哪个文件夹，都不影响结果，只有内容算数。
--- code
import hashlib

a, b = b"cat,1\n", b"dog,0\n"                     # 两个「文件」的内容
print("a 的 sha256:  ", hashlib.sha256(a).hexdigest()[:16], "...（一共 64 个字符）")
print("a 多一个空格: ", hashlib.sha256(b"cat,1 \n").hexdigest()[:16], "...")
print("直接拼起来算，a+b 和 b+a 一样吗:", hashlib.sha256(a + b).hexdigest() == hashlib.sha256(b + a).hexdigest())

def fingerprint(contents):
    hashes = sorted(hashlib.sha256(c).hexdigest() for c in contents)
    return hashlib.sha256("\n".join(hashes).encode("utf-8")).hexdigest()

print("先各算各的、排序、再合起来，顺序还有影响吗:", fingerprint([a, b]) != fingerprint([b, a]))

@@ concept
title: 种子：torch、numpy、random 要分别设
--- body
一次训练里，常常有三个互不相干的随机数来源：

- **torch**：初始化权重、Dropout、`torch.randn`。用 `torch.manual_seed(seed)` 设。
- **numpy**：很多数据代码用 `np.random.permutation` 打乱顺序、切分数据集。用 `np.random.seed(seed)` 设。
- **Python 自带的 random**：数据增强里常见的 `random.random() < 0.5`。用 `random.seed(seed)` 设。

它们各有各的状态。**只设 torch 的种子，numpy 和 random 完全不受影响。** 这时 numpy 打乱出来的顺序，取决于这个进程之前有谁用过 numpy 的随机数。同一个 seed，两次运行的数据顺序不一样，结果自然也不一样。

两条规则：

1. 训练开始时，三个种子都设上，而且只设一次。要是在每个 epoch 里重新设，每个 epoch 的数据顺序就一模一样，打乱等于没打乱。
2. 把 seed 写进实验记录。

numpy 还有一种更干净的写法：`rng = np.random.default_rng(seed)`，再用 `rng.permutation(n)`。这是一个只属于你的生成器，别的代码动不了它。

GPU 上有些算子本身就不确定（`cudnn.benchmark`、确定性算法），第 18 天讲过。今天只管种子。
--- code
import numpy as np

def shuffled(seed, also_numpy):
    torch.manual_seed(seed)
    if also_numpy:
        np.random.seed(seed)
    return np.random.permutation(6).tolist()

np.random.seed(1); a = shuffled(0, also_numpy=False)    # 模拟：之前有别的代码用过 numpy 的随机数
np.random.seed(2); b = shuffled(0, also_numpy=False)
print("只设了 torch 的种子:", a, b, "一样吗:", a == b)
np.random.seed(1); a = shuffled(0, also_numpy=True)
np.random.seed(2); b = shuffled(0, also_numpy=True)
print("numpy 也设了种子:  ", a, b, "一样吗:", a == b)
rng = np.random.default_rng(0)
print("自己的生成器 default_rng(0):", rng.permutation(6).tolist())

@@ concept
title: 存成 JSON：只认几种简单类型
--- body
实验记录、注册表，都存成 JSON：纯文本，人能直接读，任何语言都能解析，还能用 git diff 比较两个版本。

- `json.dump(obj, f)` 写进文件，`json.load(f)` 从文件读回来。
- 带 s 的 `json.dumps(obj)` / `json.loads(text)` 操作的是字符串，不是文件。

JSON 只认这几种类型：dict、list、str、int、float、True / False、None。三个常见的坑：

- **张量和 numpy 的 float32 存不进去**，会报 `TypeError: Object of type Tensor is not JSON serializable`。指标常常是 `loss.mean()` 这种 0 维张量，存之前用 `float(v)` 转成 Python 数字。
- **dict 的 key 只能是字符串。** 存进去 `{1: ...}`，读回来是 `{"1": ...}`，`1 in d` 就成了 False。所以今天的注册表把版本号放在 list 里，不拿它当 key。
- 元组读回来变成 list。

两个好习惯：`indent=2` 让文件分行缩进，好读；`sort_keys=True` 让 key 的顺序固定，两个文件才好逐行比较。打开文件时写明 `encoding="utf-8"`，不然 Windows 可能用别的编码。
--- code
import json
import numpy as np

metrics = {"val_loss": torch.tensor(0.25), "val_acc": np.float32(0.875)}
try:
    json.dumps(metrics)
except TypeError as e:
    print("存不进去:", e)
clean = {k: float(v) for k, v in metrics.items()}
print("转成 float 以后:", json.dumps(clean, sort_keys=True))
back = json.loads(json.dumps({"versions": {1: "a", 2: "b"}}))
print("int 当 key，读回来变成了:", list(back["versions"]), "  1 in 它:", 1 in back["versions"])
print(json.dumps({"lr": 0.001, "betas": (0.9, 0.95)}, indent=2))

@@ concept
title: 比较实验：谁最好，配置差在哪
ref: day24
--- body
调参时你会跑很多次实验，每次的记录都是一个 JSON 文件。比较它们，只要两个动作。

**1. 按一个指标挑最好的。** 先想清楚方向：accuracy 越大越好，用 `max`；loss 越小越好，用 `min`。不同的指标，可能挑出不同的「最好」。

`max(runs, key=lambda r: r["metrics"]["val_acc"])` 返回的是**整条记录**，不只是那个数。`key=` 告诉 `max` 拿什么来比；`lambda r: ...` 是一个只有一行的小函数。

崩掉的实验（比如 loss 变成 nan，还没评估就停了）没有这个指标。要跳过它：不能让它报错，也不能把它当成 0 分。

**2. 看两次实验的 config 差在哪。** 把两个 config 的所有 key 合在一起（`set(a) | set(b)`），一个一个比较值。只在一边有的 key（比如后来新加的 warmup），另一边记成 None。`d.get(key)` 在 key 不存在时正好返回 None。

还要注意：只有数据指纹一样的实验，分数才能直接比。换了一份测试集，分数高了，可能只是题目变容易了。
--- code
runs = sample_runs()
for r in runs:
    print(r["run_id"], " lr =", r["config"]["lr"], " batch =", r["config"]["batch_size"], " metrics =", r["metrics"])
done = [r for r in runs if "val_acc" in r["metrics"]]          # 跳过崩掉的 run-03
print("val_acc 最高: ", max(done, key=lambda r: r["metrics"]["val_acc"])["run_id"])
print("val_loss 最低:", min(done, key=lambda r: r["metrics"]["val_loss"])["run_id"])
a, b = runs[1]["config"], runs[3]["config"]
print("两个 config 的全部 key:", sorted(set(a) | set(b)))
print("warmup:", a.get("warmup"), "->", b.get("warmup"))

@@ concept
title: 模型注册表：注册、上线、历史
ref: day24
--- body
模型越训越多：哪个在线上？上一个是谁？它是哪次实验训出来的？**模型注册表**（model registry）就是回答这些问题的地方。MLflow、Weights & Biases 这些工具都有这个功能。今天我们用一个 JSON 文件自己做一个最小的：

```
{"versions": [{"version": 1, "run_id": "run-01", "metrics": {"val_acc": 0.842}},
              {"version": 2, "run_id": "run-04", "metrics": {"val_acc": 0.875}}],
 "production": 2,
 "history": [2]}
```

- **register（注册）**：加一个新版本。版本号 1、2、3 往上加，记下它来自哪次实验（run_id）和它的指标。注册不等于上线。
- **promote（上线）**：把一个版本设成 `production`，同时追加到 `history`（上线过的版本，按时间顺序）。
- **production**：线上现在是哪个版本，还没有就是 None。

一个重要的写法：**每个方法都是「读文件 → 改 → 写回文件」，不在内存里留状态。** 训练脚本、上线脚本、推理服务是不同的进程，它们只能通过这个文件看到同一个状态。

写文件要「先写临时文件，再 `os.replace`」，写到一半崩了也不会留下坏文件（第 20 天讲过）。今天的 `JsonStore` 已经写好了 `self._load()` 和 `self._save(data)`：文件还不存在时，`_load()` 返回一个空的注册表。
--- code
import json
import tempfile

with tempfile.TemporaryDirectory(ignore_cleanup_errors=True) as folder:
    reg = BasicRegistry(folder)
    print("注册，得到版本号:", reg.register("run-01", {"val_acc": 0.842}), reg.register("run-04", {"val_acc": 0.875}))
    print("线上:", reg.production())
    reg.promote(2)
    print("promote(2) 之后，新建一个对象来看，线上:", BasicRegistry(folder).production())
    print(json.dumps(reg._load()))

@@ concept
title: 上线门槛和回滚
ref: day24
--- body
**门槛（gate）**：新版本要上线，它的评估指标不能比线上的差。不然一次手滑，更差的模型就上线了。规则是：

- 线上还没有模型：直接上。
- 看清方向：`higher_is_better=True`（比如 accuracy）时，新的比旧的**小**才算更差；`False`（比如 loss）时，新的比旧的**大**才算更差。
- 一样好，可以上。
- 更差：`raise ValueError(...)`，文件一个字都不改。报错信息里写上两个数，方便排查。

**回滚（rollback）**：新版本上线后出了问题（投诉变多、延迟变高），第一件事是回到上一个版本，让线上先恢复正常，再慢慢查原因。有了 `history`，回滚就是：去掉 history 的最后一个，把 production 设成新的最后一个。history 里不到 2 个版本，就没有可回的，`raise ValueError`。

注意：**回滚不过门槛。** 上一个版本的分数通常比现在的低（不然当初也不会换掉它），拿门槛去拦它，回滚就永远做不成。出事的时候，要的是一步回到「已知能用」的状态。

真实的系统在上线前还会做更多检查，比如先只放一小部分流量（canary），第 25 天讲。
--- code
import tempfile

with tempfile.TemporaryDirectory(ignore_cleanup_errors=True) as folder:
    reg = Registry(folder)                       # 比 val_acc，越大越好
    for run_id, acc in [("run-01", 0.842), ("run-04", 0.875), ("run-05", 0.861)]:
        reg.register(run_id, {"val_acc": acc})
    reg.promote(1)
    reg.promote(2)
    try:
        reg.promote(3)
    except ValueError as e:
        print("v3 被拒绝:", e)
    print("线上:", reg.production(), " history:", reg._load()["history"])
    print("回滚到:", reg.rollback(), " history:", reg._load()["history"])

title: 模型卡：给用模型的人看的说明书
ref: day24
--- body
实验记录是写给**自己**看的：怎么复现。**模型卡**（model card）是写给**用这个模型的人**看的：它能干什么，不能干什么，什么情况下会出错。别的团队要接入你的模型，产品经理要决定能不能上线，都先看它。

一张最小的模型卡有这几节：

1. **名字和版本**：和注册表里的版本号一致。
2. **用途**：设计来做什么，比如「给英文商品评论分正面 / 负面」。
3. **不适合的用途**：明确说不该用在哪，比如「其他语言」「医疗、法律决定」。
4. **评估结果**：哪些指标，多少分。除了总分，最好还有分组的分数（比如长评论单独算一个），平均分会把弱点藏起来。
5. **训练数据**：数据是什么，加上数据指纹。
6. **怎样复现**：git commit、seed、库版本，都从实验记录里来。
7. **局限和风险**：已知的问题，比如「讽刺的句子经常判错」。

模型卡里的数字要**用代码从实验记录里填**，不要手抄。手抄的数字，迟早和真实的对不上。
--- code
rec = sample_runs()[3]
lines = ["# 模型卡：review-sentiment v2", "## 评估结果"]
lines += [f"- {k}: {v:.4f}" for k, v in sorted(rec["metrics"].items())]
lines += ["## 怎样复现", "- git commit: " + rec["git_commit"], "- seed: " + str(rec["seed"])]
print("\n".join(lines))

title: 分两次喂、换个顺序，哈希还一样吗
level: 1
cards: 数据指纹：用 sha256 认出同一份数据
--- context
数据指纹整个建立在 sha256 的两个性质上：分块喂进去和一次喂进去结果一样（所以能分块读大文件），字节顺序一变结果就变（所以多个文件要先排序）。先亲眼确认这两点。
--- prompt
读下面的代码，写出它打印的三行。
--- code
import hashlib
h = hashlib.sha256()
h.update(b"cat,1\n")
h.update(b"dog,0\n")                          # 分两次喂进去
one_go = hashlib.sha256(b"cat,1\ndog,0\n").hexdigest()
print(h.hexdigest() == one_go)
print(len(one_go))
swapped = hashlib.sha256(b"dog,0\ncat,1\n").hexdigest()
print(one_go == swapped)
--- explain
第一行 `True`：sha256 可以分好几次 `update`，结果和把所有字节一次喂进去完全一样。所以大文件可以一块一块地读、一块一块地 update，不用一次装进内存。

第二行 `64`：`hexdigest()` 是 64 个十六进制字符（256 位，每个字符表示 4 位）。

第三行 `False`：两行内容一样，只是顺序反了，拼出来的字节就不一样，哈希也就不一样。所以多个文件合成一个指纹时，要先各自算哈希、排好序，再合起来。
--- hints
- `update` 两次，喂进去的字节连起来是什么？和 `one_go` 用的字节比一比。
- 哈希只认字节。`b"cat,1\ndog,0\n"` 和 `b"dog,0\ncat,1\n"` 是同样的字节吗？

import hashlib

def file_sha256(path):
    """path -> 64 个字符的十六进制字符串"""
    h = hashlib.sha256()
    with open(path, "rb") as f:                  # 二进制模式：原样读字节
        while True:
            chunk = f.read(1 << 20)              # 每次 1 MB
            if not chunk:                        # 读到空的 b""：文件结束
                break
            h.update(chunk)
    return h.hexdigest()

import hashlib

def data_fingerprint(paths):
    """一组文件 -> 一个 64 个字符的指纹，和文件顺序、文件名都无关"""
    hashes = sorted(file_sha256(p) for p in paths)          # 排序：顺序就不算数了

    return hashlib.sha256(joined).hexdigest()

- 记录里的 config 是原来那个 dict 本身（不是拷贝），后来扫参的代码又改了它

前三个都会让记录「说谎」：

1. 有没提交的改动时，commit 对应的代码不是你真正跑的代码。要么先提交，要么把 `git diff` 一起存下来。
2. 记录里存的是同一个 dict，外面一改，记录就跟着变，记下的就不是当时的配置了。要存 `copy.deepcopy(config)`。

def best_run(runs, metric, higher_is_better=True):
    """返回 metric 最好的那条记录；没有这个指标的记录跳过"""
    have = [r for r in runs if metric in r["metrics"]]      # 跳过崩掉的实验
    if not have:
        raise ValueError(f"没有一条记录有指标 {metric!r}")
    pick = max if higher_is_better else min
    return pick(have, key=lambda r: r["metrics"][metric])


def config_diff(a, b):
    """{key: (a 的值, b 的值)}，只放值不一样的 key；缺的一边是 None"""
    diff = {}
    for k in sorted(set(a) | set(b)):                       # 两边所有的 key
        if a.get(k) != b.get(k):                            # 缺的一边，get 返回 None
            diff[k] = (a.get(k), b.get(k))
    return diff

class Registry(JsonStore):
    def register(self, run_id, metrics):
        """加一个新版本，返回版本号（1, 2, 3, ...）"""
        data = self._load()
        version = len(data["versions"]) + 1
        data["versions"].append({"version": version, "run_id": run_id, "metrics": metrics})
        self._save(data)
        return version

    def production(self):
        """线上的版本号，没有就是 None"""
        return self._load()["production"]

    def promote(self, version):
        """把 version 设成线上版本，并记进 history"""
        data = self._load()
        if not any(v["version"] == version for v in data["versions"]):
            raise ValueError(f"没有版本 {version}")
        data["production"] = version
        data["history"].append(version)
        self._save(data)

class Registry(BasicRegistry):
    def promote(self, version):
        """不比线上差才能上线；更差就 raise ValueError"""
        new = self.get(version)["metrics"][self.metric]
        data = self._load()
        current = data["production"]
        if current is not None:
            old = self.get(current)["metrics"][self.metric]
            worse = new < old if self.higher_is_better else new > old
            if worse:
                raise ValueError(f"v{version} 的 {self.metric}={new}，比线上 v{current} 的 {old} 差")
        data["production"] = version
        data["history"].append(version)
        self._save(data)

    def rollback(self):
        """回到上一个上线过的版本，返回它的版本号"""
        data = self._load()
        if len(data["history"]) < 2:
            raise ValueError("没有可以回滚的版本")
        data["history"].pop()                          # 去掉出问题的那个
        data["production"] = data["history"][-1]       # 回到上一个，不过门槛
        self._save(data)
        return data["production"]

class Registry(BasicRegistry):
    def promote(self, version):
        new = self.get(version)["metrics"][self.metric]
        data = self._load()
        current = data["production"]
        if current is not None:
            old = self.get(current)["metrics"][self.metric]
            worse = new < old if self.higher_is_better else new > old
            if worse:
                raise ValueError(f"v{version} 的 {self.metric}={new}，比线上 v{current} 的 {old} 差")
        data["production"] = version
        data["history"].append(version)
        self._save(data)

    def rollback(self):
        data = self._load()
        if len(data["history"]) < 2:
            raise ValueError("没有可以回滚的版本")
        data["history"].pop()                          # 去掉出问题的那个
        data["production"] = data["history"][-1]       # 回到上一个，不过门槛
        self._save(data)
        return data["production"]

    with tempfile.TemporaryDirectory(ignore_cleanup_errors=True) as folder:
        reg = _setup(folder, [0.80, 0.85])
        reg.promote(1)
        reg.promote(2)
        try:
            back = reg.rollback()
        except ValueError as e:
            true(False, f"rollback 报错了：{e}。回滚不过门槛：上一个版本的分数通常比现在的低。直接改 production 和 history，不要调用 promote。")
        true(back == 1, f"rollback() 应该返回回到的版本 1，你返回的是 {back!r}")
        other = Registry(folder)
        true(other.production() == 1, "rollback 之后线上应该是 v1（新建的 Registry 也要看得到）")
        history = other._load()["history"]
    true(history == [1], f"rollback 之后 history 应该是 [1]，现在是 {history}")

@check("没有可以回滚的版本：raise ValueError")
def _():
    with tempfile.TemporaryDirectory(ignore_cleanup_errors=True) as folder:
        reg = _setup(folder, [0.80, 0.85])
        reg.promote(1)
        true(_refused(reg.rollback), "只上线过 v1，没有更早的版本，rollback() 应该 raise ValueError")
        true(Registry(folder).production() == 1, "回滚失败时，线上应该还是 v1")
--- hints
- promote：先比较，通过了才改 data。
- rollback：pop 最后一个，production 取新的最后一个。
