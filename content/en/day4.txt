@@ concept
title: The big picture: shapes from start to end
ref: day4
--- body
Today you write a GPT from scratch. First the whole picture; the next cards take it apart piece by piece.

A GPT does one thing: it reads a sequence of tokens and, at **every position**, guesses the next token.

Every shape today uses these letters:
- B: batch size (how many sequences at once)
- T: sequence length (tokens per sequence)
- C: the vector length of each token (`n_embd` in the code)
- V: vocabulary size (`vocab_size`)
- nh: number of heads (`n_head`); hs: the size of each head, hs = C / nh

How the data flows:
1. `idx` (B, T): integer token ids
2. `wte(idx) + wpe(pos)` → `x` (B, T, C): token embedding plus position embedding
3. L Blocks. Each Block takes (B, T, C) and returns (B, T, C)
4. `ln_f`, then `lm_head` → `logits` (B, T, V): a raw score for every word in the vocabulary, at every position (before softmax)
5. `cross_entropy` against the targets → one number: the loss

The key point: **a Block does not change the shape**. So you can stack as many Blocks as you like. GPT-2 small stacks 12; GPT-3 stacks 96.

Today's order: causal mask → attention → multiple heads → Block → GPT → parameter count → generation. The code below uses the GPT you will have written by the end of today. Treat it as a black box for now and just watch the shapes.
--- code
torch.manual_seed(0)
m = GPT(vocab_size=10, block_size=8, n_layer=2, n_head=4, n_embd=16)
idx = torch.randint(0, 10, (2, 5))          # B=2 sequences, T=5 tokens each
print("idx           ", tuple(idx.shape), "sequence 0:", idx[0].tolist())

x = m.wte(idx) + m.wpe(torch.arange(5))     # token embedding + position embedding
print("embedded      ", tuple(x.shape))
for i, block in enumerate(m.h):
    x = block(x)
    print(f"after Block {i} ", tuple(x.shape))  # same shape

logits = m.lm_head(m.ln_f(x))
print("logits        ", tuple(logits.shape))  # 10 scores per position
print("next-token guess at each position of sequence 0:", logits[0].argmax(-1).tolist())

@@ concept
title: Causal mask: look only at the past
--- body
A language model is trained on whole sequences at once, and **every position** guesses the next token. Position 2 has to guess token 3. If position 2 could "see" token 3, it would just copy the answer and learn nothing.

So attention has one rule: **position i may look at positions 0…i (the past and itself), never at anything after i (the future)**. That rule is the causal mask.

Attention computes a (T, T) matrix of scores:
- row i = position i, the one that is looking (the query)
- column j = position j, the one being looked at (the key)
- allowed: j ≤ i, the diagonal and everything below-left of it. That is the lower triangle → `torch.tril`

Two ways to write it, same result:
- **additive mask**: 0 where allowed, `-inf` where forbidden; add it to the scores
- **masked_fill**: `scores.masked_fill(mask == 0, float("-inf"))`, where the mask has 1 = allowed and 0 = forbidden

Why `-inf`? Softmax computes e to the power of each score, and e^(-inf) = 0. So a masked cell gets a weight of **exactly 0**, and the remaining weights still add up to 1.

With T positions, T·(T−1)/2 cells are masked: 6 cells when T=4.

The mask usually has shape (1, 1, T, T). Attention scores are (B, nh, T, T); the two leading 1s broadcast over the batch and the heads, so one mask serves every sequence and every head.
--- code
T = 4
allowed = torch.tril(torch.ones(T, T))      # 1 = may look, 0 = may not
print(allowed)

bias = torch.zeros(T, T).masked_fill(allowed == 0, float("-inf"))
print(bias)
print("masked cells:", int(torch.isinf(bias).sum()), "  T*(T-1)/2 =", T * (T - 1) // 2)

torch.manual_seed(0)
scores = torch.randn(T, T)                  # some arbitrary scores
att = (scores + bias).softmax(dim=-1)
print(att.round(decimals=2))                # the upper-right part is all 0
print("each row sums to:", att.sum(dim=-1))

# (1, 1, T, T) broadcasts to (B, nh, T, T)
print((torch.randn(2, 3, T, T) + bias.view(1, 1, T, T)).shape)

@@ concept
title: Scaled dot-product attention, step by step
--- body
Attention lets each position pull information from other positions. Each position has three vectors:
- **q** (query): what am I looking for?
- **k** (key): what do I have?
- **v** (value): what I hand over if you pick me

q, k and v all have shape (B, nh, T, hs). Here is one pass with B=1, nh=1, T=4, hs=8:

1. **Scores**: `scores = q @ k.transpose(-2, -1)`. (1,1,4,8) @ (1,1,8,4) → (1,1,4,4). `scores[i, j]` is the dot product of q_i and k_j: how interested position i is in position j.
2. **Scale**: divide by `math.sqrt(hs)`, here √8 ≈ 2.83. See below for why.
3. **Mask**: fill the future cells with `-inf` (previous card).
4. **softmax(dim=-1)**: along the last dimension, i.e. along each **row**, turn scores into weights: all ≥ 0, each row sums to 1. `dim=-2` would normalise the columns instead, which is wrong.
5. **Weighted sum**: `att @ v`. (1,1,4,4) @ (1,1,4,8) → (1,1,4,8). The output at position i is the sum of all the v's, weighted by row i.

As one formula: `softmax(q @ kᵀ / √hs + mask) @ v`.

PyTorch has the same computation built in: `F.scaled_dot_product_attention(q, k, v, is_causal=True)`, SDPA for short (on a GPU it also picks a faster implementation). Checking your own version against it is called a reference comparison: the difference should be tiny (1e-6 or less, just floating-point noise).

### Why divide by √hs
Each number in q and k is roughly mean 0, standard deviation 1. A dot product adds up hs such products, so its standard deviation is about √hs: about 8 when hs=64. When softmax sees scores that differ by 10 or 20, it gives almost all the weight to the largest one (close to one-hot), the other positions get almost no gradient, and the model learns slowly. Dividing by √hs brings the standard deviation back to about 1. The last two lines of the code print both numbers.
--- code
torch.manual_seed(0)
B, nh, T, hs = 1, 1, 4, 8                   # 1 sequence, 1 head, 4 tokens, 8 numbers per head
q, k, v = (torch.randn(B, nh, T, hs) for _ in range(3))

s = q @ k.transpose(-2, -1)                 # (1,1,4,8) @ (1,1,8,4)
print("1. scores          ", tuple(s.shape))
s = s / math.sqrt(hs)                       # 2. divide by √8
s = s.masked_fill(torch.tril(torch.ones(T, T)) == 0, float("-inf"))
print("3. scaled + masked:\n", s[0, 0].round(decimals=2))
att = s.softmax(dim=-1)
print("4. after softmax, each row sums to 1:\n", att[0, 0].round(decimals=2))
out = att @ v                               # (1,1,4,4) @ (1,1,4,8)
print("5. output          ", tuple(out.shape))

sdpa = F.scaled_dot_product_attention(q, k, v, is_causal=True)
print("largest difference from SDPA:", (out - sdpa).abs().max().item())

a, b = torch.randn(1000, 64), torch.randn(1000, 64)    # 1000 pairs of q, k with hs=64
dots = (a * b).sum(-1)
print("std of the dot products with hs=64: unscaled", round(dots.std().item(), 2), "  divided by √64", round((dots / 8).std().item(), 2))

@@ concept
title: The causality test: change the future, the past must not move
--- body
Comparing with SDPA proves the numbers are right. But there is a nastier kind of bug: **information leakage**. If the mask is missing or backwards, the model peeks at the answer during training. The loss drops beautifully, and generation produces garbage. Nothing raises an error.

The test is simple and works for any causal model:
1. Compute the output once: `out1`
2. Change only the **last few positions** of the input (below: the k and v of the last 2 positions) and compute `out2`
3. The earlier positions must **not change at all**: `out1[:, :, :4]` equals `out2[:, :, :4]`
4. The changed positions' own outputs **should change**. If even they don't, your test didn't actually change anything

This is an invariant test: you don't need to know the right answer, you only check a property that must always hold. It works the same on a whole module or a whole model: change the second half of x, and the outputs of the first half must stay the same. Day 17 has more tests of this kind.

The code compares "with a causal mask" and "without a mask", using SDPA.
--- code
torch.manual_seed(0)
q, k, v = (torch.randn(1, 1, 6, 4) for _ in range(3))   # T=6
k2, v2 = k.clone(), v.clone()
k2[:, :, 4:] = torch.randn(1, 1, 2, 4)      # change only the last 2 positions
v2[:, :, 4:] = torch.randn(1, 1, 2, 4)

def changes(causal):
    out1 = F.scaled_dot_product_attention(q, k, v, is_causal=causal)
    out2 = F.scaled_dot_product_attention(q, k2, v2, is_causal=causal)
    past = (out1[:, :, :4] - out2[:, :, :4]).abs().max().item()
    future = (out1[:, :, 4:] - out2[:, :, 4:]).abs().max().item()
    return round(past, 4), round(future, 4)

print("causal mask: first 4 positions changed by", changes(True)[0], "  last 2 changed by", changes(True)[1])
print("no mask    : first 4 positions changed by", changes(False)[0], "  last 2 changed by", changes(False)[1])

@@ concept
title: Multi-head: split heads, merge heads, register_buffer
--- body
One head can learn only one way of "looking". Multi-head attention cuts the C numbers into nh pieces of hs = C / nh each, runs attention on each piece independently, and joins the results. It costs about the same as one big head, but each head can focus on something different (one looks at the previous word, another at the start of the sentence).

All the shapes, with B=2, T=5, C=12, nh=3 (so hs=4):
1. `self.qkv(x)`: (2, 5, 12) → (2, 5, 36). One Linear produces q, k and v at once, faster than three Linears
2. `.split(C, dim=-1)` → q, k, v, each (2, 5, 12)
3. `.view(B, T, nh, hs)` → (2, 5, 3, 4): cut the 12 numbers into 3 heads × 4
4. `.transpose(1, 2)` → (2, 3, 5, 4): move "head" to dimension 1. Now each head is its own (T, hs) matrix, and the attention matmuls run as a batch over (B, nh)
5. attention → (2, 3, 5, 4)
6. `.transpose(1, 2)` → (2, 5, 3, 4), then `.contiguous().view(B, T, C)` → (2, 5, 12): merge the heads
7. `self.proj(y)` → (2, 5, 12): mix the heads' results together

Why `.contiguous()`? `transpose` moves no data; it only changes the order in which memory is read. `view` needs the data laid out in order in memory, which is no longer true after a transpose, so a direct `view` fails. `.contiguous()` makes a copy in the new order. (`.reshape` also works; it copies when needed.)

### Keep the mask in a buffer
The mask is the same in every forward pass, so don't rebuild it each time. In `__init__`:
```
self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size)).view(1, 1, block_size, block_size))
```
- a buffer belongs to the module: it moves with `model.to("cuda")` and it is in `state_dict()`
- but it is **not a parameter**: it is not in `parameters()`, and the optimizer never changes it
- the input can be shorter than block_size; take a slice when you use it: `self.bias[:, :, :T, :T]`

nanoGPT calls it "bias" for historical reasons; it is really the mask.
--- code
torch.manual_seed(0)
B, T, C, nh = 2, 5, 12, 3
hs = C // nh                                # 4 numbers per head
x = torch.randn(B, T, C)
qkv = nn.Linear(C, 3 * C, bias=False)

big = qkv(x)
print("qkv(x)           ", tuple(big.shape))
q, k, v = big.split(C, dim=-1)
print("q after split    ", tuple(q.shape))
q = q.view(B, T, nh, hs)
print("view: split heads", tuple(q.shape))
q = q.transpose(1, 2)
print("transpose(1, 2)  ", tuple(q.shape))

y = torch.randn(B, nh, T, hs)               # pretend this is the attention output
y = y.transpose(1, 2)
print("back again       ", tuple(y.shape), " contiguous?", y.is_contiguous())
try:
    y.view(B, T, C)
except RuntimeError as e:
    print("view right away: ", str(e)[:60], "...")
y = y.contiguous().view(B, T, C)
print("heads merged     ", tuple(y.shape))

class WithMask(nn.Module):
    def __init__(self, block_size):
        super().__init__()
        self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size)).view(1, 1, block_size, block_size))

m = WithMask(8)
print("in state_dict:", list(m.state_dict().keys()), "  number of parameters:", sum(p.numel() for p in m.parameters()))
print("mask slice for T=5:", tuple(m.bias[:, :, :5, :5].shape))

@@ concept
title: Block: MLP + pre-LN residual
ref: day4
--- body
A Block is two sub-layers. Both follow the same pattern: `x = x + sublayer(LayerNorm(x))`.
```
x = x + self.attn(self.ln1(x))    # tokens exchange information
x = x + self.mlp(self.ln2(x))     # each token is processed on its own
```

**MLP**: `Linear(C, 4C)` → GELU → `Linear(4C, C)`, both with a bias. It widens the vector 4 times, applies a non-linear function (GELU, a smooth version of ReLU), and shrinks it back to C. It works on each position separately; positions don't talk to each other here.

**Residual**: `x = x + sublayer(...)`. The sub-layer only has to learn "what to change in x". Picture a main road from the input straight to the output (the residual stream); each sub-layer adds a little to it. Gradients also travel back along that road directly to the early layers, which is why dozens of layers still train.

**Pre-LN**: the LayerNorm sits **inside** the branch (normalise first, then the sub-layer); the x on the main road is never normalised. The original 2017 Transformer used post-LN, `x = LN(x + sublayer(x))`, which becomes unstable with many layers and needs a careful warmup. GPT-2 switched to pre-LN. Because the main road never goes through a LayerNorm, the model adds one more, `ln_f`, at the exit (next card).

**A handy test**: if both sub-layers output 0, a pre-LN Block must return x unchanged (the identity). Post-LN cannot, because LN(x) ≠ x. The practice exercise uses exactly this test.

### How many parameters in one Block
- ln1, ln2: 2C each (a LayerNorm has C weights and C biases)
- qkv: 3C²; proj: C² (no biases here, as in nanoGPT)
- fc1: 4C² + 4C; fc2: 4C² + C
- total **12C² + 9C**. Attention has 4C², the MLP 8C²: most of it is in the MLP

The code lists every parameter of one Block (C=16), then runs the identity test: the same parts wired pre-LN and post-LN.
--- code
torch.manual_seed(0)
C = 16
blk = Block(n_embd=C, n_head=4, block_size=8)      # the Block you write today (reference version)
for name, p in blk.named_parameters():
    print(f"{name:18s} {str(tuple(p.shape)):9s} {p.numel()}")
print("total", sum(p.numel() for p in blk.parameters()), "  12*C*C + 9*C =", 12 * C * C + 9 * C)

x = torch.randn(2, 5, C)
with torch.no_grad():                        # make both sub-layers output 0
    blk.attn.proj.weight.zero_()
    for p in blk.mlp.parameters():
        p.zero_()
print("pre-LN : max |Block(x) - x| =", (blk(x) - x).abs().max().item())
h = blk.ln1(x + blk.attn(x))                 # the same parts, wired post-LN
post = blk.ln2(h + blk.mlp(h))
print("post-LN: max |out - x|      =", round((post - x).abs().max().item(), 3))

@@ concept
title: GPT: embeddings, init and weight tying
ref: day4
--- body
Putting the parts together:
```
x = wte(idx) + wpe(pos)        # (B,T,C) + (T,C), broadcast
for block in h: x = block(x)
logits = lm_head(ln_f(x))      # (B,T,V)
```
- `wte = nn.Embedding(V, C)`: looks up one row (a vector) per token id
- `wpe = nn.Embedding(block_size, C)`: looks up one row per position 0…block_size−1, with `pos = torch.arange(T)`. Attention itself has no idea of order; all order information comes from here (day 5 replaces it with RoPE)
- `ln_f`: the pre-LN main road was never normalised, so normalise once at the exit
- `lm_head = nn.Linear(C, V, bias=False)`: turns each position's vector into V scores

### Init: the first loss should be about ln V
nanoGPT initialises the weights of every Linear and Embedding from a normal distribution with mean 0 and standard deviation 0.02, and sets biases to zero. How: write a function `_init(m)`, then call `self.apply(self._init)`. `apply` calls it once on every sub-module.

A freshly initialised model knows nothing, so it should treat all V words alike: each gets probability about 1/V, and the cross-entropy is about ln V (the baseline from day 3). A standard deviation of 0.02 keeps the logits small and the prediction close to uniform. `nn.Embedding` uses a standard deviation of 1 by default, 50 times larger: the logits start huge, the loss starts far from ln V, and the first few hundred training steps are spent cleaning up that mess.

### Weight tying
`self.lm_head.weight = self.wte.weight`: the output layer and the input embedding **share one** (V, C) parameter. The idea: "the vector for this word" and "the vector used to predict this word" should be similar anyway. The gain: V·C fewer parameters (about 38.6 million in GPT-2).
- it must be **the same object**: `m.lm_head.weight is m.wte.weight` must be True. Copying the values with `copy_` doesn't count; they drift apart after one training step
- `parameters()` removes duplicates, so the shared weight is counted once
- both of nanoGPT's inits are N(0, 0.02), so the tying line can go before or after `apply`

### The loss
`F.cross_entropy` wants scores of shape (N, V) and answers of shape (N,), so flatten batch and time first: `logits.reshape(-1, V)` is (B·T, V) and `targets.reshape(-1)` is (B·T,).

The whole GPT's parameter count = wte + wpe + L Blocks + ln_f; lm_head shares with wte, so it adds nothing. Exercise d4-07 turns this into a formula.
--- code
torch.manual_seed(0)
V = 65
m = GPT(vocab_size=V, block_size=16, n_layer=2, n_head=4, n_embd=32)
idx = torch.randint(0, V, (4, 16))
targets = torch.randint(0, V, (4, 16))
logits, loss = m(idx, targets)
print("logits", tuple(logits.shape), " flattened", tuple(logits.reshape(-1, V).shape))
print("first loss =", round(loss.item(), 3), "  ln(V) =", round(math.log(V), 3))

print("lm_head.weight is wte.weight:", m.lm_head.weight is m.wte.weight)
print("std of wte:", round(m.wte.weight.std().item(), 4))
print("parameters:", sum(p.numel() for p in m.parameters()), "  without tying, add", V * 32)

with torch.no_grad():
    m.wte.weight.normal_(0, 1.0)             # nn.Embedding's default init, N(0, 1)
print("loss with wte at std 1 =", round(m(idx, targets)[1].item(), 1))

@@ concept
title: Generation: greedy decoding + context cropping
ref: day4
--- body
A GPT guesses only **one** next token at a time. To write a whole passage, it goes step by step (this is called autoregressive generation):
1. Feed the current sequence to the model and get logits (B, T, V)
2. Keep only the logits of the **last position**: `logits[:, -1]`, shape (B, V). The tokens guessed at earlier positions are already in the sequence
3. Pick a token. **Greedy**: take the highest score, `argmax(-1, keepdim=True)` → (B, 1)
4. Append it to the sequence: `torch.cat([idx, nxt], dim=1)`; the length grows by 1
5. Go back to step 1

**Context cropping**: `wpe` has only block_size rows, and the mask buffer is only block_size×block_size. Once the sequence is longer than block_size, looking up the position embedding goes out of range and fails. So at each step feed only the last block_size tokens: `idx[:, -block_size:]`. While the sequence is still short, this slice changes nothing.

Two small habits:
- generation needs no gradients: put `@torch.no_grad()` on the function; it saves memory and time
- call `model.eval()` first: it turns off training-only randomness such as dropout

The nice thing about greedy decoding is that it is **deterministic**: the same input always gives the same output, which makes it easy to test. The downside is that it tends to repeat itself. Sampling methods (temperature, top-k) are on day 5.

The code runs only **one** step, and shows what happens without cropping.
--- code
torch.manual_seed(0)
m = GPT(vocab_size=11, block_size=8, n_layer=1).eval()
idx = torch.tensor([[3, 1, 4]])              # B=1, T=3

with torch.no_grad():
    logits, _ = m(idx)
print("logits       ", tuple(logits.shape))  # one guess per position
last = logits[:, -1]                         # keep only the last position
print("last position", tuple(last.shape))
nxt = last.argmax(-1, keepdim=True)
print("next token   ", nxt.tolist(), tuple(nxt.shape))
idx = torch.cat([idx, nxt], dim=1)
print("appended     ", idx.tolist())

too_long = torch.randint(0, 11, (1, 9))      # 9 tokens > block_size=8
try:
    m(too_long)
except IndexError as e:
    print("feeding 9 tokens:", type(e).__name__, "-", e)
print("cropped to the last 8:", tuple(too_long[:, -8:].shape))

--- context
A GPT sees a whole sequence during training, but position t may only use the tokens before it to guess the next one. The causal mask enforces that rule. Get the direction wrong and the model peeks at the answer while training: the loss looks great and generation is garbage.
--- prompt
Write `causal_bias(T, device=None)`. It returns an **additive mask** (a matrix you add to the attention scores) of shape `(1, 1, T, T)`:
- row i, column j: `0.0` when j ≤ i (the past and itself), `float("-inf")` when j > i (the future)
- the two leading 1s are for the batch and head dimensions, so the mask broadcasts straight onto `(B, nh, T, T)` scores
- use `torch.tril`; create the tensor on `device` (`device=None` means the default, the CPU)

For T=3 the last two dimensions should be:
```
[[0., -inf, -inf],
 [0.,   0., -inf],
 [0.,   0.,   0.]]
```

def causal_bias(T, device=None):
    m = torch.tril(torch.ones(T, T, device=device))
    return torch.zeros(1, 1, T, T, device=device).masked_fill(m == 0, float("-inf"))

- `torch.tril(torch.ones(T, T))` is 1 on and below the diagonal and 0 in the upper right: 1 means "may look".

def attention(q, k, v, causal=True):
    """q, k, v: (B, nh, T, hs)  ->  (B, nh, T, hs)
    Write scores -> scale -> mask -> softmax -> @v yourself. Do not call F.scaled_dot_product_attention.
    """
    raise todo()
--- solution
def attention(q, k, v, causal=True):
    T = q.size(-2)
    att = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
    if causal:
        att = att + causal_bias(T, q.device)
    att = att.softmax(dim=-1)
    return att @ v

--- context
This is the attention layer a real GPT uses: one Linear produces q, k and v, the heads run in parallel, and the results are merged back. Splitting and merging the heads is where most multi-head attention bugs hide.
--- prompt
Write `CausalSelfAttention(n_embd, n_head, block_size)`, an `nn.Module`. The input `x` is `(B, T, C)` (C = n_embd) and the output is `(B, T, C)` too.

In `__init__`:
- `self.qkv = nn.Linear(C, 3 * C, bias=False)`: produces q, k and v in one go
- `self.proj = nn.Linear(C, C, bias=False)`: the output projection
- store a `(1, 1, block_size, block_size)` lower-triangular mask with `self.register_buffer("bias", ...)` (the name must be `"bias"`). Don't rebuild it in every forward pass
- remember `n_head`; forward needs it

`forward(x)`:
1. `qkv(x)` → `split` into q, k, v, each `(B, T, C)`
2. split the heads: each becomes `(B, nh, T, hs)`, with hs = C // nh
3. causal attention: divide the scores by √hs; mask with the slice `[:, :, :T, :T]` of the buffer (T can be shorter than block_size)
4. merge the heads back to `(B, T, C)`, then apply `proj`

The parameter count must be exactly 3C² + C² (neither Linear has a bias). The tests also check that a T shorter than block_size works, and that changing the last few positions of x leaves the earlier outputs unchanged.
--- above

--- solution
class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        assert n_embd % n_head == 0
        self.n_head = n_head
        self.qkv = nn.Linear(n_embd, 3 * n_embd, bias=False)
        self.proj = nn.Linear(n_embd, n_embd, bias=False)
        self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size)).view(1, 1, block_size, block_size))

    def forward(self, x):
        B, T, C = x.shape
        hs = C // self.n_head
        q, k, v = self.qkv(x).split(C, dim=-1)
        q = q.view(B, T, self.n_head, hs).transpose(1, 2)
        k = k.view(B, T, self.n_head, hs).transpose(1, 2)
        v = v.view(B, T, self.n_head, hs).transpose(1, 2)
        att = q @ k.transpose(-2, -1) / math.sqrt(hs)
        att = att.masked_fill(self.bias[:, :, :T, :T] == 0, float("-inf")).softmax(-1)
        y = (att @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(y)

class Block(nn.Module):

        super().__init__()
        self.ln1 = nn.LayerNorm(n_embd)
        self.attn = CausalSelfAttention(n_embd, n_head, block_size)

        x = x + self.mlp(self.ln2(x))
        return x

--- solution
class GPT(nn.Module):
    def __init__(self, vocab_size, block_size, n_layer=2, n_head=4, n_embd=32):
        super().__init__()
        self.block_size = block_size
        self.wte = nn.Embedding(vocab_size, n_embd)
        self.wpe = nn.Embedding(block_size, n_embd)
        self.h = nn.ModuleList([Block(n_embd, n_head, block_size) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)
        self.apply(self._init)
        self.lm_head.weight = self.wte.weight     # tying: one shared Parameter object

    @staticmethod
    def _init(m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            nn.init.normal_(m.weight, 0.0, 0.02)
            if isinstance(m, nn.Linear) and m.bias is not None:
                nn.init.zeros_(m.bias)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.wte(idx) + self.wpe(pos)          # (B,T,C) + (T,C), broadcast
        for b in self.h:
            x = b(x)
        logits = self.lm_head(self.ln_f(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss

class CausalSelfAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size):
        super().__init__()
        assert n_embd % n_head == 0
        self.n_head = n_head
        self.qkv = nn.Linear(n_embd, 3 * n_embd, bias=False)
        self.proj = nn.Linear(n_embd, n_embd, bias=False)
        self.register_buffer("bias", torch.tril(torch.ones(block_size, block_size)).view(1, 1, block_size, block_size))

    def forward(self, x):
        B, T, C = x.shape
        hs = C // self.n_head
        q, k, v = self.qkv(x).split(C, dim=-1)
        q = q.view(B, T, self.n_head, hs).transpose(1, 2)
        k = k.view(B, T, self.n_head, hs).transpose(1, 2)
        v = v.view(B, T, self.n_head, hs).transpose(1, 2)
        att = q @ k.transpose(-2, -1) / math.sqrt(hs)
        att = att.masked_fill(self.bias[:, :, :T, :T] == 0, float("-inf")).softmax(-1)
        y = (att @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(y)

class GPT(nn.Module):
    def __init__(self, vocab_size, block_size, n_layer=2, n_head=4, n_embd=32):
        super().__init__()
        self.block_size = block_size
        self.wte = nn.Embedding(vocab_size, n_embd)
        self.wpe = nn.Embedding(block_size, n_embd)
        self.h = nn.ModuleList([Block(n_embd, n_head, block_size) for _ in range(n_layer)])
        self.ln_f = nn.LayerNorm(n_embd)
        self.lm_head = nn.Linear(n_embd, vocab_size, bias=False)
        self.apply(self._init)
        self.lm_head.weight = self.wte.weight     # tying: one shared Parameter object

    @staticmethod
    def _init(m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            nn.init.normal_(m.weight, 0.0, 0.02)
            if isinstance(m, nn.Linear) and m.bias is not None:
                nn.init.zeros_(m.bias)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        pos = torch.arange(T, device=idx.device)
        x = self.wte(idx) + self.wpe(pos)          # (B,T,C) + (T,C), broadcast
        for b in self.h:
            x = b(x)
        logits = self.lm_head(self.ln_f(x))
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
        return logits, loss

@check("GPT forward + loss")
def t07():
    seed(4)
    m = GPT(vocab_size=17, block_size=16, n_layer=2)
    idx = torch.randint(0, 17, (2, 9))
    logits, loss = m(idx)
    shape_is(logits, (2, 9, 17))
    true(loss is None, "without targets the loss should be None")
    logits, loss = m(idx, idx)
    true(loss.dim() == 0, "the loss must be a scalar: before cross_entropy, flatten logits to (B*T, V) and targets to (B*T,)")
    # a freshly initialised model's loss should be close to ln(V)
    true(abs(loss.item() - math.log(17)) < 0.7,
         f"first loss = {loss.item():.3f}; it should be close to ln(17)={math.log(17):.3f}. "
         "It is too far off: check the init (std=0.02) and how the loss is flattened")

@check("weight tying")
def t08():
    m = GPT(vocab_size=17, block_size=16, n_layer=1)
    true(m.lm_head.weight is m.wte.weight,
         "lm_head.weight and wte.weight must be the same object (tested with is, not equal values): self.lm_head.weight = self.wte.weight")
    n = params(m)
    true(n == 13696, f"{n} parameters, expected 13696 (off by {n - 13696}). lm_head needs bias=False, and the shared weight must exist only once")
--- hints
- Order: build the modules → `self.apply(self._init)` → tie the weights.
- forward: add the embeddings → every Block → ln_f → lm_head → with targets, flatten and compute cross_entropy.
