@@ concept
title: Diffusion: add noise, then learn to remove it
--- body
DDPM (Denoising Diffusion Probabilistic Models) is the foundation of image generators like Stable Diffusion. It does only two things:

- **Forward process (adding noise)**: take a real image `x0` and add a little Gaussian noise to it, T times (T = 1000 is common). After the last step the image is pure noise. This is a fixed formula. Nothing is learned here.
- **Reverse process (removing noise)**: train a network that looks at a noisy image and guesses "which noise was added". To make a new image, start from pure noise and subtract the predicted noise, one step at a time.

Names we use all day:

- `t`: the timestep, an integer from 0 to T-1. Larger t means more noise.
- `x0` is the clean image; `x_t` is the noisy image at step t.
- `noise` (written ε, "epsilon", in papers): standard Gaussian noise, mean 0, standard deviation 1.
- `beta_t`: how much noise step t adds. It is a small number, for example growing from 0.0001 to 0.02.

One step of noising:

```
x_t = sqrt(1 - beta_t) * x_{t-1} + sqrt(beta_t) * noise
```

First shrink the previous image a tiny bit, then add a tiny bit of new noise. Why shrink? The squares of the two coefficients add up to exactly 1. That keeps the variance near 1, so it does not grow step after step.

The code below takes a "flat grey image" (10,000 pixels, all 2.0) and noises it for 1000 steps. Watch the mean fall from 2 to 0 and the standard deviation rise from 0 to 1.
--- code
torch.manual_seed(0)
T = 1000
betas = torch.linspace(1e-4, 0.02, T)      # beta for every step: from 0.0001 up to 0.02
x = torch.full((10000,), 2.0)              # 10,000 pixels, all 2.0
for t in range(T):
    x = (1 - betas[t]).sqrt() * x + betas[t].sqrt() * torch.randn_like(x)
    if t in (0, 99, 299, 599, 999):
        print(f"t={t:4d}   mean {x.mean():.3f}   std {x.std():.3f}")

@@ concept
title: Beta schedules: linear and cosine
ref: day8
--- body
A "schedule" is three tables computed in advance, each of length T:

- `betas`: how much noise each step adds.
- `alphas = 1 - betas`: how much signal each step keeps.
- `alphas_cumprod`: the cumulative product of alphas, called alpha_bar (ᾱ) in papers. Entry t = alphas[0] × alphas[1] × … × alphas[t]. It means: going from the clean image to step t, how much signal is left in total.

Small example: alphas = [0.9, 0.8, 0.7] gives the cumulative product [0.9, 0.9×0.8, 0.9×0.8×0.7] = [0.9, 0.72, 0.504]. In PyTorch it is one line: `alphas.cumprod(0)` (0 means along dimension 0).

### Linear schedule (the original DDPM paper)
betas are T evenly spaced points from 0.0001 to 0.02: `torch.linspace(1e-4, 0.02, T)`.

### Cosine schedule (Improved DDPM)
Linear has a problem: the signal disappears too early. With T = 1000, alpha_bar is only about 0.08 at step 500. For the last few hundred steps the network is mostly "guessing pure noise from pure noise", so those training steps are wasted. This hurts most on small images (32×32, 64×64).

The cosine schedule works the other way round. It first defines the alpha_bar curve directly, then derives the betas from it:

1. `f(t) = cos((t/T + s) / (1 + s) · π/2)²` for t = 0, 1, …, T (T+1 points); s = 0.008 is a small offset
2. `alpha_bar[i] = f(i+1) / f(0)` for i = 0 … T-1
3. `beta[i] = 1 - alpha_bar[i] / alpha_bar[i-1]`; for i = 0 the "previous" value is 1
4. The betas of the last few steps get close to 1, so clip them to [0, 0.999]

The code below compares alpha_bar for both schedules. `linear_schedule` and `cosine_schedule` are hidden reference versions; you write them yourself in items 1 and 2.
--- code
alphas = torch.tensor([0.9, 0.8, 0.7])
print("cumulative product:", alphas.cumprod(0))

lin = linear_schedule(1000)["alphas_cumprod"]
cos = cosine_schedule(1000)["alphas_cumprod"]
for t in (0, 250, 500, 750, 999):
    print(f"t={t:4d}   linear {lin[t]:.4f}   cosine {cos[t]:.4f}")

@@ concept
title: extract: each sample gets its own coefficient
--- body
In a batch, every image has its own random t. So coefficients must be looked up per sample:

- The coefficient table `arr` has shape `(T,)`. The timesteps `t` have shape `(B,)`.
- `arr.gather(0, t)` (or `arr[t]`) picks each sample's coefficient. The result has shape `(B,)`.

Here is the catch. The image x has shape `(B, C, H, W)`. Multiplying it by a `(B,)` tensor goes wrong. Broadcasting (automatically lining up tensors of different shapes) matches dimensions **from the right**. So `(B,)` lines up with W, not with B.

- If W ≠ B: you get an error. At least you notice.
- If W == B: no error, just silently wrong numbers. This is the dangerous case.

The fix: reshape to `(B, 1, 1, 1)`. Then each sample's coefficient multiplies all of its own pixels. The number of 1s = number of dimensions of x − 1. The general form:

```
out.reshape(B, *([1] * (len(x_shape) - 1)))
```

`[1] * 3` is `[1, 1, 1]`. The `*` in front unpacks the list into separate arguments, so this is `out.reshape(B, 1, 1, 1)`.

One more thing: the table is usually built on the CPU, but during training t lives on the GPU. Call `arr.to(t.device)` first, or you get a device mismatch error.
--- code
arr = torch.tensor([10., 20., 30., 40.])      # a coefficient table with T = 4
t = torch.tensor([3, 0])                      # two images in the batch, with t = 3 and t = 0
c = arr.gather(0, t)
print("picked:", c, tuple(c.shape))

x = torch.ones(2, 3, 4, 4)
try:
    x * c
except RuntimeError as e:
    print("(2,3,4,4) times (2,) fails:", str(e)[:60])

x2 = torch.ones(2, 3, 2, 2)                   # here W happens to be 2 as well
wrong = x2 * c                                # no error! but c lines up with W
print("silently wrong, image 0:\n", wrong[0, 0])
right = x2 * c.reshape(2, 1, 1, 1)
print("reshaped to (2,1,1,1), image 0:\n", right[0, 0])

@@ concept
title: q_sample: jump to step t in one go, and SNR
--- body
During training every sample gets a random t. Noising from x0 step by step up to t would take 500 loop iterations on average. Far too slow.

The good news: Gaussian noise plus Gaussian noise is still Gaussian noise. So t steps collapse into one:

```
x_t = sqrt(alpha_bar_t) * x0 + sqrt(1 - alpha_bar_t) * noise
```

- The signal coefficient is `sqrt(alpha_bar_t)`; the noise coefficient is `sqrt(1 - alpha_bar_t)`. Their squares add up to 1.
- t = 0: alpha_bar ≈ 0.9999, so x_t is almost the clean image.
- t = 999 (linear schedule): alpha_bar ≈ 0.00004, so x_t is almost pure noise.

Why does it work? Look at the first two steps. Call the alphas a0 and a1, and the two noise samples e0 and e1:

```
x_1 = sqrt(a1) * (sqrt(a0) * x0 + sqrt(1-a0) * e0) + sqrt(1-a1) * e1
    = sqrt(a0*a1) * x0 + [ sqrt(a1*(1-a0)) * e0 + sqrt(1-a1) * e1 ]
```

Inside the brackets are two independent Gaussian noises added together. For independent noise, the variances simply add: a1(1-a0) + (1-a1) = 1 - a0·a1. So the brackets equal `sqrt(1 - a0*a1) * e`, where e is one new standard Gaussian noise. And a0·a1 is exactly alpha_bar_1. More steps work the same way.

### Signal-to-noise ratio (SNR)
`SNR(t) = alpha_bar_t / (1 - alpha_bar_t)`, that is, "signal power ÷ noise power". SNR falls as t grows. It only describes "how noisy is this step", whatever schedule you use. That is why papers use it to compare schedules and to weight the loss.

The code below checks the closed form against two real noising steps. The mean and the standard deviation match.
--- code
torch.manual_seed(0)
betas = torch.tensor([0.1, 0.2])
ab = (1 - betas).cumprod(0)                   # alpha_bar = [0.9, 0.72]
x0 = torch.full((100000,), 1.0)

x = x0                                        # two noising steps, one after the other
for b in betas:
    x = (1 - b).sqrt() * x + b.sqrt() * torch.randn_like(x)
xj = ab[1].sqrt() * x0 + (1 - ab[1]).sqrt() * torch.randn_like(x0)   # one jump to t=1

print(f"two steps   mean {x.mean():.3f}   std {x.std():.3f}")
print(f"one jump    mean {xj.mean():.3f}   std {xj.std():.3f}")
print(f"formula     mean {ab[1].sqrt():.3f}   std {(1 - ab[1]).sqrt():.3f}")
print("SNR:", ab / (1 - ab))

@@ concept
title: Timestep embedding: turning t into a vector
--- body
The UNet has to know how much noise is in its input, so it knows how much to remove. So besides the noisy image, we also tell it t.

Feeding a raw integer (say 537) works badly: the number is large, and neighbouring t values look almost the same. The usual trick is the same as the positional encoding in Transformers: describe t with a set of cos and sin waves of **different frequencies**.

```
half  = dim // 2
freqs = exp(-ln(max_period) * [0, 1, ..., half-1] / half)   # from 1 down to about 1/max_period
args  = t[:, None] * freqs[None]                              # (B, 1) * (1, half) -> (B, half)
emb   = cat([cos(args), sin(args)], dim=-1)                   # (B, dim)
```

- Frequency 0 is 1: when t changes by 1, cos(t) changes a lot (high frequency). It tells neighbouring t values apart.
- Later frequencies are lower: the last dimensions change slowly with t (low frequency). They encode the rough position.
- At t = 0: the cos half is all 1s and the sin half is all 0s.
- The order is **cos first, then sin**. Codebases differ here. When you load someone else's pretrained weights, the order must match theirs.
- `torch.arange` creates its tensor on the CPU by default. If t is on the GPU, multiplying them raises "Expected all tensors to be on the same device". So write `device=t.device`. You will never catch this bug with CPU-only tests.

Here are the frequencies for half = 4, and the args for t = 0, 1 and 100:
--- code
half, max_period = 4, 10000
freqs = torch.exp(-math.log(max_period) * torch.arange(half, dtype=torch.float) / half)
print("freqs:", freqs)                        # 1, 0.1, 0.01, 0.001

t = torch.tensor([0, 1, 100])
args = t.float()[:, None] * freqs[None]
print("args shape:", tuple(args.shape))
print(args)
print("cos of the t=0 row:", args.cos()[0])   # all 1s

@@ concept
title: FiLM and ResBlock: feeding t into conv features
--- body
Now t is a vector `emb` of shape `(B, t_dim)`. The conv features `h` have shape `(B, ch, H, W)`. How does emb get to influence h?

### FiLM: scale and shift each channel
1. Pass `emb` through SiLU (a smooth activation, x · sigmoid(x)), then through `nn.Linear(t_dim, 2*ch)`. That gives `(B, 2*ch)`.
2. Add two dimensions to get `(B, 2*ch, 1, 1)` and split it in half along the channel dimension: `scale` and `shift`, each `(B, ch, 1, 1)`.
3. Output `h * (1 + scale) + shift`. The `(B, ch, 1, 1)` tensors broadcast over every pixel.

Why `1 + scale` and not just `scale`? When the Linear layer outputs values near 0 (for example, when its weights are zero), `1 + scale` makes the layer do almost nothing (an identity mapping), so features pass through unchanged. With plain `scale`, the features would be multiplied by 0 and everything would be lost.

### ResBlock: the residual block
The building block of a diffusion UNet. Its structure:

```
h = Conv3x3( SiLU( GroupNorm(x) ) )     # channels in_ch -> out_ch
h = FiLM(h, emb)                        # feed in the time
h = Conv3x3( SiLU( GroupNorm(h) ) )     # channels out_ch -> out_ch
return h + skip(x)                      # residual: add the input back
```

- `nn.Conv2d(in_ch, out_ch, 3, 1, 1)`: a 3×3 convolution with stride 1 and padding 1. H and W stay the same.
- `nn.GroupNorm(8, ch)`: splits the channels into 8 groups and normalizes each sample on its own. It does not depend on the batch size, so it is more stable than BatchNorm with tiny batches. ch must be divisible by 8.
- `skip`: x must be addable to h. If the channel counts differ (in_ch ≠ out_ch), a 1×1 convolution `nn.Conv2d(in_ch, out_ch, 1)` changes the channel count. If they are the same, use `nn.Identity()` (returns its input unchanged).
--- code
emb = torch.randn(2, 16)                      # B=2, t_dim=16
proj = nn.Linear(16, 2 * 8)                   # ch = 8
p = proj(F.silu(emb))
print("after Linear:", tuple(p.shape))
p4 = p[:, :, None, None]
print("two dims added:", tuple(p4.shape))
scale, shift = p4.chunk(2, dim=1)
print("scale / shift:", tuple(scale.shape), tuple(shift.shape))

h = torch.randn(2, 8, 4, 4)
zero = torch.zeros(2, 8, 1, 1)
print("scale=shift=0: is h*(1+scale)+shift equal to h?", torch.equal(h * (1 + zero) + zero, h))
print("scale=shift=0: sum of |h*scale+shift| =", (h * zero + zero).abs().sum().item())

print("3x3 conv 8->16:", tuple(nn.Conv2d(8, 16, 3, 1, 1)(h).shape))
print("1x1 conv 8->16:", tuple(nn.Conv2d(8, 16, 1)(h).shape))
print("GroupNorm(8, 8):", tuple(nn.GroupNorm(8, 8)(h).shape))

@@ concept
title: UNet: downsample, upsample, skip concat
--- body
A diffusion network takes a noisy image and outputs a "noise prediction" of **the same shape**. A UNet fits this well:

- **Encoder (going down)**: the resolution halves at each level (32 → 16 → 8) while the number of channels grows. Each pixel "sees" a larger area.
- **Middle**: one more block at the smallest resolution.
- **Decoder (going up)**: the resolution doubles at each level (8 → 16 → 32), back to the original size.
- **Skip connections**: the encoder's output at each level is saved and sent to the decoder level with the same resolution, where the two are concatenated along the channel dimension. Details lost by downsampling come back this way. Drawn out, it looks like a U, hence the name.

The shapes of the three operations:

- Downsample `nn.Conv2d(ch, ch, 4, 2, 1)`: kernel 4, stride 2, padding 1. Output side = (H + 2×1 − 4) // 2 + 1, which is exactly H / 2 when H is even.
- Upsample `nn.Upsample(scale_factor=2, mode="nearest")`: copies every pixel into a 2×2 block, doubling each side. It has no parameters.
- Concatenate `torch.cat([up, skip], dim=1)`: dim=1 is the channel dimension, so the channel counts add up (for example 64 + 64 = 128). The ResBlock after the concat must take that sum as its input channels.

The odd-size trap: 7 downsamples to 3 (rounded down), which upsamples to 6. That does not match the skip's 7, and cat fails. The fix: pad the upsampled tensor with zeros first. `F.pad(x, (left, right, top, bottom))` lists the dimensions **starting from the last one**: first W's left and right, then H's top and bottom.
--- code
x = torch.randn(1, 32, 32, 32)
down = nn.Conv2d(32, 32, 4, 2, 1)
up = nn.Upsample(scale_factor=2, mode="nearest")
d = down(x)
print("downsample:", tuple(d.shape))
u = up(d)
print("upsample:", tuple(u.shape))
print("concat with skip:", tuple(torch.cat([u, x], dim=1).shape))

odd = torch.randn(1, 8, 7, 7)
u2 = up(nn.Conv2d(8, 8, 4, 2, 1)(odd))
print("7x7 down then up:", tuple(u2.shape))
print("pad 1 right and 1 bottom:", tuple(F.pad(u2, (0, 1, 0, 1)).shape))

@@ concept
title: The training loss and one reverse step
--- body
### Training: the network predicts the noise
One training step is just four lines:

1. A random t for every sample: `torch.randint(0, T, (B,))`
2. Sample noise: `noise = torch.randn_like(x0)`
3. Add it: `x_t = q_sample(x0, t, noise, sched)`
4. loss = `F.mse_loss(model(x_t, t), noise)`

The target is the **noise**, not x0. The noise is always standard Gaussian, so the target has the same size at every t. That makes it easy to learn.

A very useful baseline: a model that always outputs 0 gets loss = mean of noise² ≈ 1. If your training loss stays around 1, the model has learned nothing.

### Sampling: one reverse step
From x_t to x_{t-1}:

```
mean    = (x_t - beta_t / sqrt(1 - alpha_bar_t) * eps_pred) / sqrt(alpha_t)
x_{t-1} = mean + sqrt(beta_t) * z     # t > 0; z is fresh standard Gaussian noise
x_0     = mean                        # t = 0: no noise on the last step
```

- `eps_pred` is the network's predicted noise. `mean` means "remove part of the predicted noise, then scale back up".
- The last step outputs the finished image, so no random noise should be sprinkled on top.
- Samples in a batch can have different t, so "add noise or not" is decided per sample: `(t > 0).float()` gives 0/1, reshaped to `(B, 1, 1, 1)` and multiplied in.

To generate an image: start from pure noise and go from t = T-1 down to 0, calling the network once per step. T = 1000 means 1000 network calls, which is why DDPM sampling is slow. Day 9's DDIM uses far fewer steps.
--- code
torch.manual_seed(0)
x0 = torch.randn(64, 1, 8, 8) * 10           # a batch of "images", scaled up 10x on purpose
noise = torch.randn_like(x0)
zero_pred = torch.zeros_like(noise)           # a "model" that always outputs 0
print(f"target = noise:  loss = {F.mse_loss(zero_pred, noise).item():.3f}")
print(f"target = x0:     loss = {F.mse_loss(zero_pred, x0).item():.1f}")

print("random t:", torch.randint(0, 1000, (4,)))
t = torch.tensor([0, 5, 0, 9])
keep = (t > 0).float().reshape(-1, 1, 1, 1)
print("noise switch:", keep.flatten(), "shape", tuple(keep.shape))

--- context
With the linear schedule the signal disappears too early, so many training steps in the second half are spent "guessing pure noise from pure noise". The cosine schedule from Improved DDPM removes the signal more evenly. It is clearly better on small images like 32×32 and 64×64, and many codebases use it.
--- prompt
Write `cosine_schedule(T, s=0.008)`. It returns a dict with the same structure as in item 1 (three `(T,)` tensors). Steps:

1. `t = 0, 1, …, T`: T+1 float values
2. `f = cos((t/T + s) / (1 + s) · π/2) ** 2`
3. `alphas_cumprod[i] = f[i+1] / f[0]` for i = 0 … T-1 (drop entry 0, so the shape becomes `(T,)`)
4. `betas[i] = 1 - alphas_cumprod[i] / alphas_cumprod[i-1]`; for i = 0 the "previous" value is 1. Then clip betas to [0, 0.999]
5. `alphas = 1 - betas`

Use the result of step 3 directly as `"alphas_cumprod"`. `linear_schedule` is provided (a check compares against it).
--- above

--- starter

    """Returns {"betas": (T,), "alphas": (T,), "alphas_cumprod": (T,)}, with alphas_cumprod from the cosine curve"""
    raise todo()
--- solution
def cosine_schedule(T, s=0.008):
    t = torch.arange(T + 1, dtype=torch.float)
    f = torch.cos((t / T + s) / (1 + s) * math.pi / 2) ** 2
    ab = (f / f[0])[1:]
    prev = torch.cat([torch.ones(1), ab[:-1]])
    betas = (1 - ab / prev).clamp(0, 0.999)
    return {"betas": betas, "alphas": 1 - betas, "alphas_cumprod": ab}
--- tests
@check("cosine schedule")
def t02():
    c = cosine_schedule(1000)
    ab = c["alphas_cumprod"]
    shape_is(ab, (1000,), "alphas_cumprod should be (T,): remember to drop entry 0 of f")
    true(ab[0] > 0.999, f"the first step adds almost no noise, so alpha_bar[0] should be > 0.999; got {ab[0]:.5f}")
    true(ab[-1] < 0.01, f"alpha_bar at the last step should be close to 0; got {ab[-1]:.4f}")
    true((ab[1:] <= ab[:-1]).all(), "alpha_bar must never grow (it must be non-increasing)")
    true((c["betas"] >= 0).all() and (c["betas"] <= 0.999).all(), "betas must be clipped to [0, 0.999]")
    # what makes cosine special: in the middle the signal falls more slowly than with linear
    lin = linear_schedule(1000)["alphas_cumprod"]

--- hints
- `t = torch.arange(T + 1, dtype=torch.float)`; `f = torch.cos(...) ** 2`; π is `math.pi`; `ab = (f / f[0])[1:]`.
- The "previous" table: put a 1 in front of ab and drop its last entry: `prev = torch.cat([torch.ones(1), ab[:-1]])`.
- `betas = (1 - ab / prev).clamp(0, 0.999)`, then `return {"betas": betas, "alphas": 1 - betas, "alphas_cumprod": ab}`.

def timestep_embedding(t, dim, max_period=10000):
    half = dim // 2
    # the device must follow t, otherwise this line fails with "two devices" once the model is on a GPU;
    # CPU-only tests never catch this kind of bug
    freqs = torch.exp(-math.log(max_period)
                      * torch.arange(half, dtype=torch.float, device=t.device) / half)
    args = t.float()[:, None] * freqs[None]
    return torch.cat([args.cos(), args.sin()], dim=-1)

        self.n1 = nn.GroupNorm(8, in_ch)
        self.c1 = nn.Conv2d(in_ch, out_ch, 3, 1, 1)

class MiniUNet(nn.Module):
    def __init__(self, in_ch=1, t_dim=128):
        super().__init__()
        self.t_dim = t_dim
        self.t_mlp = nn.Sequential(nn.Linear(64, t_dim), nn.SiLU(), nn.Linear(t_dim, t_dim))
        self.stem = nn.Conv2d(in_ch, 32, 3, 1, 1)
        self.rb1 = ResBlock(32, 32, t_dim)
        self.ds1 = nn.Conv2d(32, 32, 4, 2, 1)
        self.rb2 = ResBlock(32, 64, t_dim)
        self.ds2 = nn.Conv2d(64, 64, 4, 2, 1)
        self.mid = ResBlock(64, 64, t_dim)
        self.up = nn.Upsample(scale_factor=2, mode="nearest")
        self.rb3 = ResBlock(64 + 64, 32, t_dim)
        self.rb4 = ResBlock(32 + 32, 32, t_dim)
        self.out = nn.Sequential(nn.GroupNorm(8, 32), nn.SiLU(), nn.Conv2d(32, in_ch, 3, 1, 1))

    def forward(self, x, t):
        emb = self.t_mlp(timestep_embedding(t, 64))
        h = self.stem(x)
        s1 = self.rb1(h, emb)
        h = self.ds1(s1)
        s2 = self.rb2(h, emb)
        h = self.ds2(s2)
        h = self.mid(h, emb)
        h = self.rb3(unet_skip_concat(self.up(h), s2), emb)
        h = self.rb4(unet_skip_concat(self.up(h), s1), emb)
        return self.out(h)

def p_sample_step(x_t, t, eps_pred, sched, noise=None):
    """One DDPM reverse step: x_t -> x_{t-1}. t: (B,); samples with t == 0 get no noise"""

--- solution
def p_sample_step(x_t, t, eps_pred, sched, noise=None):
    beta = extract(sched["betas"], t, x_t.shape)
    alpha = extract(sched["alphas"], t, x_t.shape)
    ab = extract(sched["alphas_cumprod"], t, x_t.shape)
    mean = (x_t - beta / (1 - ab).sqrt() * eps_pred) / alpha.sqrt()
    if noise is None:
        noise = torch.randn_like(x_t)
    keep = (t > 0).float().reshape(-1, *([1] * (x_t.dim() - 1)))
    return mean + keep * beta.sqrt() * noise    # no noise when t=0

type: choice
title: Why training uses the closed form
level: 1
cards: q_sample: jump to step t in one go, and SNR
--- context
A common interview question: "How do you get x_t during DDPM training?" The answer decides whether training is fast enough to run at all.
--- prompt
When training DDPM, we get x_t in one step with the closed-form `q_sample` instead of noising x0 step by step t times. What is the main reason?
--- options
- The closed form is more accurate; step-by-step noising accumulates errors
- It gets there in one step with no loop, and a batch where every sample has a different random t is computed all at once
- Step-by-step noising makes the variance grow until it explodes
- The closed form does not need a beta schedule
answer: 2
--- explain
Both ways give **the same distribution** (the second check of item 4 proves exactly that), so neither is "more accurate". Step-by-step noising does not explode either: every step first shrinks by sqrt(1 - beta), so the variance stays near 1. And the closed form still uses alpha_bar, which is computed from the betas.

The real reason is speed. With a random t per sample, step-by-step noising needs 500 loop iterations on average; the closed form needs one multiply-add, and extract handles different t values across the batch in one go.

--- solution
def p_sample_step(x_t, t, eps_pred, sched, noise=None):
    beta = extract(sched["betas"], t, x_t.shape)
    alpha = extract(sched["alphas"], t, x_t.shape)
    ab = extract(sched["alphas_cumprod"], t, x_t.shape)
    mean = (x_t - beta / (1 - ab).sqrt() * eps_pred) / alpha.sqrt()
    if noise is None:
        noise = torch.randn_like(x_t)
    keep = (t > 0).float().reshape(-1, *([1] * (x_t.dim() - 1)))
    return mean + keep * beta.sqrt() * noise    # no noise when t=0
