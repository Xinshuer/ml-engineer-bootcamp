@@ concept
title: The TTS pipeline: text → mel → waveform
--- body
A TTS (text-to-speech) model usually has two stages. The **acoustic model** turns text into a mel spectrogram (Day 11: each frame is a vector of n_mels numbers). The **vocoder** (for example HiFi-GAN) turns the mel into a waveform.

For a sentence of 20 characters, the shapes change like this (B = batch size):

1. Text token ids: (B, 20). One integer per character or phoneme (the smallest unit of sound).
2. Text encoder output: (B, 20, C). One C-dimensional vector per character.
3. Durations: (B, 20). How many mel frames each character lasts.
4. After the length regulator: (B, Tm, C). Each character's vector is copied as many times as its duration; Tm = the sum of the durations.
5. Decoder output mel: (B, Tm, n_mels).
6. Vocoder output waveform: (B, Tm × hop). Each mel frame becomes hop audio samples.

Step 4 is the hard part: there are only 20 characters but hundreds of mel frames. How do the two line up? There are two main approaches:

- **Autoregressive**, for example Tacotron 2: the decoder makes the mel one frame at a time, and at each step attention works out "which character am I reading now". It does not know how many frames it needs, so at each step it also predicts a **stop token** (stop now or not).
- **Non-autoregressive**, for example FastSpeech 2: a small network first predicts each character's duration, then the length regulator stretches the text to the mel length. The number of frames = the sum of the durations, all frames are made **in parallel** in one pass, and no stop token is needed. The duration labels for training come from a forced-alignment tool (for example the Montreal Forced Aligner).

The example below uses the simplest possible layers in place of real networks. Only the shapes matter here.
--- code
torch.manual_seed(0)
B, Tt, C, n_mels, hop = 2, 5, 16, 80, 256
ids = torch.randint(0, 40, (B, Tt))          # 2 sentences, 5 characters each
h = nn.Embedding(40, C)(ids)                 # text encoder (just one Embedding layer here)
dur = torch.full((B, Tt), 3)                 # pretend every character lasts 3 frames
h_long = h.repeat_interleave(3, dim=1)       # length regulator: copy each character 3 times
mel = nn.Linear(C, n_mels)(h_long)           # decoder (just one Linear layer here)
n_samples = mel.size(1) * hop                # vocoder: each frame becomes hop samples
print("text ids       ", tuple(ids.shape))
print("encoder output ", tuple(h.shape))
print("durations      ", tuple(dur.shape))
print("after length reg", tuple(h_long.shape))
print("mel            ", tuple(mel.shape))
print("waveform       ", (B, n_samples), f"about {n_samples / 22050:.2f} s @22050Hz")

@@ concept
title: The length regulator: copy by duration
--- body
The length regulator is the heart of the FastSpeech family, and what it does is very simple: if character i has duration d, copy its feature vector d times.

One PyTorch function does it: `x.repeat_interleave(repeats, dim=0)`. `repeats` is an integer tensor; element i is repeated `repeats[i]` times.

- A character with duration 0 disappears: it takes no frames at all. This is how punctuation and silent symbols are handled.
- Durations must be integers and must not be negative, or you get an error.
- Want slower speech? Multiply all durations by 1.2 and round. That is how FastSpeech controls the speaking rate.

Each sentence in a batch has a different total number of frames, so you copy one sentence at a time, then pad the shorter ones with zeros on the right to build one (B, Tm, C) tensor. `x.new_zeros(...)` makes a zero tensor with the same dtype and device as x.
--- code
x = torch.tensor([[10., 11.], [20., 21.], [30., 31.]])   # 3 characters, C=2 each
d = torch.tensor([2, 0, 3])
print(x.repeat_interleave(d, dim=0))    # character 2 (20, 21) is gone

# a batch: the two sentences have 2 and 5 frames in total; pad the shorter one with 0
xb = torch.ones(2, 2, 1)
db = torch.tensor([[1, 1], [3, 2]])
outs = [xb[b].repeat_interleave(db[b], dim=0) for b in range(2)]
print([o.size(0) for o in outs])
out = xb.new_zeros(2, 5, 1)
for b, o in enumerate(outs):
    out[b, :o.size(0)] = o
print(out[..., 0])

@@ concept
title: Alignment: boundaries, frame owners, the matrix
--- body
There are three common ways to look at the same durations. Take durations = [2, 0, 3]:

1. **Boundaries**: which frames each character covers, written as a half-open range [start, end): the start frame is included, the end frame is not. The end frames are the running sum of the durations, `cumsum`: [2, 2, 5]. The start frames are end − duration: [0, 2, 2]. Character 1 is [2, 2), which is empty.
2. **Frame owners**: which character each frame belongs to. Repeat the character indices [0, 1, 2] by the durations: [0, 0, 2, 2, 2].
3. **Alignment matrix**: a 0/1 matrix of shape (frames, characters). `A[f, i] = 1` means frame f comes from character i. Each row has exactly one 1, and each column sums to that character's duration.

An alignment is always **monotonic**: as the frame index goes up, the character index stays the same or goes up, never back (people do not read backwards). Drawn as a picture, the matrix is a staircase from top left to bottom right that never turns back. This is the "alignment plot" everyone checks when training TTS: if the staircase breaks, jumps or turns back, the model is skipping or repeating words.

To set many entries to 1 at once, index with two index tensors: `A[rows, cols] = 1.0` sets every position (rows[k], cols[k]) to 1.
--- code
d = torch.tensor([2, 0, 3])
ends = d.cumsum(0)
starts = ends - d
print(torch.stack([starts, ends], dim=-1))   # each row is [start, end)

idx = torch.arange(3).repeat_interleave(d)   # which character each frame belongs to
print(idx)

A = torch.zeros(5, 3)
A[torch.arange(5), idx] = 1.0                # row f gets its 1 in column idx[f]
print(A)
print(A.sum(0))                              # column sums = durations

@@ concept
title: Teacher forcing: shift the input right by one
--- body
An autoregressive decoder (like Tacotron 2's) looks at frames 0 to t−1 when it makes frame t.

At **inference** time it has to go one frame at a time. At **training** time we have the whole real mel, so we feed the real previous frame as the input. This is called **teacher forcing**. The whole sequence can then be computed in one pass, which makes training much faster.

How: shift the target mel **right by one** along the time axis, put an all-zero **go frame** (the "start" signal) at the front, and drop the last target frame. If the targets are [a, b, c], the inputs are [0, a, b]: step 0 sees the go frame and must predict a; step 1 sees a and must predict b.

This is the same idea as the language model on Day 4: "the input is x[:-1], the labels are x[1:]".

If you forget the shift and feed the target itself, step t can see the answer for frame t, and the model only has to learn to copy. The training loss becomes suspiciously low, and at inference time (with no answer to copy) the model only produces mush.
--- code
mel = torch.arange(1, 7.).reshape(1, 3, 2)   # target: 3 frames, 2 mel values each
go = torch.zeros_like(mel[:, :1])            # an all-zero go frame, shape (1, 1, 2)
dec_in = torch.cat([go, mel[:, :-1]], dim=1)
print("target:\n", mel[0])
print("decoder input:\n", dec_in[0])        # everything moved down one row

@@ concept
title: Stop tokens and the autoregressive loop
--- body
An autoregressive model does not know how many frames a sentence needs. So at each step, besides one mel frame, it also outputs a **stop logit** (a raw score before sigmoid). `sigmoid(stop_logit)` is the probability of "stop now"; above a threshold (usually 0.5) the model stops.

**Training labels**: one row of 0/1 per sample. Only the last real frame (index `length − 1`) is 1; everything else is 0. They are trained with BCE (binary cross-entropy), so the labels must be float. The classes are very unbalanced: a 200-frame sentence has one 1, so some implementations give the positive class more weight (`pos_weight` in `BCEWithLogitsLoss`).

**The parts of the inference loop**:

- At the start there is only the go frame: `prev` has shape (1, 1, n_mels).
- At each step the decoder looks at `prev` and outputs a new frame (1, n_mels) and a stop logit.
- The new frame needs `unsqueeze(1)` to become (1, 1, n_mels); then `torch.cat(..., dim=1)` appends it to `prev`, so the next step can see it.
- Keep the generated frames in a Python list and stack them at the end with `torch.stack(frames, dim=1)` into (1, T, n_mels).
- Always have a maximum number of steps, `max_steps`: an undertrained model may never say stop, and without a limit the service hangs.
- Use `@torch.no_grad()` at inference time: no gradients are recorded, which saves memory.
--- code
lengths = torch.tensor([3, 5])
pos = torch.arange(5)
stop = (pos[None, :] == (lengths - 1)[:, None]).float()   # compare indices: 1 only at length-1
print(stop)

prev = torch.zeros(1, 1, 2)            # only the go frame
new = torch.tensor([[0.5, 0.7]])       # the frame made at this step: (1, n_mels)
prev = torch.cat([prev, new.unsqueeze(1)], dim=1)
print(prev.shape)                      # 2 frames after appending

frames = [new, new * 2, new * 3]
print(torch.stack(frames, dim=1).shape)

for logit in [-3.0, 0.0, 2.0]:
    p = torch.sigmoid(torch.tensor(logit)).item()
    print(logit, round(p, 3), "stop" if p > 0.5 else "go on")

@@ concept
title: Masked loss: padding does not count
--- body
Sentences in a batch have different lengths, so their mels have different numbers of frames. To build one tensor, the shorter ones are padded on the right (Day 11). Padding frames are not real sound and must **not** count in the loss. Otherwise:

- the model spends effort fitting meaningless values;
- the loss depends on how much padding there is, so the same model gets a different loss with a different batch mix.

Three steps:

1. Build the mask from the real lengths: `torch.arange(T)[None, :] < lengths[:, None]` gives (B, T), True on real frames.
2. The mask is (B, T) but the error is (B, T, n_mels). `mask.unsqueeze(-1)` makes it (B, T, 1), which broadcasts over every mel value when you multiply.
3. When you average, divide by **the number of elements that really count** = real frames × n_mels, not by the number of all elements.

`F.l1_loss(pred, target)` averages over every position by default, padding included, so you cannot use it directly here.
--- code
lengths = torch.tensor([4, 2])
mask = torch.arange(4)[None, :] < lengths[:, None]
print(mask.long())

pred = torch.zeros(2, 4, 3)
target = torch.ones(2, 4, 3)
target[1, 2:] = 50.0                  # sample 2 has junk values in its padding
print("without mask:", F.l1_loss(pred, target).item())

m = mask.unsqueeze(-1).float()        # (2, 4, 1)
print("with mask:   ", ((pred - target).abs() * m).sum().item() / (m.sum().item() * 3))

@@ concept
title: Durations are regressed in the log domain
--- body
The duration predictor in FastSpeech 2 does not output frame counts directly. It outputs values in the **log domain**. Why?

Durations have a **long tail**: most phonemes last 3–10 frames, but a pause at the end of a sentence can last 40 frames or more. With MSE on raw frame counts, the errors on a few long pauses (20 frames off is 400 when squared) drown out all the normal phonemes. After a log, the values are squeezed into roughly 0 to 4, and every phoneme's error matters about equally.

- **Training**: the target is `log(d + 1)`. The +1 is needed because a duration can be 0, and log(0) = −∞. An integer tensor needs `.float()` before you can take its log. The loss only counts real text positions (padding does not count, as in the previous card).
- **Inference**: undo it with `exp(prediction) − 1`, round to an integer, turn negatives into 0 (`clamp(min=0)`), and convert to int64 (`.long()`). Without the clamp, a negative duration makes `repeat_interleave` raise an error.
- **Total frames**: the number of mel frames to make for a sentence = the sum of the durations over the real text positions. Predictions on padding positions are arbitrary, so zero them with the mask before adding.

PyTorch also has `torch.log1p(x)` = log(1 + x) and `torch.expm1(x)` = exp(x) − 1, which do the same thing.
--- code
d = torch.tensor([0, 1, 3, 10, 40])
t = torch.log(d.float() + 1)
print(t)                                                   # between 0 and 3.7
print((t.exp() - 1).round().clamp(min=0).long())           # and back
print((torch.tensor([-0.3, 0.2, 1.5]).exp() - 1).round().clamp(min=0).long())
try:
    torch.arange(3).repeat_interleave(torch.tensor([1, -1, 2]))
except RuntimeError as e:
    print("negative duration:", e)

--- context
This step is the core of non-autoregressive TTS such as FastSpeech 2. The text has 20 characters but the mel has 160 frames; copying each character's features by its duration makes the two lengths match. Speaking-rate control also works by changing the durations here.
--- prompt
Write `length_regulator(x, durations, max_len=None)`.

- `x`: (B, Tt, C), the text-side features (Tt = text length, C = channels)
- `durations`: (B, Tt) int64, how many mel frames character i of sentence b lasts
- Return (B, Tm, C): each character's feature vector repeated by its duration; characters with duration 0 are skipped
- Tm: if `max_len` is given, Tm = `max_len` (cut what is longer, pad what is shorter); otherwise Tm = the largest duration sum in the batch
- Sentences with fewer than Tm frames are padded with 0 on the right

Example: the 3 characters' features are [1], [2], [3] and durations = [2, 0, 3] → [1, 1, 3, 3, 3].

You can use `repeat_interleave`; a Python loop over the batch is fine.
--- starter
def length_regulator(x, durations, max_len=None):
    """x: (B, Tt, C)   durations: (B, Tt) int64
    -> (B, Tm, C), Tm = max_len or the largest duration sum in the batch; pad with 0 on the right.
    """
    raise todo()
--- solution
def length_regulator(x, durations, max_len=None):
    outs = [x[b].repeat_interleave(durations[b], dim=0) for b in range(x.size(0))]
    Tm = max_len or max(o.size(0) for o in outs)
    out = x.new_zeros(x.size(0), Tm, x.size(2))
    for b, o in enumerate(outs):
        n = min(o.size(0), Tm)
        out[b, :n] = o[:n]
    return out

@check("shorter sentences in the batch are padded with 0")

--- hints

- Loop again: for each sentence take `n = min(length, Tm)` and write `out[b, :n] = o[:n]`.

Write two functions. Both handle one sentence, with no batch dimension.

def duration_to_boundaries(durations):
    ends = durations.cumsum(0)
    starts = ends - durations
    return torch.stack([starts, ends], dim=-1)

def frame_to_text_index(durations, n_frames):
    idx = torch.arange(durations.numel(), device=durations.device).repeat_interleave(durations)
    return idx[:n_frames]

Autoregressive models like Tacotron 2 make the mel one frame at a time. In training we feed the real previous frame (teacher forcing), so a whole sentence is computed in one pass. Get the shift wrong and the model can peek at the answer: the training loss looks amazing and inference produces mush.

def make_decoder_inputs(mel):

    raise todo()

def make_decoder_inputs(mel):
    go = torch.zeros_like(mel[:, :1])
    return torch.cat([go, mel[:, :-1]], dim=1)

--- context
Sentences in a batch have different lengths, so short mels are padded. Padding frames are not real sound: counting them makes the model learn meaningless values, and the loss changes with the amount of padding. Almost every sequence model needs a masked loss like this one.
--- prompt
Write `masked_mel_loss(pred, target, mask)`.

- `pred`, `target`: (B, T, n_mels)
- `mask`: (B, T), 1 on real frames and 0 on padding (it may be integer or bool)
- Return a scalar: the mean L1 error |pred − target| over the real frames only
- The denominator is "real frames × n_mels", the number of elements that really count

Changing the target at padding positions must not change the result. Do not use `F.l1_loss`: it averages the padding in too.
--- starter
def masked_mel_loss(pred, target, mask):
    """pred/target: (B, T, n_mels)   mask: (B, T), 1 on real frames.
    L1 over the real frames only; divide by "real frames x n_mels".
    """
    raise todo()
--- solution
def masked_mel_loss(pred, target, mask):
    m = mask.unsqueeze(-1).to(pred.dtype)
    return ((pred - target).abs() * m).sum() / (m.sum() * pred.size(-1))

def duration_loss(log_pred, target_dur, mask):
    tgt = torch.log(target_dur.float() + 1)
    m = mask.to(log_pred.dtype)
    return (((log_pred - tgt) ** 2) * m).sum() / m.sum()

    """step_fn(prev) -> (mel_next, stop_logit)
       prev: (1, t, n_mels), the first frame is the all-zero go frame
       mel_next: (1, n_mels)   stop_logit: (1,)
    Return (1, T, n_mels) without the go frame.

    raise todo()
--- solution
@torch.no_grad()
def ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5):
    prev = torch.zeros(1, 1, n_mels)          # go frame
    frames = []
    for _ in range(max_steps):
        mel_next, stop_logit = step_fn(prev)
        frames.append(mel_next)
        prev = torch.cat([prev, mel_next.unsqueeze(1)], dim=1)
        if torch.sigmoid(stop_logit).item() > stop_thresh:
            break
    return torch.stack(frames, dim=1)

    outs = [x[b].repeat_interleave(durations[b], dim=0) for b in range(x.size(0))]
    Tm = max_len or max(o.size(0) for o in outs)
    out = x.new_zeros(x.size(0), Tm, x.size(2))
    for b, o in enumerate(outs):
        n = min(o.size(0), Tm)
        out[b, :n] = o[:n]
    return out

--- context
The autoregressive generation loop looks the same in TTS, language models and audio-token models: start from a start symbol, append each new output, and stop on a stop condition or a step limit. If you can write it closed-book, a different model will not scare you.

@torch.no_grad()
def ar_decode(step_fn, n_mels, max_steps, stop_thresh=0.5):
    prev = torch.zeros(1, 1, n_mels)          # go frame
    frames = []
    for _ in range(max_steps):
        mel_next, stop_logit = step_fn(prev)
        frames.append(mel_next)
        prev = torch.cat([prev, mel_next.unsqueeze(1)], dim=1)
        if torch.sigmoid(stop_logit).item() > stop_thresh:
            break
    return torch.stack(frames, dim=1)
