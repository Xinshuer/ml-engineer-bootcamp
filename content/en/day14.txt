@@ concept
title: The five questions: what to pull out of a paper
--- body
A paper can run to 20 or 30 pages, but to write the code you only need five answers. On the first pass, do not read from start to end. Go hunting for these five:

1. **What are the input and output shapes?** Write them with real numbers, like (8, 3, 64, 64), not just "an image".
2. **What is the shape of the middle representation (the latent)?** The latent is the compressed version the model builds inside. Is it a continuous vector, or discrete integer ids?
3. **How many loss terms are there, and what does each one push?** Count the terms in the loss formula. For each one, work out which parameters its gradient updates.
4. **How does the condition get in?** A condition is extra control information, such as a class, a text or a time step. There are 5 common ways: `add` (added to the features), `cross-attn` (cross-attention), `adaln` (the condition produces the scale and shift of a LayerNorm), `concat` (joined to the input), `none` (no condition).
5. **How does sampling (generation) work?** 3 common ways: `single` (one forward pass gives the result), `autoregressive` (one piece at a time, each step looking at what was generated before), `iterative-denoise` (start from noise and remove it step by step).

Where to look: the architecture figure in the method section, the loss equation, the algorithm box (Algorithm 1), the hyperparameter table in the appendix. Related work and ablations can wait until your code runs.

Once the five answers are written down, they are your first tests: the shapes become the `expect_shape` of a smoke test, each loss term becomes a function, and the sampling style decides what the inference loop looks like.

Below is the example of DDPM from day 8: trained on 32×32 colour images, batch 16.
--- code
ddpm = {
    "input shape": (16, 3, 32, 32),     # the noisy image x_t (plus the time step t)
    "output shape": (16, 3, 32, 32),    # the predicted noise, same size as the input
    "latent shape": (16, 3, 32, 32),    # no compression: x_1 ... x_T are as big as the image
    "loss terms": 1,                    # just MSE(predicted noise, true noise)
    "condition injection": "add",       # the time-step embedding is added to every ResBlock's features
    "sampling": "iterative-denoise",    # start from pure noise, denoise step by step
}
for k, v in ddpm.items():
    print(f"{k}: {v}")

# the answers turn into code right away
x = torch.randn(ddpm["input shape"])
print("input built from the answers:", tuple(x.shape))

@@ concept
title: Smoke test: run the forward pass once first
--- body
The name "smoke test" comes from hardware: the first time you power a new circuit board, you check whether smoke comes out. Models are the same. When the forward pass is written, feed it random data once before you start training.

It checks only three things:

1. It runs to the end without an error.
2. The output shape matches what you wrote down in the five questions.
3. The output has no `nan` (not a number) and no `inf` (infinity).

For point 3, use `torch.isfinite(t)`: True for every normal number, False for nan or inf. Add `.all()` and you get True only if every element is True.

nan spreads: anything computed with a nan becomes nan. So if a nan appears anywhere inside the forward pass, you will see it in the output.

In a helper function, `*input_shapes` collects "any number of input shapes": for the call `f((2, 4), (2, 3))`, `input_shapes` inside the function is `((2, 4), (2, 3))`. The other way round, `model(*xs)` unpacks the list `xs` and passes each element as its own argument.

When a check fails, `raise AssertionError("say which check failed")`.
--- code
t = torch.tensor([1.0, float("nan"), float("inf"), -2.0])
print(torch.isfinite(t))
print("all finite:", torch.isfinite(t).all().item())

def make_inputs(*input_shapes):
    print("shapes received:", input_shapes)
    return [torch.randn(s) for s in input_shapes]

xs = make_inputs((2, 4))
out = nn.Linear(4, 3)(*xs)
print("output shape:", tuple(out.shape))
print("nan spreads:", (out * float("nan")).sum().item())

@@ concept
title: Overfit one batch: the fastest bug detector
--- body
Your model is written. Can it learn? The quickest test: take one small batch and train on it again and again for a few hundred steps.

A batch has only a dozen or so examples. Any correctly written model can memorise them, so the loss should fall close to 0.

- It falls close to 0: the chain forward → loss → backward → optimizer works. You can start real training.
- It does not fall: there is a bug in the code. Tuning the learning rate, adding data or trying a bigger model is wasted time. Go back and check the code first.

The order inside each step: compute the loss → `opt.zero_grad(set_to_none=True)` (clear the previous step's gradients) → `loss.backward()` (compute this step's gradients) → `opt.step()` (update the parameters). Create the optimizer once, outside the loop.

When you record the loss, store `loss.item()` (a Python float), not `loss` itself: the tensor keeps its whole computation graph alive in memory.

For classification, the loss at the start is about ln(number of classes): the model is still guessing, with about the same probability for every class. With 5 classes that is ln 5 ≈ 1.609. A starting value far from that also tells you something is wrong.

What to check, step by step, when the loss will not go down? That is day 15. Today you turn this check into a tool you can use any time.
--- code
torch.manual_seed(0)
model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 5))
x, y = torch.randn(16, 8), torch.randint(0, 5, (16,))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)
print("ln 5 =", round(math.log(5), 3))
for step in range(201):
    loss = F.cross_entropy(model(x), y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    opt.step()
    if step % 50 == 0:
        print("step", step, "loss", round(loss.item(), 4))

@@ concept
title: Gradient clipping: log the norm, then clip
--- body
Now and then one training step gets a very large gradient (a strange example, or a learning rate that is too high). That update pushes the parameters too far, the loss jumps up, and it may even become nan.

Gradient clipping works like this:

1. Put every gradient element of every parameter together and compute the total norm: total_norm = sqrt(sum of the squares of all gradient elements).
2. If total_norm > max_norm, multiply all gradients by max_norm / total_norm. The direction stays the same; only the length shrinks to max_norm.
3. If not, do nothing.

In PyTorch it is one line: `torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)`.

- The trailing `_` means "in place": it changes each parameter's `.grad` directly.
- It returns the total norm from **before** clipping (a 0-dimensional tensor). Log it: a sudden jump in this number often comes right before the loss turns into nan.
- Call it after `loss.backward()` and before `opt.step()`.

Example: two parameters with gradients [6, 8] and [0]. Total norm = sqrt(36 + 64 + 0) = 10. With max_norm = 2, everything is multiplied by 2 / 10 = 0.2 and becomes [1.2, 1.6] and [0].
--- code
m = nn.Linear(2, 1)
m.weight.grad = torch.tensor([[6.0, 8.0]])
m.bias.grad = torch.tensor([0.0])
before = torch.nn.utils.clip_grad_norm_(m.parameters(), max_norm=2.0)
print("total norm before clipping:", before.item())
print("weight.grad after clipping:", m.weight.grad)
print("total norm after clipping:", round(m.weight.grad.norm().item(), 4))

@@ concept
title: VQ part 1: nearest code and the straight-through estimator
--- body
VQ (vector quantization) did not appear in the first 13 days. Today you write it as "a new module from a new paper". It comes from the VQ-VAE paper; the discrete codes that the day-13 audio codecs produce are made with this kind of method too.

**Codebook**: a learnable (K, D) matrix holding K "reference vectors", each of length D.
**Quantization**: replace each encoder output vector z (length D) with the codebook vector e that is closest to it, and remember e's index.

In code, that is three steps:

1. `d = torch.cdist(z, codebook)`: z is (B, D), codebook is (K, D), d is (B, K). d[i, k] is the distance from vector i to code k.
2. `idx = d.argmin(-1)`: the position of the smallest distance in each row, shape (B,), dtype int64.
3. `e = codebook[idx]`: pick the codebook vectors by index, shape (B, D).

The problem: argmin "picks one", and picking has no derivative. The gradient stops here, and the encoder learns nothing.

The fix is called the **straight-through estimator**: `z_q = z + (e - z).detach()`

- Forward: z + e − z = e, so the value is exactly the codebook vector.
- Backward: the `.detach()` part counts as a constant, so the derivative of z_q with respect to z is 1. The gradient goes "straight through" to z, as if the quantization step were not there.

The sg[·] (stop-gradient) you see in papers is `.detach()` in PyTorch: the value stays the same, the gradient stops there.
--- code
codebook = torch.tensor([[0.0, 0.0], [2.0, 2.0]])   # K=2 codes, each D=2
z = torch.tensor([[0.3, -0.2], [1.5, 2.5], [1.2, 0.9]], requires_grad=True)
d = torch.cdist(z, codebook)
print("distances d, shape", tuple(d.shape))
print(d.detach().round(decimals=3))
idx = d.argmin(-1)
print("indices:", idx.tolist(), idx.dtype)
e = codebook[idx]
z_q = z + (e - z).detach()
print("values of z_q (equal to e):")
print(z_q.detach())
z_q.sum().backward()
print("z.grad (the gradient comes straight through: all ones):")
print(z.grad)

@@ concept
title: VQ part 2: the two stop-gradient terms
--- body
The straight-through estimator has a side effect: in `z + (e - z).detach()`, the codebook vector e sits entirely inside the detach. So whatever loss comes after it (a reconstruction error, for example), its gradient **never reaches the codebook**. The codebook will not move by itself.

That is why the VQ-VAE paper adds two terms to the loss. The sg[·] in the formulas is `.detach()`:

- **Codebook term**: ‖sg[z] − e‖². z is blocked, so only e gets a gradient. Job: pull the codebook vectors towards the encoder outputs.
- **Commitment term**: β‖z − sg[e]‖². e is blocked, so only z gets a gradient. Job: keep the encoder outputs close to the code they picked (they "commit" to it). The paper uses β = 0.25.

In code, ‖a − b‖² is `F.mse_loss(a, b)`, which by default averages over all elements.

With the reconstruction error, the VQ-VAE loss has three terms. Where the gradients go:

- reconstruction term → the decoder, then through the straight-through path to the encoder; **never the codebook**
- codebook term → only the codebook
- commitment term → only the encoder

To tell what a loss term updates, look at which quantities in its formula are **not** wrapped in sg.

The example below: z = [3, 2], e = [1, 1]. Codebook term = mean(2², 1²) = 2.5, commitment term = 0.25 × 2.5 = 0.625.
--- code
z = torch.tensor([[3.0, 2.0]], requires_grad=True)   # plays the encoder output
e = torch.tensor([[1.0, 1.0]], requires_grad=True)   # plays the chosen codebook vector

codebook_term = F.mse_loss(z.detach(), e)
codebook_term.backward()
print("codebook term:", codebook_term.item(), " e.grad:", e.grad.tolist(), " z.grad:", z.grad)

e.grad = None
commit_term = 0.25 * F.mse_loss(z, e.detach())
commit_term.backward()
print("commitment term:", commit_term.item(), " z.grad:", z.grad.tolist(), " e.grad:", e.grad)

title: Plugging a new module into a training loop
ref: day14
--- body
Once the new module is a function and tested on its own, run a small experiment before it goes into the real training loop: data so simple that you know the right answer, to see whether it can learn it.

Today's experiment uses `_toy_data()`: 64 one-dimensional points around four centres -3, -1, 1 and 3, 16 points per centre, noise with standard deviation 0.1. Shape (64, 1).

The codebook has 4 codes, deliberately squeezed near 0 at the start: [-0.3, -0.1, 0.1, 0.3]. If VQ is written correctly, after training each of the 4 codes should sit near one centre.

There is no encoder or decoder here; the data itself plays z. loss = reconstruction term + `vq_loss(..., beta=0.0)` (no encoder, so no commitment term needed). The optimizer only updates the codebook.

**The counter-intuitive part**: the reconstruction term `F.mse_loss(z_q, data)` has **no gradient** to the codebook. The data needs no gradient, and the codebook is blocked by the straight-through estimator's detach, so this term's `requires_grad` is False. It is just a number to watch. What actually moves the codebook is the codebook term inside vq_loss. In the example below the two terms have exactly the same value (z_q's value is e), yet only the codebook term carries a gradient.

One more detail: at the start every point picks one of the two outer codes (-0.3 or 0.3). Nobody picks the two middle codes, so their gradient is 0. Only after the outer codes move outwards do the middle codes start getting picked.

To find out whether a loss can train a parameter, check directly: `loss.requires_grad`, `loss.grad_fn`, or the parameter's `.grad` after backward.
--- code
data = _toy_data()
cb = nn.Parameter(torch.linspace(-0.3, 0.3, 4).reshape(4, 1))
print("data:", tuple(data.shape), " codebook:", cb.detach().flatten())

zq, idx = vq_quantize(data, cb)
print("times each code was picked:", torch.bincount(idx, minlength=4).tolist())
recon = F.mse_loss(zq, data)
print("reconstruction term:", round(recon.item(), 3), " requires_grad:", recon.requires_grad)

book = F.mse_loss(data.detach(), cb[idx])     # the codebook term
book.backward()
print("codebook term:", round(book.item(), 3))
print("gradient of the codebook:", cb.grad.flatten())

@@ concept
title: Symptom → cause: five patterns to recognise
--- body
Once a new module is plugged in, training rarely works on the first try. An experienced engineer looks at the symptom and has a good guess about what broke. Learn to recognise these five first; days 15–17 show how to track them down step by step.

- **The model learns nothing**: it gives every token about the same probability. Guessing evenly over V words gives a cross-entropy of exactly ln V, so the loss sits at ln(vocab size). Common reasons: the gradient does not reach the parameters, the learning rate is too small, `opt.step()` is missing.
- **lr too high or fp16 overflow**: one update is far too big; or half precision fp16 (largest value 65504) cannot hold some intermediate value, which becomes inf, and nan follows in the next step. It usually shows up within the first few steps.
- **Label leakage**: during training the model can see the answer. For example the causal mask is flipped or missing, or the inputs and labels are not shifted by one position. The training loss gets absurdly low, but real generation (where the answer is not visible) produces garbage.
- **Forgot model.eval()**: dropout is still on at inference and randomly switches off some neurons on every call. Greedy decoding (always pick the most likely token) should give the same result every time; now the same input gives a different output each time.
- **Tensors with graphs kept in a loop**: for example `total += loss` instead of `total += loss.item()`. Every step's computation graph stays in memory and piles up, until later in training the GPU runs out of memory (OOM).
--- code
for name, V in [("character-level Shakespeare", 65), ("GPT-2 vocabulary", 50257), ("5 classes", 5)]:
    print(f"{name}: V = {V}, loss when guessing = ln V = {math.log(V):.3f}")
print("largest fp16 value:", torch.finfo(torch.float16).max)
print("anything bigger becomes:", torch.tensor(70000.0).half())

--- prompt
Write `smoke_test(model, *input_shapes, expect_shape=None)`:

2. Pass them all to the model: `out = model(*xs)`.

def smoke_test(model, *input_shapes, expect_shape=None):
    """Run the forward pass once on random tensors and check:
      1) no error
      2) output shape == expect_shape (if given)
      3) no nan / inf in the output
    Return True; if any check fails, raise AssertionError (the message says which one).
    Build the inputs with torch.randn, one per shape in input_shapes.
    """
    raise todo()
--- solution
def smoke_test(model, *input_shapes, expect_shape=None):
    xs = [torch.randn(s) for s in input_shapes]
    out = model(*xs)
    if expect_shape is not None and tuple(out.shape) != tuple(expect_shape):
        raise AssertionError(f"output shape {tuple(out.shape)} != expected {tuple(expect_shape)}")
    if not torch.isfinite(out).all():
        raise AssertionError("the output contains nan / inf")
    return True

Overfitting one batch is the cheapest bug test there is: in seconds it proves that forward, loss, backward and the optimizer work together. If the loss will not get close to 0, go back to the code first; do not tune hyperparameters or add data.

Write `overfit_one_batch(model, x, y, steps=300, lr=1e-2)`:

- Train `steps` steps on the same `(x, y)`, with the loss `F.cross_entropy(model(x), y)`.
- The order in each step: compute the loss → `zero_grad` → `backward` → `step`.
- Return the list of the losses of every step, as Python floats (use `loss.item()`).

The grader uses a small 8 → 32 → 5 MLP and 16 examples, and wants the last loss below 0.01.
--- starter
def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    """Train again and again on the same (x, y). Return the list of losses (floats).
    Use AdamW + F.cross_entropy. If this does not get close to 0, the model or the loss is wrong:
    do not touch the data or the hyperparameters, fix the code first.
    """
    raise todo()
--- solution
def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    losses = []
    for _ in range(steps):
        loss = F.cross_entropy(model(x), y)
        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return losses
--- tests
@check("16 examples get memorised: the loss falls below 0.01")
def t03():
    seed(0)
    model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 5))
    x, y = torch.randn(16, 8), torch.randint(0, 5, (16,))
    made = []
    real_adamw = torch.optim.AdamW

    class CountingAdamW(real_adamw):                    # counts how often an optimizer is created
        def __init__(self, *args, **kwargs):
            made.append(1)
            super().__init__(*args, **kwargs)

    torch.optim.AdamW = CountingAdamW
    try:
        losses = overfit_one_batch(model, x, y)
    finally:
        torch.optim.AdamW = real_adamw
    true(isinstance(losses[0], float), "store loss.item() (a Python float) in the list, not the tensor")
    true(len(made) <= 1,
         f"AdamW was created {len(made)} times. Create it once, before the loop: a new AdamW every step "
         "throws away its running averages (momentum), so it no longer works like Adam")
    true(losses[-1] < 0.01,
         f"the last loss is {losses[-1]:.4f}. A batch of 16 examples should be easy to memorise; "
         "if it is not, the code has a bug (zero_grad or step missing?)")
    true(losses[-1] < losses[0], "the loss did not go down")

--- starter
def vq_quantize(z, codebook):
    """z: (B, D)   codebook: (K, D)
    Return (z_q, indices): z_q is (B, D), indices is (B,) int64.
    z_q must use the straight-through estimator so that the gradient reaches z.

--- solution
def vq_quantize(z, codebook):
    d = torch.cdist(z, codebook)             # (B, K)
    idx = d.argmin(-1)
    e = codebook[idx]
    return z + (e - z).detach(), idx         # straight through: forward is e, backward skips the quantization

- commitment term: β‖z − sg[e]‖², updates only the encoder (e is blocked)

--- starter

    """z: encoder output (B, D) (with gradient)   z_q_hard: the chosen codebook vectors (B, D)
    codebook loss  = ||sg[z] - e||²        (updates only the codebook)
    commitment loss= beta * ||z - sg[e]||²  (updates only the encoder)
    Return the sum of the two (both with mse_loss's default mean).
    """

--- solution
def vq_loss(z, z_q_hard, beta=0.25):

    commit = beta * F.mse_loss(z, z_q_hard.detach())
    return codebook + commit

def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    losses = []
    for _ in range(steps):
        loss = F.cross_entropy(model(x), y)
        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return losses
