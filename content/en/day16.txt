title: Reading a PyTorch traceback: the last line and your last frame
error_demo: yes
--- body
When an error happens, Python prints a long traceback (a record of the calls: who called whom, one level after another, with the most recent call at the bottom). Do not read it from the top. Read two places:

1. **The last line**: the error type and the message. Shape, device and dtype errors are almost always `RuntimeError`; the useful part comes after the colon.
2. **The last frame in your own code**: go up from the bottom and find the first `File "..."` that is your own file. It shows which of your lines handed the wrong thing to PyTorch.

Write the model from this card's code as a file net.py (with the imports at the top and without the print line) and run it in a terminal. You get this traceback (paths shortened, the `~~~^^^` marker lines removed):

```
Traceback (most recent call last):
  File "net.py", line 17, in <module>
    out = model(torch.randn(4, 8))
  File ".../torch/nn/modules/module.py", line 1778, in _wrapped_call_impl
    return self._call_impl(*args, **kwargs)
  File ".../torch/nn/modules/module.py", line 1789, in _call_impl
    return forward_call(*args, **kwargs)
  File "net.py", line 13, in forward
    return self.fc2(h)
  File ".../torch/nn/modules/module.py", line 1778, in _wrapped_call_impl
    return self._call_impl(*args, **kwargs)
  File ".../torch/nn/modules/module.py", line 1789, in _call_impl
    return forward_call(*args, **kwargs)
  File ".../torch/nn/modules/linear.py", line 134, in forward
    return F.linear(input, self.weight, self.bias)
RuntimeError: mat1 and mat2 shapes cannot be multiplied (4x10 and 12x3)
```

- The last line: `mat1` is the input to this Linear layer, 4 rows and 10 columns (4 samples, 10 features each). `mat2` is the layer's weight (transposed), 12 rows and 3 columns. A matrix product needs the two inner numbers to be equal: 10 ≠ 12.
- The last frame in your code: net.py line 13, `return self.fc2(h)`. So fc2 wants 12 input features, but only 10 arrive.
- The `module.py` and `linear.py` frames in between are PyTorch passing the call along inside. Skip them at first.

This card's code really raises this error; press Run to see it. The page shows only the frames in your code and the last line.

Keywords in common error messages:
- `mat1 and mat2 shapes cannot be multiplied`: the Linear layer's in_features differs from the last dimension of its input.
- `The size of tensor a (3) must match the size of tensor b (4) at non-singleton dimension 1`: an element-wise operation on two tensors whose dimension 1 is 3 in one and 4 in the other; neither is 1, so they cannot broadcast.
- `view size is not compatible with input tensor's size and stride`: view on a tensor that is not contiguous (see "view, reshape and contiguous").
- `Expected all tensors to be on the same device`: one tensor is on the GPU, another on the CPU.
- `mat1 and mat2 must have the same dtype, but got Double and Float`: a float64 input went into a float32 model.
- `expected target dtype to be Long or Byte, but got Float`: the cross_entropy labels are not integers.
--- code
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(8, 10)
        self.fc2 = nn.Linear(12, 3)   # wrong: fc1 outputs only 10 features

    def forward(self, x):
        h = torch.relu(self.fc1(x))
        print("shape of h before fc2:", tuple(h.shape))
        return self.fc2(h)


model = Net()
out = model(torch.randn(4, 8))

title: Silent broadcasting: (B,) vs (B, 1)
--- body
Broadcasting: when you combine two tensors of different shapes element by element, PyTorch stretches them to one common shape. The rule: line the shapes up from the rightmost dimension; each pair of sizes must be equal, or one of them must be 1 (a missing dimension counts as 1).

This is handy, and it is dangerous. The classic trap:

- A regression model ends with `nn.Linear(..., 1)`, so its output `pred` has shape (B, 1).
- The labels `target` have shape (B,).
- `pred - target`: aligned from the right, (B,) is treated as (1, B), and the result is **(B, B)**. Row i, column j holds pred_i − target_j.
- Then `.mean()` still gives one number. No error, and the loss still goes down. It just measures the wrong thing: the best the model can learn is the average of all labels.

In this card's code the predictions are **perfect**, yet the wrong version gives a loss of 2.5.

How to protect yourself:
- Make both shapes equal before computing the loss: `pred.squeeze(-1)` or `target.unsqueeze(-1)`. Use `squeeze(-1)`, not `squeeze()` without an argument: with B = 1, `squeeze()` also removes the batch dimension.
- Add an assertion: `assert pred.shape == target.shape, (pred.shape, target.shape)`.
- One step further: write the expected shape as a spec such as "B,T,C". The same letter must mean the same size in every tensor, and a number must match exactly.
- `F.mse_loss` prints a UserWarning in this case (easy to miss in a long log); the hand-written `((pred - target) ** 2).mean()` gives no warning at all.
--- code
pred = torch.tensor([[1.0], [2.0], [3.0], [4.0]])   # (4, 1): output of Linear(..., 1)
target = torch.tensor([1.0, 2.0, 3.0, 4.0])         # (4,): labels
diff = pred - target
print("shape of pred - target:", tuple(diff.shape))
print(diff)
print("wrong loss:", (diff ** 2).mean().item())
print("right loss:", ((pred.squeeze(-1) - target) ** 2).mean().item())

@@ concept
title: view, reshape and contiguous
--- body
A tensor = one block of memory + a shape + a stride (for each dimension: how many elements to skip in memory to move one step along it).

- `torch.arange(6).view(2, 3)` has stride (3, 1): the next row is 3 elements further, the next column 1 element further. This is called contiguous: reading row by row, left to right, follows the order in memory exactly.
- `.t()`, `.transpose()` and `.permute()` **do not move data**; they only swap strides. After a transpose the stride is (1, 3), and the tensor is no longer contiguous.
- `view` does not move data either; it just reads the same memory in a different way. When the tensor is not contiguous, many views are impossible, and you get `view size is not compatible with input tensor's size and stride`.
- `reshape`: a view when possible, otherwise a copy. `.contiguous()`: a contiguous copy (or the tensor itself if it already is contiguous).

So the fix for that error is `x.contiguous().view(...)`, or simply `x.reshape(...)`.

**The more dangerous case raises no error.** reshape and view always read elements in logical order (row by row); they **never** reorder dimensions for you. To turn (B, C, H, W) into (B, H*W, C), writing `reshape(B, H*W, C)` raises nothing, but every position now holds shuffled numbers. Reordering dimensions needs transpose / permute; reshape only merges or splits **neighbouring** dimensions.
--- code
x = torch.arange(6).view(2, 3)
print(x.tolist(), "stride", x.stride(), "contiguous?", x.is_contiguous())
t = x.t()                       # (3, 2), no data moved
print(t.tolist(), "stride", t.stride(), "contiguous?", t.is_contiguous())
try:
    t.view(6)
except RuntimeError as e:
    print("t.view(6) fails:", e)
print("t.reshape(6):", t.reshape(6).tolist())
print("t.contiguous().view(6):", t.contiguous().view(6).tolist())
print("x.reshape(3, 2):", x.reshape(3, 2).tolist(), " is not the transpose", t.tolist())

@@ concept
title: Devices: new tensors follow the input
--- body
All tensors in one operation must be on the same device: all on the CPU, or all on the same GPU (for example `cuda:0`). That includes the model's parameters, the input, and any tensor you **create inside** forward.

The most common bug: `torch.arange(T)`, `torch.zeros(...)` or `torch.ones(...)` inside forward without a device, so they are always created on the CPU. On a laptop with only a CPU everything works; on the GPU server you get `Expected all tensors to be on the same device, but found at least two devices, cuda:0 and cpu!`.

The fix: make new tensors follow the input.
- `torch.arange(T, device=x.device)`
- `torch.zeros(B, T, device=x.device, dtype=x.dtype)`, or the shorter `x.new_zeros(B, T)` and `torch.zeros_like(x)`
- for a tensor that already exists: `other.to(x.device)`

Do not hard-code `.cuda()`: it fails on a machine without a GPU, and `.cuda()` goes to the current GPU (usually `cuda:0`), so it no longer matches when the model is on `cuda:1`.

One exception: a 0-dimensional CPU tensor (such as `torch.tensor(2.0)`) can be combined with GPU tensors; PyTorch treats it like a plain number.

**How do you test this without a GPU?** Use the meta device. It is a "fake device": its tensors have a shape and a dtype but no real data, so it works on any machine. Mixing a CPU tensor with a meta tensor raises the same kind of error: `Tensor on device cpu is not on the expected device meta!`. Several checks today test devices this way.
--- code
def add_positions(x):                   # x: (B, T)
    pos = torch.arange(x.shape[1])      # bug: no device, always on the CPU
    return x + pos

def add_positions_fixed(x):
    pos = torch.arange(x.shape[1], device=x.device)
    return x + pos

x = torch.zeros(2, 5, device="meta")    # pretend this input is on the GPU
for fn in (add_positions, add_positions_fixed):
    try:
        out = fn(x)
        print(fn.__name__, "OK:", out.device, tuple(out.shape))
    except RuntimeError as e:
        print(fn.__name__, "fails:", e)

@@ concept
title: register_buffer: tensors that move with the module
--- body
`model.to("cuda")`, `model.cuda()`, `model.double()` and `model.half()` only handle the tensors the module knows about:
- parameters: `nn.Parameter`, updated by the optimizer (for example a Linear layer's weight).
- buffers: tensors registered with `self.register_buffer("name", tensor)`. They are not trained, but they go wherever the module goes: to another device, to another dtype, and into the `state_dict`.

A plain attribute `self.mask = torch.tril(...)` is **invisible** to the module. Move the model to the GPU and the mask stays on the CPU; forward then raises a device error. Creating the mask anew in every forward is not good either: by default it lands on the CPU as float32, and you recompute it for nothing.

So fixed helper tensors (causal masks, position tables, normalisation means and variances) are created once in `__init__` and registered with `register_buffer`. `persistent=False` means "do not save it in the state_dict": it can always be recomputed, leaving it out keeps checkpoints a little smaller, and changing max_len then does not break loading.

**How do you test "does it move along" without a GPU?** Change the dtype. `.double()` and `.to("cuda")` run the same code inside the module (`Module._apply`): a buffer goes from float32 to float64, a plain attribute does not change. Note that `.double()` and `.half()` only change floating-point tensors; bool and integer buffers keep their dtype (but they still move to a new device).
--- code
class M(nn.Module):
    def __init__(self):
        super().__init__()
        self.lin = nn.Linear(3, 3)
        self.plain = torch.ones(3)                                    # plain attribute: the module does not know it
        self.register_buffer("buf", torch.ones(3))                    # buffer: moves along
        self.register_buffer("tmp", torch.ones(3), persistent=False)  # moves along, not saved

m = M().double()
print("lin.weight:", m.lin.weight.dtype)
print("buf:       ", m.buf.dtype)
print("tmp:       ", m.tmp.dtype)
print("plain:     ", m.plain.dtype, " <- unchanged")
print("buffers:   ", [name for name, _ in m.named_buffers()])
print("state_dict:", list(m.state_dict().keys()))
m = m.to("meta")
print("after to(meta): buf is on", m.buf.device, ", plain is on", m.plain.device)

@@ concept
title: dtypes: long labels, float64 from numpy, integer division
--- body
The dtype (data type) decides how each number in a tensor is stored. The three most common traps:

**1. numpy defaults to float64.** PyTorch's default float is float32, and so are the model's parameters. `torch.from_numpy(a)` and `torch.tensor(a)` both keep float64; feed that to the model and you get `mat1 and mat2 must have the same dtype, but got Double and Float`. The fix: `.float()`. Element-wise operations do not fail: float32 + float64 is quietly promoted to float64, which doubles the memory.

**2. Class labels must be long (int64).** The labels of `F.cross_entropy`, the token ids of `nn.Embedding` and index tensors must all be integers. Float labels give `expected target dtype to be Long or Byte, but got Float`. The other way round, regression targets (MSE) must be float.

**3. Integer division.** Python's `//` is floor division: `3 // 4 == 0`. Accuracy computed as `correct // total` is always 0 unless every prediction is right. Use `/`. In PyTorch, `/` on integer tensors gives floats (true division); `//` is floor division. An integer tensor cannot call `.mean()` directly (`mean(): could not infer output dtype`); call `.float()` first.

Also: `pred == y` is a bool tensor, and its `.sum()` is int64.
--- code
import numpy as np

a = np.array([0.5, 1.5])
print("numpy:", a.dtype, "-> torch.from_numpy:", torch.from_numpy(a).dtype)
print("torch.tensor([1, 2]):", torch.tensor([1, 2]).dtype)
print("torch.tensor([1.0, 2.0]):", torch.tensor([1.0, 2.0]).dtype)
try:
    nn.Linear(2, 1)(torch.from_numpy(a).view(1, 2))
except RuntimeError as e:
    print("float64 into Linear:", e)
try:
    F.cross_entropy(torch.randn(2, 3), torch.tensor([0.0, 2.0]))
except RuntimeError as e:
    print("float labels:", e)
correct, total = 3, 4
print("3 // 4 =", correct // total, "   3 / 4 =", correct / total)
y = torch.tensor([7, 8])
print("integer tensor / 2:", y / 2, "   // 2:", y // 2)

@@ concept
title: Forward hooks: every layer reports its output shape
--- body
When a model raises a shape error, what you want to know is **the output shape of every layer**. Adding a print to each layer by hand is tedious. A forward hook does it without changing the model's code.

- `handle = layer.register_forward_hook(fn)`: from now on, every time layer finishes a forward pass, `fn(module, inputs, output)` is called. `inputs` is a tuple (everything the layer received), and `output` is what the layer returned.
- `handle.remove()`: takes the hook off again. If you forget, it stays attached and fires on every later forward pass.
- `model.named_modules()`: yields `(name, module)` pairs, including the whole model itself (its name is the empty string `''`) and containers in between (such as `nn.Sequential`). Nested names are joined with dots, like `'2.0'` or `'enc.0'`.
- To see only the layers that do the work, pick the leaf modules, the ones without children: `len(list(m.children())) == 0`.
- One module can be called several times (for example one `nn.ReLU` used twice); its hook then fires several times too.

Always take the hooks off when you are done, even when forward crashes halfway. Use try / finally; the code in `finally` runs whether or not there was an error:

```
handles = [...]
try:
    model(x)
finally:
    for h in handles:
        h.remove()
```

If you want to carry on after an error, add an `except Exception as e:` part in between that stores the error instead of letting it escape.

When the model crashes, the last layer that printed is the last one that finished; the crash is in the layer after it.

The output size of a convolution: `(input + 2·padding − kernel) // stride + 1`.
--- code
model = nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Sequential(nn.Linear(8, 8), nn.Tanh()), nn.Linear(8, 2))

for name, mod in model.named_modules():
    leaf = len(list(mod.children())) == 0
    print(repr(name), type(mod).__name__, "leaf" if leaf else "container")

def show(module, inputs, output):
    print("  ", type(module).__name__, tuple(inputs[0].shape), "->", tuple(output.shape))

handles = [m.register_forward_hook(show) for m in model.modules() if len(list(m.children())) == 0]
try:
    model(torch.randn(5, 4))
finally:
    for h in handles:
        h.remove()
print("hooks removed; running again prints nothing:")
model(torch.randn(5, 4))

@@ concept
title: Nested batches: walk dicts, lists and tuples recursively
--- body
In real projects a batch is rarely a single tensor. A DataLoader often gives you something like this:

```
{"input_ids": (B, T) long, "attention_mask": (B, T) bool,
 "pixels": (B, 3, H, W) float, "meta": {"lengths": [...], "ids": ("a", "b")}}
```

To move all of it to the GPU, or to print every tensor's shape, you have to walk through this nested structure. That is a classic use of recursion (a function that calls itself):
- a tensor: handle it and return the result.
- a dict: recurse into every value, keep the keys, build a dict again.
- a list / tuple: recurse into every element and build **the same kind** of container (a tuple stays a tuple).
- anything else (strings, numbers, None): return it unchanged.

Check the type with `isinstance(obj, torch.Tensor)`, `isinstance(obj, dict)` and `isinstance(obj, (list, tuple))`. `type(obj)(...)` builds a new container of the original type: `type((1, 2))([3, 4])` gives `(3, 4)`.

Be careful when changing the dtype: only floating-point tensors (`t.is_floating_point()` is True) should become float16, float64 and so on. Token ids and labels are long, masks are bool; turn them into floats and the Embedding or cross_entropy further on raises an error.
--- code
def describe(obj):
    """Replace every tensor in a nested batch with a short description; keep everything else."""
    if isinstance(obj, torch.Tensor):
        kind = "float" if obj.is_floating_point() else "not float"
        return f"{tuple(obj.shape)} {obj.dtype} {kind}"
    if isinstance(obj, dict):
        return {k: describe(v) for k, v in obj.items()}
    if isinstance(obj, (list, tuple)):
        return type(obj)(describe(v) for v in obj)
    return obj

batch = {
    "input_ids": torch.randint(0, 100, (2, 6)),
    "attention_mask": torch.ones(2, 6, dtype=torch.bool),
    "pixels": torch.randn(2, 3, 8, 8),
    "meta": {"lengths": [6, 4], "ids": ("a", "b")},
}
for key, value in describe(batch).items():
    print(key, "->", value)

type: predict
title: What shape is (B, 1) minus (B,)?
level: 1
cards: Silent broadcasting: (B,) vs (B, 1)
--- context
Regression, scoring and reward models often output (B, 1), while the labels are often (B,). Subtracting them raises no error; you quietly get (B, B). This is one of the classic reasons a model "trains but does not learn".
--- prompt
Work out what each line prints before you run anything, then write it down, one line per print. Write tuples the way Python prints them, for example `(4,)` and `()`.
--- code
pred = torch.zeros(4, 1)      # model output: Linear(..., 1)
target = torch.zeros(4)       # labels
print(tuple((pred - target).shape))
print(tuple((pred.squeeze(-1) - target).shape))
print(tuple((pred - target.unsqueeze(-1)).shape))
print(tuple(torch.zeros(1, 1).squeeze().shape))
--- explain
- `(4, 1)` and `(4,)` are aligned from the right: (4,) is treated as (1, 4); taking the larger size in each dimension gives (4, 4). Sixteen differences, no error.
- `squeeze(-1)` removes the trailing 1, so both sides are (4,).
- `unsqueeze(-1)` makes the labels (4, 1), so both sides are (4, 1). This is also a correct fix.
- `squeeze()` without an argument removes **every** dimension of size 1. With B = 1, (1, 1) becomes (), and the batch dimension is gone too. That is why you write `squeeze(-1)`.
--- hints
- Broadcasting aligns shapes from the rightmost dimension; a missing dimension counts as 1.
- (4, 1) against (1, 4): take the larger size in each dimension.

level: 1

--- context
This bug raises no error and the loss goes down, but the model never learns: it is trained to predict the average of all labels. People can spend days before they find it. The fix is one line; the hard part is thinking of looking at the shapes.
--- prompt
`regression_loss(model, x, y)`: `model(x)` outputs (B, 1) and `y` is (B,). Return one number: for each sample, its prediction minus **its own** label, squared, then averaged (MSE).

The current code runs but computes the wrong thing. Fix it. Consider adding an assert so that different shapes raise an error right away.
--- starter
def regression_loss(model, x, y):
    """model(x): (B, 1)   y: (B,)   returns the scalar MSE"""
    pred = model(x)
    return ((pred - y) ** 2).mean()
--- solution
def regression_loss(model, x, y):
    """model(x): (B, 1)   y: (B,)   returns the scalar MSE"""
    pred = model(x).squeeze(-1)          # (B, 1) -> (B,)
    assert pred.shape == y.shape, (pred.shape, y.shape)
    return ((pred - y) ** 2).mean()
--- tests
@check("the value of the loss")
def _():
    seed(0)
    model = nn.Linear(3, 1)
    x, y = torch.randn(5, 3), torch.randn(5)

    shape_is(loss, (), "the loss should be a single number")
    want = ((model(x)[:, 0] - y) ** 2).mean()

def assert_shape(x, spec, sizes):
    """Check that x.shape matches spec (such as "B,T,C"): return x if it does, else raise ValueError.
    sizes: dict, name -> size. Stored the first time a name is seen; must match after that."""
    dims = [d.strip() for d in spec.split(",")]
    shape = tuple(x.shape)
    if len(dims) != len(shape):
        raise ValueError(f"shape {shape} does not match {spec!r}: expected {len(dims)} dimensions, got {len(shape)}")
    for i, (d, n) in enumerate(zip(dims, shape)):
        if d.isdigit():
            if n != int(d):
                raise ValueError(f"shape {shape} does not match {spec!r}: dimension {i} should be {d}, got {n}")
        elif d in sizes and sizes[d] != n:
            raise ValueError(f"shape {shape} does not match {spec!r}: {d} was {sizes[d]} before, here it is {n}")
        else:
            sizes[d] = n
    return x

--- solution
def trace_shapes(model, x):
    """Run model(x) once and return (records, error).
    records: [(name, shape), ...], output shapes of the leaf modules, in the order they ran
    error: None normally; the exception object when forward raised one
    Remove every hook before returning."""
    names = {mod: name for name, mod in model.named_modules()}
    records = []

    def hook(module, inputs, output):
        records.append((names[module], tuple(output.shape)))

    handles = [m.register_forward_hook(hook) for m in model.modules() if len(list(m.children())) == 0]
    error = None
    try:
        model(x)
    except Exception as e:          # catch it and return it
        error = e
    finally:
        for h in handles:           # remove them after success and after failure
            h.remove()
    return records, error
