@@ concept
title: patchify: cutting an image into tokens
--- body
A Transformer takes a sequence of tokens with shape (B, N, D). An image has shape (B, C, H, W). DiT (Diffusion Transformer) cuts the image into small p×p squares called patches. Each patch is flattened into one vector, and that vector is one token.

Example: (B, C, H, W) = (2, 3, 8, 8) and p = 2.

- 8/2 = 4 patches down and 4 across, so N = 4×4 = 16 patches
- each patch holds C×p×p = 3×2×2 = 12 numbers
- the result has shape (2, 16, 12)

Three steps with only reshape and permute:

1. `x.reshape(B, C, nh, p, nw, p)`: split H into (nh, p) and W into (nw, p). nh = H/p says "which row of patches"; the p after it says "which pixel row inside the patch"
2. `permute(0, 2, 4, 1, 3, 5)` gives (B, nh, nw, C, p, p): the two "which patch" dimensions move to the front, the "inside the patch" dimensions go to the back
3. `reshape(B, nh*nw, C*p*p)`: merge the first two into N and the last three into one vector

Patches come in row-major order: token 0 is the top-left patch, token 1 is the one to its right, token nw is the first patch of the second row. Inside a patch the numbers go channel first, then row inside the patch, then column inside the patch.

Why not just `x.reshape(B, N, C*p*p)`? In memory the numbers are stored one full pixel row after another. A plain reshape puts several neighbouring pixels of one row into the same token, which is not a square. The code below shows it.

unpatchify goes backwards: reshape to (B, nh, nw, C, p, p), permute back to (B, C, nh, p, nw, p), then reshape to (B, C, H, W).
--- code
x = torch.arange(16.).reshape(1, 1, 4, 4)     # 1 image, 1 channel, 4×4 pixels
print(x[0, 0])

B, C, H, W = x.shape
p = 2
nh, nw = H // p, W // p                        # 2 patches down, 2 across
t = x.reshape(B, C, nh, p, nw, p)              # split H into (nh, p) and W into (nw, p)
t = t.permute(0, 2, 4, 1, 3, 5)                # (B, nh, nw, C, p, p)
tok = t.reshape(B, nh * nw, C * p * p)
print(tok.shape)                               # 4 patches, each 1*2*2 = 4 numbers
print(tok[0])                                  # row 0 is the top-left patch: 0 1 4 5

wrong = x.reshape(B, nh * nw, C * p * p)       # wrong: reshape without permute
print(wrong[0, 0])                             # 0 1 2 3: one pixel row, not a square

@@ concept
title: 2D position embeddings: telling the model where each patch is
--- body
Attention by itself does not know the order of the tokens. Shuffle the input tokens and the output is just shuffled the same way (an exercise lets you see this). So every token gets a "position vector" added to it; only then can the model tell the top-left corner from the bottom-right.

Start with the 1D sine embedding. It is the same idea as day 8's time embedding: describe a number with sines and cosines of different frequencies.

- pick d/2 frequencies: `freqs = 1 / 10000 ** (arange(0, d, 2) / d)`
- the embedding of position pos is `cat([sin(pos * freqs), cos(pos * freqs)])`, length d

A position in an image is two numbers: (row, column). DiT's 2D version is simple: half of the dimensions encode the row, the other half encode the column, and the two are concatenated.

- `row = pe_1d(dim/2, row index)`, `col = pe_1d(dim/2, column index)`
- the embedding of position (i, j) is `cat([row[i], col[j]])`, length dim
- tokens are in row-major order: token k sits in row `k // w`, column `k % w`

Example: a 4×4 grid with dim = 64. Token 0 is at (0, 0), token 3 at (0, 3), token 12 at (3, 0). Tokens 0 and 3 share a row, so their first 32 numbers are equal. Tokens 0 and 12 share a column, so their last 32 numbers are equal.

The table is fixed; it is not trained. A model stores it with `register_buffer`, so it moves with `.to(device)` but the optimizer never changes it.
--- code
def pe_1d(d, pos):
    freqs = 1.0 / (10000 ** (torch.arange(0, d, 2).float() / d))   # d/2 frequencies
    a = pos.float()[:, None] * freqs[None]                          # (len(pos), d/2)
    return torch.cat([a.sin(), a.cos()], dim=-1)                    # (len(pos), d)

print(pe_1d(4, torch.arange(3)))       # 3 positions, 4 numbers each; position 0 is [0, 0, 1, 1]

h, w, dim = 2, 3, 8
row = pe_1d(dim // 2, torch.arange(h))    # (2, 4): one per row
col = pe_1d(dim // 2, torch.arange(w))    # (3, 4): one per column
k = torch.arange(h * w)
print("row:", k // w)                     # the row of each token
print("col:", k % w)                      # the column of each token
table = torch.stack([torch.cat([row[i // w], col[i % w]]) for i in range(h * w)])
print(table.shape)                                  # (6, 8)
print(torch.equal(table[0, :4], table[2, :4]))      # True: tokens 0 and 2 are both in row 0
print(torch.equal(table[0, 4:], table[3, 4:]))      # True: tokens 0 and 3 are both in column 0

@@ concept
title: modulate: scale and shift by the condition
--- body
At every step a diffusion model must know "what time is it, how much noise is there" (the time t). When it draws a given class or follows a text prompt, it must know that too. All of this is first turned into one condition vector c with shape (B, D). The question is: how does c get into every token?

Day 8's UNet used FiLM: `h * (1 + scale) + shift`, where scale and shift are computed from the condition. DiT uses the same formula, placed right after a LayerNorm, so it is called adaLN (adaptive LayerNorm):

`modulate(x, shift, scale) = x * (1 + scale) + shift`

The shapes must line up. x is (B, N, D): N tokens. shift and scale are (B, D): one set per image. `unsqueeze(1)` turns them into (B, 1, D) so they broadcast over all tokens of that image. All N tokens of one image use the same shift and scale.

Why `1 + scale` and not `scale`? With scale = 0 and shift = 0, modulate does nothing (it is the identity). At the start of training the network outputs numbers near 0, so it starts from "change nothing". That is much more stable than starting from "multiply everything by 0".

Why `elementwise_affine=False` on the LayerNorm? A normal LayerNorm has its own learnable γ (scale) and β (shift). adaLN's scale and shift already do that job, and they also change with the condition. So the LayerNorm's own copy is switched off.
--- code
x = torch.randn(2, 3, 4)          # 2 images, 3 tokens each, 4 numbers per token
shift = torch.zeros(2, 4)
scale = torch.zeros(2, 4)
print(scale.shape, scale.unsqueeze(1).shape)

y = x * (1 + scale.unsqueeze(1)) + shift.unsqueeze(1)
print(torch.equal(y, x))          # True: all zeros means identity

scale[0] = 1.0                    # scale = 1 for image 0 only
y = x * (1 + scale.unsqueeze(1)) + shift.unsqueeze(1)
print(torch.equal(y[0], 2 * x[0]), torch.equal(y[1], x[1]))   # True True: image 0 doubled, image 1 unchanged

@@ concept
title: adaLN-Zero: gates and zero init
--- body
Every DiT block has two residual branches: attention and MLP. Each branch needs three sets of numbers: shift, scale and gate. That makes 6 sets, all computed from the condition c:

`SiLU → Linear(D, 6D)` gives (B, 6D). `chunk(6, dim=-1)` cuts it into 6 pieces of (B, D), in the order shift_msa, scale_msa, gate_msa, shift_mlp, scale_mlp, gate_mlp (msa = multi-head self-attention).

The gate multiplies the branch output: `x = x + gate * attn(...)`. With gate = 0 the branch has no effect at all.

The "Zero" in adaLN-Zero: this Linear's weight and bias both start at 0. So at the start of training all 6 sets are 0:

- shift = scale = 0, so modulate is the identity
- gate = 0, so both branches are switched off
- the whole block is the identity: output = input

Why? When dozens of blocks are stacked and each one changes the signal a little at random, the signal gets more and more scrambled. Starting from the identity, every block first "does nothing", and training opens the gates slowly. The DiT paper compared several ways to add the condition, and adaLN-Zero worked best.

Zero init does not mean "cannot learn". The gradient of the gate comes from the branch output, which is not 0, so after the first update the gate is no longer 0. The code below shows that the gate group does get a gradient.
--- code
D = 4
lin = nn.Linear(D, 6 * D)
nn.init.zeros_(lin.weight)
nn.init.zeros_(lin.bias)

c = torch.randn(2, D)                                 # condition vectors for 2 images
groups = lin(F.silu(c)).chunk(6, dim=-1)
print(len(groups), groups[0].shape)                   # 6 groups, each (2, 4)
print(all(bool((g == 0).all()) for g in groups))      # True: all zero at the start

x = torch.randn(2, 3, D)
branch = nn.Linear(D, D)                              # any layer will do as the branch
gate = groups[2]                                      # gate_msa
y = x + gate.unsqueeze(1) * branch(x)
print(torch.equal(y, x))                              # True: identity

y.pow(2).sum().backward()
print(lin.weight.grad[2 * D:3 * D].abs().sum() > 0)   # tensor(True): the gate group has a gradient

@@ concept
title: DiTBlock: day 4's Block with a new way in for the condition
--- body
First recall day 4's pre-LN Block:

```
x = x + attn(ln1(x))
x = x + mlp(ln2(x))
```

DiTBlock changes only three things:

1. The LayerNorms have no γ/β (`elementwise_affine=False`) and are followed by modulate
2. Each branch output is multiplied by a gate
3. The attention has no causal mask: every patch of the image can see every other patch; there is no "future"

```
s1, sc1, g1, s2, sc2, g2 = modulation(c)
x = x + g1.unsqueeze(1) * attn(modulate(norm1(x), s1, sc1))
x = x + g2.unsqueeze(1) * mlp(modulate(norm2(x), s2, sc2))
```

The MLP is the same as on day 4: `Linear(D, 4D) → GELU → Linear(4D, D)`. x comes in as (B, N, D) and leaves as (B, N, D); c is (B, D).

The exercises already provide `SelfAttention(dim, n_head)`: it is the class in the code below, so just use it. It differs from day 4's CausalSelfAttention in only two ways: no causal mask, and so no block_size and no lower-triangular buffer. The `F.scaled_dot_product_attention` it calls computes the same thing as the softmax(QKᵀ/√d)·V you wrote by hand on day 4.
--- code
class SelfAttention(nn.Module):
    def __init__(self, dim, n_head):
        super().__init__()
        self.n_head = n_head
        self.qkv = nn.Linear(dim, 3 * dim, bias=False)
        self.proj = nn.Linear(dim, dim, bias=False)

    def forward(self, x):
        B, T, C = x.shape
        hd = C // self.n_head
        q, k, v = self.qkv(x).split(C, dim=-1)
        q, k, v = (t.view(B, T, self.n_head, hd).transpose(1, 2) for t in (q, k, v))
        o = F.scaled_dot_product_attention(q, k, v)     # no is_causal=True: every token sees every token
        return self.proj(o.transpose(1, 2).reshape(B, T, C))


torch.manual_seed(0)
attn = SelfAttention(8, 2)
x = torch.randn(1, 4, 8)          # 4 tokens
x2 = x.clone()
x2[0, 3] += 1.0                   # change only the last token
with torch.no_grad():
    diff = (attn(x)[0, 0] - attn(x2)[0, 0]).abs().max()
print(f"{diff.item():.4f}")       # not 0: token 0 also "sees" the last token

@@ concept
title: Rectified flow: a straight line from noise to data
--- body
Day 8's DDPM adds noise step by step following a beta schedule, the model predicts the noise ε, the formulas are full of alpha and alpha_bar, and the original sampler takes 1000 steps.

Flow matching takes a different view. Here we use its simplest form, called rectified flow:

- take some noise x0 ~ N(0, I) and a real image x1
- draw a straight line between them: `x_t = (1 - t) * x0 + t * x1`, with t going from 0 to 1
- t = 0 is pure noise and t = 1 is clean data. This is the opposite of DDPM, where a larger t means more noise. Some papers and libraries (Stable Diffusion 3, for example) flip it again and put the noise at t = 1, so check the convention before reading someone's code
- the speed along this line (the derivative of x_t with respect to t) is `v = x1 - x0`. It does not depend on t, because speed along a straight line is constant

The model learns this velocity: it takes (x_t, t) and returns a v with the same shape as x_t. One training step is just four things:

1. draw one t ~ U(0, 1) per sample: `torch.rand(B)`
2. draw noise with the data's shape: `torch.randn_like(x1)`
3. compute x_t
4. loss = MSE(model(x_t, t), x1 - x0)

A shape detail: t is (B,) and the images are (B, C, H, W). Reshape t to (B, 1, 1, 1) so each sample uses its own t. A general form is `t.reshape(-1, *([1] * (x.dim() - 1)))`; it works however many dimensions the data has.

A handy check: if the model always outputs 0, the loss equals the variance of the target v. When the data is also standard normal, Var(x1 - x0) = 1 + 1 = 2, so the loss is about 2.
--- code
torch.manual_seed(0)
x0 = torch.randn(3)                         # noise
x1 = torch.tensor([2.0, -1.0, 0.5])         # "data"
for t in [0.0, 0.5, 1.0]:
    print(t, (1 - t) * x0 + t * x1)         # t=0 is noise, t=1 is data
print("v:    ", x1 - x0)

h = 1e-3                                    # numerical derivative: how fast x_t changes near t=0.3
xa = (1 - 0.3) * x0 + 0.3 * x1
xb = (1 - 0.3 - h) * x0 + (0.3 + h) * x1
print("dx/dt:", (xb - xa) / h)              # almost exactly v

img = torch.randn(4, 3, 8, 8)               # a batch of images
t = torch.rand(4)                           # one t per image
print(t.reshape(-1, *([1] * (img.dim() - 1))).shape)   # (4, 1, 1, 1)

data, noise = torch.randn(100000), torch.randn(100000)
print(((data - noise) ** 2).mean())         # about 2: the loss of a model that always outputs 0

@@ concept
title: Euler sampling: follow the velocity, step by step
--- body
A trained model tells you the velocity v(x, t) at position x and time t. Sampling means starting from pure noise and following the velocity in small steps until t = 1. The simplest way to do this is Euler's method:

```
x = pure noise;  dt = 1 / steps
for i in range(steps):
    t = i * dt
    x = x + v(x, t) * dt
```

Points to get right:

- time starts at t = 0; the last step uses t = 1 - dt and ends exactly at t = 1
- the t you give the model is a (B,) tensor, `torch.full((B,), i * dt)`, one value per sample in the batch
- sampling needs no gradients: put `@torch.no_grad()` on the function to save memory and time

A good way to test the loop: use a fake model whose velocity is always 5. Starting from x and moving for 1 unit of time must give x + 5, whether steps is 4 or 100. If dt is wrong (for example `1 / (steps - 1)`), the result changes with the number of steps.

Steps and path shape: when the velocity never changes (a straight path), Euler's method makes no error at all. The more the path bends, the bigger the error per step, and the more steps you need. In the code below, "velocity = x" is a bent path: starting at 1, the true end point is e ≈ 2.718, and 1 step only reaches 2.0. Rectified flow learns paths that are mostly straight (not perfectly: many noise-to-data lines cross, and the model learns their average velocity), so 20–50 steps are often enough, while the original DDPM sampler takes 1000.
--- code
def euler(v, x, steps):
    dt = 1.0 / steps
    for i in range(steps):
        x = x + v(x, i * dt) * dt
    return x

const5 = lambda x, t: torch.full_like(x, 5.0)     # velocity is always 5
x0 = torch.tensor([1.0, -2.0])
print(euler(const5, x0, 4), euler(const5, x0, 100))   # both are x0 + 5

curved = lambda x, t: x                           # velocity = x itself: a bent path
for n in [1, 4, 100]:
    print(n, round(euler(curved, torch.tensor([1.0]), n).item(), 4))   # true value e ≈ 2.7183

@@ concept
title: MiniDiT: putting the parts together
ref: day8, day10
--- body
MiniDiT takes a noisy image x (B, C, H, W) and a time t (B,), and returns a velocity with the same shape as x. Follow the shapes with in_ch = 4, img = 8, patch = 2, dim = 64, B = 2:

1. `patchify(x, 2)`: (2, 4, 8, 8) → (2, 16, 16). 16 patches of 2×2×4 = 16 numbers
2. `Linear(16, 64)`: every token becomes 64 numbers, (2, 16, 64)
3. add the 2D position table `pos_embed_2d(64, 4, 4)`, shape (16, 64); it broadcasts over the batch
4. the time condition: `c = t_mlp(timestep_embedding(t, 64))`, shape (2, 64). timestep_embedding is day 8's sine time embedding; t_mlp is `Linear(64, 64) → SiLU → Linear(64, 64)`
5. n_layer DiTBlocks: `h = block(h, c)`, the shape stays (2, 16, 64)
6. the output layer: LayerNorm (no γ/β) → modulate → `Linear(64, 16)`, giving (2, 16, 16). This modulate needs only 2 sets, shift and scale: `Linear(64, 128)(silu(c))` then `chunk(2)`
7. `unpatchify`: (2, 16, 16) → (2, 4, 8, 8)

Zero init: in the output layer, the Linear that computes shift/scale and the final `Linear(64, 16)` get weight and bias set to 0. So before training, the whole network outputs 0 for any input. This is how the DiT paper does it, and it is not a bug: training starts from "predict velocity 0" and the gradients grow from a clean starting point.

How do you check that the time condition is really connected? With zero init the output is all zeros, so you cannot tell. Add a little random noise to every parameter first (as if it had trained a few steps), then compare the outputs for t = 0 and t = 1. They should differ.

The code below calls today's patchify, pos_embed_2d, DiTBlock and unpatchify (reference versions are loaded in the background; you write them in the exercises) and day 8's timestep_embedding. It only looks at shapes.
--- code
torch.manual_seed(0)
B, C, H, p, dim = 2, 4, 8, 2, 64
x = torch.randn(B, C, H, H)
t = torch.rand(B)

tok = patchify(x, p)
print("patchify:   ", tuple(tok.shape))
h = nn.Linear(p * p * C, dim)(tok) + pos_embed_2d(dim, H // p, H // p)
print("embed + pos:", tuple(h.shape))
t_mlp = nn.Sequential(nn.Linear(dim, dim), nn.SiLU(), nn.Linear(dim, dim))
c = t_mlp(timestep_embedding(t, dim))
print("condition c:", tuple(c.shape))
h = DiTBlock(dim, 4)(h, c)
print("DiTBlock:   ", tuple(h.shape))
out = unpatchify(nn.Linear(dim, p * p * C)(h), p, H, H, C)
print("output:     ", tuple(out.shape))

--- solution
def patchify(x, p):
    B, C, H, W = x.shape
    nh, nw = H // p, W // p
    x = x.reshape(B, C, nh, p, nw, p)
    x = x.permute(0, 2, 4, 1, 3, 5)            # (B, nh, nw, C, p, p)
    return x.reshape(B, nh * nw, C * p * p)


def unpatchify(tok, p, H, W, C):
    B = tok.size(0)
    nh, nw = H // p, W // p
    x = tok.reshape(B, nh, nw, C, p, p).permute(0, 3, 1, 4, 2, 5)   # (B, C, nh, p, nw, p)
    return x.reshape(B, C, H, W)

--- hints
- First split H into (nh, p) and W into (nw, p): `x.reshape(B, C, nh, p, nw, p)` with nh = H // p.
- Then `permute(0, 2, 4, 1, 3, 5)` gives (B, nh, nw, C, p, p); finish with `reshape(B, nh * nw, C * p * p)`.
- unpatchify runs backwards: `tok.reshape(B, nh, nw, C, p, p).permute(0, 3, 1, 4, 2, 5).reshape(B, C, H, W)`.

--- context
Attention cannot tell the order of tokens. Without position information the model does not know whether a patch is in the top-left or the bottom-right. DiT uses a fixed 2D sine table: computed, not trained, and stored in the model as a buffer.
--- prompt
Write `pos_embed_2d(dim, h, w)`. It returns a position table of shape (h*w, dim). Tokens are in row-major order: token k sits in row `k // w`, column `k % w`.

How:

1. First write the 1D embedding `_pe_1d(d, pos)`: pos is a 1D tensor of L integer positions; return (L, d). `freqs = 1 / 10000 ** (arange(0, d, 2) / d)`, `a = pos * freqs` (an outer product, shape (L, d/2)), and the result is `cat([sin(a), cos(a)], dim=-1)`
2. Row table `row = _pe_1d(dim // 2, arange(h))`, column table `col = _pe_1d(dim // 2, arange(w))`
3. The embedding of position (i, j) is `cat([row[i], col[j]])`: the first half depends only on the row, the second half only on the column

dim is a multiple of 4, so dim/2 is even.

Checks: (64, 4, 4) gives (16, 64); neighbouring tokens differ; tokens in the same row share their first 32 numbers, tokens in the same column share their last 32.

def _pe_1d(d, pos):
    freqs = 1.0 / (10000 ** (torch.arange(0, d, 2).float() / d))
    a = pos.float()[:, None] * freqs[None]         # (L, d/2)
    return torch.cat([a.sin(), a.cos()], dim=-1)   # (L, d)


def pos_embed_2d(dim, h, w):
    half = dim // 2
    row = _pe_1d(half, torch.arange(h))         # (h, half)
    col = _pe_1d(half, torch.arange(w))         # (w, half)
    r = row[:, None, :].expand(h, w, half)
    c = col[None, :, :].expand(h, w, half)
    return torch.cat([r, c], dim=-1).reshape(h * w, dim)
--- tests

- The plainest way to build the table is a loop: token k gets `torch.cat([row[k // w], col[k % w]])`; `torch.stack` them at the end.

def flow_interpolate(x0_noise, x1_data, t):
    tt = t.reshape(-1, *([1] * (x0_noise.dim() - 1)))    # (B,) -> (B, 1, 1, 1)

@torch.no_grad()
def flow_sample(model, shape, steps=20, device="cpu"):
    x = torch.randn(shape, device=device)
    dt = 1.0 / steps
    for i in range(steps):
        t = torch.full((shape[0],), i * dt, device=device)
        x = x + model(x, t) * dt
    return x

class MiniDiT(nn.Module):
    def __init__(self, in_ch=4, img=8, patch=2, dim=64, n_layer=2, n_head=4):
        super().__init__()
        self.in_ch, self.img, self.patch, self.dim = in_ch, img, patch, dim
        pdim = patch * patch * in_ch
        self.embed = nn.Linear(pdim, dim)
        self.register_buffer("pos", pos_embed_2d(dim, img // patch, img // patch))
        self.t_mlp = nn.Sequential(nn.Linear(dim, dim), nn.SiLU(), nn.Linear(dim, dim))
        self.blocks = nn.ModuleList([DiTBlock(dim, n_head) for _ in range(n_layer)])
        self.norm_out = nn.LayerNorm(dim, elementwise_affine=False)
        self.mod_out = nn.Linear(dim, 2 * dim)
        nn.init.zeros_(self.mod_out.weight)
        nn.init.zeros_(self.mod_out.bias)
        self.head = nn.Linear(dim, pdim)
        nn.init.zeros_(self.head.weight)
        nn.init.zeros_(self.head.bias)

    def forward(self, x, t):
        h = self.embed(patchify(x, self.patch)) + self.pos        # (B, N, dim)
        c = self.t_mlp(timestep_embedding(t, self.dim))           # (B, dim)
        for b in self.blocks:
            h = b(h, c)
        shift, scale = self.mod_out(F.silu(c)).chunk(2, dim=-1)
        h = self.head(modulate(self.norm_out(h), shift, scale))   # (B, N, patch*patch*in_ch)
        return unpatchify(h, self.patch, self.img, self.img, self.in_ch)

--- context
The token count N sets the cost of attention (proportional to N²). In the DiT paper, going from patch 8 to patch 2 means 16 times more tokens, much more compute, and much better images. It is the most common trade-off when choosing a model configuration.
--- prompt
Read the code and write the three lines it prints. `patchify` is the function you wrote in d10-01. Each line prints p, the shape of the tokens, and N² (the number of token pairs attention has to score).
--- code
x = torch.randn(1, 4, 32, 32)       # the latent of a 256×256 image after the VAE
for p in [2, 4, 8]:
    tok = patchify(x, p)
    print(p, tuple(tok.shape), tok.shape[1] ** 2)
--- explain
N = (32 / p)², and each token holds 4·p·p numbers. p = 2: N = 16² = 256, 16 numbers per token, N² = 65536. p = 4: N = 64, 64 numbers each, N² = 4096. p = 8: N = 16, 256 numbers each, N² = 256.

Every time p is halved, the token count goes up 4× and the number of pairs attention scores goes up 16×. Each token gets shorter, though: the total count of numbers is always 4×32×32 = 4096. patchify only cuts the same numbers differently and loses nothing.

--- prompt
Read the code and write the two lines it prints (each is True or False). `SelfAttention` is the attention without a mask from the card, and `pos_embed_2d` is the function from d10-02. `perm` is one way to shuffle the 9 tokens.
--- code
torch.manual_seed(0)
attn = SelfAttention(16, 4)
x = torch.randn(1, 9, 16)              # 3×3 = 9 patches
pe = pos_embed_2d(16, 3, 3)            # (9, 16)
perm = torch.tensor([8, 3, 5, 0, 1, 7, 2, 6, 4])
with torch.no_grad():
    a = attn(x)[:, perm]               # compute, then shuffle
    b = attn(x[:, perm])               # shuffle, then compute
    print(torch.allclose(a, b, atol=1e-5))
    a = attn(x + pe)[:, perm]          # compare again with position embeddings added
    b = attn(x[:, perm] + pe)          # the position table itself is not shuffled
    print(torch.allclose(a, b, atol=1e-5))
--- explain
Line one is True. In attention every token scores its similarity with every token and takes a weighted sum. A sum does not care about order, so "shuffle, then compute" equals "compute, then shuffle". The model has no way to know whether a patch was in the top-left or the bottom-right.

Line two is False. Position embeddings are tied to positions: position k always gets pe[k]. When a token moves, the position vector added to it changes, so the output is no longer just a shuffled copy. That is exactly what pos_embed_2d is for: the same content at a different place looks different to the model.
--- hints
- Attention output = a softmax(similarity)-weighted sum of V. If you shuffle the tokens, does the set of tokens each one looks at change?
- In the second comparison the content moves with perm but pe does not, so each token gets a different position vector.

answer: 1
--- context
"Zero-initialize the new layer so the network starts as the identity" shows up in DiT, LoRA and ControlNet. Explaining what it does, and what it does not do, earns points in interviews.
--- prompt
DiT initializes the adaLN modulation Linear (weight and bias) to 0. What is the direct effect at the start of training?
--- options
- Every DiTBlock is the identity: gate = 0 switches off both branches, so the output equals the input
- These parameters can never learn, because the parameters are 0 and so their gradients are 0 too
- The model draws clean images right away
- It saves the cost of the LayerNorm
--- explain
After zero init all 6 groups are 0: shift = scale = 0 makes modulate the identity, and gate = 0 switches off both the attention and the MLP branch, so x = x + 0 = x.

Option 2 is wrong: a parameter being 0 does not make its gradient 0. The gate's gradient comes from the branch output, and after the first update the gate is no longer 0. Option 3 is wrong: an untrained MiniDiT predicts a velocity of 0 everywhere, so sampling returns the starting noise unchanged. Option 4 is wrong: the LayerNorm still runs; only its own γ/β are switched off.
--- hints
- With all 6 groups at 0, put gate = 0 into `x = x + gate * attn(...)`.
- "The parameter is 0" and "the gradient is 0" are different things: the gradient depends on what the parameter multiplies.

The velocity field below is the ideal one when there is only one data point, d = 3: at time t and position x it always points at d, with just the right size to reach d in the remaining time 1 - t. The start is -1. Write the three lines it prints.
--- code
d = torch.tensor([3.0])
v = lambda x, t: (d - x) / (1 - t)

for steps in [1, 2, 4]:
    x = torch.tensor([-1.0])           # the start ("noise")
    dt = 1.0 / steps
    for i in range(steps):

--- explain
All three lines end in 3.0. The first step, at t = 0, has v = (3 - (-1)) / 1 = 4. A real model faces many data points and learns an average velocity, so its paths bend a little and it still needs 20–50 steps. The bent path "velocity = x" from the card reaches only 2.0 in 1 step, far from the true e ≈ 2.718.

def flow_loss(model, x1_data):
    B = x1_data.size(0)
    t = torch.rand(B, device=x1_data.device)
    noise = torch.randn_like(x1_data)
    tt = t.reshape(-1, *([1] * (x1_data.dim() - 1)))
    xt = (1 - tt) * noise + tt * x1_data
    return F.mse_loss(model(xt, t), x1_data - noise)
