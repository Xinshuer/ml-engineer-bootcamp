@@ concept
title: Conv2d and its output size
--- body
In PyTorch a batch of images has shape `(B, C, H, W)`: B images, C channels each (a color image has C=3: red, green, blue), height H, width W.

`nn.Conv2d(in_ch, out_ch, kernel, stride, padding)` is a convolution layer:

- A small kernel×kernel window slides over the image. At each position it outputs `out_ch` numbers.
- **stride**: how many pixels the window moves each step. With stride=2 the output side is about half as long.
- **padding**: rings of zeros added around the image first, so the window can fully cover the border pixels too.

The output side length (`//` is floor division: it rounds down):

```text
H_out = (H + 2*padding - kernel) // stride + 1
```

Example: H=32, kernel=4, stride=2, padding=1 → (32 + 2 − 4) // 2 + 1 = 30 // 2 + 1 = 16.

Three settings worth memorizing:

- kernel 3, stride 1, padding 1: same size
- kernel 4, stride 2, padding 1: half the size
- kernel 1, stride 1, padding 0 (a 1×1 conv): same size, only the number of channels changes

The number of output channels is simply `out_ch`. The formula above does not affect it.
--- code
x = torch.zeros(1, 3, 32, 32)                      # (B, C, H, W)
for k, s, p in [(3, 1, 1), (4, 2, 1), (1, 1, 0), (5, 1, 0)]:
    y = nn.Conv2d(3, 8, k, s, p)(x)
    formula = (32 + 2 * p - k) // s + 1
    print(f"k={k} s={s} p={p}: output {tuple(y.shape)}, the formula gives side {formula}")

@@ concept
title: The VAE: encode an image as a distribution
--- body
An **autoencoder** has two halves:

- The **encoder** squeezes an image into a small block of numbers called the **latent** (written z).
- The **decoder** turns z back into an image.

It is trained to make the copy as close to the original as possible.

A plain autoencoder has a problem: its latent space is full of "holes". Pick a random z, give it to the decoder, and you mostly get garbage. So you cannot use it to make new images.

What a **VAE** (variational autoencoder) changes: the encoder no longer outputs one fixed z. For every number in z it outputs a normal distribution:

- `mu`: the mean
- `logvar`: the log of the variance, log(σ²)

During training we sample a z from that distribution and let the decoder rebuild the image. The loss gets an extra KL term that pulls every distribution toward the standard normal N(0, 1). This fills the latent space and makes it smooth: after training, you can sample any z from N(0, 1) and the decoder draws a reasonable image.

Why logvar: the standard deviation σ must be greater than 0, but a conv layer can output negative numbers. logvar can be any real number, and `std = exp(0.5 * logvar)` is always greater than 0. The 0.5 is there because σ = √(σ²), and inside a log a square root becomes "multiply by 0.5".

The shapes of today's small VAE:

```text
x (B, 3, 32, 32)
  --Encoder-->  mu, logvar (B, 4, 8, 8)
  --sample--->  z (B, 4, 8, 8)
  --Decoder-->  x_hat (B, 3, 32, 32)
```
--- code
logvar = torch.tensor([-4.0, -1.0, 0.0, 1.0, 4.0])   # the network can output any real number
std = torch.exp(0.5 * logvar)                        # standard deviation: always > 0
print("logvar:", logvar.tolist())
print("std   :", [round(v, 3) for v in std.tolist()])
print("var   :", [round(v, 3) for v in (std ** 2).tolist()])

@@ concept
title: Reparameterization: sampling that gradients can pass through
--- body
Training a VAE means sampling z from N(mu, std²). The gradient has to flow from the loss back to the `mu` and `logvar` that the encoder produced. But "draw a random sample" is not ordinary arithmetic.

Sampling with `torch.normal(mu, std)` **raises no error**, but PyTorch defines its gradient with respect to `mu` and `std` as 0. The encoder gets no signal and never learns.

The **reparameterization trick** moves the randomness out of the parameters:

1. First draw standard normal noise that does not depend on any parameter: `eps = torch.randn_like(std)` (same shape and device as `std`)
2. Then compute `z = mu + std * eps`

z has the same distribution as before (mean mu, standard deviation std). But now z is just an addition and a multiplication of mu and std: dz/dmu = 1 and dz/dstd = eps, so the gradient flows back.

`torch.distributions.Normal` works the same way: `.sample()` carries no gradient, and `.rsample()` (r for reparameterized) uses this trick.
--- code
mu = torch.tensor([1.0, 2.0], requires_grad=True)
logvar = torch.tensor([0.0, 2.0], requires_grad=True)

std = torch.exp(0.5 * logvar)
eps = torch.randn_like(std)          # the randomness lives here, independent of the parameters
z = mu + std * eps
z.sum().backward()

print("eps        :", eps)
print("mu.grad    :", mu.grad)                    # dz/dmu = 1
print("logvar.grad:", logvar.grad)                # equals 0.5 * std * eps
print("0.5*std*eps:", (0.5 * std * eps).detach())

@@ concept
title: KL divergence: closed form and Monte Carlo
--- body
The **KL divergence** measures how far a distribution q is from a distribution p. It is always ≥ 0, and it is 0 only when q and p are identical. It is not a true "distance": KL(q‖p) and KL(p‖q) are usually different.

In a VAE, q = N(mu, σ²) (the encoder's distribution) and p = N(0, 1) (the standard normal). For this case the KL has a ready-made formula, called the **closed form**. Per dimension:

```text
KL = 0.5 * (mu² + σ² - 1 - log σ²)
   = 0.5 * (mu² + exp(logvar) - 1 - logvar)
```

- mu=0, logvar=0 (q is p): 0.5 × (0 + 1 − 1 − 0) = 0
- mu=1, logvar=0: 0.5 × (1 + 1 − 1 − 0) = 0.5

The latent dimensions are independent, so the KL of the whole z is the **sum** of the per-dimension KLs. For a mu of shape `(B, 4, 8, 8)`: `.flatten(1)` makes it `(B, 256)`, then `.sum(1)` leaves one number per sample, shape `(B,)`.

A **Monte Carlo estimate** (an average over random samples) follows the definition directly: draw many z from q and average log q(z) − log p(z). More samples make it more accurate, but it is slow and noisy. So training uses the closed form, and Monte Carlo is only a check that the formula is right.
--- code
mu, logvar = torch.tensor(1.0), torch.tensor(0.5)
closed = 0.5 * (mu ** 2 + logvar.exp() - 1 - logvar)

std = torch.exp(0.5 * logvar)
z = mu + std * torch.randn(200000)                     # 200,000 samples from q
log_q = torch.distributions.Normal(mu, std).log_prob(z)
log_p = torch.distributions.Normal(0.0, 1.0).log_prob(z)

print(f"closed form: {closed.item():.4f}")
print(f"Monte Carlo: {(log_q - log_p).mean().item():.4f}")

@@ concept
title: Encoder and decoder: shrink, then grow back
--- body
The **encoder** halves the side length again and again with stride-2 convs: 32 → 16 → 8. The number of channels goes up, so each position can hold more information.

The last layer outputs `2 * z_ch` channels. Cut them in two along the channel dimension (dimension 1):

- `h[:, :z_ch]` → mu
- `h[:, z_ch:]` → logvar

The last layer has no activation after it, because mu and logvar can be any real number.

Between layers we use the **SiLU** activation: SiLU(x) = x · sigmoid(x), a smooth version of ReLU that VAEs and diffusion models use a lot.

The **decoder** does the opposite and doubles the side length again and again:

- `nn.Upsample(scale_factor=2, mode="nearest")` copies each pixel into a 2×2 block, so the side doubles. It has no learnable parameters.
- A conv with kernel 3, stride 1, padding 1 follows (same size). It smooths out the copied blocks.
- Why not upsample with `nn.ConvTranspose2d` (transposed convolution): its windows overlap unevenly, which tends to leave a checkerboard pattern on the image.

The decoder ends with **tanh**, which squeezes any real number into (-1, 1). Training images are usually normalized to [-1, 1] first (pixel value ÷ 127.5 − 1), so the ranges match.

`nn.Sequential(layer1, layer2, ...)` chains layers in order. Calling it passes the input through each layer in turn.
--- code
x = torch.randn(2, 3, 32, 32)
h = nn.Conv2d(3, 8, 4, 2, 1)(x)
print("stride-2 conv       :", tuple(h.shape))
mu, logvar = h[:, :4], h[:, 4:]
print("split along channels:", tuple(mu.shape), tuple(logvar.shape))

up = nn.Upsample(scale_factor=2, mode="nearest")
print("Upsample x2         :", tuple(up(mu).shape))
print(up(torch.tensor([[[[1.0, 2.0], [3.0, 4.0]]]])))
print("tanh:", torch.tanh(torch.tensor([-5.0, 0.0, 0.5, 5.0])))

@@ concept
title: The VAE loss: reconstruction + β·KL
--- body
The VAE loss has two terms. Both are costs (smaller is better), so we **add** them:

```text
total = recon + beta * kl
```

- **recon** (reconstruction error): for each image, **sum** the squared error over all its pixels, then average over the batch.
- **kl**: each sample's KL (summed over all latent dimensions), then averaged over the batch.

Why recon uses a sum and not a mean: a 3×32×32 image has 3072 numbers, while a 4×8×8 latent has only 256. When both terms are "summed per sample", their sizes are comparable (in the code below both are around 30). If recon averaged over pixels, it would be thousands of times smaller, and the KL would win: the model stores nothing in z and the reconstructions come out blurry.

`F.mse_loss(x_hat, x, reduction="sum") / B` is the same number as "sum per image, then average over the batch" (B is the batch size).

**beta** (β) sets the balance between the two:

- Large β: the latent space is closer to the standard normal and smoother, but reconstructions are blurrier and dimensions collapse more easily.
- Small β: sharper reconstructions, but the latent space does not look like a standard normal, so images generated from N(0, 1) samples get worse.
--- code
x = torch.rand(4, 3, 32, 32) * 2 - 1              # 4 images, values in [-1, 1]
x_hat = x + 0.1 * torch.randn_like(x)             # a decent reconstruction
sq = (x_hat - x) ** 2
print("mean over every pixel         :", round(sq.mean().item(), 4))
print("sum per image, mean over batch:", round(sq.flatten(1).sum(1).mean().item(), 2))
print("F.mse_loss(sum) / B           :", round((F.mse_loss(x_hat, x, reduction="sum") / 4).item(), 2))

mu, logvar = 0.5 * torch.randn(4, 4, 8, 8), torch.zeros(4, 4, 8, 8)
kl = 0.5 * (mu ** 2 + logvar.exp() - 1 - logvar).flatten(1).sum(1).mean()
print("KL (sum per sample, then mean):", round(kl.item(), 2))

@@ concept
title: Latent space: compression ratio and scaling_factor
--- body
**Why a latent space**: to generate one image, a diffusion model (day 8) runs a big network tens of times. Stable Diffusion first uses a VAE to squeeze a 512×512×3 image into a 64×64×4 latent. The diffusion model works only in that latent space, and at the end the decoder turns the latent back into an image.

**Compression ratio** = number of elements in the image ÷ number of elements in the latent:

- 512 × 512 × 3 = 786,432
- 64 × 64 × 4 = 16,384
- 786,432 ÷ 16,384 = 48 times

**scaling_factor**: a diffusion model adds standard normal noise to its data, so it wants the data itself to have a standard deviation of about 1. Stable Diffusion's VAE was trained with a very small KL weight (about 1e-6), so its latents were never pulled to N(0, 1): their standard deviation is about 5.5.

The fix: measure the standard deviation σ of a batch of latents and take s = 1/σ.

- After encoding, multiply by s and give the result to the diffusion model (standard deviation ≈ 1).
- When the diffusion model is done, divide by s to undo it, then give the result to the decoder.

That is where the 0.18215 of Stable Diffusion 1.x / 2.x comes from: 1 / 5.49 ≈ 0.182. A different VAE needs its own value (for example, the SDXL VAE uses 0.13025).
--- code
print("compression ratio:", (512 * 512 * 3) / (64 * 64 * 4))

lat = torch.randn(16, 4, 8, 8) * 5.49            # pretend these are latents from a VAE encoder
s = 1.0 / lat.std().item()
z = lat * s                                      # what the diffusion model gets
print(f"std before = {lat.std().item():.2f}, s = {s:.4f}, std after = {z.std().item():.2f}")
print("dividing by s undoes it:", torch.allclose(z / s, lat))

@@ concept
title: Posterior collapse: latent dimensions left unused
--- body
The **posterior** is the distribution the encoder outputs, q(z|x): what z should look like once we have seen the image x.

**Posterior collapse**: for some dimensions, the encoder outputs mu≈0 and logvar≈0 no matter which image it sees. That is exactly the standard normal N(0, 1). The KL of that dimension is ≈0, so the loss is happy. But the dimension carries no information about the image, and the decoder learns to ignore it. It is wasted.

Common causes: β is too large; the decoder is so strong that it can rebuild the input without z (common in text VAEs); early in training the KL term overpowers the reconstruction.

**How to detect it**: look at the KL per dimension, averaged over a batch.

1. For mu and logvar of shape `(B, D)`, compute the KL element by element: shape `(B, D)`.
2. `.mean(0)` averages over the batch: one number per dimension, shape `(D,)`.
3. A dimension whose average KL is below a threshold (for example 0.01) has collapsed.

Do not sum over the dimensions first (that is what `kl_normal` does): then you cannot tell which dimension is unused.

Common remedies: a smaller β; KL warm-up (β grows slowly from 0 to 1 at the start of training).
--- code
B, D = 256, 4
mu, logvar = torch.zeros(B, D), torch.zeros(B, D)
mu[:, 0] = torch.randn(B) * 1.5      # dimension 0: each image gets its own mu, so it carries information
mu[:, 1] = torch.randn(B) * 0.05     # dimension 1: barely changes from image to image
                                     # dimensions 2 and 3: always exactly N(0, 1)
kl = 0.5 * (mu ** 2 + logvar.exp() - 1 - logvar)       # (B, D)
per_dim = kl.mean(0)                                    # (D,)
print("average KL per dimension:", [round(v, 4) for v in per_dim.tolist()])

--- context
While training a VAE you sample z from the distribution the encoder gives you. Sample it directly and the gradient cannot reach the encoder, so the encoder learns nothing. Reparameterization is what makes a VAE trainable, and "why do we need the reparameterization trick?" is a classic interview question.
--- prompt
Write `reparameterize(mu, logvar)`:

- Input: `mu` and `logvar` with the same shape (any shape, for example `(B, 4, 8, 8)`). `logvar` is the log of the variance.
- Output: `z`, same shape as `mu`, drawn from a normal distribution with mean `mu` and standard deviation `std`.
- How: `std = exp(0.5 * logvar)`; draw standard normal noise `eps` with the same shape as `std`; `z = mu + std * eps`.
- Do not use `torch.normal` or `.sample()` from `torch.distributions`: the gradient would not reach `mu` and `logvar`.

The check draws 20,000 samples to test the mean and the standard deviation, then makes sure gradients reach `mu` and `logvar`.
--- starter
def reparameterize(mu, logvar):
    """z = mu + std * eps, where std = exp(0.5 * logvar) and eps ~ N(0, 1)."""
    raise todo()
--- solution
def reparameterize(mu, logvar):
    std = torch.exp(0.5 * logvar)
    return mu + std * torch.randn_like(std)
--- tests
@check("reparameterization")
def t02():
    seed(0)
    mu = torch.zeros(20000, 3)
    logvar = torch.full((20000, 3), math.log(4.0))    # variance 4 -> standard deviation 2
    z = reparameterize(mu, logvar)
    shape_is(z, mu.shape)
    true(abs(z.mean().item()) < 0.05, f"the mean should be about 0 (mu is all zeros), it is {z.mean().item():.3f}")
    true(abs(z.std().item() - 2.0) < 0.05,
         f"the standard deviation should be about 2 (= exp(0.5 * log 4)), it is {z.std().item():.3f}. "
         "With exp(logvar) you would get 4")
    # gradients must reach mu and logvar
    mu2 = torch.zeros(4, 3, requires_grad=True)
    lv2 = torch.zeros(4, 3, requires_grad=True)
    reparameterize(mu2, lv2).sum().backward()
    true(mu2.grad is not None and lv2.grad is not None,
         "no gradient reaches mu or logvar (grad is None): compute z directly from mu and std, without detach")
    true(lv2.grad.abs().sum() > 0,
         "the gradient of logvar is all zeros. torch.normal(mu, std) raises no error but its gradient is 0: write mu + std * eps")
--- hints
- The variance is std squared, so log(std) is half of logvar: `std = torch.exp(0.5 * logvar)`, not `torch.exp(logvar)`.
- `torch.randn_like(std)` makes standard normal noise with the same shape and device as `std`.
- The last line: `return mu + std * torch.randn_like(std)`

--- context
The VAE loss has a KL term that pulls the encoder's distribution toward the standard normal. It is computed at every step, so we use the formula directly (the closed form) instead of sampling. Get one sign wrong and the model still trains, just badly, so we check the formula against a Monte Carlo estimate.
--- prompt
Write `kl_normal(mu, logvar)`: return the KL divergence of q = N(mu, exp(logvar)) from p = N(0, 1).

- Input: `mu` and `logvar` of shape `(B, ...)`. Dimension 0 is the batch; any number of dimensions can follow (for example `(B, 4)` or `(B, 4, 8, 8)`).
- The KL of each element (each dimension): `0.5 * (mu² + exp(logvar) − 1 − logvar)`.
- For each sample, add up the KL over all its dimensions. Return shape `(B,)`.

The second check compares your closed form with a Monte Carlo estimate from 400,000 samples.
--- starter
def kl_normal(mu, logvar):
    """KL( N(mu, exp(logvar)) || N(0, 1) ), summed over all dimensions of each sample; returns (B,)."""
    raise todo()
--- solution
def kl_normal(mu, logvar):
    return 0.5 * (mu ** 2 + logvar.exp() - 1 - logvar).flatten(1).sum(1)
--- tests
@check("closed-form KL")
def t03():
    mu, lv = torch.zeros(2, 5), torch.zeros(2, 5)
    eq(kl_normal(mu, lv), torch.zeros(2), msg="with mu=0 and logvar=0, q is N(0, 1), so the KL must be 0, with shape (B,)")
    k = kl_normal(torch.ones(1, 1), torch.zeros(1, 1))
    eq(k, torch.tensor([0.5]), msg="with mu=1 and logvar=0, KL = 0.5 × (1 + 1 − 1 − 0) = 0.5")

def t04():

    mu = torch.tensor([[0.5, -1.0]])
    lv = torch.tensor([[0.3, -0.7]])
    closed = kl_normal(mu, lv)[0]

    n = 400000
    std = (0.5 * lv).exp()
    z = mu + std * torch.randn(n, 2)
    log_q = (-0.5 * ((z - mu) / std) ** 2 - lv * 0.5 - 0.5 * math.log(2 * math.pi)).sum(-1)

    mc = (log_q - log_p).mean()

         f"closed form {closed.item():.4f} vs Monte Carlo estimate {mc.item():.4f}: too far apart, the closed form is wrong")
--- hints

- `t.flatten(1)` turns `(B, 4, 8, 8)` into `(B, 256)`; then `.sum(1)` gives `(B,)`. It works for `(B, 4)` as well.

class Encoder(nn.Module):
    def __init__(self, z_ch=4):
        super().__init__()
        self.z_ch = z_ch
        self.net = nn.Sequential(
            nn.Conv2d(3, 32, 4, 2, 1), nn.SiLU(),
            nn.Conv2d(32, 64, 4, 2, 1), nn.SiLU(),
            nn.Conv2d(64, 2 * z_ch, 3, 1, 1),
        )
