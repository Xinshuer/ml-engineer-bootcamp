@@ concept
title: state_dict: save the numbers, not the code
ref: day20
--- body
`model.state_dict()` is an ordered dict: **parameter name → tensor**. The name is the attribute path, for example `body.weight`. Besides parameters it also holds buffers (tensors that are part of the model's state but are not trained, like BatchNorm's `running_mean`). Layers without parameters (ReLU, Dropout) do not appear.

There are two ways to save a model:

- `torch.save(model.state_dict(), path)`: saves only the numbers. To load, you first build the model in code (`Net()`), then fill in the numbers with `load_state_dict`. **Use this one.**
- `torch.save(model, path)`: pickles the whole model object. The file records "which module the class lives in and what it is called", plus all attributes. Loading needs **the same class at the same import path**. Rename a file, move a folder or rename the class, and the old file no longer opens. It is also unsafe (next card).

Remember one sentence: **the structure comes from code, the numbers come from the file.**

`Net` below is the small model we use all day: `body` (Linear 4→8) → ReLU → `drop` (Dropout) → `head` (Linear 8→2).
--- code
import os, tempfile

model = Net()
sd = model.state_dict()
for name, t in sd.items():
    print(f"{name:12s} {tuple(t.shape)}")        # drop has no parameters, so it does not appear

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "net.pt")
    torch.save(sd, path)
    fresh = Net()                                                # structure from code
    fresh.load_state_dict(torch.load(path, weights_only=True))   # numbers from the file

model.eval(); fresh.eval()                       # turn dropout off before comparing
x = torch.randn(2, 4)
print("same output?", torch.equal(model(x), fresh(x)))

@@ concept
title: torch.load and pickle: loading can run code
--- body
`.pt` / `.pth` / `.bin` files use pickle (Python's built-in way to turn objects into bytes). Pickle stores more than data: it also stores "which function to call, with which arguments" to rebuild each object when loading. An object can use `__reduce__` to say: when you load me, please call `os.system("...")`. So **loading a pickle = running code the file's author wrote**.

`torch.load(path, weights_only=True)` uses a restricted loader. It only allows plain data: tensors, dicts, lists, tuples, numbers, strings. If the file contains any other function or class, it raises `UnpicklingError` (the message contains "Unsupported global") and runs nothing.

- Since PyTorch 2.6, `weights_only=True` is the default for `torch.load`. Use the `weights_only=False` you see in old tutorials only on files you created yourself.
- This is one more reason to save only the state_dict: it holds only tensors and strings, so `weights_only=True` loads it directly. A file with a pickled model object is refused.
- numpy arrays are not on the allow list either: to save numpy's random state, convert the array inside it to a tensor first.
- For weights from unknown sources, prefer safetensors (later cards).
--- code
import os, pickle, tempfile

class Sneaky:
    def __reduce__(self):          # tells pickle: when loading me, call print(...)
        return (print, ("This line ran while loading! os.system would run just the same.",))

data = pickle.dumps(Sneaky())
pickle.loads(data)                 # we only "loaded", and the code ran

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "bad.pt")
    torch.save({"w": torch.ones(2), "x": Sneaky()}, path)
    try:
        torch.load(path, weights_only=True)
    except Exception as e:
        line = [l for l in str(e).splitlines() if "Unsupported global" in l][0]
        print(type(e).__name__, "->", line.split("Unsupported global:")[1].split(" was")[0].strip())

    torch.save({"w": torch.ones(2)}, path)           # a dict of tensors only
    print(torch.load(path, weights_only=True))       # loads fine

@@ concept
title: Key prefixes: module. and _orig_mod.
ref: day20
--- body
Two common "wrappers" change the keys of a state_dict:

- **DDP / DataParallel** (multi-GPU training): `DDP(model)` keeps your model in the attribute `module`, so `body.weight` becomes `module.body.weight`.
- **torch.compile**: `torch.compile(model)` returns a new wrapper object that keeps the original model in the attribute `_orig_mod`, so the key becomes `_orig_mod.body.weight`. Use both and you may get `_orig_mod.module.body.weight`.

The model you serve has no wrapper, so loading directly fails with a long list of Missing / Unexpected keys. Two fixes:

1. **Save the inner model**: `ddp.module.state_dict()`, or keep the `model` variable from before `torch.compile` and save that. This is the cleanest.
2. **Strip the prefix when loading**: strip it only at the **start** of the key (`str.removeprefix`) and leave the middle alone (the `module` in `encoder.module.weight` may be a real submodule name). PyTorch also has `torch.nn.modules.utils.consume_prefix_in_state_dict_if_present(sd, "module.")`, which changes sd in place.

Below, `Wrapper` imitates DDP (real DDP needs several processes; here we only look at how the keys change).
--- code
model = Net()
wrapped = Wrapper(model)                 # just like DDP(model)
sd = wrapped.state_dict()
print(list(sd)[:2])

fresh = Net()
try:
    fresh.load_state_dict(sd)
except RuntimeError as e:
    for line in str(e).splitlines()[1:]:
        print(line.strip())

print(list(wrapped.module.state_dict())[:2])      # fix 1: save the inner model
clean = {k.removeprefix("module."): v for k, v in sd.items()}
print(fresh.load_state_dict(clean))               # fix 2: strip the prefix at the start

@@ concept
title: strict=False hides bugs
ref: day20
--- body
`model.load_state_dict(sd)` uses `strict=True` by default: the keys on both sides must match exactly, otherwise it raises and lists:

- **missing keys**: the model needs them, the file does not have them. These parameters keep their random initial values.
- **unexpected keys**: the file has them, the model does not know them. These numbers are thrown away.

`strict=False` does not raise. It only puts the two lists in the return value (`result.missing_keys` / `result.unexpected_keys`). Most people never look at the return value. So: a refactor renames `classifier` to `head`, loading "works", the head stays random, and the service ships anyway.

A few rules:

- Loading matches by **name**, not by position. Same structure with different names loads nothing.
- A shape mismatch raises even with `strict=False` (size mismatch).
- When it raises, PyTorch may already have copied the parameters that did match, so the model is left "half new, half old". To stay clean, **check first, then load**.
- If you really want to load only part of a model (say, a new classification head for fine-tuning), use `strict=False` and **check the return value**: the missing keys must be exactly the ones you plan to train from scratch.
--- code
torch.manual_seed(0)
v1 = Net()
sd = {k.replace("head.", "classifier."): v for k, v in v1.state_dict().items()}   # the old version called it classifier

v2 = Net()
result = v2.load_state_dict(sd, strict=False)      # no error!
print("missing:   ", result.missing_keys)
print("unexpected:", result.unexpected_keys)
print("body loaded:", torch.equal(v2.body.weight, v1.body.weight))
print("head loaded:", torch.equal(v2.head.weight, v1.head.weight))

try:
    Net().load_state_dict(sd)                      # default strict=True: fails right away
except RuntimeError as e:
    print("strict=True:", str(e).splitlines()[1].strip())

@@ concept
title: safetensors: a file that holds only tensors
ref: day20
--- body
safetensors is a weight format made by Hugging Face; most open models now ship as `model.safetensors`. The file is simple: a small JSON header (each tensor's name, dtype, shape and position in the file), then the raw bytes.

- **Safe**: only data, no code. Loading someone else's file runs nothing.
- **Fast**: the file can be mapped into memory, and you can read just the one tensor you need (`safe_open` + `get_tensor`).
- **Tensors only**: optimizer state, the step and RNG states do not fit. Small facts can go into `metadata`, but metadata must be "string → string".
- Tensors must be contiguous, and no two names may share the same memory (next card).

The functions you use most (all in `safetensors.torch`):

- `save_file(sd, path, metadata={...})`: saves a "name → tensor" dict.
- `load_file(path)`: reads the dict back; then call `model.load_state_dict(...)`.
- `with safe_open(path, framework="pt") as f:`, then `f.keys()`, `f.get_tensor(name)`, `f.metadata()`.

A common split: weights you publish or deploy go into safetensors; the full mid-training checkpoint (with optimizer and RNG states) goes into a `.pt` file that you load with `weights_only=True`.
--- code
import os, tempfile
from safetensors.torch import save_file, load_file, safe_open

model = Net()
with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "net.safetensors")
    save_file(model.state_dict(), path, metadata={"step": "1200", "arch": "Net"})

    sd = load_file(path)                              # name -> tensor
    print({k: tuple(v.shape) for k, v in sd.items()})
    with safe_open(path, framework="pt") as f:
        print(f.metadata())
        print(f.get_tensor("head.bias").shape)        # read only this one tensor

    try:
        save_file(model.state_dict(), path, metadata={"step": 1200})
    except TypeError as e:
        print("metadata must be strings:", e)

@@ concept
title: Tied weights meet safetensors
ref: day20
--- body
Many language models use one weight matrix for both the token embedding and the output layer (tied weights, as in GPT-2). On the way in it turns tokens into vectors; on the way out it turns vectors back into a score per word. This saves vocab × dim parameters: 50257 × 768 ≈ 38.6 million for GPT-2 small.

In code it is one line: `self.head.weight = self.emb.weight`. Two names, one Parameter. But `state_dict()` lists both names.

- `torch.save` knows they are the same memory, stores it once, and they are still shared after loading.
- safetensors' `save_file` **refuses**: `RuntimeError: Some tensors share memory...`. A flat file cannot say "these two names are the same memory"; forcing it means storing it twice.

The fix: `save_model(model, path)` / `load_model(model, path)` (also in `safetensors.torch`).

- `save_model` finds the shared tensors, stores one name only, and writes "head.weight is really emb.weight" into the metadata.
- `load_model` loads strictly, except that the name dropped because of sharing does not count as missing.
- The weights are still shared after loading, because the sharing is set up by **the model's constructor**; loading only copies numbers into the existing Parameter.
--- code
import os, tempfile
from safetensors.torch import save_file, save_model, load_model, safe_open

lm = TinyLM()
print("same Parameter:", lm.head.weight is lm.emb.weight)
print("state_dict keys:", list(lm.state_dict()))

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "lm.safetensors")
    try:
        save_file(lm.state_dict(), path)
    except RuntimeError as e:
        print("save_file error:", str(e).strip().split(",")[0])

    save_model(lm, path)                                  # stored once
    with safe_open(path, framework="pt") as f:
        print("in the file:", list(f.keys()), f.metadata())

    fresh = TinyLM()
    print("missing, unexpected:", load_model(fresh, path))
    print("still shared:", fresh.head.weight is fresh.emb.weight)
    print("same numbers:", torch.equal(fresh.emb.weight, lm.emb.weight))

@@ concept
title: What a resumable checkpoint must hold
ref: day20
--- body
The bar for "resumable": **interrupted + resumed = never interrupted**, down to the last digit of the loss. For that, the checkpoint needs:

- **The model**: `model.state_dict()`.
- **The optimizer**: `opt.state_dict()`. AdamW keeps two running averages per parameter (`exp_avg`, `exp_avg_sq`, often called momentum) and a step count. Forget it and the loss jumps after resuming.
- **The learning-rate scheduler**: `sched.state_dict()` (which step it is on, the current learning rate). Forget it and the warm-up runs again, or the learning rate jumps back to its peak.
- **The step** (and the epoch, and how far into the data you are): decides where to continue and how the logs join up.
- **RNG states** (the random number generators): `torch.get_rng_state()`; with a GPU also `torch.cuda.get_rng_state_all()`; if you use the `random` module, `random.getstate()`. Dropout and data shuffling depend on them. Forget them and training still runs, but the result differs from the uninterrupted run and cannot be reproduced.
- **EMA weights** (if you use an EMA, common in diffusion models): a second copy of the weights that must be saved too.

To load: build the model, optimizer and scheduler in code, load each `state_dict` back in, and restore the RNG states last.

**How to prove the checkpoint is complete**: run A trains 5 steps without stopping. Run B trains 3 steps → saves → scrambles the RNG and builds brand-new objects (like a restarted process) → loads → trains 2 more steps. A and B must end with exactly the same losses and weights.

Below, `make_run()` returns a model + AdamW + StepLR (halves the learning rate every 2 steps), and `train_step()` trains one step (data is made on the spot with `torch.randn`, and the model has dropout). This checkpoint holds only the model and the optimizer: the first 3 steps match, the 2 resumed steps do not.
--- code
import os, tempfile

torch.manual_seed(0)
model, opt, sched = make_run()
full = [round(train_step(model, opt, sched), 4) for _ in range(5)]
print("5 steps, no stop:   ", full)

torch.manual_seed(0)
model, opt, sched = make_run()
losses = [round(train_step(model, opt, sched), 4) for _ in range(3)]
with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "ckpt.pt")
    torch.save({"model": model.state_dict(), "optimizer": opt.state_dict(), "step": 3}, path)  # only half of it
    torch.manual_seed(999)                 # like a restarted process: a completely different RNG state
    model, opt, sched = make_run()         # brand-new objects
    ckpt = torch.load(path, weights_only=True)
    model.load_state_dict(ckpt["model"])
    opt.load_state_dict(ckpt["optimizer"])
losses += [round(train_step(model, opt, sched), 4) for _ in range(2)]
print("3 steps + 2 resumed:", losses)
print("same?", losses == full)

@@ concept
title: Atomic save: temp file first, then os.replace
--- body
`torch.save(obj, path)` first empties `path`, then writes into it. If the process is killed halfway (pre-emption, OOM, power cut, full disk), you end up with **the old checkpoint gone and the new one broken**.

An atomic save ("either all of it happens, or none of it"):

1. Write to a temporary file first, for example `path + ".tmp"`.
2. Once it is completely written, swap it in with one call: `os.replace(tmp, path)`.

On one file system, `os.replace` is atomic: either it did not happen at all (the old file is still there) or it happened completely (the new file is in place). There is no "half". A few details:

- Put the temporary file in **the same folder** as the target. Across drives (say C: to G:) `os.replace` cannot be atomic, and on Windows it simply fails.
- Use `os.replace`, not `os.rename`: on Windows, `os.rename` fails when the target already exists.
- On an error, delete the temporary file, then re-raise the error unchanged; do not swallow it.
- To be even safer: after writing, call `f.flush()` and `os.fsync(f.fileno())` so the data really reaches the disk (protects against power cuts).
--- code
import io, os, tempfile

new_bytes = io.BytesIO()
torch.save({"step": 200, "w": torch.ones(1000)}, new_bytes)
half = new_bytes.getvalue()[: len(new_bytes.getvalue()) // 2]      # "crashed halfway through writing"

with tempfile.TemporaryDirectory() as folder:
    path = os.path.join(folder, "ckpt.pt")

    # overwrite in place
    torch.save({"step": 100, "w": torch.ones(1000)}, path)          # yesterday's good checkpoint
    with open(path, "wb") as f:
        f.write(half)                                               # half written, process killed
    try:
        torch.load(path, weights_only=True)
    except Exception as e:
        print("overwrite in place: old one gone, new one broken ->", type(e).__name__)

    # atomic
    torch.save({"step": 100, "w": torch.ones(1000)}, path)
    tmp = path + ".tmp"
    with open(tmp, "wb") as f:
        f.write(half)                        # same crash halfway; we never reach os.replace
    print("atomic: the old one is still there -> step", torch.load(path, weights_only=True)["step"])

    torch.save({"step": 200, "w": torch.ones(1000)}, tmp)           # try again, fully written this time
    os.replace(tmp, path)                                           # swap it in with one call
    print("swapped in -> step", torch.load(path, weights_only=True)["step"], sorted(os.listdir(folder)))

def save_and_reload(model, path):
    torch.save(model.[[state_dict()]], path)          # numbers only: name -> tensor

    return fresh

@@ item d20-02
type: choice
title: Why you should not torch.load someone else's .pt
level: 1
cards: torch.load and pickle: loading can run code
--- context
Downloading models from the internet is everyday work. PyTorch 2.6 changed the default of torch.load to weights_only=True precisely to block the attack below.
--- prompt
A colleague found a `model.pt` on a forum. Loading it fails with `UnpicklingError: Weights only load failed ... Unsupported global`. He plans to use `torch.load("model.pt", weights_only=False)` to "make it work". What is the biggest risk?
--- options
- The file is large, and weights_only=False reads it all into memory at once, which can run out of memory
- A .pt file is a pickle; with weights_only=False, loading runs any Python code the file's author put in it (delete files, steal API keys, install a backdoor)
- weights_only=False converts the weights to float64, which hurts precision and speed
- Loading is a little slower, and nothing else changes
answer: 2
--- explain
Pickle stores more than data: it also stores "which function to call when loading, and with which arguments". An object can use `__reduce__` to make the loader call `os.system(...)`. The "Unsupported global" in the error means the file really does contain a function or class to call, not just tensors. So use `weights_only=False` only on files you (or someone you fully trust) created. For other people's weights: prefer safetensors; if all you have is a .pt, use `weights_only=True`. It allows only plain data (tensors, dicts, lists, numbers, strings) and refuses everything else.
--- hints
- The error says "Unsupported global": besides numbers, the file contains something to call.
- When loading, pickle calls functions named in the file to rebuild the objects. Who wrote those instructions?

--- solution
def strip_prefix(sd, prefixes=("module.", "_orig_mod.")):
    out = {}
    for key, value in sd.items():
        while key.startswith(prefixes):          # startswith accepts a tuple: True if the key starts with any of them
            for p in prefixes:
                key = key.removeprefix(p)        # only at the start; unchanged if the key does not start with p
        out[key] = value
    return out

def load_strict(model, sd):
    want = model.state_dict()
    missing = sorted(set(want) - set(sd))
    unexpected = sorted(set(sd) - set(want))
    wrong_shape = [f"{k}: checkpoint {tuple(sd[k].shape)} vs model {tuple(want[k].shape)}"
                   for k in want if k in sd and tuple(sd[k].shape) != tuple(want[k].shape)]

import random

def save_checkpoint(path, model, opt, sched, step):
    ckpt = {
        "model": model.state_dict(),
        "optimizer": opt.state_dict(),        # AdamW's running averages and step count
        "scheduler": sched.state_dict(),      # which step it is on, the current learning rate
        "step": step,
        "rng_torch": torch.get_rng_state(),   # dropout and torch.randn depend on it
        "rng_cuda": torch.cuda.get_rng_state_all() if torch.cuda.is_available() else [],
        "rng_python": random.getstate(),
    }
    torch.save(ckpt, path)

    ckpt = torch.load(path, weights_only=True)
    model.load_state_dict(ckpt["model"])
    opt.load_state_dict(ckpt["optimizer"])
    sched.load_state_dict(ckpt["scheduler"])
    torch.set_rng_state(ckpt["rng_torch"])
    if ckpt["rng_cuda"] and torch.cuda.is_available():
        torch.cuda.set_rng_state_all(ckpt["rng_cuda"])
    random.setstate(ckpt["rng_python"])
    return ckpt["step"]

import os

def atomic_save(obj, path):
    tmp = path + ".tmp"                 # same folder, so os.replace is atomic
    try:
        torch.save(obj, tmp)
        os.replace(tmp, path)           # either it does not happen at all, or it happens completely
    except BaseException:
        if os.path.exists(tmp):
            os.remove(tmp)              # leave no half-written temp file behind
        raise                           # re-raise the original error

    seen, real_save = [], torch.save
    def fake(o, f, *args, **kwargs):

        if hasattr(f, "write"):

import random

def save_checkpoint(path, model, opt, sched, step):
    ckpt = {
        "model": model.state_dict(),
        "optimizer": opt.state_dict(),
        "scheduler": sched.state_dict(),
        "step": step,
        "rng_torch": torch.get_rng_state(),
        "rng_cuda": torch.cuda.get_rng_state_all() if torch.cuda.is_available() else [],
        "rng_python": random.getstate(),
    }
    torch.save(ckpt, path)


def load_checkpoint(path, model, opt, sched):
    ckpt = torch.load(path, weights_only=True)
    model.load_state_dict(ckpt["model"])
    opt.load_state_dict(ckpt["optimizer"])
    sched.load_state_dict(ckpt["scheduler"])
    torch.set_rng_state(ckpt["rng_torch"])
    if ckpt["rng_cuda"] and torch.cuda.is_available():
        torch.cuda.set_rng_state_all(ckpt["rng_cuda"])
    random.setstate(ckpt["rng_python"])
    return ckpt["step"]

def load_strict(model, sd):
    want = model.state_dict()
    missing = sorted(set(want) - set(sd))
    unexpected = sorted(set(sd) - set(want))
    wrong_shape = [f"{k}: checkpoint {tuple(sd[k].shape)} vs model {tuple(want[k].shape)}"
                   for k in want if k in sd and tuple(sd[k].shape) != tuple(want[k].shape)]
    if missing or unexpected or wrong_shape:
        raise ValueError(
            "the checkpoint does not match the model:\n"
            f"  missing (in the model, not in the file): {missing}\n"
            f"  unexpected (in the file, not in the model): {unexpected}\n"
            f"  wrong shape: {wrong_shape}")
    model.load_state_dict(sd)
    return model
