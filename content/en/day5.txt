@@ concept
title: From GPT-2 to Llama: what changed
--- body
Yesterday (day 4) you wrote a GPT-2 style Transformer by hand. Llama (Meta's family of open models) has the same skeleton: token embedding → many blocks → a final norm → lm_head. Each block still does "norm, then attention, add the residual; norm, then FFN, add the residual".

What changes are the parts. Today you swap them one at a time:

1. LayerNorm → **RMSNorm**: no mean subtraction, just divide by the root mean square. Half the parameters.
2. The learned position embedding (GPT-2's `wpe`) → **RoPE**: nothing is added to the input. Instead, every attention layer "rotates" q and k by position.
3. The GELU MLP → **SwiGLU**: one extra "gate" matrix and a slightly narrower hidden layer, so the parameter count stays about the same.
4. No bias in the Linear layers.
5. Multi-head attention (MHA) → **GQA**: several q heads share one k/v head. Used since Llama 2 70B and in Llama 3.

The second half of the day is about generation (inference): the **KV cache** (don't recompute old tokens while generating) and **sampling** (temperature, top-k, top-p, repetition penalty). GPT-2 uses these too, and interviews often ask about them together with Llama.

The example uses Llama-7B's width C = 4096 and counts the parameters before and after some of these changes.
--- code
C = 4096   # the width of every Llama-7B layer
print(f"one norm layer     LayerNorm: {2 * C:,}   RMSNorm: {C:,}")
print(f"one FFN (no bias)  GPT-2 MLP (C->4C->C): {2 * C * 4 * C:,}")
print(f"                   SwiGLU (3 x C x 11008): {3 * C * 11008:,}")
print(f"positions          GPT-2 wpe (1024 positions): {1024 * C:,}   RoPE: 0")

@@ concept
title: RMSNorm: no mean, just the root mean square
--- body
LayerNorm does three things to each token's vector (length C): subtract the mean, divide by the standard deviation, then multiply by a weight and add a bias. It has 2C parameters.

RMSNorm (Root Mean Square Norm) is simpler:
```
rms = sqrt(mean(x²) + eps)
y   = x / rms * weight
```
- It does not subtract the mean. There is no "centring" step.
- It only has a weight (shape (C,), starts as all ones) and no bias: C parameters.
- With the weight at all ones, the output's mean square mean(y²) ≈ 1.
- eps is a tiny number (for example 1e-6) that prevents division by 0.

Why switch: one step less, half the parameters, about the same quality. Llama, Mistral and Qwen all use it.

Two tools for the code: `torch.rsqrt(a)` is 1 / sqrt(a). `x.pow(2).mean(-1, keepdim=True)` averages over the last dimension (C) and keeps it: (B, T, C) becomes (B, T, 1), which broadcasts against (B, T, C).

PyTorch has shipped `nn.RMSNorm` since version 2.4. Interviews and today's exercises want you to write it yourself.
--- code
x = torch.tensor([[1.0, 2.0, 3.0, 4.0]])
ms = x.pow(2).mean(-1, keepdim=True)          # (1+4+9+16)/4 = 7.5
y = x * torch.rsqrt(ms + 1e-6)
print("mean(x^2) =", ms.item())
print("RMSNorm  :", y)
print("mean(y^2) =", round(y.pow(2).mean().item(), 4))
print("LayerNorm:", F.layer_norm(x, (4,)), " <- mean removed: some values are negative")
with torch.no_grad():
    print("built-in nn.RMSNorm:", nn.RMSNorm(4, eps=1e-6)(x))

@@ concept
title: RoPE: rotate q and k by position
--- body
GPT-2 adds "the vector for position t" to the token embedding. RoPE (Rotary Position Embedding) adds nothing. Instead, in every attention layer it **rotates** q and k by an angle that depends on the position. v is not rotated.

How the rotation works:
- A vector of length hd (head_dim, the width of one head) is seen as hd/2 pairs of numbers. Each pair is a point in a plane.
- Pair i has its own angular speed ω_i = 1 / θ^(2i / hd). θ is usually 10000, and i = 0, 1, …, hd/2 − 1.
- At position t, pair i is turned by t · ω_i radians.

With hd = 8, ω = [1, 0.1, 0.01, 0.001]. Pair 0 turns 1 radian per position (fast); the last pair turns only 0.001 radians (slow). Fast pairs tell neighbouring positions apart; slow pairs can express long distances. Llama 3 raises θ to 500000 so the slow pairs turn even more slowly, which helps with longer texts.

All the angles form one table of shape (max_seq_len, hd/2): angle[t, i] = t · ω_i. It is computed once when the model is built; its cos and sin are stored and every layer looks them up. At position 0 every angle is 0: cos = 1 and sin = 0, so nothing turns.

Two tools: `torch.arange(0, hd, 2)` is [0, 2, 4, …], exactly the 2i in the formula. `torch.outer(a, b)` (the outer product) multiplies every element of a with every element of b and gives a (len(a), len(b)) table.

Turning a point (a, b) by φ radians:
```
a' = a · cos φ − b · sin φ
b' = a · sin φ + b · cos φ
```

RoPE has two important properties:
- **Lengths do not change**: a rotation never makes q or k longer or shorter.
- **The dot product depends only on the distance**: q at position m was turned by m·ω, k at position n by n·ω. The dot product of two vectors depends only on their lengths and the angle between them, and after both rotations that angle has changed by exactly (n − m)·ω. So the attention score q·k depends only on the distance n − m: q at 3 with k at 5 gives the same score as q at 20 with k at 22. The model learns "how many positions apart", not "at which position".
--- code
print("2i =", torch.arange(0, 8, 2))
w = 1.0 / (10000.0 ** (torch.arange(0, 8, 2).float() / 8))
print("angular speeds ω for hd=8:", w)
print("an outer product:\n", torch.outer(torch.arange(3).float(), torch.tensor([1.0, 0.1])))

def rot2(v, phi):                      # turn a point (a, b) by phi radians
    c, s = math.cos(phi), math.sin(phi)
    return torch.stack([v[0] * c - v[1] * s, v[0] * s + v[1] * c])

q, k = torch.tensor([1.0, 2.0]), torch.tensor([0.5, -1.0])
w0 = 0.3                               # the angular speed of this pair
print("q at 3,  k at 5 :", round((rot2(q, 3 * w0) @ rot2(k, 5 * w0)).item(), 4))
print("q at 20, k at 22:", round((rot2(q, 20 * w0) @ rot2(k, 22 * w0)).item(), 4), " <- same distance, same dot product")
print("q at 3,  k at 9 :", round((rot2(q, 3 * w0) @ rot2(k, 9 * w0)).item(), 4), " <- other distance, other dot product")

@@ concept
title: Writing RoPE: pairs, interleaving, complex numbers
--- body
Before writing RoPE code you must decide which two dimensions form a "pair". There are two conventions:
- **Neighbouring pairs** (Meta's original Llama code, and today's exercises): (x0, x1), (x2, x3), …. `x[..., 0::2]` takes all even dimensions (the first number a of each pair); `x[..., 1::2]` takes all odd dimensions (the second number b).
- **Half-and-half pairs** (HuggingFace's `rotate_half`): the first half is paired with the second half. With hd = 8 the pairs are (x0, x4), (x1, x5), ….

Both are correct. But the weights were trained (or converted) for one of them. Using the wrong one **raises no error**; the model just produces garbage.

With neighbouring pairs, after computing the new a' and b' you must **interleave** them back: a'0, b'0, a'1, b'1, …. `torch.stack([a', b'], dim=-1)` gives (…, hd/2, 2), and `.flatten(-2)` merges the last two dimensions into (…, hd). A plain `torch.cat([a', b'], dim=-1)` gives a'0, a'1, …, b'0, b'1, …, which is the wrong order.

How the shapes fit: x is (B, nh, T, hd), so `x[..., 0::2]` is (B, nh, T, hd/2). cos and sin are (T, hd/2), the same as its last two dimensions, so they broadcast. No loop needed.

**The complex-number form** (what Meta's original code does): see a pair (a, b) as the complex number a + bi. Multiplying by e^(iφ) = cos φ + i·sin φ turns it by φ radians, because multiplying complex numbers adds their angles and multiplies their lengths.
- `torch.view_as_complex(t)`: the last dimension of t must be 2; (…, hd/2, 2) becomes a complex tensor (…, hd/2). So first `reshape(*x.shape[:-1], -1, 2)`.
- `torch.polar(r, φ)`: the complex number with length r and angle φ. With r = 1 everywhere it is e^(iφ).
- `torch.view_as_real(z)`: complex (…, hd/2) back to (…, hd/2, 2); then `.flatten(-2)`.
- Complex tensors only support types such as float32/float64, so start with `x.float()` and finish with `.type_as(x)` to return x's original dtype.
--- code
x = torch.arange(8.0)
a, b = x[0::2], x[1::2]
print("even dims a:", a, " odd dims b:", b)
print("stack + flatten:", torch.stack([a, b], dim=-1).flatten(-2), " <- interleaved: original order")
print("cat            :", torch.cat([a, b], dim=-1), " <- order is scrambled")

z = torch.view_as_complex(torch.tensor([3.0, 4.0]))           # 3 + 4i
turn = torch.polar(torch.tensor(1.0), torch.tensor(math.pi / 2))   # e^(i·90°)
print("complex:", z)
print("turned by 90°:", torch.view_as_real(z * turn).round(decimals=4), " <- (3, 4) becomes (-4, 3); length still 5")

@@ concept
title: SwiGLU: an FFN with a gate
--- body
GPT-2's FFN (feed-forward layer): C → 4C → C with GELU in the middle. Two matrices with 2 · C · 4C = 8C² parameters (not counting biases).

Llama's SwiGLU uses three Linear layers without bias:
```
w1: C -> H     w3: C -> H     w2: H -> C
out = w2( silu(w1(x)) * w3(x) )
```
- `silu(z) = z · sigmoid(z)` (also called Swish); in PyTorch it is `F.silu`.
- `w3(x)` acts as a "gate": it is multiplied element by element with `silu(w1(x))` and decides how much of each hidden unit gets through.
- The three matrices have 3 · C · H parameters. To match GPT-2's 8C², take H = (2/3) · 4C = 8C/3, so that 3 · C · H = 8C².

8C/3 is usually not a whole number, nor a size the hardware likes. Llama first rounds it down with `int(...)`, then rounds **up** to a multiple of multiple_of (for example 256). For C = 4096: 8 × 4096 / 3 = 10922.67 → 10922 → up to a multiple of 256 = 11008 (43 × 256). That is Llama-7B's FFN width.

Rounding h up to a multiple of m with integers: `((h + m - 1) // m) * m` (`//` is integer division).
--- code
z = torch.tensor([-2.0, 0.0, 2.0])
print("F.silu        :", F.silu(z))
print("z * sigmoid(z):", z * torch.sigmoid(z))
print("8C/3, C=4096  :", 2 * (4 * 4096) / 3, "-> int:", int(2 * (4 * 4096) / 3))
m = 256
for h in (10922, 11008, 11009):
    print(h, "rounded up to a multiple of 256 ->", ((h + m - 1) // m) * m)

@@ concept
title: GQA: several q heads share one k/v head
--- body
Ordinary multi-head attention (MHA): with n_head q heads there are also n_head k heads and n_head v heads. During generation the k and v of every layer are stored (the KV cache, next card), and that is where most of the memory goes.

GQA (Grouped-Query Attention): k and v only have n_kv_head heads (for example 8). Each group of n_rep = n_head / n_kv_head q heads shares one k/v head. The KV cache becomes n_rep times smaller. Example: Llama 2 70B has 64 q heads and 8 kv heads, so n_rep = 8 and the cache is 8 times smaller. The extreme case n_kv_head = 1 is called MQA (Multi-Query Attention).

Before attention, the head dimension of k and v is "copied" up to n_head heads. After that it is exactly ordinary attention. This function is usually called `repeat_kv`.

The order matters: q heads 0 to n_rep − 1 belong to group 0, so the copied kv heads must be ordered 0,0,…,1,1,… (each one repeated back to back), not 0,1,0,1,….

Three steps:
1. `x[:, :, None]`: insert a new dimension of length 1 after the head dimension. (B, n_kv, T, hd) → (B, n_kv, 1, T, hd).
2. `.expand(B, n_kv, n_rep, T, hd)`: "stretch" that length-1 dimension to n_rep. expand copies no memory; it just lets the same data be seen n_rep times.
3. `.reshape(B, n_kv * n_rep, T, hd)`: merge the (n_kv, n_rep) dimensions into one.
--- code
x = torch.tensor([1.0, 2.0]).view(1, 2, 1, 1)     # (B=1, n_kv_head=2, T=1, hd=1)
x5 = x[:, :, None]
print("after inserting a dim:", tuple(x5.shape))
e = x5.expand(1, 2, 2, 1, 1)                        # n_rep = 2
print("after expand:", tuple(e.shape))
print("merged into 4 heads:", e.reshape(1, 4, 1, 1).flatten().tolist(), " <- each kv head twice, back to back")

@@ concept
title: KV cache: compute only the newest token
--- body
Text is generated one token at a time: feed the sequence to the model, take the logits at the last position, sample the next token, append it, and repeat.

Without a cache, step t recomputes k and v for every earlier token. But the previous step already computed them, and they cannot change (with causal attention, old positions cannot see the new token, so their results do not depend on it).

**KV cache**: every layer stores the k and v it has already computed. From then on, each step feeds only the one new token:
1. Compute q, k, v for the new token only; the time dimension has length 1: (B, nh, 1, hd).
2. Apply RoPE to q and k using the token's **position t in the whole sequence**, not 0.
3. Append the new k and v to the cache along the time dimension (dim=-2): `torch.cat([old, new], dim=-2)`.
4. Run attention with this one q over all k and v in the cache.

Step 4 needs **no causal mask**. A causal mask stops a position from seeing the positions after it. Here the only q is the newest position, and every k in the cache is before it (or is itself), so it may see all of them anyway.

How to prove it is right (this is also how it is tested at work): the output of feeding one token at a time must equal, position by position, the output of feeding the whole sequence at once (with a causal mask). If they differ, the position index is wrong nine times out of ten. How much memory a KV cache takes is worked out on day 23.
--- code
torch.manual_seed(0)
q, k, v = torch.randn(1, 1, 5, 4), torch.randn(1, 1, 5, 4), torch.randn(1, 1, 5, 4)
full = F.scaled_dot_product_attention(q, k, v, is_causal=True)   # all 5 positions at once
last = F.scaled_dot_product_attention(q[:, :, -1:], k, v)         # only the last q, no mask
print("last position of the full pass:", full[0, 0, -1])
print("one step (no mask)            :", last[0, 0, 0])
print("equal:", torch.allclose(full[:, :, -1:], last, atol=1e-6))

cache_k = torch.zeros(1, 2, 0, 4)                 # empty cache: time length 0
for t in range(3):
    cache_k = torch.cat([cache_k, torch.randn(1, 2, 1, 4)], dim=-2)
    print(f"after step {t}, cache shape:", tuple(cache_k.shape))

@@ concept
title: Sampling: temperature, top-k, top-p, repetition penalty
--- body
At the last position the model outputs logits (the raw score for every word, before softmax), shape (B, V), where V is the vocabulary size. The usual way to pick the next token:
1. **Repetition penalty** (optional): lower the scores of tokens that have already appeared.
2. **Temperature**: logits / T. T < 1 makes the distribution sharper (more certain); T > 1 makes it flatter (more random). T = 0 is the convention for "greedy": keep only the largest (argmax). You cannot actually divide by 0.
3. **top-k**: keep the k largest scores and set the rest to -inf. After softmax, -inf has probability 0.
4. **top-p** (nucleus sampling): sort by probability, largest first, and add them up. Stop when the running total **first reaches ≥ p**; keep that token too and drop everything after it. Always keep at least 1.
5. Softmax gives probabilities; `torch.multinomial` draws one token.

A top-p example: probabilities [0.5, 0.3, 0.15, 0.05], p = 0.7. Running total: 0.5, 0.8. The total first reaches ≥ 0.7 at the 2nd token, so the first 2 are kept. A handy rule: if the running total **before** a token (not counting itself) is already ≥ p, drop that token.

The top-p code sorts first: `s, idx = logits.sort(dim=-1, descending=True)`; s holds the sorted values and idx their original positions. Decide what to drop in sorted order, then use `scatter` with idx to put the decision back in the original order.

**Repetition penalty** (the `repetition_penalty` parameter of HuggingFace `generate`): penalty > 1. For every token that has appeared: if its logit > 0, divide by penalty; if ≤ 0, multiply by penalty. Both make it smaller. If you only divided, a negative logit would grow (−2 / 2 = −1) and become more likely.

Reading and writing by index in one go: `logits.gather(1, ids)` reads the scores at ids; `logits.scatter(1, ids, new_values)` writes them back and returns a new tensor.
--- code
logits = torch.tensor([1.0, 2.0, 3.0, 4.0])
for T in (0.5, 1.0, 2.0):
    print(f"T={T}: probabilities", (logits / T).softmax(-1))
print("the 2 largest:", logits.topk(2).values)

probs = torch.tensor([0.5, 0.3, 0.15, 0.05])
print("running total             :", probs.cumsum(-1))
print("total before each (w/o it):", probs.cumsum(-1) - probs)

ids = torch.tensor([3, 0])
print("gather:", logits.gather(0, ids))
print("scatter:", logits.scatter(0, ids, torch.tensor([-1.0, -1.0])))

--- context
Every layer of Llama, Mistral and Qwen uses RMSNorm instead of LayerNorm. You will meet it when reading open-source model code and in hand-written interview questions.
--- prompt
Write `RMSNorm(nn.Module)`:
- `__init__(self, dim, eps=1e-6)`: store `eps` and create one learnable parameter `self.weight` (an `nn.Parameter`) of shape `(dim,)`, starting as all ones. No bias.

    """y = x / sqrt(mean(x^2) + eps) * weight
    Only one learnable parameter, weight, of shape (dim,), starting as all ones. No bias, no mean subtraction.
    """

    def __init__(self, dim, eps=1e-6):
        super().__init__()
        raise todo()

    def forward(self, x):
        raise todo()
--- solution
class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps) * self.weight
--- tests
@check("parameters = dim, output mean square ≈ 1, mean not removed")
def t01():
    seed(0)
    m = RMSNorm(8)
    true(params(m) == 8, f"there should be 8 parameters (only the weight). LayerNorm has 16; the bias is the half you save. Yours: {params(m)}")
    x = torch.randn(2, 5, 8) * 7 + 3
    y = m(x)
    eq(y.pow(2).mean(-1), torch.ones(2, 5), tol=1e-3,
       msg="the mean square mean(y²) over the last dimension should be ≈ 1. Check that you average over the last dimension (-1) with keepdim=True")
    # the key difference from LayerNorm: the mean is not subtracted
    true(abs(y.mean().item()) > 1e-3, "the output mean is almost 0: did you subtract the mean? RMSNorm does not")
--- hints
- There is one parameter: `self.weight = nn.Parameter(torch.ones(dim))`. Don't forget `self.eps = eps`.
- The mean square: `x.pow(2).mean(-1, keepdim=True)`, shape (..., 1), which broadcasts against x. `torch.rsqrt(a)` is 1 / sqrt(a).
- `forward` is one line: `return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps) * self.weight`

title: The RoPE frequency table

--- context
RoPE's cos/sin table is computed once when the model is built, and every layer reads it at every step. If the table is wrong (say, a wrong exponent), the model still runs; the position information is just scrambled. That kind of bug is very hard to spot.
--- prompt
Write `precompute_freqs(head_dim, max_seq_len, theta=10000.0)` that returns `(cos, sin)`, both of shape `(max_seq_len, head_dim // 2)`.
- The angular speed of pair i: `ω_i = 1 / theta ** (2i / head_dim)`, for i = 0, 1, …, head_dim/2 − 1.
- The angle of pair i at position t is `t * ω_i`.
- Return the cos and sin of this table of angles.

Example: with head_dim = 8, ω = [1, 0.1, 0.01, 0.001], so cos[3, 0] = cos(3) and sin[5, 0] = sin(5). No Python loops.
--- above
# Where the input comes from: when a Llama model is built, the cos/sin table is computed once from the head width and max length
head_dim, max_seq_len = 4, 6   # one head has 4 dims (2 pairs), at most 6 positions
--- below
cos, sin = precompute_freqs(head_dim, max_seq_len)
print("cos:", tuple(cos.shape), " sin:", tuple(sin.shape))
print("position 0, cos:", cos[0].tolist(), " sin:", sin[0].tolist())
print("position 2, cos:", [round(v, 4) for v in cos[2].tolist()])
--- starter
def precompute_freqs(head_dim, max_seq_len, theta=10000.0):
    """Returns (cos, sin), both of shape (max_seq_len, head_dim // 2).
    angular speed of pair i = 1 / theta ** (2i / head_dim), i = 0, 1, ..., head_dim/2 - 1
    angle at position t = t * angular speed
    """
    raise todo()
--- solution
def precompute_freqs(head_dim, max_seq_len, theta=10000.0):
    inv = 1.0 / (theta ** (torch.arange(0, head_dim, 2).float() / head_dim))
    ang = torch.outer(torch.arange(max_seq_len).float(), inv)   # (T, hd/2)
    return ang.cos(), ang.sin()
--- tests
@check("shapes, no turn at position 0, pair 0 has speed 1, high dims turn slower")
def t02():
    cos, sin = precompute_freqs(8, 16)
    shape_is(cos, (16, 4), "cos should be (max_seq_len, head_dim // 2)")
    shape_is(sin, (16, 4), "sin should be (max_seq_len, head_dim // 2)")
    eq(cos[0], torch.ones(4), msg="every angle at position 0 is 0, so cos should be all ones")
    eq(sin[0], torch.zeros(4), msg="every angle at position 0 is 0, so sin should be all zeros")
    # pair 0 has angular speed 1, so its angle at position t is just t
    eq(cos[3, 0], torch.tensor(math.cos(3.0)), msg="pair 0 has speed 1, so its angle at position 3 is 3: cos[3, 0] = cos(3)")
    eq(sin[5, 0], torch.tensor(math.sin(5.0)), msg="pair 0 has speed 1, so its angle at position 5 is 5: sin[5, 0] = sin(5)")
    # the last pair turns slowest
    true(abs(sin[1, -1].item()) < abs(sin[1, 0].item()), "the last pair should turn slowest: check that the exponent is 2i / head_dim and not upside down")
--- hints
- `torch.arange(0, head_dim, 2)` is exactly [0, 2, 4, …], the 2i in the formula. Add `.float()` so the division and power work on decimals, not integers.
- Take the outer product of the positions `torch.arange(max_seq_len).float()` and ω: `torch.outer(positions, ω)` gives the (T, hd/2) table of angles.
- `inv = 1.0 / (theta ** (torch.arange(0, head_dim, 2).float() / head_dim))`, `ang = torch.outer(torch.arange(max_seq_len).float(), inv)`, then return `ang.cos(), ang.sin()`.

    """x: (B, nh, T, hd)   cos/sin: (T, hd//2)  ->  (B, nh, T, hd)

def apply_rope(x, cos, sin):
    x1, x2 = x[..., 0::2], x[..., 1::2]        # neighbouring pairs
    o1 = x1 * cos - x2 * sin
    o2 = x1 * sin + x2 * cos
    return torch.stack([o1, o2], dim=-1).flatten(-2)   # interleave back

def swiglu_hidden(n_embd, multiple_of=256):
    h = int(2 * (4 * n_embd) / 3)
    return multiple_of * ((h + multiple_of - 1) // multiple_of)

class KVCache:
    def __init__(self):
        self.k = None
        self.v = None

    @property
    def length(self):
        return 0 if self.k is None else self.k.size(-2)

    def update(self, k, v):
        self.k = k if self.k is None else torch.cat([self.k, k], dim=-2)
        self.v = v if self.v is None else torch.cat([self.v, v], dim=-2)
        return self.k, self.v

    def reset(self):
        self.k = self.v = None

def attn_step(q, k_all, v_all):

def incremental_attention(x, wq, wk, wv, cos, sin):
    B, T, C = x.shape
    nh, hd = 2, C // 2
    cache = KVCache()
    outs = []
    for t in range(T):
        xt = x[:, t:t + 1]
        q = (xt @ wq).view(B, 1, nh, hd).transpose(1, 2)
        k = (xt @ wk).view(B, 1, nh, hd).transpose(1, 2)
        v = (xt @ wv).view(B, 1, nh, hd).transpose(1, 2)
        q = apply_rope(q, cos[t:t + 1], sin[t:t + 1])    # the key point: use position t's angles
        k = apply_rope(k, cos[t:t + 1], sin[t:t + 1])
        K, V = cache.update(k, v)
        o = attn_step(q, K, V)
        outs.append(o.transpose(1, 2).reshape(B, 1, C))
    return torch.cat(outs, dim=1)

def apply_temperature(logits, t):
    if t == 0:
        return logits.masked_fill(logits < logits.max(-1, keepdim=True).values, float("-inf"))
    return logits / t

def top_k_filter(logits, k):
    kth = logits.topk(k, dim=-1).values[..., -1:]
    return logits.masked_fill(logits < kth, float("-inf"))

def top_p_filter(logits, p):
    s, idx = logits.sort(dim=-1, descending=True)
    probs = s.softmax(-1)
    cum = probs.cumsum(-1)
    remove = (cum - probs) >= p          # the total *before* this token is already enough -> drop it
    remove[..., 0] = False               # keep at least one
    mask = torch.zeros_like(remove).scatter(-1, idx, remove)
    return logits.masked_fill(mask, float("-inf"))

    """logits: (B, V)   prev_ids: (B, T) tokens generated so far.

--- solution
def repetition_penalty(logits, prev_ids, penalty=1.2):
    s = logits.gather(1, prev_ids)
    s = torch.where(s > 0, s / penalty, s * penalty)
    return logits.scatter(1, prev_ids, s)

```python
def _full_attention(x, wq, wk, wv, cos, sin):
    B, T, C = x.shape
    nh, hd = 2, C // 2
    q = (x @ wq).view(B, T, nh, hd).transpose(1, 2)
    k = (x @ wk).view(B, T, nh, hd).transpose(1, 2)
    v = (x @ wv).view(B, T, nh, hd).transpose(1, 2)
    q, k = apply_rope(q, cos[:T], sin[:T]), apply_rope(k, cos[:T], sin[:T])
    return F.scaled_dot_product_attention(q, k, v, is_causal=True).transpose(1, 2).reshape(B, T, C)
```

--- solution
def incremental_attention(x, wq, wk, wv, cos, sin):
    B, T, C = x.shape
    nh, hd = 2, C // 2
    cache = KVCache()
    outs = []
    for t in range(T):
        xt = x[:, t:t + 1]
        q = (xt @ wq).view(B, 1, nh, hd).transpose(1, 2)
        k = (xt @ wk).view(B, 1, nh, hd).transpose(1, 2)
        v = (xt @ wv).view(B, 1, nh, hd).transpose(1, 2)
        q = apply_rope(q, cos[t:t + 1], sin[t:t + 1])    # the key point: use position t's angles
        k = apply_rope(k, cos[t:t + 1], sin[t:t + 1])
        K, V = cache.update(k, v)
        o = attn_step(q, K, V)
        outs.append(o.transpose(1, 2).reshape(B, 1, C))
    return torch.cat(outs, dim=1)
