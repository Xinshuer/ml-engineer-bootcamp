@@ concept
title: Functions: return hands the result back
--- body
A function is a piece of code with a name. When you define it with `def`, the code inside does not run yet. It runs when you call it: the name followed by parentheses.

`return` does three things:

1. It hands a value back to the caller. After `r = double(5)`, r holds that value.
2. It ends the function at once. Code below `return` does not run.
3. A function without `return` gives back `None` ("no value"). Even if it computed the right thing, the result is thrown away.

Parameters can have defaults: with `def power(base, exp=2)`, calling it without `exp` uses 2. You can also pass by name: `power(3, exp=4)`. That is clearer, and model code does it everywhere.

To return several values, write `return lo, hi`. That returns a tuple, and the caller can split it: `lo, hi = min_max(xs)`. This is called unpacking. You will see it all the time: `logits, loss = model(x, y)`.

### Reading an error: start at the last line

The last line of an error message (a traceback) says what went wrong. The lines above it say where. The line that failed is often just the victim; the cause is earlier. The most common ones:

- `TypeError: ... 'NoneType' ...`: you computed with `None`. First question: which function gave you this value, and does it have a `return`?
- `NameError: name 'x' is not defined`: a typo, or you used a local variable from another function.
- `AttributeError: 'X' object has no attribute 'y'`: the object has no y. Usual causes: you forgot `self.y = ...` in `__init__`, or you forgot `super().__init__()`.
- `KeyError`: the dict has no such key. `IndexError`: the index is out of range (the largest index is `len(xs) - 1`).
--- code
def double(n):
    return n * 2

def no_return(n):
    n * 2              # computed, but no return: the result is thrown away

def min_max(xs):
    return min(xs), max(xs)

print(double(5))
print(no_return(5))
lo, hi = min_max([3, 1, 4, 1, 5])
print(lo, hi)

try:
    no_return(5) * 3   # multiplying None by 3
except TypeError as e:
    print("TypeError:", e)

@@ concept
title: Slices and loops: the start is in, the end is out
--- body
`xs[a:b]` takes the elements at indexes a, a+1, …, b-1: **the start is included, the end is not**, so you get b-a elements. Indexes start at 0, and `xs[-1]` is the last element. `xs[:k]` and `xs[k:]` split a list into two halves that do not overlap. Strings slice the same way, and a slice of a string is a string.

`range(start, stop, step)` follows the same rule: `range(0, 10, 3)` gives 0, 3, 6, 9.

`for x in xs:` takes the elements out one at a time. For each one, it runs the indented code below from top to bottom. Common patterns:

- Accumulate: start with `total = 0`, then `total += x` inside the loop. Summing up the loss during training works like this.
- Comprehension: `[x * x for x in xs]` builds a new list in one line. To read it, look at the `for` in the middle first, then at the front: what each round produces.
- `enumerate(xs)` gives the index and the element together. `zip(a, b)` pairs two lists by position and stops at the shorter one, so `zip(xs, xs[1:])` gives every pair of neighbours.
- `continue` skips the rest of this round and moves to the next one; `break` ends the whole loop at once.

### Next-token training data is two slices

`x = data[i:i + T]` and `y = data[i + 1:i + 1 + T]`. Each element of y is the element that comes right after the one at the same position in x. Get this `+ 1` wrong and the model learns to copy the answer, with no error at all.
--- code
xs = [10, 20, 30, 40, 50]
print(xs[1:3], xs[:2], xs[2:], xs[-1])
print("abcdef"[1:4])
print(list(range(0, 10, 3)))

total = 0
for x in xs:
    total += x
print("total =", total)
print([x // 10 for x in xs])

for i, (a, b) in enumerate(zip(xs, xs[1:])):
    print(i, a, b, b - a)

data = list(range(10))
i, T = 3, 4
print("x =", data[i:i + T])
print("y =", data[i + 1:i + 1 + T])

@@ concept
title: dict: counting and sorting
--- body
A list uses number indexes (`xs[0]`). A dict uses keys that you choose: `cfg["lr"]`. If the key is missing, `cfg["x"]` raises `KeyError`, while `cfg.get("x", 0)` returns the default you gave, 0.

The standard way to count. Read it as "take c's count so far (0 if there is none), add 1, store it back":

```
counts[c] = counts.get(c, 0) + 1
```

`d.items()` gives every `(key, value)` pair. `sorted(things, key=function)` sorts by the value the function computes, smallest first, and returns a new list:

- `lambda kv: ...` is a small function without a name. Here kv is one `(key, value)` pair, and `kv[1]` is the value.
- Largest first: negate inside the key, `key=lambda kv: -kv[1]`.
- "By count, largest first; if counts tie, by key, smallest first": let the key return a tuple, `(-kv[1], kv[0])`. Tuples compare their first elements first, and only look at the second element on a tie.

A dict comprehension works like a list comprehension: `{c: i for i, c in enumerate(chars)}`. On day 3 the tokenizer uses exactly this to turn characters into numbers.
--- code
counts = {}
for c in "banana":
    counts[c] = counts.get(c, 0) + 1
print(counts)
print(counts.get("z", 0))

for k, v in counts.items():
    print(k, v)

print(sorted(counts.items(), key=lambda kv: -kv[1]))
print(sorted([("x", 1), ("r", 2), ("b", 2)], key=lambda kv: (-kv[1], kv[0])))

stoi = {c: i for i, c in enumerate("abc")}
print(stoi)

@@ concept
title: Assignment is a label, not a copy
--- body
In Python, `b = a` never copies data. It sticks a second label, b, on the thing a points to. If that thing can be changed in place (a list, a dict, and later tensors and models), changing it through b also changes what you see through a. Passing a list to a function works the same way: the function gets the same list, not a copy.

- To really copy, say so: `a.copy()` or `list(a)`.
- `==` asks "are the values equal?"; `is` asks "is it the same object?".
- Numbers, strings and tuples cannot be changed in place. `n = n + 1` makes n point to a new number, and no other name is affected, so there is nothing to worry about.

### The trap that follows: mutable default arguments

In `def f(x, acc=[])`, that `[]` is created **when the function is defined**, and only once. Every later call uses the same list, so results from one call leak into the next.

The fix: use `None` as the default and create the list inside the function (`if acc is None: acc = []`), or do not make it a parameter at all and write `acc = []` as the function's first line.

A list field in a dataclass must be `field(default_factory=list)` for the same reason: each object gets a fresh list.
--- code
a = [1, 2, 3]
b = a
b.append(4)
print("a =", a, "| a is b:", a is b)

c = a.copy()
c.append(5)
print("a =", a, "| c =", c, "| a is c:", a is c)

def bad(x, acc=[]):
    acc.append(x)
    return acc

print(bad(1))
print(bad(2))      # you expected [2]

def good(x, acc=None):
    if acc is None:
        acc = []   # a new list on every call
    acc.append(x)
    return acc

print(good(1))
print(good(2))

@@ concept
title: class: self, __init__ and __call__
--- body
A class is a blueprint. It packs some data together with the functions that work on that data. The things built from the blueprint are instances (objects). You can build many, and they do not affect each other.

- `__init__(self, ...)`: Python calls it automatically when an object is built. Use it to attach the starting data to the object. It has no `return`.
- `self` is the object to the left of the dot. When you write `a.add(5)`, Python actually runs `Counter.add(a, 5)`. That is why a method's first parameter is `self`, and why you do not pass it when you call the method.
- `self.n = 0` attaches data to the object, so other methods and outside code can read it. A variable without `self.` inside a method is local and disappears when the method ends. In one sentence: **if data must outlive the function, attach it to self.**
- `__call__(self, ...)`: define it and the object can be called like a function. `obj(x)` is the same as `obj.__call__(x)`.

Methods with two underscores on each side ("dunder" methods) are the ones Python calls for you at specific moments.

In PyTorch, `y = model(x)` works because `nn.Module` defines `__call__`, which then calls the `forward` you wrote. So always write `model(x)`, never `model.forward(x)` (that skips the hooks PyTorch has registered).
--- code
class Scaler:
    def __init__(self, factor):
        self.factor = factor      # attached to self: every later method can use it
        self.calls = 0

    def __call__(self, x):
        self.calls += 1
        return x * self.factor

double = Scaler(2)
triple = Scaler(3)
print(double(21), triple(21))
print(double(1), double.calls, triple.calls)
print(Scaler.__call__(double, 5))  # exactly the same as double(5)

class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(4, 2)

    def forward(self, x):
        return self.fc(x)

m = Tiny()
y = m(torch.ones(3, 4))            # nn.Module's __call__ -> your forward
print(y.shape)

@@ concept
title: Inheritance, super() and @property
--- body
Inheritance: `class B(A):` means B starts with a copy of all of A's methods, then adds some and changes some. A method in the child with the same name replaces the parent's.

`super()` means "the parent class". Two standard uses:

- If the child writes its own `__init__`, the parent's `__init__` is replaced and does not run by itself. So the first line of the child's `__init__` is `super().__init__(...)`: let the parent attach its attributes first, then add your own.
- If the child rewrites a method but wants to keep the parent's behaviour, call `super().method_name(...)` inside it first, then add your own steps.

The first line of every `nn.Module` subclass's `__init__` is `super().__init__()`. Forget it, and assigning `self.fc = nn.Linear(...)` raises `AttributeError: cannot assign module before Module.__init__() call`.

### @property: a method you read without parentheses

Put `@property` on the line above a method, and you read it without parentheses: `m.left` instead of `m.left()`. It suits values computed from other attributes: every read computes it fresh, so it always matches the data and you can never forget to update it.

A property is read-only by default. `m.left = 1` raises an error (`property 'left' of ... object has no setter`). If a child class needs a different formula, it defines a new `@property` with the same name.
--- code
class Meter:
    def __init__(self, total):
        self.total = total
        self.used = 0

    def use(self, k):
        self.used += k

    @property
    def left(self):                # computed fresh on every read
        return self.total - self.used

class LoggedMeter(Meter):
    def __init__(self, total):
        super().__init__(total)    # let the parent attach total and used first
        self.history = []

    def use(self, k):
        super().use(k)             # keep the parent's behaviour
        self.history.append(k)     # then add our own step

m = LoggedMeter(10)
m.use(3)
m.use(4)
print(m.used, m.left, m.history)

class Forgot(Meter):
    def __init__(self, total):
        self.history = []          # forgot super().__init__(total)

try:
    Forgot(10).left
except AttributeError as e:
    print("AttributeError:", e)

class BadNet(nn.Module):
    def __init__(self):
        self.fc = nn.Linear(2, 2)  # forgot super().__init__()

try:
    BadNet()
except AttributeError as e:
    print("AttributeError:", e)

@@ concept
title: The shell of a training script: dataclass, f-strings, pathlib
--- body
Open any training project and the outer layer looks the same: a config object, a log line every few steps, and checkpoints (saved copies of the model's weights) written to some folder.

### dataclass: the config object

Put `@dataclass` above a class and write only "field_name: type = default". The `__init__`, the printed form and comparisons are generated for you. To change a value, pass it by name: `Cfg(lr=1e-3)`. You can still write methods in a dataclass. The type after the colon is only for humans; Python does not check it.

A mutable default such as a list or dict cannot be written as `= []` (dataclass raises an error right away). Write `field(default_factory=list)` so each object builds its own new list (the card "Assignment is a label, not a copy" explains why).

### f-strings: logs

Put `f` in front of a string and you can place variables and expressions inside `{}`. After a colon comes the format:

- `{step:5d}`: an integer, right-aligned, width 5
- `{loss:.4f}`: 4 decimal places
- `{lr:.2e}`: scientific notation with 2 decimals (`3e-4` prints as `3.00e-04`)
- `{step:06d}`: width 6, padded with zeros
- `{dt * 1000:.1f}`: compute first, then format

### pathlib: paths

`Path("runs") / "gpt-tiny" / "ckpt.pt"` joins paths with `/`, and it is right on both Windows and Linux. `p.name` is the file name and `p.parent` is its folder. `d.mkdir(parents=True, exist_ok=True)` creates the folder: `parents=True` also creates missing parent folders, and `exist_ok=True` means no error if it already exists.

Pad the step number in file names with zeros (`ckpt_000009.pt`) so that sorting by name gives the right order.
--- code
from dataclasses import dataclass, field
from pathlib import Path

@dataclass
class Cfg:
    lr: float = 3e-4
    n_layer: int = 6
    tags: list = field(default_factory=list)

a = Cfg()
b = Cfg(lr=1e-3)
a.tags.append("baseline")
print(a)
print(b)

step, loss, lr, dt = 7, 2.718281, 6e-4, 0.0421
print(f"[{step:5d}] [{loss:.4f}] [{lr:.2e}] [{dt * 1000:.1f}ms] [{step:06d}]")

p = Path("runs") / "gpt-tiny" / "last.pt"
print(p.name, p.parent.name, p.suffix)
print(sorted(f"ckpt_{s}.pt" for s in [9, 10, 100]))
print(sorted(f"ckpt_{s:06d}.pt" for s in [9, 10, 100]))

@@ concept
title: *args / **kwargs and decorators
--- body
`def f(*args, **kwargs)` accepts any arguments. Arguments passed by position are collected in `args` (a tuple); arguments passed by name are collected in `kwargs` (a dict). The other way round, stars in a call unpack: `g(*args, **kwargs)` hands them on to another function unchanged.

A decorator is a function that takes a function and returns a new function.

```
@deco
def f(x): ...
```

This is the same as defining `f` and then running `f = deco(f)`.

The standard shape of a decorator: inside it, define `wrapper(*args, **kwargs)`. Do the extra work first, then `return fn(*args, **kwargs)` to pass everything on, and finally `return wrapper`. Put `@functools.wraps(fn)` above the wrapper so the new function keeps the original name (`__name__`); otherwise its name becomes `wrapper`.

Decorators you will see in model code every day: `@dataclass`, `@property`, and `@torch.no_grad()` (do not record gradient information inside this function; used for inference).
--- code
import functools

def show_all(*args, **kwargs):
    print("args =", args, "| kwargs =", kwargs)

show_all(1, 2, lr=0.01)

def power(base, exp):
    return base ** exp

print(power(*(2, 10)), power(**{"base": 3, "exp": 4}))

def traced(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        print("calling", fn.__name__, args, kwargs)
        return fn(*args, **kwargs)
    return wrapper

@traced
def add(a, b):
    return a + b

print(add(1, b=2))
print(add.__name__)

def no_wraps(fn):
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper

@no_wraps
def mul(a, b):
    return a * b

print(mul.__name__)   # the name is lost

type: code
title: Slicing: chunk
level: 2
cards: Slices and loops: the start is in, the end is out
targets: chunk
ref: day1
--- context
To train a language model, a long stream of tokens is cut into samples of equal length. Pieces of different lengths cannot be stacked into one batch, so the short piece at the end is usually dropped.
--- prompt
Write `chunk(seq, n)`: cut the sequence `seq`, in order, into pieces of `n` elements each and return a list of the pieces. Drop the last piece if it has fewer than `n` elements.

```
chunk([0, 1, 2, 3, 4, 5, 6], 3)  ->  [[0, 1, 2], [3, 4, 5]]    # 6 alone is not 3 elements: dropped
chunk("abcdefg", 2)              ->  ["ab", "cd", "ef"]
chunk([], 3)                     ->  []
```

Use slices to take each piece, so that it works for lists and for strings (a slice of a string is a string). Return a real list.
--- starter
def chunk(seq, n):
    """chunk([0, 1, 2, 3, 4, 5, 6], 3) -> [[0, 1, 2], [3, 4, 5]] (the last 6 is not a full piece of 3: dropped)"""
    raise todo()
--- solution
def chunk(seq, n):
    return [seq[i:i + n] for i in range(0, len(seq) - n + 1, n)]
--- tests
@check("list: pieces of n, the short piece at the end is dropped")
def t02a():
    got = chunk(list(range(7)), 3)
    true(got == [[0, 1, 2], [3, 4, 5]], f"chunk(list(range(7)), 3) should be [[0, 1, 2], [3, 4, 5]], yours: {got!r}")
    got = chunk(list(range(6)), 3)
    true(got == [[0, 1, 2], [3, 4, 5]], f"chunk(list(range(6)), 3) should be [[0, 1, 2], [3, 4, 5]], yours: {got!r}")
    got = chunk([], 3)
    true(got == [], f"chunk([], 3) should be [], yours: {got!r}")

@check("strings work too")
def t02b():
    got = chunk("abcdefg", 2)
    true(got == ["ab", "cd", "ef"], f"it must work for strings too (slicing works on any sequence): chunk('abcdefg', 2) should be ['ab', 'cd', 'ef'], yours: {got!r}")
--- hints
- The pieces start at 0, n, 2n, …; `range(0, len(seq), n)` gives you those starts one by one. The piece that starts at `i` is `seq[i:i + n]`.
- The last piece may be short: check `len(piece) == n` before keeping it, or let the range stop at `len(seq) - n + 1` so every start has n elements after it.
- With a loop: `out = []`, then for each start take `piece = seq[i:i + n]`, `out.append(piece)` only if it is full, and finally `return out`.

--- context
A language model is trained to predict the next token. The input x and the answer y come from the same stretch of data; y is just shifted one step to the right. Get that shift wrong and the model copies the answer: the loss drops close to 0, it learns nothing, and no error is raised.
--- prompt
Write `make_xy(data, i, block_size)`: take one training sample starting at position `i` and return two lists `(x, y)`:

- `x = data[i : i + block_size]`
- `y` has the same length as `x` but is shifted one step to the right: each element of `y` is the element that comes right after the one at the same position in `x`.

```
data = list(range(20))
make_xy(data, 3, 5)  ->  ([3, 4, 5, 6, 7], [4, 5, 6, 7, 8])
```

This is the plain Python version. On day 3, `get_batch` does the same thing with tensors for a whole batch at once.
--- starter
def make_xy(data, i, block_size):
    """Take one training sample starting at i; return (x, y), two lists of length block_size.
    x = data[i : i+block_size]
    y = x shifted one step to the right (the "next" element at each position)
    """
    raise todo()
--- solution
def make_xy(data, i, block_size):
    x = data[i:i + block_size]
    y = data[i + 1:i + 1 + block_size]
    return x, y
--- tests
@check("x is block_size elements starting at i")
def t03a():
    x, y = make_xy(list(range(20)), 3, 5)
    true(x == [3, 4, 5, 6, 7], f"x should be [3, 4, 5, 6, 7], yours: {x}")

@check("y is x shifted by one, same length")
def t03b():
    x, y = make_xy(list(range(20)), 3, 5)
    true(y == [4, 5, 6, 7, 8], f"y should be [4, 5, 6, 7, 8], yours: {y}  (y is x shifted one step to the right, not x itself)")
    true(len(x) == len(y) == 5, f"x and y should both have 5 elements, yours: {len(x)} and {len(y)}")
--- hints
- Write x exactly as the task says: `x = data[i:i + block_size]`.
- y starts one later and ends one later than x: `data[i + 1 : ...]`.
- Finish with `return x, y` to return both values.

--- starter

--- solution
class RunningMean:
    def __init__(self):
        self.reset()

    def reset(self):
        self.total = 0.0
        self.n = 0

    def __call__(self, x):
        self.total += float(x)
        self.n += 1
        return self.value

    @property
    def value(self):
        return self.total / self.n if self.n else 0.0
--- tests

def t05a():
    m = RunningMean()
    true(not callable(m.value), "value is a normal method: put @property on the line above it so you can read it without parentheses")
    true(m.value == 0.0 and m.n == 0, f"when new, n should be 0 and value 0.0, yours: n={m.n!r}, value={m.value!r}")

@check("after m(1.0); m(3.0): value = 2.0, n = 2")
def t05b():
    m = RunningMean()
    m(1.0)
    m(3.0)
    true(close(m.value, 2.0), f"the average should be 2.0, yours: {m.value}")
    true(m.n == 2, f"n should be 2, yours: {m.n}")

@check("reset() goes back to the new state")
def t05c():
