@@ concept
title: Images become token sequences
--- body
Attention works on a sequence of tokens with shape (B, T, C): B samples, T tokens each, every token a vector of C numbers. An image feature map has shape (B, C, H, W). To use attention on image features, first flatten the map into a sequence.

- Every pixel position becomes one token. Its vector is the C channel values at that position.
- There are H*W tokens. The order is **row-major**: row 0 from left to right, then row 1, and so on.
- In code: `x.flatten(2)` merges the dimensions from 2 on, (H, W), into one: (B, C, H*W). Then `.transpose(1, 2)` swaps dimensions 1 and 2: (B, H*W, C).

After attention you go back to convolutions, so you need the reverse: `transpose(1, 2)` back to (B, C, H*W), then `reshape(B, C, H, W)`. After a transpose the memory is not contiguous, and `view` then fails whenever it has to merge dimensions. `reshape` always works, so make it your habit after a transpose.

Real numbers: a 64×64 feature map with 320 channels becomes 4096 tokens of 320 numbers each.
--- code
import torch

x = torch.arange(12.).reshape(1, 3, 2, 2)   # B=1, C=3, H=2, W=2
print(x[0, 0])                               # channel 0, a 2x2 grid
tok = x.flatten(2).transpose(1, 2)
print(tok.shape)                             # 4 tokens of 3 numbers
print(tok[0])                                # row 0 = the top-left pixel's 3 channels; row 1 = the pixel to its right
back = tok.transpose(1, 2).reshape(1, 3, 2, 2)
print(torch.equal(back, x))                  # back to the image, exactly

@@ concept
title: Cross-attention: the image asks, the text answers
--- body
In self-attention, Q, K and V all come from the same sequence. Cross-attention splits them:

- **Q comes from the image tokens** x, shape (B, Tx, C). Each pixel position asks: "which words in the text matter to me?"
- **K and V come from the text embeddings** ctx, shape (B, Tc, Cc). The text width Cc can differ from C, so the projections wk and wv have shape (Cc, C): they map the text into C dimensions.
- The attention matrix is (Tx, Tc): every image token scores every text token. After softmax each row sums to 1.
- The output is (B, Tx, C). **The output length follows Q (the image)**, not the text. With 7 text tokens or 77, the output shape is the same.

No causal mask: every image token may look at the whole text.

Heads work as on day 4: after the projection, `view(B, T, n_head, hd).transpose(1, 2)` gives (B, n_head, T, hd) with hd = C // n_head; after `F.scaled_dot_product_attention`, `transpose(1, 2).reshape(B, T, C)` joins the heads again. The one difference: Q has length Tx, K and V have length Tc.

This is how Stable Diffusion "tells" the UNet what the prompt says: many UNet layers have a cross-attention where Q is the image features and K, V are the text encoder's output.
--- code
import torch
import torch.nn.functional as F

torch.manual_seed(0)
B, Tx, Tc, C, Cc = 1, 6, 3, 8, 5
x = torch.randn(B, Tx, C)        # 6 image tokens of 8 numbers
ctx = torch.randn(B, Tc, Cc)     # 3 text tokens of 5 numbers
wq, wk, wv = torch.randn(C, C), torch.randn(Cc, C), torch.randn(Cc, C)
q, k, v = x @ wq, ctx @ wk, ctx @ wv
print("q", tuple(q.shape), "k", tuple(k.shape), "v", tuple(v.shape))
att = (q @ k.transpose(1, 2) / C ** 0.5).softmax(-1)
print("attention matrix", tuple(att.shape))   # each image token scores the 3 text tokens
print("row sums", att.sum(-1))
out = F.scaled_dot_product_attention(q, k, v)
print("output", tuple(out.shape))              # the length follows the image

@@ concept
title: Class conditioning: add it to the time embedding
--- body
The "condition" is whatever you want to control: a class ("draw a 7") or a sentence. Text is long, so it goes in through cross-attention (previous card). A **class** is just a number. The simplest way in:

1. `nn.Embedding(num_classes, D)` turns the class number into a vector of D numbers (the class embedding).
2. **Add it to the time embedding**: `emb = t_emb + class_emb`, both (B, D).
3. emb then goes through day 8's FiLM into every ResBlock, as before.

Why is adding enough? After the sum, the next Linear layer gets one vector that holds both "which step is this" and "what to draw". The network learns to use both. DiT and many class-conditional diffusion models do exactly this.

One extra thing for CFG: keep one more number for "no condition" (null). With 10 classes, build `nn.Embedding(11, D)`; number 10 means "I won't tell you what to draw".
--- code
import torch
import torch.nn as nn

torch.manual_seed(0)
D, num_classes = 4, 10
class_table = nn.Embedding(num_classes + 1, D)   # number 10 = null (no condition)
t_emb = torch.zeros(3, D)                         # pretend these are 3 time embeddings
labels = torch.tensor([7, 7, 10])                 # two "7"s and one "no condition"
emb = t_emb + class_table(labels)
print(emb.shape)
print(emb.detach().round(decimals=2))             # rows 0 and 1 match: same class, same step

@@ concept
title: Condition dropout: what makes CFG possible
--- body
CFG (next card) needs **two** predictions at sampling time: one with the condition and one without. Do you train two models? No. During training, randomly replace the condition of some samples with null. Then one model learns both:

- with the real condition: the noise to remove "for this condition"
- with null: the noise to remove "when it knows nothing"

Key points:

- The drop probability p is usually 0.1: 10% of the samples get no condition.
- **Drop per sample, not per element.** A sample keeps its whole condition or gets the whole null. Zeroing some numbers inside the vector, like normal dropout, gives "half a condition" that sampling never uses.
- In code: draw **one** random number per sample, `keep = torch.rand(B, 1) >= p`. Shape (B, 1) broadcasts to (B, D). Turn keep into floats, then `keep * cond + (1 - keep) * null`.
- Only during training. At sampling time you choose the condition.
--- code
import torch

torch.manual_seed(0)
B, D, p = 6, 3, 0.5                # p = 0.5 here so you can see it; real training often uses 0.1
cond = torch.ones(B, D)            # real condition: all ones
null = torch.zeros(D)              # null condition: all zeros
keep = (torch.rand(B, 1) >= p).float()
print(keep.squeeze(1))             # one 0 or 1 per sample
out = keep * cond + (1 - keep) * null
print(out)                         # every row is all ones or all zeros

@@ concept
title: CFG: the formula and the batch trick
--- body
Classifier-free guidance (CFG) is the knob that makes a model follow the condition more closely. At every sampling step the model predicts the noise twice:

- eps_u: the prediction with the null condition (unconditional)
- eps_c: the prediction with the real condition (conditional)

Then it combines them:

```
eps = eps_u + scale * (eps_c - eps_u)
```

- `eps_c - eps_u` is "what the condition changes": a direction.
- scale = 0: the result is eps_u; the condition is ignored.
- scale = 1: the result is exactly eps_c, plain conditional generation.
- scale > 1: **push further** along that direction (extrapolation). The image matches the condition better but varies less; too high (say 20) and colours oversaturate. Stable Diffusion uses 7.5 by default.

The distance from eps_u is exactly scale × |eps_c - eps_u|, so a larger scale always lands further away.

**The batch trick**: do not run the model twice. Duplicate the input and do one forward pass:

1. x becomes `torch.cat([x, x])`, shape (2B, ...); the timesteps t are duplicated the same way.
2. The conditions become `torch.cat([null expanded to B rows, cond])`: **first half null, second half cond**. This is a convention; you must split the same way.
3. `out.chunk(2)` splits the output into two blocks: the first is eps_u, the second eps_c. Then apply the formula.

On a GPU, one forward pass with batch 2B is faster than two with batch B. The cost: twice the activation memory for that step.
--- code
import torch

eps_u = torch.tensor([0.0, 1.0])
eps_c = torch.tensor([1.0, 1.0])
for scale in [0.0, 1.0, 3.0, 7.5]:
    eps = eps_u + scale * (eps_c - eps_u)
    print(scale, eps.tolist(), "distance from eps_u", (eps - eps_u).norm().item())

B, D = 2, 4
x = torch.randn(B, 1, 8, 8)
cond = torch.ones(B, D)
null = torch.zeros(D)
both_x = torch.cat([x, x])
both_c = torch.cat([null.expand(B, -1), cond])     # first half null, second half cond
print(both_x.shape, both_c.shape)
print(both_c)

@@ concept
title: DDIM timesteps: skipping ahead
--- body
Day 8's DDPM trains with T=1000 steps and also samples one step at a time, 1000 steps. Too slow. DDIM uses **the same trained model** but walks through only a few of those timesteps, say 50 or even 10. No retraining.

Which ones: evenly spaced. The gap is k = T // steps (integer division), and the timesteps are 0, k, 2k, …, (steps-1)*k, exactly steps of them. Sampling starts where the noise is largest, so **reverse** them, largest first:

- T=1000, steps=5: k=200, timesteps [800, 600, 400, 200, 0]
- T=1000, steps=50: k=20, timesteps [980, 960, …, 20, 0]

Two details:

- The last one is always 0. The last step must land on the clean image.
- There must be exactly steps of them. `torch.arange(0, T, k)` works when steps divides T; with T=100 and steps=30, k=3 and it gives 34 values (0, 3, …, 99), four too many.

Each step goes from t to the next timestep in the list, called t_prev (for example 800 to 600). The last step goes from 0 to "-1", which means "the clean image itself".
--- code
import torch

T, steps = 1000, 5
k = T // steps
print("k =", k)
print(torch.arange(0, T, k))              # smallest first
print(torch.arange(0, T, k).flip(0))      # reversed: start where the noise is largest

T, steps = 100, 30
k = T // steps
print(f"k = {k}; arange(0, T, k) gives {len(torch.arange(0, T, k))} values, we want {steps}")

@@ concept
title: One DDIM step: guess x0, then re-noise
ref: day8
--- body
Recall day 8's q_sample: `x_t = sqrt(ab_t) * x0 + sqrt(1 - ab_t) * eps`. ab is alphas_cumprod (the running product of the alphas). The larger t, the smaller ab and the more noise in x_t.

One DDIM step (eta=0: no new random noise) has two halves:

1. **Recover x0 from x_t.** The model predicted the noise eps; solve the q_sample formula for x0: `x0_pred = (x_t - sqrt(1 - ab_t) * eps) / sqrt(ab_t)`
2. **Add the same eps back, at level t_prev**: `x_prev = sqrt(ab_prev) * x0_pred + sqrt(1 - ab_prev) * eps`

Step 2 is just `q_sample(x0_pred, t_prev, eps)`. So if the predicted eps is exactly the noise that was added, one DDIM step lands **exactly** on `q_sample(x0, t_prev, eps)`. That makes the best unit test for a sampler.

- t_prev = -1 means "done": use ab_prev = 1, so x_prev is x0_pred.
- There are no random numbers in the whole process. The same starting noise always gives the same image. DDPM adds fresh random noise at every step, so it differs every time.
- t and t_prev are (B,) tensors. Take the coefficients with day 8's `extract(arr, t, x.shape)`; it turns (B,) into (B, 1, 1, 1), which broadcasts against the image.
- The gather inside `extract` does not accept -1. Take ab_prev with `t_prev.clamp(min=0)` first, then use `torch.where` to put 1 where t_prev < 0.

**The sampling loop**: start from `x = torch.randn(shape)` and walk (t, t_prev) = (800, 600), (600, 400), …, (0, -1). At each step, `eps = model(x, t)`, then `x = ddim_step(x, t, t_prev, eps, sched)`. The final x is the generated image.

The example shows only half 1: at t=600, x_t is almost pure noise, yet with the true eps the recovered x0 is exact.
--- code
torch.manual_seed(0)
s = linear_schedule(1000)
x0 = torch.randn(1, 4)                 # a "clean image" of just 4 numbers
eps = torch.randn(1, 4)                # the noise that was added
t = torch.tensor([600])
x_t = q_sample(x0, t, eps, s)
ab = extract(s["alphas_cumprod"], t, x_t.shape)
print("ab_600 =", round(ab.item(), 4))  # small: x_t is almost all noise
print("x_t    ", x_t)
x0_pred = (x_t - (1 - ab).sqrt() * eps) / ab.sqrt()
print("x0     ", x0)
print("x0_pred", x0_pred)              # the same as x0

@@ concept
title: Latent diffusion: the shapes in Stable Diffusion
--- body
Diffusion directly on 512×512 pixels is expensive: one image is 3×512×512 ≈ 786,000 numbers, and the UNet processes all of them at every step. Stable Diffusion uses latent diffusion: a VAE like day 7's first shrinks the image, diffusion runs on the small latent, and the VAE decodes the result back to pixels at the end.

Fixed numbers in Stable Diffusion 1.x:

- VAE: height and width shrink 8 times; the latent has 4 channels.
- The UNet's first convolution lifts the 4 channels to 320.
- The text encoder (CLIP) turns the prompt into 77 tokens of 768 numbers each.

With these you can work out every shape. Example with batch 2 and 256×256 images:

1. Image: (2, 3, 256, 256)
2. VAE encoder: 256 ÷ 8 = 32, so the latent is (2, 4, 32, 32). 48 times fewer numbers.
3. Adding noise, the UNet's noise prediction and DDIM denoising all happen on the latent. The UNet output (the predicted noise) has the latent's shape: (2, 4, 32, 32).
4. Inside the UNet: after the first convolution, (2, 320, 32, 32); flattened into tokens, (2, 32*32, 320) = (2, 1024, 320).
5. Text embeddings: (2, 77, 768).
6. Cross-attention: Q from (2, 1024, 320), K and V from (2, 77, 768) (wk and wv map 768 to 320). The output follows Q: (2, 1024, 320).
7. After sampling, the VAE decodes back to (2, 3, 256, 256).

Add CFG's batch trick and the batch the UNet actually processes at every step doubles.
--- code
import torch
import torch.nn as nn

B, H, W = 2, 256, 256
image = torch.zeros(B, 3, H, W)
latent = torch.zeros(B, 4, H // 8, W // 8)        # VAE: height and width / 8, 4 channels
print("image ", tuple(image.shape), image[0].numel(), "numbers per image")
print("latent", tuple(latent.shape), latent[0].numel(), "numbers per image")
print(f"{image.numel() // latent.numel()} times fewer numbers")
h = nn.Conv2d(4, 320, 3, padding=1)(latent)       # the UNet's first layer: 4 -> 320 channels
tokens = h.flatten(2).transpose(1, 2)
print("latent tokens", tuple(tokens.shape))

Attention layers in a UNet, DiT and ViT all flatten a (B, C, H, W) feature map into a token sequence and turn it back afterwards. Get the order wrong and tokens no longer match their pixels: nothing crashes, but the model learns badly.

--- context
Cross-attention is how Stable Diffusion tells the UNet what the prompt says: image features are Q, text embeddings are K and V. The text can have any length and the output shape follows the image, so one UNet works with prompts of any length.
--- prompt
Write `cross_attention(x, ctx, wq, wk, wv, n_head)`:

- x: (B, Tx, C), image tokens. ctx: (B, Tc, Cc), text embeddings. Tc has nothing to do with Tx, and Cc may differ from C.

- Return (B, Tx, C).

--- starter
def cross_attention(x, ctx, wq, wk, wv, n_head):
    """x:   (B, Tx, C)    image tokens
    ctx: (B, Tc, Cc)   text embeddings (length unrelated to Tx)
    wq: (C, C)   wk: (Cc, C)   wv: (Cc, C)
    Returns (B, Tx, C). F.scaled_dot_product_attention is allowed (no causal mask).
    """
    raise todo()
--- solution
def cross_attention(x, ctx, wq, wk, wv, n_head):
    B, Tx, C = x.shape
    Tc = ctx.size(1)
    hd = C // n_head
    q = (x @ wq).view(B, Tx, n_head, hd).transpose(1, 2)       # Q comes from the image
    k = (ctx @ wk).view(B, Tc, n_head, hd).transpose(1, 2)     # K and V come from the text
    v = (ctx @ wv).view(B, Tc, n_head, hd).transpose(1, 2)
    o = F.scaled_dot_product_attention(q, k, v)                 # (B, n_head, Tx, hd)
    return o.transpose(1, 2).reshape(B, Tx, C)
--- tests

- Project first: `x @ wq` is (B, Tx, C); `ctx @ wk` and `ctx @ wv` are (B, Tc, C).

    """With probability p, replace a sample's whole condition with null_emb (the unconditional embedding).

--- solution
def drop_cond(cond_emb, null_emb, p, generator=None):
    B = cond_emb.size(0)
    keep = (torch.rand(B, 1, generator=generator) >= p).to(cond_emb.dtype)   # one random number per sample
    return keep * cond_emb + (1 - keep) * null_emb.expand_as(cond_emb)

def cfg_forward(model, x, t, cond, null_cond, scale):
    """Do not run the model twice. Duplicate x, stack the conditions as [null, cond], run once, split.
    x: (B,C,H,W)   t: (B,)   cond: (B,D)   null_cond: (D,)
    model(x, t, c) -> same shape as x
    Returns the combined (B,C,H,W).
    """
    raise todo()
--- solution
def cfg_forward(model, x, t, cond, null_cond, scale):
    B = x.size(0)
    both_x = torch.cat([x, x])
    both_t = torch.cat([t, t])
    both_c = torch.cat([null_cond.expand(B, -1), cond])       # convention: first half null, second half cond
    out = model(both_x, both_t, both_c)
    e_u, e_c = out.chunk(2)
    return cfg_combine(e_u, e_c, scale)

def ddim_step(x_t, t, t_prev, eps_pred, sched):
    """x0_pred = (x_t - sqrt(1-ab_t) * eps) / sqrt(ab_t)
    x_prev  = sqrt(ab_prev) * x0_pred + sqrt(1-ab_prev) * eps      (eta=0, no random noise)
    t / t_prev are both (B,) tensors. t_prev may be -1; then ab_prev = 1 (return x0_pred).
    """
    raise todo()
--- solution
def ddim_step(x_t, t, t_prev, eps_pred, sched):
    ab = extract(sched["alphas_cumprod"], t, x_t.shape)
    x0 = (x_t - (1 - ab).sqrt() * eps_pred) / ab.sqrt()          # half 1: recover x0
    prev_ok = (t_prev >= 0)
    tp = t_prev.clamp(min=0)                                       # gather does not accept -1
    ab_prev = extract(sched["alphas_cumprod"], tp, x_t.shape)
    ones = torch.ones_like(ab_prev)
    ab_prev = torch.where(prev_ok.reshape(-1, *([1] * (x_t.dim() - 1))), ab_prev, ones)
    return ab_prev.sqrt() * x0 + (1 - ab_prev).sqrt() * eps_pred   # half 2: re-noise with the same eps

def ddim_sample(model, shape, sched, steps=10, device="cpu"):
    ts = ddim_timesteps(len(sched["betas"]), steps).to(device)
    x = torch.randn(shape, device=device)

--- context
A common interview question: "why is CFG called classifier-free, and where does the unconditional prediction come from?" The answer is condition dropout during training.
--- prompt
A text-to-image model was trained **without** condition dropout (p=0): every sample always had its real condition. Now you sample with CFG (scale=7.5), feeding the null embedding to the unconditional branch. What happens?
--- options
- Nothing special. CFG is a sampling trick and has nothing to do with training
- The unconditional branch is unreliable: the model never saw the null condition, so eps_uncond is an output it never learned, and the direction (eps_cond - eps_uncond) means nothing
- It raises an error because the null embedding has the wrong shape
- Sampling gets faster because the unconditional branch can be skipped

No error: the null embedding has the same shape as a real condition, so the code runs. That is what makes it dangerous. Not faster either: CFG still computes both branches.

--- solution
def ddim_step(x_t, t, t_prev, eps_pred, sched):
    ab = extract(sched["alphas_cumprod"], t, x_t.shape)
    x0 = (x_t - (1 - ab).sqrt() * eps_pred) / ab.sqrt()
    tp = t_prev.clamp(min=0)
    ab_prev = extract(sched["alphas_cumprod"], tp, x_t.shape)
    ab_prev = torch.where((t_prev >= 0).reshape(-1, *([1] * (x_t.dim() - 1))), ab_prev, torch.ones_like(ab_prev))
    return ab_prev.sqrt() * x0 + (1 - ab_prev).sqrt() * eps_pred
