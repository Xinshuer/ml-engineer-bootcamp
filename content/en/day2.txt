@@ concept
title: Shapes and dims: read the tensor first
--- body
A tensor is a multi-dimensional array. `x.shape` tells you how long each dimension is. Most bugs in model code are shapes that do not fit together. So build one habit: after every line you write, say the shape of the result in your head before you go on.

In language-model code you will see these three letters everywhere:
- `B`: batch, how many samples go into the model at once
- `T`: time, how many tokens each sample has
- `C`: channels, how long the vector for each token is

`(B, T, C) = (2, 5, 4)` reads: 2 samples, 5 tokens each, and every token is a vector of 4 numbers.

`dim` means "which dimension". Counting starts at 0, and you can also count from the end: `dim=-1` is the last dimension. Here is what common operations do to the shape (x is `(2, 5, 4)`):
- `x.sum(dim=-1)`, `x.mean(dim=-1)`: sum or average along the last dim; that dim disappears → `(2, 5)`
- add `keepdim=True`: the dim stays, with length 1 → `(2, 5, 1)`. Use this when you still want to add it to or subtract it from x
- `x.unsqueeze(1)`: insert a dim of length 1 at position 1 → `(2, 1, 5, 4)`. `squeeze(1)` does the opposite
- `torch.cat([x, x], dim=0)`: join along dim 0, which gets longer → `(4, 5, 4)`
- `x.transpose(0, 1)`: swap two dims → `(5, 2, 4)`. `x.permute(2, 0, 1)` puts all dims in a new order at once → `(4, 2, 5)`
- `x.flatten(1)`: merge dim 1 through the last dim into one → `(2, 20)`
- `x @ W`: matrix multiply. Only the last two dims take part, and the last dim of x must equal the second-to-last dim of W. With W of shape `(4, 3)` → `(2, 5, 3)`; the leading dims stay as they are
--- code
x = torch.randn(2, 5, 4)             # (B, T, C)
W = torch.randn(4, 3)
print("x                    ", tuple(x.shape))
print("x.mean(dim=-1)       ", tuple(x.mean(dim=-1).shape))
print("x.mean(-1, keepdim)  ", tuple(x.mean(dim=-1, keepdim=True).shape))
print("x.unsqueeze(1)       ", tuple(x.unsqueeze(1).shape))
print("torch.cat([x, x], 0) ", tuple(torch.cat([x, x], dim=0).shape))
print("x.transpose(0, 1)    ", tuple(x.transpose(0, 1).shape))
print("x.permute(2, 0, 1)   ", tuple(x.permute(2, 0, 1).shape))
print("x.flatten(1)         ", tuple(x.flatten(1).shape))
print("x @ W                ", tuple((x @ W).shape))

@@ concept
title: Broadcasting: line up from the right
--- body
When you use `+ - * /` on two tensors with different shapes, PyTorch **broadcasts** them automatically: it stretches the smaller one until it matches the bigger one, then works element by element. (No memory is really copied, but you can think of it that way.)

There is only one rule: **line the two shapes up on the right and compare them pair by pair, starting from the last dim**. Every pair must be one of these:
- the two lengths are equal
- one of them is 1 (it gets stretched to the other length)
- one tensor does not have this dim at all (it counts as 1)

Examples:
- `(2, 3, 4) + (4,)`: `(4,)` is treated as `(1, 1, 4)`, result `(2, 3, 4)`. This is how you add the same bias to every token
- `(2, 1, 4) + (3, 1)`: lined up, that is `(2, 1, 4)` and `(1, 3, 1)`. Each dim takes the bigger length, result `(2, 3, 4)`. Both sides were stretched
- `(2, 3, 4) + (3,)`: the last pair is 4 and 3, neither is 1 → error

The dangerous part of broadcasting is **a wrong result with no error**. A model often outputs `(B, 1)` while the labels are `(B,)`. Subtracting them gives `(B, B)`: every prediction minus every label. The loss still comes out as a number; it is just completely wrong. Fix it with `squeeze(-1)` first, so the output becomes `(B,)`.

Broadcasting is also very handy: multiply a `(B, T, C)` feature tensor by a `(B, T, 1)` mask, and whole vectors at some positions become zero (card 7 uses this).
--- code
x = torch.ones(2, 3, 4)
bias = torch.tensor([0., 10., 20., 30.])        # (4,)
print("(2,3,4) + (4,)  ->", tuple((x + bias).shape))
print("first token     :", (x + bias)[0, 0].tolist())   # every token got the same bias
a = torch.zeros(2, 1, 4)
b = torch.zeros(3, 1)
print("(2,1,4) + (3,1) ->", tuple((a + b).shape))
pred = torch.tensor([[1.0], [2.0], [3.0]])      # (3, 1)
y = torch.tensor([1.0, 2.0, 3.0])               # (3,)
print("(3,1) - (3,)    ->", tuple((pred - y).shape), " no error, but already wrong")
print("after squeeze   ->", tuple((pred.squeeze(-1) - y).shape))
try:
    x + torch.ones(3)
except RuntimeError as e:
    print("(2,3,4) + (3,) fails:", e)

@@ concept
title: Splitting and merging heads: view, transpose, contiguous
--- body
Multi-head attention (day 4 covers it in detail) cuts each token's C-dim vector into `nh` pieces (nh is the number of heads). Each piece has length `hs = C / nh` (the head size), and every head does its own work.

Usually one Linear computes q, k and v in one go, stuck together as `(B, T, 3C)`. `qkv.split(C, dim=-1)` cuts the last dim into blocks of C and gives three `(B, T, C)` tensors.

Then each of them is split into heads. The shape goes like this:

`(B, T, C)` → `view(B, T, nh, hs)` → `(B, T, nh, hs)` → `transpose(1, 2)` → `(B, nh, T, hs)`

Why the transpose? The matrix multiplies that come next only look at the last two dims. With the heads moved to the front, the last two dims are `(T, hs)`: each head holds a small "T tokens × hs numbers" matrix.

How the three tools differ:
- `view(new shape)`: copies nothing; it reads the same memory in a different shape. The number of elements must stay the same. It cuts in memory order: splitting the last dim C into `(nh, hs)` gives head 0 exactly the first hs numbers
- `transpose(i, j)`: swaps two dims. It copies nothing either, it only changes the order in which memory is read. The result is **not contiguous** any more (contiguous: elements stored row by row, right next to each other)
- `.contiguous()`: really makes a copy in the current order, so it is contiguous again

Merging heads is the reverse: `(B, nh, T, hs)` → `transpose(1, 2)` → `(B, T, nh, hs)` → `(B, T, C)`. A plain `view` right after the transpose fails with `view size is not compatible with input tensor's size and stride`, because view needs contiguous memory. The fix: `.contiguous().view(...)`, or use `.reshape(...)` instead (it copies when it has to).

Careful: you cannot skip the transpose and view `(B, nh, T, hs)` straight into `(B, T, C)`. The shape looks right and nothing fails, but the numbers end up in the wrong order.
--- code
B, T, nh, hs = 1, 3, 2, 2
C = nh * hs
x = torch.arange(B * T * C).view(B, T, C)   # 3 tokens, 4 numbers each; each number = its place in memory
print("x[0]      :", x[0].tolist())
h = x.view(B, T, nh, hs).transpose(1, 2)    # split heads -> (B, nh, T, hs)
print("split     :", tuple(h.shape))
print("head 0    :", h[0, 0].tolist())       # the first 2 numbers of every token
print("head 1    :", h[0, 1].tolist())       # the last 2 numbers of every token
y = h.contiguous()                          # pretend this is a fresh attention output
t = y.transpose(1, 2)                       # (B, T, nh, hs)
print("contiguous after transpose?", t.is_contiguous())
try:
    t.view(B, T, C)
except RuntimeError as e:
    print("plain view fails:", str(e)[:48], "...")
back = t.contiguous().view(B, T, C)
print("contiguous().view gives x back?", torch.equal(back, x))

@@ concept
title: Matrix multiply: Linear, attention scores, einsum
--- body
`nn.Linear(in, out)` holds two parameters: `weight` with shape `(out, in)` (not `(in, out)`!), and `bias` with shape `(out,)`. All it does is one line:

`y = x @ W.T + b`

`x` can be `(N, in)` or `(B, T, in)`. `@` multiplies using only the last two dims and keeps the leading dims as they are, so the output is `(..., out)`. The bias is broadcast onto every row.

Attention scores (day 4 covers them in detail): every query takes a dot product with every key, divided by `sqrt(hs)`. q and k are both `(B, nh, T, hs)`. Swap the last two dims of k and you can multiply directly:

`q @ k.transpose(-2, -1)`: `(B, nh, T, hs) @ (B, nh, hs, T)` → `(B, nh, T, T)`

Row i, column j of the result is the dot product of query i and key j.

`torch.einsum` is another way to write this. You give every dim a letter, and you can see at a glance which dims are multiplied and which are summed. The rules:
- commas separate the dim names of each input; the names after the arrow are the output dims
- a letter that appears in the inputs but not in the output is multiplied and summed over
- a letter in both the inputs and the output is kept as it is

For example, the plain matrix product `a @ b` is `torch.einsum("ik,kj->ij", a, b)`: k is not in the output, so it is multiplied and summed over. `"btc,btc->bt"` is the dot product of two vectors at every token.
--- code
lin = nn.Linear(4, 3)
print("weight", tuple(lin.weight.shape), " bias", tuple(lin.bias.shape))
x = torch.randn(2, 5, 4)                                  # (B, T, in)
mine = x @ lin.weight.T + lin.bias
print("by hand:", tuple(mine.shape), " same as nn.Linear?", torch.allclose(mine, lin(x), atol=1e-6))
a, b = torch.randn(3, 4), torch.randn(4, 2)
print("einsum ik,kj->ij equals a @ b?", torch.allclose(torch.einsum("ik,kj->ij", a, b), a @ b, atol=1e-6))
u, v = torch.randn(2, 5, 4), torch.randn(2, 5, 4)
dots = torch.einsum("btc,btc->bt", u, v)                  # one dot product per token
print("per-token dot products:", tuple(dots.shape), torch.allclose(dots, (u * v).sum(-1), atol=1e-6))

@@ concept
title: Along the last dim: softmax, LayerNorm, RMSNorm
--- body
These three follow the same pattern: **each vector is handled on its own** (along the last dim). First compute one statistic per vector with `keepdim=True` (the max, the mean, the variance), with shape `(..., 1)`. Then broadcasting applies it to every element of that vector.

**softmax** turns a list of any real numbers into probabilities that add up to 1:

`softmax(x)_i = exp(x_i) / (exp(x_1) + ... + exp(x_n))`

Computing it directly has a trap: `exp(1000)` is `inf` in float32, and `inf / inf = nan`. The fix is to subtract the largest value m first. Top and bottom are both multiplied by `exp(-m)`, so the result does not change; but the largest number becomes 0, so `exp` is at most 1 and cannot overflow.

**LayerNorm**: subtract each vector's own mean, divide by its own standard deviation, then multiply by a learned `g` (gain, a scale) and add a learned `b` (bias, a shift):

`y = (x - mean) / sqrt(var + eps) * g + b`

Here `var` divides by N: `x.var(-1, keepdim=True, unbiased=False)`. The default `unbiased=True` divides by N-1 and will not match PyTorch's LayerNorm. `eps` is a tiny number that prevents dividing by 0.

**RMSNorm** (Llama uses it; you will need it on day 5) is simpler: no mean subtraction and no b, only a division by the root mean square:

`y = x / sqrt(mean(x²) + eps) * g`

`torch.rsqrt(t)` is `1 / sqrt(t)`. With g all ones, every vector has `mean(y²)` close to 1 after RMSNorm.
--- code
x = torch.tensor([1000.0, 1001.0, 1002.0])
print("direct      :", (x.exp() / x.exp().sum()).tolist())
e = (x - x.max()).exp()                     # subtract the max first
print("minus max   :", [round(v, 4) for v in (e / e.sum()).tolist()])
print("F.softmax   :", [round(v, 4) for v in F.softmax(x, dim=0).tolist()])

h = torch.tensor([[1.0, 2.0, 3.0, 6.0]])
mu = h.mean(-1, keepdim=True)
var = h.var(-1, keepdim=True, unbiased=False)
print("mean", mu.item(), " var", var.item(), " shape of the statistic", tuple(mu.shape))
z = (h - mu) / torch.sqrt(var + 1e-5)
print("normalised  :", [round(v, 3) for v in z[0].tolist()])
print("new mean %.3f  new var %.3f" % (abs(z.mean().item()), z.var(unbiased=False).item()))

@@ concept
title: cross_entropy: log_softmax plus gather
--- body
A classifier outputs V **logits** per sample (raw scores, before softmax), where V is the number of classes (for a language model, the vocabulary size). **cross_entropy** cares about one thing: how much probability p the model gives to the correct answer. The loss of one sample is `-log(p)`, averaged over all samples. The closer p is to 1, the closer the loss is to 0.

By hand it takes three steps:
1. Log probabilities: `logp = logits - logits.logsumexp(dim=-1, keepdim=True)`. This is exactly `F.log_softmax`. `logsumexp` computes `log(exp(x_1) + ... + exp(x_n))` and already subtracts the max inside, so it cannot overflow. Do not write `softmax(...).log()`: when a probability is so small that it becomes 0, `log(0) = -inf`
2. Use `gather` to pick each sample's log probability for the correct class
3. Negate and take the mean

`input.gather(dim, index)` picks values along `dim` at the positions listed in `index`. `index` must have the same number of dims as `input`. The labels are `(N,)`, so `unsqueeze(-1)` them to `(N, 1)` first; the result is `(N, 1)`, and `squeeze(-1)` brings it back to `(N,)`.

A number to remember: if all logits are equal (the model guesses uniformly), every class gets probability `1/V`, and the loss is `-log(1/V) = ln V`. A freshly initialised model should start with a loss close to this.

A language model's logits are `(B, T, V)` and its labels are `(B, T)`. `F.cross_entropy` wants the classes in dim 1: `(N, V)` with `(N,)`. The easiest way is to merge B and T into one dim: `logits.reshape(-1, V)` with `targets.reshape(-1)`. That is `B*T` separate "pick 1 of V" questions.
--- code
logits = torch.tensor([[2.0, 0.0, -1.0],
                       [0.0, 3.0,  0.0]])        # N=2 samples, V=3 classes
y = torch.tensor([0, 2])                         # index of the correct class
logp = F.log_softmax(logits, dim=-1)
print("log probs   :", [[round(v, 3) for v in row] for row in logp.tolist()])
picked = logp.gather(-1, y.unsqueeze(-1))        # index (2, 1) -> result (2, 1)
print("gathered    :", [round(v, 3) for v in picked.squeeze(-1).tolist()])
print("minus mean  :", round(-picked.mean().item(), 4))
print("F.cross_entropy:", round(F.cross_entropy(logits, y).item(), 4))
V = 3
flat = F.cross_entropy(torch.zeros(1, V), torch.tensor([1]))
print("equal logits:", round(flat.item(), 4), "  ln 3 =", round(math.log(V), 4))

@@ concept
title: Variable-length sequences: padding and masks
--- body
The sentences in a batch have different lengths, but a tensor must be a neat box. The answer is **padding**: add a special `pad_id` to the right of each short sample until it is as long as the longest one, `Tmax`. At the same time, build a **mask** with the same shape: 1 where there is a real token, 0 where padding was added.

The function a DataLoader uses to stack samples into a batch is called `collate_fn`, and padding usually happens there. Useful tools:
- `torch.full((B, Tmax), pad_id, dtype=torch.long)`: make a tensor full of pad_id first, then fill in the real tokens
- `x[i, :n] = s`: put sample s (length n) into the first n positions of row i
- token ids must be `int64` (that is `torch.long`), because `nn.Embedding` only accepts integer ids

Once there is padding, every statistic must respect the mask. For example, the average vector of each sample: padded positions must not count in the sum, and the divisor counts only real tokens:

`average = sum(x * mask) / sum(mask)`

x is `(B, T, C)` and the mask is `(B, T)`. `mask.unsqueeze(-1)` makes it `(B, T, 1)`, and broadcasting multiplies it into every channel. If the mask holds integers, turn it into floats with `.to(x.dtype)`.
--- code
seqs = [torch.tensor([5, 6, 7]), torch.tensor([8])]
x = torch.full((2, 3), 0, dtype=torch.long)       # pad_id = 0
x[0, :3] = seqs[0]
x[1, :1] = seqs[1]
print("padded     :", x.tolist())

feat = torch.tensor([[[1.0], [3.0], [8.0]],      # sample 0: 2 real tokens + 1 pad
                     [[2.0], [8.0], [8.0]]])     # sample 1: 1 real token + 2 pads   (B=2, T=3, C=1)
mask = torch.tensor([[1, 1, 0],
                     [1, 0, 0]])                 # the 8.0 at pad positions is meaningless
print("plain mean :", feat.mean(1).squeeze(-1).tolist())    # the pads were counted too
m = mask.unsqueeze(-1).to(feat.dtype)                      # (2, 3, 1)
print("masked mean:", ((feat * m).sum(1) / m.sum(1)).squeeze(-1).tolist())

@@ concept
title: Parameters, buffers and autograd
--- body
Your own models subclass `nn.Module`. There are three ways to keep a tensor in `__init__`, and they behave very differently:
- `self.w = nn.Parameter(t)`: a **learnable parameter**. It shows up in `model.parameters()`, the optimizer updates it, and it is saved in `state_dict()` (the saved weights)
- `self.register_buffer("name", t)`: a **buffer**. Not learned, but part of the model's state: it is saved in `state_dict()` and moves along with `model.to("cuda")`. It is not in `parameters()`, so the optimizer leaves it alone. Examples: BatchNorm's running averages, a fixed causal mask
- `self.t = torch.zeros(3)`: a plain attribute. It is neither: it is lost when you save, and it stays behind on `.to()`, so on a GPU you get a "different devices" error

To update a buffer, do it inside `with torch.no_grad():` with the in-place `self.name.copy_(new_value)`, so it does not become part of the graph.

**autograd** (automatic differentiation): when you compute with tensors that have `requires_grad=True`, PyTorch records the computation graph. After `loss.backward()` on a scalar, each of those tensors has `d loss / d itself` in its `.grad`. You can check it with a formula you work out by hand. For example, with `loss = sum(x³)` the derivative for each element is `3x²`. If the loss contains a `mean`, remember that a mean divides by the number of elements N, so the derivative is divided by N too.

Each step of a training loop does four things:
1. forward: compute the loss
2. `opt.zero_grad()`: clear last step's gradients. `.grad` **adds up** by default; without clearing it keeps growing
3. `loss.backward()`: compute the gradients
4. `opt.step()`: update the parameters with the gradients

`zero_grad` just has to come before `backward`. Record the loss with `loss.item()`, which returns a plain Python number; putting the `loss` tensor itself into a list keeps its whole computation graph in memory.
--- code
class Tiny(nn.Module):
    def __init__(self):
        super().__init__()
        self.w = nn.Parameter(torch.ones(2))
        self.register_buffer("count", torch.zeros(()))
        self.plain = torch.zeros(2)                    # a plain attribute
m = Tiny()
print("parameters:", [n for n, _ in m.named_parameters()])
print("state_dict:", list(m.state_dict().keys()), " <- no plain")

x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)
loss = (x ** 3).sum()
loss.backward()
print("autograd  :", x.grad.tolist())
print("3x² by hand:", (3 * x.detach() ** 2).tolist())

w = torch.tensor(1.0, requires_grad=True)
for step in range(3):
    (2 * w).backward()                                 # d(2w)/dw = 2
    print("step", step, "without zero_grad, w.grad =", w.grad.item())

--- hints
- `@` only looks at the last two dims: `(..., n, k) @ (k, m)` → `(..., n, m)`. Broadcasting lines shapes up from the rightmost dim; dims of length 1 or missing dims get stretched
- `view` can change the shape as long as the number of elements stays the same; `transpose(1, 2)` swaps dims 1 and 2; `flatten(2)` multiplies dim 2 through the last dim together; `keepdim=True` leaves a dim of length 1
- `c + torch.zeros(16, 1)`: lined up on the right, that is `(8, 1, 64)` and `(1, 16, 1)`; each dim takes the bigger length

def my_softmax(x, dim=-1):
    """softmax along dim. Subtract the max first, or large numbers overflow."""
    raise todo()
--- solution
def my_softmax(x, dim=-1):
    m = x.max(dim=dim, keepdim=True).values
    e = (x - m).exp()
    return e / e.sum(dim=dim, keepdim=True)

def my_layernorm(x, g, b, eps=1e-5):
    mu = x.mean(-1, keepdim=True)
    var = x.var(-1, keepdim=True, unbiased=False)
    return (x - mu) / torch.sqrt(var + eps) * g + b

    rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + eps)
    return x * rms * g

def collate(samples, pad_id=0):

--- options
- `y.transpose(1, 2).view(B, T, nh * hs)`

def my_cross_entropy(logits, target):
    logp = logits - logits.logsumexp(dim=-1, keepdim=True)
    picked = logp.gather(-1, target.unsqueeze(-1)).squeeze(-1)
    return -picked.mean()
