@@ concept
title: 第一步的 loss：约等于 ln C
--- body
刚初始化的分类模型什么都不懂。它给 C 个类别的概率应该差不多，都在 1/C 附近。

cross-entropy（交叉熵）= 「正确类别的概率」取负对数。所以第一步的 loss 应该约等于 -ln(1/C) = **ln C**：

- 10 类：ln 10 ≈ 2.30
- GPT-2 的词表有 50257 个 token：ln 50257 ≈ 10.8

训练开始前先心算这个数，再和日志里第一步的 loss 比一比：

- 差不多（只差零点几）：正常。
- 大很多：模型一开始就「很自信地猜错」。常见原因是初始化的权重太大，或者 logits（模型对每个类别打的原始分数，还没过 softmax）被放大了。
- 小很多：什么都没学的模型不可能比瞎猜更好，所以多半是 loss 写错了，或者权重不是新初始化的（比如不小心加载了训练好的 checkpoint）。标签混进了输入并不会让第一步的 loss 变小，它要过几步才露馅：loss 快得可疑地降到接近 0。

下面的例子里，正常初始化时第一步的 loss 是 2.478，接近 ln 10 = 2.303；把权重放大 30 倍，第一步的 loss 就变成了 25.738。
--- code
torch.manual_seed(0)
C = 10
model = nn.Linear(32, C)
x = torch.randn(64, 32)
y = torch.randint(0, C, (64,))

print("ln C               =", round(math.log(C), 3))
print("第一步的 loss       =", round(F.cross_entropy(model(x), y).item(), 3))
with torch.no_grad():
    model.weight.mul_(30)            # 模拟「初始化太大」
print("权重 ×30 之后的 loss =", round(F.cross_entropy(model(x), y).item(), 3))

@@ concept
title: 读 loss 曲线：平、爆、跳、地板
--- body
每隔几步把 loss 打印出来（或者画成曲线），先看它的形状。常见的「不对劲」有这几种：

- **平的**：一直停在第一步的值附近（10 类时一直是 2.30 左右），说明模型什么都没学到。要么参数根本没被更新（被冻住了、不在优化器里、lr 是 0），要么标签和输入对不上。
- **爆炸**：越来越大，常常一路涨到 inf 或 nan。最常见的原因是学习率太大。
- **来回跳**：忽高忽低，看不出往下走的趋势。通常是学习率偏大。
- **有地板**：降到某个值就再也下不去，连一个小 batch 都背不下来。这多半是代码 bug，比如 cross_entropy 前面多做了一次 softmax。

学习率（lr）= 每一步沿着梯度走多远。它直接决定曲线的形状。下面用最简单的例子演示：只有一个参数 w，loss = (w - 3)²，最低点在 w = 3。

- lr = 0.05：每步只走一小段，loss 降得很慢。
- lr = 0.4：几步就到 3，loss 降到 0。
- lr = 1.1：每一步都跨过谷底，跳到 3 的另一边，而且一次比一次跳得远，loss 越来越大。这就是「爆炸」。真实训练里再多跳几步，权重大到溢出，loss 就变成 inf 或 nan。
--- code
for lr in (0.05, 0.4, 1.1):
    w = torch.tensor(0.0, requires_grad=True)
    ws, losses = [], []
    for step in range(6):
        loss = (w - 3) ** 2
        ws.append(round(w.item(), 2))
        losses.append(round(loss.item(), 2))
        w.grad = None
        loss.backward()
        with torch.no_grad():
            w -= lr * w.grad            # 沿梯度的反方向走 lr 那么远
    print(f"lr={lr:<5} w   : {ws}")
    print(f"{'':9}loss: {losses}")

@@ concept
title: NaN 和 inf 从哪里来
--- body
inf 是「无穷大」，nan 是「不是一个数」（Not a Number）。loss 里一旦出现它们，backward 会把它们带进每一个梯度，优化器走一步之后，所有权重都变成 nan，模型就废了。常见来源：

- **log(0) = -inf**：概率被算成了正好 0（比如 softmax 算出来的概率太小，float32 表示不了）。
- **exp 太大**：float32 最大约 3.4e38，exp(88.7) 就到顶了，再大就是 inf。
- **除以 0**：1/0 = inf，0/0 = nan。比如做标准化时除以标准差，而某一列数据全都一样，标准差是 0。
- **inf 再参与运算**：0 × inf = nan，inf - inf = nan。
- **负数开方、负数取 log**：结果是 nan。
- **fp16 溢出**（下一张卡片）和**学习率太大**（权重越更新越大，最后溢出）。

还有一个坑：**nan 和任何数比较都是 False**。`nan > 10` 是 False，`nan == nan` 也是 False。所以 `if loss > 100: 报警` 永远抓不到 nan。

要判断一个数正不正常，用 `math.isfinite(x)`（Python 的数）或 `torch.isfinite(t)`（tensor）：普通的数返回 True，nan、inf、-inf 都返回 False。
--- code
print(torch.exp(torch.tensor([10.0, 50.0, 90.0])).tolist())   # 90 已经溢出
print(torch.tensor(-1.0).sqrt().item(), float("inf") - float("inf"))

x = torch.tensor([[1.0, 5.0], [1.0, 7.0]])      # 第 0 列全是 1，标准差是 0
print(((x - x.mean(0)) / x.std(0)).tolist())     # 0 / 0 = nan

print(torch.tensor([1.0, float("nan"), 3.0]).sum().item())   # 一个 nan 污染整个和

nan = float("nan")
print(nan > 10, nan < 10, nan == nan)                          # 全是 False
print(math.isfinite(nan), math.isfinite(float("inf")), math.isfinite(2.5))

@@ concept
title: fp16 的天花板：65504
--- body
混合精度训练（mixed precision）把很多计算放到 16 位浮点数里做：省显存，也更快。但两种 16 位格式差别很大：

- **float16（fp16）**：最大只能表示 65504。256 × 256 = 65536，已经超了，变成 inf。
- **bfloat16（bf16）**：能表示的范围和 float32 一样大（最大约 3.4e38），几乎不会溢出。代价是精度低，只有 2～3 位有效数字。
- **float32**：最大约 3.4e38，大约 7 位有效数字。

fp16 最容易溢出的地方：平方（x²）、很多数加在一起（sum）、注意力分数 q·k、方差和范数。它们在 float32 里完全正常，一换成 fp16 就变成 inf。之后 inf 可能变成 nan，也可能「悄悄地」变成 0：比如 1/sqrt(inf) = 0，整层输出都被乘成 0，而且不报错。

常见的修法：

1. 危险的那一小段先转成 float32 算，算完再转回来：`xf = x.float()` … `.to(x.dtype)`。Llama 的 RMSNorm 就是这么写的。
2. 显卡支持的话，用 bf16 代替 fp16。
3. 用 fp16 训练时配上 `torch.amp.GradScaler`：它先把 loss 放大再 backward，防止很小的梯度在 fp16 里变成 0；梯度里出现 inf 时，它会跳过这一步更新。
--- code
print("float16 最大值:", torch.finfo(torch.float16).max)
print("bfloat16 最大值:", torch.finfo(torch.bfloat16).max)

a = torch.tensor([255.0, 256.0], dtype=torch.float16)
print("fp16 平方:", (a * a).tolist())
print("bf16 平方:", (a.bfloat16() * a.bfloat16()).tolist())
print("fp32 平方:", (a.float() * a.float()).tolist())

s = torch.full((1000,), 100.0, dtype=torch.float16)
print("1000 个 100 在 fp16 里求和:", s.sum().item())
print("先转成 float32 再求和:   ", s.float().sum().item())

@@ concept
title: 数值稳定的写法
--- body
同一个公式，换一种写法就能避开 inf 和 nan。记住这几条：

- **不要自己写 `torch.log(torch.softmax(x))`**。某个概率小到 float32 表示不了时会变成 0，log(0) = -inf。用 `F.log_softmax(x, dim=-1)`：它在内部先减掉最大值再算，结果是一个正常的负数，不会是 -inf。
- **`F.cross_entropy` 要的是 logits**（原始分数），它内部自己会做 log_softmax。**不要**在它前面再加 softmax。
- **二分类同理**：不要先 sigmoid 再 log，用 `F.binary_cross_entropy_with_logits`。
- **可能碰到 0 的地方加一点保护**：`torch.log(p.clamp_min(1e-12))`、`torch.sqrt(x + 1e-12)`、`x / (std + 1e-5)`。
- **容易溢出的一小段**（平方、求和、方差）在 float32 里算完，再转回低精度。

下面的例子：logits 是 [0, 200]，第 0 类的概率是 e^-200，float32 表示不了，softmax 直接给出 0，再取 log 就是 -inf；log_softmax 算出的是准确的 -200。
--- code
logits = torch.tensor([[0.0, 200.0]])
print("log(softmax):", torch.log(logits.softmax(-1)).tolist())
print("log_softmax :", F.log_softmax(logits, -1).tolist())

z = torch.tensor([40.0])             # 模型非常确定是「正类」，但标签是 0
p = torch.sigmoid(z)
print("sigmoid 之后:", p.item(), "  log(1 - p):", torch.log(1 - p).item())
print("with_logits 版本的 loss:", F.binary_cross_entropy_with_logits(z, torch.tensor([0.0])).item())

@@ concept
title: 抓住第一个 NaN：isfinite 和 detect_anomaly
--- body
nan 一出现就会往后扩散，所以要找的是**第一个**出问题的地方。

1. **每一步检查 loss**：`if not torch.isfinite(loss): raise FloatingPointError(...)`。训练会停在出事的那一步，你可以把那一步的 batch 存下来慢慢查，而不是带着 nan 权重再跑几个小时。
2. **forward 里出的 nan**：让输入一层一层地经过模型，每一层之后检查 `torch.isfinite(out).all()`。第一个不通过的层就是源头，后面的层只是被传染了。
3. **backward 里出的 nan**：forward 的输出都正常，梯度却是 nan。这时把 forward 和 backward 都包进 `with torch.autograd.detect_anomaly():`。backward 一算出 nan 就会报错，错误信息里写着是哪个反向函数，比如 `Function 'LogBackward0' returned nan values`。它还会打印一段 warning，列出这个运算在 forward 里是从哪里调用的：在里面找到你自己代码的那一行。它会让训练慢很多，只在调试时打开。

一个经典的例子：`torch.where(x > 0, torch.log(x), 0)`。forward 完全没问题：x ≤ 0 的位置选的是 0。但 backward 时，两个分支的梯度都会算：log 的反向是「上游梯度 ÷ x」，在 x = 0 的位置就是 0 ÷ 0 = nan。修法是先让 log 的输入变安全：`torch.log(torch.where(x > 0, x, 1.0))`。
--- code
loss = torch.tensor(float("nan"))
print("isfinite:", torch.isfinite(loss).item(), "  loss > 100:", (loss > 100).item())

x = torch.tensor([0.0, 2.0], requires_grad=True)
y = torch.where(x > 0, torch.log(x), torch.zeros_like(x))
print("forward 正常:", y.tolist())
y.sum().backward()
print("梯度:", x.grad.tolist())                  # 第 0 个是 nan

x.grad = None
try:
    with torch.autograd.detect_anomaly():
        y = torch.where(x > 0, torch.log(x), torch.zeros_like(x))
        y.sum().backward()
except RuntimeError as e:
    print("detect_anomaly 报错:", str(e).splitlines()[0])

@@ concept
title: 每一层的梯度范数
--- body
backward 之后，每个参数的 `.grad` 里存着它的梯度。**梯度范数**就是把梯度看成一个长长的向量，算它的长度：`p.grad.norm()`。它告诉你这一层「被推得有多用力」。

按层打印一遍，很多问题一眼就能看出来：

- **None**：这个参数根本没收到梯度。要么被冻住了（`requires_grad=False`），要么它没参与计算 loss（比如定义了一层，却没在 forward 里用上）。
- **0**：收到了，但全是 0。比如 ReLU 前面的值全是负数（「死掉」的 ReLU），或者 loss 其实和它没关系。
- **很大**（几百、几千）或 inf：梯度爆炸，下一步就可能出 nan。先降低 lr，或者做梯度裁剪（`torch.nn.utils.clip_grad_norm_`）。
- **前面几层比后面几层小好几个数量级**：梯度消失，前面的层几乎学不到东西。

训练时把总的梯度范数和 loss 一起打印出来（`clip_grad_norm_` 的返回值就是裁剪前的总范数）。loss 爆炸之前，梯度范数通常会先涨起来。
--- code
torch.manual_seed(0)
model = nn.Sequential(nn.Linear(8, 16), nn.ReLU(), nn.Linear(16, 4))
model[0].weight.requires_grad_(False)           # 假装有人把第一层的权重冻住了
x, y = torch.randn(32, 8), torch.randint(0, 4, (32,))
F.cross_entropy(model(x), y).backward()

for name, p in model.named_parameters():
    g = None if p.grad is None else round(p.grad.norm().item(), 4)
    print(f"{name:9s} requires_grad={p.requires_grad!s:5s}  梯度范数 = {g}")

@@ concept
title: loss 不降：按顺序查这几项
--- body
loss 不降的时候，先别急着调超参数。先确认代码没错，按这个顺序查：

1. **先在一个小 batch 上过拟合**（第 14 天学过）：拿同一个 batch 反复训练，loss 应该能降到接近 0。降不下去，就是代码有 bug，调 lr、加数据都没用。
2. **每一步都 zero_grad 了吗？** PyTorch 的梯度是**累加**的：不清零，这一步的梯度会加在上一步的上面，每一步的更新都不对。
3. **参数真的在被训练吗？** 看每层的梯度范数：None = 被冻住了；有梯度但权重从来不变 = 它不在优化器里（常见于先建了优化器，后来又换掉了模型的某一层）。
4. **标签还和输入对得上吗？** 打乱数据时，x 和 y 必须用同一个顺序。打印几对 (x, y) 看一眼。配错之后，loss 会卡在 ln C 附近。
5. **cross_entropy 前面是不是多了一个 softmax？** 它要的是 logits。多做一次 softmax 之后，就算模型完全答对，loss 也有一块下不去的「地板」：C 类时是 ln(1 + (C-1)/e)，4 类约 0.744，10 类约 1.46。
6. **学习率**：太大会爆炸或来回跳，太小会降得很慢。每次乘或除以 10 试一试。
--- code
w = torch.tensor([1.0], requires_grad=True)
for step in range(3):
    loss = 3 * w.sum()                # 这个 loss 对 w 的梯度永远是 3
    loss.backward()
    print("没有清零，第", step, "步 w.grad =", w.grad.item())

logits = torch.tensor([[100.0, 0.0, 0.0, 0.0]])   # 模型非常确定，而且答对了
y = torch.tensor([0])
print("cross_entropy(logits)          =", F.cross_entropy(logits, y).item())
print("cross_entropy(softmax(logits)) =", round(F.cross_entropy(logits.softmax(-1), y).item(), 4))

--- explain

大的训练一跑就是几个小时，没有人会一直盯着看。训练脚本里通常有一个小函数自动检查 loss，发现 nan 或爆炸就报警、停下，不浪费 GPU 时间。
--- prompt
写 `curve_verdict(losses)`：

- `losses`：Python float 的 list，每步一个（至少 2 个）
- 按下面的顺序判断，返回第一个满足条件的字符串：
  1. 有任何一个值是 nan、inf 或 -inf → `"nan"`
  2. 最后一个值 > 2 × 第一个值 → `"exploding"`
  3. |最后一个值 - 第一个值| < 0.01 × 第一个值（变化不到 1%）→ `"flat"`
  4. 其他情况 → `"ok"`

注意：不能用 `v == float("nan")` 来判断 nan。为什么？看卡片「NaN 和 inf 从哪里来」。
--- starter
def curve_verdict(losses):
    """losses: list of float -> "nan" / "exploding" / "flat" / "ok"（按顺序判断）。"""
    raise todo()
--- solution
def curve_verdict(losses):
    if not all(math.isfinite(v) for v in losses):     # nan 和 ±inf 都不是有限的数
        return "nan"
    if losses[-1] > 2 * losses[0]:
        return "exploding"
    if abs(losses[-1] - losses[0]) < 0.01 * losses[0]:
        return "flat"
    return "ok"
--- tests
@check("nan 和 inf 要最先查出来")
def _():
    nan, inf = float("nan"), float("inf")
    true(curve_verdict([2.3, 1.9, nan]) == "nan",
         '最后一个值是 nan，应该返回 "nan"。nan 和任何数比较（>、<、==）都是 False，要用 math.isfinite 判断')
    true(curve_verdict([2.3, nan, 1.1]) == "nan",
         '中间出现过 nan 也算：每一个值都要检查，不只是最后一个')
    true(curve_verdict([2.3, 8.0, inf]) == "nan",
         'inf 也算坏值（math.isfinite(inf) 是 False），应该返回 "nan"')
    true(curve_verdict([2.3, -inf]) == "nan", '-inf 也算坏值，应该返回 "nan"')

@check("exploding、flat、ok")
def _():
    true(curve_verdict([2.3, 3.1, 9.8]) == "exploding", '9.8 > 2 × 2.3，应该是 "exploding"')
    true(curve_verdict([2.3026, 2.3026, 2.3021]) == "flat", '从 2.3026 到 2.3021 只变了 0.02%，应该是 "flat"')
    true(curve_verdict([2.3, 1.2, 0.4]) == "ok", '从 2.3 降到 0.4 是正常的，应该返回 "ok"')
    true(curve_verdict([1.0, 0.5, 1.9]) == "ok", '1.9 没有超过 2 × 1.0，也不算平，应该返回 "ok"')
    true(curve_verdict([1.0, 5.0, 2.5]) == "exploding", '只比较第一个和最后一个：2.5 > 2 × 1.0，应该是 "exploding"')

    opt = torch.optim.SGD(model.parameters(), lr=lr)
    losses = []
    for step in range(steps):

        loss = F.cross_entropy(logits, y)            # 修 1：直接给 logits，它内部会做 log_softmax
        if not torch.isfinite(loss):

        opt.zero_grad()                              # 修 2：清掉上一步的梯度

def grad_norms(model):
    out = {}
    for name, p in model.named_parameters():
