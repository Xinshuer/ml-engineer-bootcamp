@@ concept
title: 从 GPT-2 到 Llama：改了哪几处
--- body
昨天（第 4 天）你手写了一个 GPT-2 风格的 Transformer。Llama（Meta 开源的大模型系列）的骨架和它一样：token embedding → 很多层 block → 最后一个 norm → lm_head。每个 block 里还是「先 norm，再 attention，加残差；先 norm，再 FFN，加残差」。

变的是零件。今天一处一处换：

1. LayerNorm → **RMSNorm**：不减均值，只除以均方根，参数少一半。
2. 学出来的位置 embedding（GPT-2 的 `wpe`）→ **RoPE**：不再往输入上加位置向量，而是在每层 attention 里按位置「旋转」q 和 k。
3. GELU 的 MLP → **SwiGLU**：多一个「门」矩阵，隐层变窄一点，总参数量差不多。
4. Linear 层去掉 bias。
5. 多头 attention（MHA）→ **GQA**：几个 q head 共用一组 k/v。Llama 2 的 70B 和 Llama 3 开始用。

后半天讲生成（推理）时的两件事：**KV cache**（生成时不重复计算旧 token）和**采样**（temperature、top-k、top-p、重复惩罚）。这两件 GPT-2 也用，面试里常和 Llama 一起问。

下面的例子用 Llama-7B 的宽度 C = 4096，算几处改动前后的参数量。
--- code
C = 4096   # Llama-7B 每层的宽度
print(f"一个 norm 层     LayerNorm: {2 * C:,}   RMSNorm: {C:,}")
print(f"一个 FFN（不算 bias）  GPT-2 的 MLP (C->4C->C): {2 * C * 4 * C:,}")
print(f"                       SwiGLU (3 个 C x 11008): {3 * C * 11008:,}")
print(f"位置编码         GPT-2 的 wpe (1024 个位置): {1024 * C:,}   RoPE: 0")

@@ concept
title: RMSNorm：不减均值，只除以均方根
--- body
LayerNorm 对每个 token 的向量（长度 C）做三步：减去均值，除以标准差，再乘 weight、加 bias。参数有 2C 个。

RMSNorm（Root Mean Square Norm，均方根归一化）更简单：
```
rms = sqrt(mean(x²) + eps)
y   = x / rms * weight
```
- 不减均值，没有「居中」这一步。
- 只有 weight（形状 (C,)，初始全 1），没有 bias，参数 C 个。
- weight 全 1 时，输出的均方值 mean(y²) ≈ 1。
- eps 是一个很小的数（比如 1e-6），防止除以 0。

为什么换：少算一步，参数少一半，效果差不多。Llama、Mistral、Qwen 都用它。

写代码时的两个工具：`torch.rsqrt(a)` 就是 1 / sqrt(a)。`x.pow(2).mean(-1, keepdim=True)` 在最后一维（C）上求平均，并保留这一维：(B, T, C) 变成 (B, T, 1)，这样才能和 (B, T, C) 广播相乘。

PyTorch 2.4 起自带 `nn.RMSNorm`。面试和今天的练习都要你自己写。
--- code
x = torch.tensor([[1.0, 2.0, 3.0, 4.0]])
ms = x.pow(2).mean(-1, keepdim=True)          # (1+4+9+16)/4 = 7.5
y = x * torch.rsqrt(ms + 1e-6)
print("mean(x^2) =", ms.item())
print("RMSNorm  :", y)
print("mean(y^2) =", round(y.pow(2).mean().item(), 4))
print("LayerNorm:", F.layer_norm(x, (4,)), " <- 减了均值，有正有负")
with torch.no_grad():
    print("官方 nn.RMSNorm:", nn.RMSNorm(4, eps=1e-6)(x))

@@ concept
title: RoPE：按位置旋转 q 和 k
--- body
GPT-2 把「位置 t 的向量」加到 token embedding 上。RoPE（Rotary Position Embedding，旋转位置编码）不加任何东西，而是在每层 attention 里，把 q 和 k 按位置**旋转**一个角度。v 不转。

怎么转：
- 把长度为 hd（head_dim，一个 head 的宽度）的向量看成 hd/2 对数。每一对就是平面上的一个点。
- 第 i 对有自己的角速度 ω_i = 1 / θ^(2i / hd)。θ 通常取 10000，i = 0, 1, …, hd/2 − 1。
- 在位置 t，第 i 对转 t · ω_i 弧度。

hd = 8 时，ω = [1, 0.1, 0.01, 0.001]。第 0 对每走一个位置转 1 弧度（很快），最后一对只转 0.001 弧度（很慢）。转得快的对能分辨相邻的位置，转得慢的对能表示很远的距离。Llama 3 把 θ 调到 500000，让慢的更慢，用来支持更长的文本。

把所有位置、所有对的角度排成一张表，形状 (max_seq_len, hd/2)：角度[t, i] = t · ω_i。这张表只在建模型时算一次，提前算好 cos 和 sin，每层都查它。位置 0 的角度全是 0：cos = 1，sin = 0，也就是不转。

两个工具：`torch.arange(0, hd, 2)` 是 [0, 2, 4, …]，正好是公式里的 2i。`torch.outer(a, b)`（外积）把 a 的每个元素和 b 的每个元素相乘，得到 (len(a), len(b)) 的表。

旋转一个点 (a, b)，转 φ 弧度：
```
a' = a · cos φ − b · sin φ
b' = a · sin φ + b · cos φ
```

RoPE 有两个重要性质：
- **不改变长度**：旋转不会让 q、k 变长或变短。
- **内积只看相对距离**：q 在位置 m 转了 m·ω，k 在位置 n 转了 n·ω。两个向量的内积只取决于它们的长度和夹角，两个都转以后，夹角只多了 (n − m)·ω。所以 attention 分数 q·k 只和距离 n − m 有关：q 在 3、k 在 5，和 q 在 20、k 在 22，分数一样。模型学到的是「隔了几个位置」，不是「在第几个位置」。
--- code
print("2i =", torch.arange(0, 8, 2))
w = 1.0 / (10000.0 ** (torch.arange(0, 8, 2).float() / 8))
print("hd=8 的角速度 ω:", w)
print("外积的例子:\n", torch.outer(torch.arange(3).float(), torch.tensor([1.0, 0.1])))

def rot2(v, phi):                      # 把一个点 (a, b) 转 phi 弧度
    c, s = math.cos(phi), math.sin(phi)
    return torch.stack([v[0] * c - v[1] * s, v[0] * s + v[1] * c])

q, k = torch.tensor([1.0, 2.0]), torch.tensor([0.5, -1.0])
w0 = 0.3                               # 这一对的角速度
print("q 在 3,  k 在 5 :", round((rot2(q, 3 * w0) @ rot2(k, 5 * w0)).item(), 4))
print("q 在 20, k 在 22:", round((rot2(q, 20 * w0) @ rot2(k, 22 * w0)).item(), 4), " <- 距离一样，内积一样")
print("q 在 3,  k 在 9 :", round((rot2(q, 3 * w0) @ rot2(k, 9 * w0)).item(), 4), " <- 距离不同，内积不同")

@@ concept
title: RoPE 的写法：配对、交错和复数
--- body
写 RoPE 代码时，先要决定哪两维算「一对」。有两种约定：
- **相邻配对**（Meta 原版 Llama 代码，也是今天练习用的）：(x0, x1)、(x2, x3)、…。`x[..., 0::2]` 取出所有偶数维（每对的第一个数 a），`x[..., 1::2]` 取出所有奇数维（每对的第二个数 b）。
- **对半配对**（HuggingFace 的 `rotate_half`）：前一半和后一半配对。hd = 8 时是 (x0, x4)、(x1, x5)、…。

两种都对。但权重是按其中一种训练（或转换）出来的。用错约定**不会报错**，模型只会输出乱码。

相邻配对算出新的 a'、b' 以后，要**交错**放回去：a'0, b'0, a'1, b'1, …。`torch.stack([a', b'], dim=-1)` 得到 (…, hd/2, 2)，再 `.flatten(-2)` 把最后两维压成 (…, hd)。直接 `torch.cat([a', b'], dim=-1)` 会得到 a'0, a'1, …, b'0, b'1, …，顺序就错了。

形状怎么对上：x 是 (B, nh, T, hd)，`x[..., 0::2]` 是 (B, nh, T, hd/2)。cos、sin 是 (T, hd/2)，和它的最后两维一样，直接广播，不用写循环。

**复数写法**（Meta 原版代码就这么写）：一对 (a, b) 看成复数 a + bi。乘以 e^(iφ) = cos φ + i·sin φ 就是转 φ 弧度，因为复数相乘时角度相加、长度相乘。
- `torch.view_as_complex(t)`：t 的最后一维必须是 2，(…, hd/2, 2) 变成复数张量 (…, hd/2)。所以先 `reshape(*x.shape[:-1], -1, 2)`。
- `torch.polar(r, φ)`：长度 r、角度 φ 的复数。r 全取 1，就是 e^(iφ)。
- `torch.view_as_real(z)`：复数 (…, hd/2) 变回 (…, hd/2, 2)，再 `.flatten(-2)`。
- 复数只支持 float32/float64 这类类型，所以先 `x.float()`，最后 `.type_as(x)` 转回 x 原来的 dtype。
--- code
x = torch.arange(8.0)
a, b = x[0::2], x[1::2]
print("偶数维 a:", a, " 奇数维 b:", b)
print("stack + flatten:", torch.stack([a, b], dim=-1).flatten(-2), " <- 交错，顺序还原")
print("cat            :", torch.cat([a, b], dim=-1), " <- 顺序乱了")

z = torch.view_as_complex(torch.tensor([3.0, 4.0]))           # 3 + 4i
turn = torch.polar(torch.tensor(1.0), torch.tensor(math.pi / 2))   # e^(i·90°)
print("复数:", z)
print("转 90° 以后:", torch.view_as_real(z * turn).round(decimals=4), " <- (3, 4) 变成 (-4, 3)，长度还是 5")

@@ concept
title: SwiGLU：带「门」的 FFN
--- body
GPT-2 的 FFN（前馈层）：C → 4C → C，中间用 GELU。两个矩阵，参数 2 · C · 4C = 8C²（不算 bias）。

Llama 的 SwiGLU 用三个没有 bias 的 Linear：
```
w1: C -> H     w3: C -> H     w2: H -> C
out = w2( silu(w1(x)) * w3(x) )
```
- `silu(z) = z · sigmoid(z)`（也叫 Swish），PyTorch 里是 `F.silu`。
- `w3(x)` 像一个「门」：和 `silu(w1(x))` 逐元素相乘，决定每个隐藏单元放多少信息过去。
- 三个矩阵共 3 · C · H 个参数。要和 GPT-2 的 8C² 差不多，取 H = (2/3) · 4C = 8C/3，这样 3 · C · H = 8C²。

8C/3 通常不是整数，也不是硬件喜欢的尺寸。Llama 的做法：先 `int(...)` 取整，再**向上**取到 multiple_of（比如 256）的倍数。C = 4096 时：8 × 4096 / 3 = 10922.67 → 10922 → 向上取到 256 的倍数 = 11008（43 × 256）。这就是 Llama-7B 的 FFN 宽度。

向上取整到 m 的倍数，整数写法是 `((h + m - 1) // m) * m`（`//` 是整除）。
--- code
z = torch.tensor([-2.0, 0.0, 2.0])
print("F.silu        :", F.silu(z))
print("z * sigmoid(z):", z * torch.sigmoid(z))
print("8C/3, C=4096  :", 2 * (4 * 4096) / 3, "-> int:", int(2 * (4 * 4096) / 3))
m = 256
for h in (10922, 11008, 11009):
    print(h, "向上取到 256 的倍数 ->", ((h + m - 1) // m) * m)

@@ concept
title: GQA：几个 q head 共用一组 k/v
--- body
普通的多头 attention（MHA）：有 n_head 个 q head，就有 n_head 个 k head 和 n_head 个 v head。生成时要把所有层的 k、v 都存下来（KV cache，下一张卡片），这是显存的大头。

GQA（Grouped-Query Attention，分组查询注意力）：k、v 只有 n_kv_head 组（比如 8 组）。每 n_rep = n_head / n_kv_head 个 q head 共用同一组 k/v。KV cache 直接小 n_rep 倍。例：Llama 2 70B 有 64 个 q head、8 个 kv head，n_rep = 8，缓存小 8 倍。n_kv_head = 1 的极端情况叫 MQA（Multi-Query Attention）。

算 attention 之前，把 k、v 的 head 维「复制」到 n_head 个，后面就和普通 attention 一模一样。这个函数通常叫 `repeat_kv`。

顺序很重要：q head 0 到 n_rep − 1 属于第 0 组，所以复制后的 kv head 要排成 0,0,…,1,1,…（每个连续重复），不能是 0,1,0,1,…。

写法分三步：
1. `x[:, :, None]`：在 head 维后面插一个长度为 1 的新维度。(B, n_kv, T, hd) → (B, n_kv, 1, T, hd)。
2. `.expand(B, n_kv, n_rep, T, hd)`：把长度 1 的那一维「拉」成 n_rep。expand 不复制内存，只是让同一份数据被看 n_rep 次。
3. `.reshape(B, n_kv * n_rep, T, hd)`：把 (n_kv, n_rep) 两维合成一维。
--- code
x = torch.tensor([1.0, 2.0]).view(1, 2, 1, 1)     # (B=1, n_kv_head=2, T=1, hd=1)
x5 = x[:, :, None]
print("插一维以后:", tuple(x5.shape))
e = x5.expand(1, 2, 2, 1, 1)                        # n_rep = 2
print("expand 以后:", tuple(e.shape))
print("合成 4 个 head:", e.reshape(1, 4, 1, 1).flatten().tolist(), " <- 每个 kv head 连续出现 2 次")

@@ concept
title: KV cache：生成时只算最新的 token
--- body
生成文本是一个 token 一个 token 来的：把序列喂给模型，取最后一个位置的 logits，采样出下一个 token，接到末尾，再来一遍。

没有缓存时，第 t 步要把前面所有 token 的 k、v 重新算一遍。可是它们上一步已经算过了，而且不会变（因果 attention 里，旧位置看不到新 token，所以旧位置的结果不受新 token 影响）。

**KV cache**：每层把已经算过的 k、v 存起来。之后每一步只喂新来的那一个 token：
1. 只算新 token 的 q、k、v，时间维长度是 1：(B, nh, 1, hd)。
2. 对 q、k 做 RoPE，用它**在整个序列里的位置 t**，不是 0。
3. 把新的 k、v 沿时间维（dim=-2）接到缓存后面：`torch.cat([旧的, 新的], dim=-2)`。
4. 用这一个 q 对缓存里全部的 k、v 做 attention。

第 4 步**不需要 causal mask**。causal mask 的作用是不让一个位置看到它后面的位置。现在唯一的 q 就是最新的位置，缓存里的 k 全在它之前（或者就是它自己），本来就都可以看。

怎么证明写对了（工作里也这样测）：一次喂一个 token 得到的输出，必须和一次喂整个序列（带 causal mask）的输出逐个位置一致。对不上的话，九成是位置索引错了。KV cache 会占多少显存，第 23 天再算。
--- code
torch.manual_seed(0)
q, k, v = torch.randn(1, 1, 5, 4), torch.randn(1, 1, 5, 4), torch.randn(1, 1, 5, 4)
full = F.scaled_dot_product_attention(q, k, v, is_causal=True)   # 一次算完 5 个位置
last = F.scaled_dot_product_attention(q[:, :, -1:], k, v)         # 只用最后一个 q，不加 mask
print("全量前向的最后一个位置:", full[0, 0, -1])
print("单步（不加 mask）      :", last[0, 0, 0])
print("一样吗:", torch.allclose(full[:, :, -1:], last, atol=1e-6))

cache_k = torch.zeros(1, 2, 0, 4)                 # 空缓存：时间维长度 0
for t in range(3):
    cache_k = torch.cat([cache_k, torch.randn(1, 2, 1, 4)], dim=-2)
    print(f"第 {t} 步以后，缓存的 shape:", tuple(cache_k.shape))

@@ concept
title: 采样：temperature、top-k、top-p 和重复惩罚
--- body
模型在最后一个位置输出 logits（每个词的原始分数，还没过 softmax），形状 (B, V)，V 是词表大小。选下一个 token 的常见流程：
1. **重复惩罚**（可选）：已经出现过的 token，分数压低一点。
2. **temperature**：logits / T。T < 1 让分布更尖（更确定），T > 1 更平（更随机）。T = 0 约定为「贪心」：只留最大的那个（argmax）。不能真的除以 0。
3. **top-k**：只留分数最大的 k 个，其余设成 -inf。softmax 以后 -inf 的概率就是 0。
4. **top-p**（核采样）：按概率从大到小排好，一个个往上加。累计概率**第一次 ≥ p** 时停下，这个 token 也留下，后面的全部去掉。至少留 1 个。
5. softmax 得到概率，用 `torch.multinomial` 抽一个。

top-p 的例子：概率 [0.5, 0.3, 0.15, 0.05]，p = 0.7。累加：0.5、0.8。加到第 2 个时第一次 ≥ 0.7，所以留前 2 个。一个好用的判断：一个 token「之前」的累计概率（不含它自己）已经 ≥ p，它就该去掉。

top-p 的代码要先排序：`s, idx = logits.sort(dim=-1, descending=True)`，s 是排好的值，idx 是它们原来的下标。在排好的顺序里算出「去掉哪些」，再用 `scatter` 按 idx 放回原来的位置。

**重复惩罚**（repetition penalty，HuggingFace `generate` 里的同名参数）：penalty > 1。对出现过的 token，logit > 0 就除以 penalty，logit ≤ 0 就乘以 penalty。两种都让它变小。如果只会「除以」，负数反而会变大（−2 / 2 = −1），更容易被选中。

按下标批量取值和写回：`logits.gather(1, ids)` 按 ids 取出分数；`logits.scatter(1, ids, 新值)` 按 ids 写回，返回一个新张量。
--- code
logits = torch.tensor([1.0, 2.0, 3.0, 4.0])
for T in (0.5, 1.0, 2.0):
    print(f"T={T}: 概率", (logits / T).softmax(-1))
print("最大的 2 个:", logits.topk(2).values)

probs = torch.tensor([0.5, 0.3, 0.15, 0.05])
print("累计概率          :", probs.cumsum(-1))
print("之前的累计（不含自己）:", probs.cumsum(-1) - probs)

ids = torch.tensor([3, 0])
print("gather:", logits.gather(0, ids))
print("scatter:", logits.scatter(0, ids, torch.tensor([-1.0, -1.0])))

class RMSNorm(nn.Module):
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

def apply_rope(x, cos, sin):
    """x: (B, nh, T, hd)   cos/sin: (T, hd//2)  ->  (B, nh, T, hd)
    配对方式是**相邻两维**: (x0,x1) 一对, (x2,x3) 一对, ...
        out[..., 2i]   = x[2i]*cos[i] - x[2i+1]*sin[i]
        out[..., 2i+1] = x[2i]*sin[i] + x[2i+1]*cos[i]

--- solution
def apply_rope(x, cos, sin):
    x1, x2 = x[..., 0::2], x[..., 1::2]        # 相邻两维配对
    o1 = x1 * cos - x2 * sin
    o2 = x1 * sin + x2 * cos
    return torch.stack([o1, o2], dim=-1).flatten(-2)   # 交错还原

    B, nkv, T, hd = x.shape

class KVCache:
    def __init__(self):
        self.k = None
        self.v = None

    @property
    def length(self):
        return 0 if self.k is None else self.k.size(-2)

    def update(self, k, v):
        self.k = k if self.k is None else torch.cat([self.k, k], dim=-2)
        self.v = v if self.v is None else torch.cat([self.v, v], dim=-2)
        return self.k, self.v

    def reset(self):
        self.k = self.v = None

def attn_step(q, k_all, v_all):
    # q 是序列里最新的那个位置，它本来就有权看到全部历史，所以不需要 mask
    att = (q @ k_all.transpose(-2, -1) / math.sqrt(q.size(-1))).softmax(-1)
    return att @ v_all

def incremental_attention(x, wq, wk, wv, cos, sin):
    B, T, C = x.shape
    nh, hd = 2, C // 2
    cache = KVCache()
    outs = []
    for t in range(T):
        xt = x[:, t:t + 1]
        q = (xt @ wq).view(B, 1, nh, hd).transpose(1, 2)
        k = (xt @ wk).view(B, 1, nh, hd).transpose(1, 2)
        v = (xt @ wv).view(B, 1, nh, hd).transpose(1, 2)
        q = apply_rope(q, cos[t:t + 1], sin[t:t + 1])    # 关键: 用第 t 个位置的角度
        k = apply_rope(k, cos[t:t + 1], sin[t:t + 1])
        K, V = cache.update(k, v)
        o = attn_step(q, K, V)
        outs.append(o.transpose(1, 2).reshape(B, 1, C))
    return torch.cat(outs, dim=1)

写三个函数。输入 logits 的形状是 (..., V)，都返回同样形状的新 logits，被去掉的位置设成 `float("-inf")`：
1. `apply_temperature(logits, t)`：返回 `logits / t`。t == 0 时不能除，改成贪心：最大值保留，其余全部 -inf。

3. `top_p_filter(logits, p)`：按 softmax 概率从大到小排，累计概率**第一次 ≥ p** 的那个 token 也保留，它后面的全部 -inf。至少保留 1 个。返回的 logits 要在**原来的顺序**上。

def apply_temperature(logits, t):
    if t == 0:
        return logits.masked_fill(logits < logits.max(-1, keepdim=True).values, float("-inf"))
    return logits / t

def top_k_filter(logits, k):
    kth = logits.topk(k, dim=-1).values[..., -1:]
    return logits.masked_fill(logits < kth, float("-inf"))

def top_p_filter(logits, p):
    s, idx = logits.sort(dim=-1, descending=True)
    probs = s.softmax(-1)
    cum = probs.cumsum(-1)
    remove = (cum - probs) >= p          # 累计到"这个 token 之前"就已经够了 -> 丢掉
    remove[..., 0] = False               # 至少留一个
    mask = torch.zeros_like(remove).scatter(-1, idx, remove)
    return logits.masked_fill(mask, float("-inf"))

def repetition_penalty(logits, prev_ids, penalty=1.2):
    s = logits.gather(1, prev_ids)
    s = torch.where(s > 0, s / penalty, s * penalty)
    return logits.scatter(1, prev_ids, s)

--- prompt
用 KV cache 生成时，每一步的 attention 只有一个 q（最新的 token），它对缓存里全部的 k、v 做 attention，不加 causal mask。为什么这样是对的？
--- options
- RoPE 已经把位置信息编码进去了，所以不需要 mask
- 唯一的 q 就是最新的位置，缓存里的 k、v 全在它之前（或就是它自己），本来就都能看
- softmax 会自动把未来位置的权重变成 0
- 其实不完全对，只是误差很小，可以忽略
--- explain
causal mask 的作用是不让位置 t 看到 t 之后的位置。单步时根本没有「之后」：缓存里只有过去和现在。所以单步的输出和全量前向（带 mask）的最后一个位置完全相等，不是近似。RoPE 只负责编码位置，不会阻止看未来；softmax 也不会自己把哪个位置变成 0。注意：如果一次喂进好几个新 token（比如先把整段 prompt 一起算），这几个 q 之间还是要加 causal mask。
--- hints
- causal mask 挡住的到底是什么？单步的时候，这些东西存在吗？
- 看卡片「KV cache」里的例子：全量前向最后一个位置的输出，和不加 mask 的单步输出，是差不多，还是完全一样？

def incremental_attention(x, wq, wk, wv, cos, sin):
    B, T, C = x.shape
    nh, hd = 2, C // 2
    cache = KVCache()
    outs = []
    for t in range(T):
        xt = x[:, t:t + 1]
        q = (xt @ wq).view(B, 1, nh, hd).transpose(1, 2)
        k = (xt @ wk).view(B, 1, nh, hd).transpose(1, 2)
        v = (xt @ wv).view(B, 1, nh, hd).transpose(1, 2)
        q = apply_rope(q, cos[t:t + 1], sin[t:t + 1])    # 关键: 用第 t 个位置的角度
        k = apply_rope(k, cos[t:t + 1], sin[t:t + 1])
        K, V = cache.update(k, v)
        o = attn_step(q, K, V)
        outs.append(o.transpose(1, 2).reshape(B, 1, C))
    return torch.cat(outs, dim=1)
