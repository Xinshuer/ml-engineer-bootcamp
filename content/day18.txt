@@ concept
title: 训练和推理不一致：一份预处理，两边共用
--- body
**训练和推理不一致**（train/serve skew）：模型在训练、评测时看到的输入，和上线后在服务里看到的输入，处理方式不一样。它不报错，只是线上效果悄悄变差。

最常见的来源：

- 训练时在 notebook 里写了一段预处理，服务里又手写了一遍，细节不一样（顺序、默认值、要不要小写）
- 标准化用的均值和标准差：训练时在训练集上算，服务里却拿「当前这批请求」现算
- tokenizer 升级了，或者词表换了顺序（下一张卡）

规则只有一条：**预处理只写一份代码**，训练和服务都 import 它。它需要的统计量（均值、标准差、词表）只在训练数据上算一次（为什么不能碰测试集，第 17 天讲过），和模型权重**存进同一个文件**，服务启动时一起加载，不再重新算。

写成一个类，用起来是这样：

```
pre = Preprocessor().fit(train_x)          # 训练时：只在训练数据上 fit
torch.save({"model": model.state_dict(), "pre": pre.state_dict()}, "bundle.pt")

bundle = torch.load("bundle.pt")           # 服务启动时
pre = Preprocessor()
pre.load_state_dict(bundle["pre"])         # 加载统计量，不再 fit
x = pre.transform(request_x)
```

下面的例子：服务里只来了 1 条请求。拿它自己算均值和标准差，结果是 nan（1 条数据减去自己的均值是 0，标准差也是 0，0/0 = nan）；用训练时存下的统计量才对。
--- code
torch.manual_seed(0)
train = torch.randn(100, 2) * torch.tensor([10.0, 0.1]) + torch.tensor([50.0, 3.0])
mean, std = train.mean(dim=0), train.std(dim=0)      # 只在训练数据上算一次
bundle = {"pre": {"mean": mean, "std": std}}         # 和模型权重放进同一个文件

req = torch.tensor([[60.0, 3.1]])                    # 服务里来了一条请求
print("用训练时的统计量:  ", (req - mean) / std)
print("用请求自己的统计量:", (req - req.mean(dim=0)) / req.std(dim=0, correction=0))

@@ concept
title: tokenizer 也有版本：用指纹对上号
--- body
模型 embedding 表的第 17 行，学的是训练时「id 为 17 的那个词」。如果服务里加载了另一版词表（tokenizer 升级了、重新建了词表、顺序变了），同一个词会变成另一个 id。代码不报错，模型收到的却是另一句话。

做法：训练时给词表算一个**指纹**（一个短字符串，词表有任何变化它就会变），和 checkpoint 存在一起。服务启动时对当前词表再算一次，对不上就拒绝启动。

怎么算指纹：

1. `json.dumps(vocab, sort_keys=True)`：把 dict 变成一段文本。`sort_keys=True` 按 key 排序，这样结果和 dict 的插入顺序无关
2. `hashlib.sha256(文本.encode("utf-8")).hexdigest()`：算出 64 个十六进制字符的摘要，取前 16 个就够用

不要用 Python 自带的 `hash()`：字符串的 `hash()` 每次启动 Python 都不一样（为了安全故意随机化的），训练进程和服务进程算出来永远对不上。
--- code
import hashlib
import json

def fingerprint(vocab):
    text = json.dumps(vocab, sort_keys=True)
    return hashlib.sha256(text.encode("utf-8")).hexdigest()[:16]

v1 = {"<pad>": 0, "hello": 1, "world": 2}
v2 = {"world": 2, "hello": 1, "<pad>": 0}     # 同一份词表，只是插入顺序不同
v3 = {"<pad>": 0, "world": 1, "hello": 2}     # 同样的词，id 换了
print(json.dumps(v2, sort_keys=True))
print("v1:", fingerprint(v1))
print("v2:", fingerprint(v2))
print("v3:", fingerprint(v3))

@@ concept
title: 推理两件套：eval() 和 inference_mode()
--- body
推理前要拨两个开关，它们管的是两件不同的事：

- `model.eval()`：改变**层的行为**。Dropout 不再随机丢神经元；BatchNorm 改用训练时存下的 running mean / var，不再用当前 batch 的统计量（细节第 17 天讲过）。它不关梯度。
- `with torch.inference_mode():`：关掉 autograd 的记账（不建计算图，不存反向传播要用的中间结果），更省内存、更快。它不改变任何层的行为。

所以两个都要。只有 inference_mode：dropout 还在随机丢。只有 eval：每次推理还在白白建计算图。

`torch.no_grad()` 也能关梯度。`inference_mode` 更彻底：在它里面算出来的张量，以后不能再拿去参与反向传播（会报错），所以只在纯推理时用。省多少内存、快多少，第 19 天再量。

两个常见的坑：

- 刚建好（或刚训练完）的模型默认是 train 模式。服务加载模型后忘了 `eval()`，线上就一直开着 dropout。
- 训练循环里每个 epoch 末尾跑验证时调了 `model.eval()`，回到训练却忘了 `model.train()`。
--- code
torch.manual_seed(0)
net = nn.Sequential(nn.Linear(4, 8), nn.Dropout(0.5), nn.Linear(8, 2))
x = torch.randn(1, 4)

with torch.inference_mode():
    a, b = net(x), net(x)
print("只有 inference_mode，两次一样吗:", torch.equal(a, b))

net.eval()
c = net(x)
print("只有 eval，requires_grad =", c.requires_grad)

with torch.inference_mode():
    d, e = net(x), net(x)
print("两个都有，两次一样吗:", torch.equal(d, e), " requires_grad =", d.requires_grad)

@@ concept
title: 结果不该随 batch 变
--- body
服务里常把几条请求拼成一个 batch 一起算。一条请求的结果，不应该取决于它和谁拼在一起、这个 batch 有多大。

会破坏这一点的常见原因：

- BatchNorm 还在 train 模式：它用「当前这个 batch」的均值和方差做标准化，伙伴一换，结果就变。（train 模式下 batch 里只有 1 条时，它甚至直接报错 `Expected more than 1 value per channel when training`，这常常是「忘了 eval()」最早露出来的信号。）
- 按 batch 里最长的序列补 pad，而模型没用 attention mask，把 pad 也算了进去
- 很小的浮点差：batch 大小不同，底层可能换一种计算顺序，结果差 1e-7 左右。这是正常的，比较时给一点容差就好（最后一张卡）

检查方法叫 **batch 无关性测试**：同一批数据，一起算一次，再拆开算一次，比最大差值。差值在 1e-6 以下，就说明和 batch 无关。下面把 5 条数据拆成 3 + 2 两批来比。
--- code
torch.manual_seed(0)
net = nn.Sequential(nn.Linear(4, 8), nn.BatchNorm1d(8), nn.Linear(8, 2))
x = torch.randn(5, 4)

for mode in ["train", "eval"]:
    net.train(mode == "train")
    with torch.inference_mode():
        together = net(x)                                  # 5 条一起算
        split = torch.cat([net(x[:3]), net(x[3:])])        # 拆成 3 条 + 2 条
    print(mode, "最大差值:", (together - split).abs().max().item())

@@ concept
title: 批量生成（一）：右填充为什么出错
ref: day18
--- body
decoder-only 模型（GPT、Llama 这类）生成时，每一步都是：把整段序列喂进去，取**最后一个位置**的 logits（模型给词表里每个词打的原始分数），挑分数最高的词，接到末尾，再来一次。

一条一条生成很简单。把几条长度不同的 prompt 放进一个 batch，就得补 pad，让它们一样长。如果 pad 补在右边（右填充）：

```
[3, 7, 2, 9]
[5, 1, 0, 0]      ← 0 是 pad
```

第二行的「最后一个位置」是 pad。模型接着 pad 往下预测，结果当然不对；新生成的词也会接在 pad 后面，中间留着两个洞。

改成左填充，每一行的最后一个位置都是它真实的最后一个词：

```
[3, 7, 2, 9]
[0, 0, 5, 1]
```

但只把 pad 挪到左边还不够，下一张卡讲另外两件事。

下面的代码用一个很小的 decoder-only 模型 `tiny_lm()`（token 0 是 pad）。`generate_one(model, prompt, n)` 一条一条地贪心生成 n 个词，不补任何 pad，是「正确答案」。
--- code
model = tiny_lm()
prompts = [[3, 7, 2, 9], [5, 1]]
alone = [generate_one(model, p, 1)[0] for p in prompts]    # 一条一条算，没有 pad

right = torch.tensor([[3, 7, 2, 9], [5, 1, 0, 0]])         # 右填充
with torch.inference_mode():
    batch = model(right)[:, -1].argmax(dim=-1).tolist()
print("一条一条:  ", alone)
print("右填充批量:", batch)

@@ concept
title: 批量生成（二）：左填充 + attention mask + position ids
ref: day18
--- body
左填充之后，还要告诉模型两件事：

1. **attention mask**：哪些位置是真的（1），哪些是 pad（0）。模型在 attention 里把 pad 这几列屏蔽掉，真实的词就看不到 pad。没有它，第二行的 5 和 1 会去 attend 左边的两个 pad，结果被污染。
2. **position ids**：每个词在「自己那条序列」里的位置。左填充后，第二行的 5 站在第 2 格，但它其实是这条序列的第 0 个词。模型靠位置编码区分先后，位置错了，结果就错。

以 `[[5, 6, 7], [8]]`、pad = 0 为例：

```
input_ids      = [[5, 6, 7], [0, 0, 8]]
attention_mask = [[1, 1, 1], [0, 0, 1]]
position_ids   = [[0, 1, 2], [0, 0, 0]]
```

mask 要按「这个位置是不是补出来的」来填，不能写 `ids != pad_id`：很多模型（比如 GPT-2）拿 eos 当 pad，真实的 eos 也会被当成 pad 屏蔽掉。

position ids 用 mask 算：`mask.cumsum(-1) - 1` 在真实位置上正好是 0, 1, 2, …；pad 位置会得到 -1，用 `.clamp(min=0)` 改成 0。pad 位置反正会被 mask 掉，填几都行，但不能是负数，否则 embedding 查表会报错。

生成的每一步，新词接到 `input_ids` 末尾，同时：

- `attention_mask` 末尾接一列 1（新词是真的）
- `position_ids` 末尾接「每行最后一个位置 + 1」

在 Hugging Face 里，对应的是 `tokenizer.padding_side = "left"`，再把 `attention_mask` 传给 `generate`；很多模型的 `generate` 会用同样的 cumsum 办法替你算 position ids。

下面的 `left_pad(seqs, pad_id)` 返回这三样东西（练习区里你要自己写它）。
--- code
mask = torch.tensor([[1, 1, 1], [0, 0, 1]])
print(mask.cumsum(-1) - 1)
print((mask.cumsum(-1) - 1).clamp(min=0))

model = tiny_lm()
prompts = [[3, 7, 2, 9], [5, 1]]
ids, mask, pos = left_pad(prompts, pad_id=0)
print(ids)
with torch.inference_mode():
    logits = model(ids, attention_mask=mask, position_ids=pos)
print("一条一条:  ", [generate_one(model, p, 1)[0] for p in prompts])
print("左填充批量:", logits[:, -1].argmax(dim=-1).tolist())

@@ concept
title: 可复现：种子和确定性开关
--- body
同一份代码跑两次，结果应该一样。这样出了问题才能复现、才能比较两次实验。随机数有三个来源，各有各的种子：

- Python 的 `random`：`random.seed(seed)`
- NumPy：`np.random.seed(seed)`
- PyTorch：`torch.manual_seed(seed)`（CPU 和所有 GPU 一起播种；老代码里常见的 `torch.cuda.manual_seed_all(seed)` 多写一行也没坏处）

`torch.manual_seed` 管不到另外两个。数据增强用 `random`、划分数据集用 NumPy 的代码很常见，只播 torch 的种子，每次运行还是不一样。

种子一样，GPU 上的结果也不一定一样。还有三个开关：

- `torch.backends.cudnn.benchmark = False`：设成 True 时，cuDNN 会先试跑几种卷积算法、挑最快的。不同次运行可能挑到不同的算法，结果差在最后几位。
- `torch.backends.cudnn.deterministic = True`：卷积只用确定性的算法。
- `torch.use_deterministic_algorithms(True)`：所有算子都必须用确定性实现；某个算子没有确定性版本，就直接报错，而不是悄悄给出不同的结果。在 GPU 上，还要在程序一开始（任何 GPU 计算之前）设置环境变量 `CUBLAS_WORKSPACE_CONFIG=:4096:8`，否则矩阵乘会报错。

这些开关会让程序变慢，一般只在调试、写测试、需要严格复现时打开。

还要记住：换了 GPU 型号、驱动、PyTorch 版本，或者 batch 大小变了，最后几位还是可能不同。所以比较两份结果时，永远带容差。
--- code
import random
import numpy as np

torch.manual_seed(0)
a = (random.random(), np.random.rand(), torch.rand(1).item())
torch.manual_seed(0)
b = (random.random(), np.random.rand(), torch.rand(1).item())
print("random, numpy, torch 两次一样吗:", [x == y for x, y in zip(a, b)])
print("cudnn.benchmark =", torch.backends.cudnn.benchmark)
print("确定性算法开着吗:", torch.are_deterministic_algorithms_enabled())

title: 精度和容差：fp32 / TF32 / bf16 / fp16
--- body
四种常见的浮点格式。尾数位决定精度（能分辨多小的差别），指数位决定范围（能表示多大的数）。eps 是「1 和比 1 大的下一个数」之差：

- **fp32**：23 位尾数，eps ≈ 1.2e-7，最大约 3.4e38。PyTorch 的默认格式。
- **TF32**：不是一种存储格式，而是 NVIDIA 显卡（Ampere 以后，比如 A100、RTX 30/40/50 系列）做 fp32 矩阵乘、卷积时的一种算法：输入只保留 10 位尾数再相乘，结果仍存成 fp32。快很多，但相对误差到 1e-3 左右。卷积默认允许用它（`torch.backends.cudnn.allow_tf32` 是 True）；矩阵乘默认不用，但很多训练脚本会写 `torch.set_float32_matmul_precision("high")` 把它打开。
- **bf16**：7 位尾数，eps ≈ 7.8e-3，精度粗；指数位和 fp32 一样多，所以不容易溢出。训练和推理都常用。
- **fp16**：10 位尾数，eps ≈ 9.8e-4，比 bf16 精细；但最大只有 65504，超过就变成 inf。

比较两份输出（比如 bf16 的服务输出 vs fp32 的参考输出）时：

1. 两边都转成 fp32 再相减：`(got.float() - ref.float()).abs()`
2. 同时用绝对容差 atol 和相对容差 rtol：`|got - ref| <= atol + rtol * |ref|`。只用相对误差不行：ref 接近 0 的地方，相对误差会大得离谱（下面的例子里，bf16 的最大相对误差超过 10）。只用绝对误差也不行：数值大的地方，舍入误差本来就大。
3. 按精度低的那一边选容差。给模型输出用的一组经验值：fp32 约 1e-5，fp16 约 1e-2，bf16 约 5e-2。单个运算可以更严，`torch.testing.assert_close` 按 dtype 自带默认容差。真正的 bug 通常差 0.1 以上，远远超过这些容差。
4. 容差不是越松越好：拿 bf16 的容差去比 fp32 的输出，会把 bug 放过去。
--- code
for dt in (torch.float32, torch.float16, torch.bfloat16):
    fi = torch.finfo(dt)
    print(f"{str(dt):15s} eps={fi.eps:.1e}  max={fi.max:.1e}")

torch.manual_seed(0)
a, b = torch.randn(64, 64), torch.randn(64, 64)
ref = a @ b                                    # fp32 参考
for dt in (torch.float16, torch.bfloat16):
    got = (a.to(dt) @ b.to(dt)).float()        # 低精度算，转回 fp32 再比
    diff = (got - ref).abs()
    print(dt, f"最大绝对误差 {diff.max():.3f}", f"最大相对误差 {(diff / ref.abs()).max():.1f}")

--- context
线上效果比离线评测差一截，最常见的原因之一是服务里的预处理和训练时不一样。把预处理写成一个类，统计量随模型一起保存，训练和服务用同一份代码，这类 bug 就不会出现。
--- prompt
写一个 `Preprocessor` 类，做标准化 `(x - mean) / std`。x 的 shape 是 `(N, D)`：N 条数据，每条 D 个特征。

- `fit(x)`：在训练数据上算每个特征的 `mean = x.mean(dim=0)` 和 `std = x.std(dim=0)`，std 再 `.clamp_min(1e-6)`（某一列是常数时 std 为 0，防止除以 0）。存进 `self.mean`、`self.std`，最后 `return self`。
- `transform(x)`：返回 `(x - self.mean) / self.std`。**只用存下的统计量**，不能拿 x 自己现算。既没 fit 也没加载过就调用，要 `raise RuntimeError(...)`。
- `state_dict()`：返回 `{"mean": ..., "std": ...}`（两个 tensor），用来和模型权重存进同一个文件。
- `load_state_dict(d)`：从这样一个 dict 恢复 `self.mean` 和 `self.std`。

--- solution
class Preprocessor:
    def __init__(self):
        self.mean = None
        self.std = None

    def fit(self, x):
        self.mean = x.mean(dim=0)
        self.std = x.std(dim=0).clamp_min(1e-6)     # 常数列：std = 0，别除以 0
        return self

    def transform(self, x):
        if self.mean is None:
            raise RuntimeError("先 fit() 或 load_state_dict()")
        return (x - self.mean) / self.std           # 永远用存下的统计量

    def state_dict(self):
        return {"mean": self.mean.clone(), "std": self.std.clone()}

    def load_state_dict(self, d):
        self.mean = d["mean"].clone()
        self.std = d["std"].clone()
        return self

import hashlib
import json


def vocab_fingerprint(vocab):
    text = json.dumps(vocab, sort_keys=True)       # 按 key 排序：和插入顺序无关
    return hashlib.sha256(text.encode("utf-8")).hexdigest()[:16]


def check_vocab(saved_fp, vocab):
    fp = vocab_fingerprint(vocab)
    if fp != saved_fp:
        raise ValueError(f"词表对不上：checkpoint 用的是 {saved_fp}，现在加载的是 {fp}")

def batch_gap(model, x):
    with torch.inference_mode():
        together = model(x)
        alone = torch.cat([model(x[i:i + 1]) for i in range(x.shape[0])], dim=0)

--- solution
def left_pad(seqs, pad_id=0):
    T = max(len(s) for s in seqs)
    ids = torch.full((len(seqs), T), pad_id, dtype=torch.long)
    mask = torch.zeros((len(seqs), T), dtype=torch.long)
    for i, s in enumerate(seqs):
        ids[i, T - len(s):] = torch.tensor(s, dtype=torch.long)   # 真实 token 靠右放
        mask[i, T - len(s):] = 1
    pos = (mask.cumsum(dim=-1) - 1).clamp(min=0)                 # 真实位置 0, 1, 2, …；pad 是 0
    return ids, mask, pos

def generate_batch(model, prompts, n_new, pad_id=0):
    ids, mask, pos = left_pad(prompts, pad_id)
    new = []
    with torch.inference_mode():
        for _ in range(n_new):
            logits = model(ids, attention_mask=mask, position_ids=pos)   # (B, T, V)
            nxt = [[logits[:, -1].argmax(dim=-1)]]
            new.append(nxt)
            ids = torch.cat([ids, [[nxt.unsqueeze(1)]]], dim=1)
            mask = torch.cat([mask, [[torch.ones_like(mask[:, :1])]]], dim=1)
            pos = torch.cat([pos, [[pos[:, -1:] + 1]]], dim=1)
    return torch.stack(new, dim=1).tolist()                               # B 个列表，每个 n_new 个词

def set_seed(seed, deterministic=False):

TOL = {                          # (rtol, atol)，给模型输出用的经验值
    torch.float32: (1e-5, 1e-5),
    torch.float16: (1e-2, 1e-2),
    torch.bfloat16: (5e-2, 5e-2),
}


def outputs_match(ref, got):
    if ref.shape != got.shape:
        return False
    rtol, atol = TOL[got.dtype]                   # 按精度低的那一边选容差
    ref32, got32 = ref.float(), got.float()       # 在 fp32 里比
    ok = (got32 - ref32).abs() <= atol + rtol * ref32.abs()
    return bool(ok.all())                         # nan 和任何数比较都是 False

class Preprocessor:
    def __init__(self):
        self.mean = None
        self.std = None

    def fit(self, x):
        self.mean = x.mean(dim=0)
        self.std = x.std(dim=0).clamp_min(1e-6)
        return self

    def transform(self, x):
        if self.mean is None:
            raise RuntimeError("先 fit() 或 load_state_dict()")
        return (x - self.mean) / self.std

    def state_dict(self):
        return {"mean": self.mean.clone(), "std": self.std.clone()}

    def load_state_dict(self, d):
        self.mean = d["mean"].clone()
        self.std = d["std"].clone()
        return self

--- prompt
不看卡片，写出 `left_pad(seqs, pad_id=0)`，返回三个 shape 为 `(B, T)` 的张量（T 是最长那条的长度）：

- `input_ids`：pad 补在左边，dtype 为 `torch.long`
- `attention_mask`：真实 token 为 1，pad 为 0（按位置判断）
- `position_ids`：每个真实 token 在自己那条序列里的位置，pad 位置填 0，dtype 为 `torch.long`

`left_pad([[5, 6, 7], [8]])` → ids `[[5, 6, 7], [0, 0, 8]]`，mask `[[1, 1, 1], [0, 0, 1]]`，pos `[[0, 1, 2], [0, 0, 0]]`。

--- solution
def left_pad(seqs, pad_id=0):
    T = max(len(s) for s in seqs)
    ids = torch.full((len(seqs), T), pad_id, dtype=torch.long)
    mask = torch.zeros((len(seqs), T), dtype=torch.long)
    for i, s in enumerate(seqs):
        ids[i, T - len(s):] = torch.tensor(s, dtype=torch.long)
        mask[i, T - len(s):] = 1
    pos = (mask.cumsum(dim=-1) - 1).clamp(min=0)
    return ids, mask, pos
