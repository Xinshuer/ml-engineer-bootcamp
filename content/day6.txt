@@ concept
title: LoRA：原权重不动，旁边加一条小路
--- body
微调（fine-tuning）就是拿别人训练好的模型，用自己的数据再训练一会儿。全量微调要更新每一个参数。一个 7B 模型有 70 亿个参数，全量微调它要的显存远远超过普通显卡（最后一张卡「显存账」会算给你看）。

LoRA（Low-Rank Adaptation，低秩适配）的想法：原来的权重 `W`（形状 `(out, in)`）一个数都不改，只在旁边加一条小路：

```
y = base(x) + (x @ A.T @ B.T) * scaling
```

- `A` 的形状是 `(r, in)`，`B` 的形状是 `(out, r)`。
- `r` 叫 rank（秩），很小，常见 4、8、16。
- x 先乘 `A.T`，被压成 r 维；再乘 `B.T`，变回 out 维。所以旁路输出和 `base(x)` 形状一样，可以直接相加。
- `B @ A` 的形状是 `(out, in)`，和 `W` 一样大，但它只由 `r*in + out*r` 个数决定。

下面算一个 4096×4096 的层：原权重有 16,777,216 个参数；r = 8 时，A 和 B 加起来只有 65,536 个，占 0.39%。
--- code
in_f, out_f, r = 4096, 4096, 8
full = in_f * out_f
lora = r * in_f + out_f * r
print("原权重参数量:", full)
print("A + B 参数量:", lora)
print(f"占比: {lora / full:.2%}")

# 用小尺寸看看形状
x = torch.randn(2, 16)     # 2 个样本，in = 16
A = torch.randn(4, 16)     # (r, in)
B = torch.randn(8, 4)      # (out, r)
print("x @ A.T:", tuple((x @ A.T).shape))
print("x @ A.T @ B.T:", tuple((x @ A.T @ B.T).shape))

@@ concept
title: LoRA 的三个细节：冻结、B 置 0、alpha / r
--- body
自己写或者读别人的 LoRA 代码，先查这三点。哪一点错了都不会报错，只会让微调效果变差。

1. **冻结 base**：`for p in base.parameters(): p.requires_grad_(False)`。`requires_grad=False` 的参数，backward 之后 `.grad` 还是 `None`，优化器也不会改它。只有 A、B 在训练。检查方法：数一数可训练参数，应该正好等于 A 和 B 的大小。
2. **B 初始化为全 0，A 用小随机数**（比如 `normal_(0, 0.01)`）：刚开始 `B @ A` 全是 0，旁路输出 0，模型和原模型一模一样。微调从原模型出发，而不是从「被随机噪声打乱的原模型」出发。
3. **scaling = alpha / r**：alpha 是一个超参数（常取 r 的 1～2 倍）。除以 r 的好处：换一个 r，旁路输出的大小变化不大，学习率不用重调。alpha = 8、r = 4 时，scaling = 2.0。

新加的矩阵要包成 `nn.Parameter`。这样模块才会把它算进 `parameters()`，优化器才会更新它。

下面的代码还能看到梯度怎么流：第一步 B 有梯度（B 的梯度要乘上 `x @ A.T`，而 A 不是 0）；A 的梯度是 0（A 的梯度要乘上 B，而 B 是 0）。B 更新一步、不再是 0 之后，A 也就有梯度了。
--- code
torch.manual_seed(0)
base = nn.Linear(16, 8)
for p in base.parameters():
    p.requires_grad_(False)                      # 1) 冻结 base
A = nn.Parameter(torch.randn(4, 16) * 0.01)      # 2) A：小随机数
B = nn.Parameter(torch.zeros(8, 4))              #    B：全 0
scaling = 8 / 4                                  # 3) alpha / r

x = torch.randn(3, 16)
y = base(x) + (x @ A.T @ B.T) * scaling
print("和原模型输出一样吗:", torch.allclose(y, base(x)))

y.sum().backward()
print("base.weight.grad:", base.weight.grad)
print("B 有梯度吗:", bool(B.grad.abs().sum() > 0))
print("A 有梯度吗:", bool(A.grad.abs().sum() > 0))

@@ concept
title: 合并 LoRA：上线时没有额外开销
--- body
训练完以后，A 和 B 就不再变了。上线时如果还留着旁路，每一层都要多做两次矩阵乘法。其实可以把旁路「合并」进原权重。

矩阵乘法可以换括号，而且 `A.T @ B.T == (B @ A).T`，所以：

```
x @ A.T @ B.T * s  ==  x @ (s * B @ A).T
```

于是：

```
W_merged = W + s * (B @ A)     # 形状 (out, in)，和 W 一样
bias 不变
```

合并后就是一个普通的 `nn.Linear`：参数量和速度都和原模型一样。注意顺序是 `B @ A`，写成 `A @ B` 形状就对不上。

往 `nn.Linear` 的参数里写值，要放在 `with torch.no_grad():` 里，用 `.copy_()`。不这样做会报错：需要梯度的参数不能被原地修改。
--- code
torch.manual_seed(0)
W = torch.randn(8, 16)
A, B, s = torch.randn(4, 16), torch.randn(8, 4), 2.0
x = torch.randn(3, 16)

two_paths = x @ W.T + (x @ A.T @ B.T) * s        # 原权重 + 旁路
W_merged = W + s * (B @ A)
print("B @ A 的形状:", tuple((B @ A).shape))

lin = nn.Linear(16, 8, bias=False)
with torch.no_grad():
    lin.weight.copy_(W_merged)
print("合并后输出一样吗:", torch.allclose(lin(x), two_paths, atol=1e-4))
print("合并后参数量:", sum(p.numel() for p in lin.parameters()))

@@ concept
title: SFT 的 labels：-100 的位置不算 loss
--- body
SFT（Supervised Fine-Tuning，监督微调）用「问题 + 标准回答」来训练模型。一条样本 = prompt 的 token 后面接上 answer 的 token，拼成一条 `input_ids`。

我们只想让模型学「写回答」，不想让它学「复述问题」。做法：造一个和 `input_ids` 一样长的 `labels`，prompt 部分填 -100，answer 部分照抄 `input_ids`。

- `F.cross_entropy` 有个参数 `ignore_index`，默认就是 -100。label 是 -100 的位置不算 loss，**也不算进平均的分母**。
- labels 必须是 `torch.long`（整数）。
- 「用第 t 个 token 预测第 t+1 个」需要错开一位。Hugging Face 的语言模型在算 loss 时会自己在内部错位，所以 labels 和 input_ids 对齐着写就行。
- 写错了（忘了掩码，或者把 answer 也掩掉了），程序照样跑，loss 照样降，但模型学歪了。只能靠打印 labels 来检查。

下面的 logits 是模型对每个词打的原始分数（还没过 softmax）。两个 loss 应该一样。
--- code
torch.manual_seed(0)
input_ids = torch.tensor([11, 12, 13, 21, 22])   # 前 3 个是 prompt，后 2 个是 answer
labels = input_ids.clone()
labels[:3] = -100
print("labels:", labels.tolist())

logits = torch.randn(5, 30)                       # 5 个位置，每个位置 30 个词的分数
masked = F.cross_entropy(logits, labels)          # -100 的位置被跳过
answer_only = F.cross_entropy(logits[3:], input_ids[3:])
print("带 -100 的 loss:", round(masked.item(), 4))
print("只算 answer 的 loss:", round(answer_only.item(), 4))

@@ concept
title: chat template：把对话拼成模型认识的格式
--- body
聊天模型训练时看到的不是 Python 列表，而是一段带特殊标记的文字。把 `messages` 列表拼成这段文字的规则，叫 chat template（对话模板）。每个模型家族的模板都不一样。微调和推理都必须用模型训练时的那一套，差一个换行，模型就可能答非所问。

Qwen 等很多模型用 ChatML 格式。每条消息拼成：

```
<|im_start|>{role}\n{content}<|im_end|>\n
```

- `<|im_start|>` 和 `<|im_end|>` 是特殊 token，标出一条消息从哪开始、到哪结束。
- role 是 `system`（系统设定）、`user`（用户）或 `assistant`（模型）。
- 推理时，最后再接一句 `<|im_start|>assistant\n`（参数 `add_generation_prompt=True`），意思是「轮到你说了」。模型接着往下写，写出 `<|im_end|>` 就停。
- SFT 训练时不加这一句，因为 assistant 的回答已经在数据里了。上一张卡的 `prompt_len`，就是 assistant 回答正文之前那一段（包括 `<|im_start|>assistant\n`）的 token 数。

用 `repr()` 打印字符串，能看清里面的换行符 `\n`。
--- code
m = {"role": "user", "content": "1+1=?"}
one = f"<|im_start|>{m['role']}\n{m['content']}<|im_end|>\n"
print(one)
print(repr(one))
print(repr("<|im_start|>assistant\n"))

@@ concept
title: 梯度累积：几个小 batch 凑成一个大 batch
--- body
显存只够一次喂 8 个样本，但你想要 batch = 32 的效果？可以每次喂 8 个，连做 4 次 forward + backward，然后才更新一次参数。这叫梯度累积（gradient accumulation）。

它能成立，是因为 `.backward()` 会把梯度**加到** `.grad` 上，而不是覆盖。所以普通训练每一步都要先 `zero_grad()`；梯度累积则是故意攒几次再清。

有一个坑：`F.cross_entropy` 默认对 batch 取**平均**。4 份各自的平均直接加起来，是大 batch 平均的 4 倍。所以每份的 loss 要先除以份数 `n_micro`：

```
model.zero_grad()
for 每一份 (xb, yb):
    loss = F.cross_entropy(model(xb), yb) / n_micro
    loss.backward()          # 梯度加到 .grad 上
optimizer.step()             # 攒够了才更新一次
```

忘了除，不会报错，只是梯度大了 n_micro 倍。用 SGD 时，这等于把学习率偷偷调大了 n_micro 倍；梯度裁剪和打印出来的 loss 也都会不对。
--- code
torch.manual_seed(0)
model = nn.Linear(3, 2)
xs, ys = torch.randn(8, 3), torch.randint(0, 2, (8,))

model.zero_grad()
F.cross_entropy(model(xs), ys).backward()           # 一次喂 8 个
big = model.weight.grad.clone()

model.zero_grad()
F.cross_entropy(model(xs[:4]), ys[:4]).backward()   # 前 4 个
F.cross_entropy(model(xs[4:]), ys[4:]).backward()   # 后 4 个：梯度加上去
print("直接相加 == 大 batch ?", torch.allclose(model.weight.grad, big))
print("相加后 / 2 == 大 batch ?", torch.allclose(model.weight.grad / 2, big))

@@ concept
title: warmup + cosine：学习率先升后降
--- body
学习率（lr）不是从头到尾不变的。训练大模型最常见的安排分三段：

1. **warmup（预热）**：前 `warmup_iters` 步，lr 从很小线性升到 `max_lr`。刚开始模型和 Adam 的统计量都还不稳定，一上来就用大 lr 容易炸。
2. **cosine decay（余弦衰减）**：然后沿着余弦曲线，从 `max_lr` 慢慢降到 `min_lr`。
3. 过了 `max_iters`，一直保持 `min_lr`。

公式（`it` 是第几步，从 0 开始）：

```
warmup:  lr = max_lr * (it + 1) / warmup_iters
cosine:  progress = (it - warmup_iters) / (max_iters - warmup_iters)   # 0 → 1
         coeff = 0.5 * (1 + cos(pi * progress))                        # 1 → 0
         lr = min_lr + coeff * (max_lr - min_lr)
```

为什么是 `it + 1`：这样第 0 步的 lr 不是 0（lr 为 0 的那一步等于白跑），而 warmup 的最后一步 `it = warmup_iters - 1` 正好到 `max_lr`。progress = 0.5（余弦段的正中间）时 coeff = 0.5，lr 正好是 max_lr 和 min_lr 的平均。
--- code
for progress in [0, 0.25, 0.5, 0.75, 1.0]:
    coeff = 0.5 * (1 + math.cos(math.pi * progress))
    print("progress", progress, "-> coeff", round(coeff, 3))

@@ concept
title: 显存账：参数、梯度、优化器状态
--- body
训练时，显存里主要放 4 样东西：

1. 参数（weights）
2. 梯度：每个参数一个
3. 优化器状态：AdamW 给每个参数存 2 个数（`exp_avg` 一阶动量、`exp_avg_sq` 二阶动量）；带动量的 SGD 存 1 个；普通 SGD 不存
4. 激活值：forward 的中间结果，backward 要用。它和 batch 大小、序列长度有关，今天先不算

前三样只和参数量有关，可以直接算。fp32 每个数占 4 字节。AdamW 是「参数 + 梯度 + 2 份状态」= 4 份，所以每个参数 16 字节（这里 1 GB 按 10^9 字节算）：

- 10 亿（1B）参数 → 16 GB
- 70 亿（7B）参数 → 112 GB，一张 80 GB 的卡都放不下，还没算激活值

LoRA 省在哪：base 被冻结，没有梯度，也没有优化器状态，只剩参数本身。梯度和优化器状态只为 A、B 存，而 A、B 不到原参数量的 1%。

下面的代码里，`step` 只是一个计数，不占什么地方；`exp_avg` 和 `exp_avg_sq` 都和权重一样大。
--- code
model = nn.Linear(100, 10)                       # 100*10 + 10 = 1010 个参数
opt = torch.optim.AdamW(model.parameters(), lr=1e-3)
model(torch.randn(4, 100)).sum().backward()
opt.step()                                       # 第一次 step 时才建好状态

state = opt.state[model.weight]
print({k: tuple(v.shape) for k, v in state.items()})
n = sum(p.numel() for p in model.parameters())
print("参数量:", n)
print("参数 + 梯度 + 2 份状态:", n * 4 * 4, "字节")
print("7B 模型:", 7_000_000_000 * 4 * 4 / 1e9, "GB")

--- solution
class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=4, alpha=8):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad_(False)
        self.A = nn.Parameter(torch.empty(r, base.in_features).normal_(0, 0.01))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))   # 必须是 0
        self.scaling = alpha / r

    def forward(self, x):
        return self.base(x) + (x @ self.A.T @ self.B.T) * self.scaling

--- solution
def merge_lora(m):
    out_f, in_f = m.base.out_features, m.base.in_features
    lin = nn.Linear(in_f, out_f, bias=m.base.bias is not None)
    with torch.no_grad():
        lin.weight.copy_(m.base.weight + m.scaling * (m.B @ m.A))
        if m.base.bias is not None:
            lin.bias.copy_(m.base.bias)
    return lin

- 先清空旧梯度。然后把这个大 batch 按顺序平均切成 `n_micro` 份（每份叫一个 micro-batch），每份做一次 forward、算 `F.cross_entropy`、backward。
- 累积出的梯度必须和「一次把 N 个都喂进去」算出的梯度一样（误差在 1e-5 以内）。
- 返回字典 `{参数名: 梯度的 clone}`，用 `model.named_parameters()` 遍历。

--- starter
def grad_accum_step(model, xs, ys, n_micro):
    """把大 batch 切成 n_micro 份，依次 forward/backward，累积出和大 batch 一样的梯度。
    返回 {参数名: grad.clone()}。"""
    raise todo()
--- solution
def grad_accum_step(model, xs, ys, n_micro):
    model.zero_grad(set_to_none=True)
    n = xs.size(0) // n_micro
    for i in range(n_micro):
        xb, yb = xs[i * n:(i + 1) * n], ys[i * n:(i + 1) * n]
        # 每份内部已经对自己的 batch 求了平均，再除以份数才等于整体平均
        (F.cross_entropy(model(xb), yb) / n_micro).backward()
    return {k: p.grad.clone() for k, p in model.named_parameters()}

def get_lr(it, warmup_iters, max_iters, max_lr, min_lr):
    if it < warmup_iters:
        return max_lr * (it + 1) / warmup_iters
    if it > max_iters:

    coeff = 0.5 * (1.0 + math.cos(math.pi * progress))

- it = 15：progress = 1，cos(π) = −1，coeff = 0，lr = min_lr = 0.0
- it = 20：超过 max_iters，一直是 min_lr = 0.0

- 第 10 步：progress = (10 - 5) / (15 - 5) = 0.5，而 cos(0.5π) = 0。

读别人的 LoRA 代码时，初始化是最值得看一眼的地方。初始化错了不报错，loss 就是不降，很难从日志里看出原因。
--- prompt
同事为了「保证一开始输出不变」，把 LoRA 的 A 和 B **都**初始化成了全 0（base 已冻结）。训练起来会怎样？
--- options
- 没问题，和只把 B 置 0 的效果一样
- 一开始输出就和原模型不同
- A 和 B 的梯度一直是 0，LoRA 什么也学不到，loss 停在原模型的水平
- PyTorch 报错：参数不能全是 0
answer: 3
--- explain
旁路是 `x @ A.T @ B.T`。

- B 的梯度要乘上 `x @ A.T`。A = 0 时，它是 0。
- A 的梯度要乘上 B。B = 0 时，它也是 0。

两个梯度都是 0，优化器什么也不改（AdamW 的 weight decay 作用在 0 上还是 0），下一步还是一样，永远卡住。只把 B 置 0 时，A 是随机的，所以 B 第一步就有梯度；B 一旦不是 0，A 也就有梯度了。这种 bug 不报错，只表现为 loss 不降。
--- hints
- 回看卡片里的例子：B = 0 时，A 的梯度是多少？
- 反过来：A = 0 时，B 的梯度要乘上 `x @ A.T`，那是多少？

--- solution
class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, r=4, alpha=8):
        super().__init__()
        self.base = base
        for p in self.base.parameters():
            p.requires_grad_(False)
        self.A = nn.Parameter(torch.empty(r, base.in_features).normal_(0, 0.01))
        self.B = nn.Parameter(torch.zeros(base.out_features, r))   # 必须是 0
        self.scaling = alpha / r

    def forward(self, x):
        return self.base(x) + (x @ self.A.T @ self.B.T) * self.scaling

- 累积出的梯度要和一次喂整个大 batch 的梯度一样

--- starter

--- solution
def grad_accum_step(model, xs, ys, n_micro):
    model.zero_grad(set_to_none=True)
    n = xs.size(0) // n_micro
    for i in range(n_micro):
        xb, yb = xs[i * n:(i + 1) * n], ys[i * n:(i + 1) * n]
        # 每份内部已经对自己的 batch 求了平均，再除以份数才等于整体平均
        (F.cross_entropy(model(xb), yb) / n_micro).backward()
    return {k: p.grad.clone() for k, p in model.named_parameters()}
--- tests
