@@ concept
title: 五问法：读论文只找五件事
--- body
论文动辄二三十页，但写代码只需要五个答案。第一遍别从头读到尾，带着这五个问题去找：

1. **输入和输出的 shape 是什么？** 用具体的数写出来，比如 (8, 3, 64, 64)，别只写「一张图」。
2. **中间表示（潜变量）的 shape 是什么？** 潜变量就是模型内部压缩出来的那份表示。它是连续的向量，还是离散的整数编号？
3. **loss 有几项？每一项在推动谁？** 数清公式里加了几项，想清楚每一项的梯度会更新哪部分参数。
4. **条件怎么注入？** 条件是额外的控制信息，比如类别、文字、时间步。常见的有 5 种：`add`（加到特征上）、`cross-attn`（交叉注意力）、`adaln`（用条件算出 LayerNorm 的缩放和平移）、`concat`（拼到输入上）、`none`（没有条件）。
5. **怎么采样（生成）？** 常见的有 3 种：`single`（一次前向就出结果）、`autoregressive`（自回归：一个一个生成，每次都看前面已经生成的）、`iterative-denoise`（从噪声出发，一步步去噪）。

去哪找：方法那一节的结构图、loss 公式、算法框（Algorithm 1）、附录里的超参数表。相关工作、消融实验这些，等代码跑通再看。

五个答案写下来，就是你的第一份测试：shape 变成 smoke test 里的 `expect_shape`，loss 的每一项变成一个函数，采样方式决定推理循环怎么写。

下面用第 8 天的 DDPM 举例：在 32×32 的彩色图上训练，batch 16。
--- code
ddpm = {
    "输入 shape": (16, 3, 32, 32),    # 加了噪声的图 x_t（另外还有时间步 t）
    "输出 shape": (16, 3, 32, 32),    # 预测的噪声，和输入一样大
    "潜变量 shape": (16, 3, 32, 32),  # 没有压缩：x_1 ... x_T 和原图一样大
    "loss 有几项": 1,                 # 只有 MSE(预测的噪声, 真实的噪声)
    "条件注入方式": "add",            # 时间步的嵌入加到每个 ResBlock 的特征上
    "采样方式": "iterative-denoise",  # 从纯噪声出发，一步步去噪
}
for k, v in ddpm.items():
    print(f"{k}: {v}")

# 五问的答案马上就能变成代码
x = torch.randn(ddpm["输入 shape"])
print("照答案造的输入:", tuple(x.shape))

@@ concept
title: smoke test：写完 forward 先跑一次
--- body
smoke test（冒烟测试）这个名字来自硬件：新电路板第一次通电，先看会不会冒烟。模型也一样：forward 写完，先喂一次随机数据，别急着训练。

它只检查三件事：

1. 能跑完，不报错。
2. 输出的 shape 和你五问法里写的一样。
3. 输出里没有 `nan`（不是一个数）和 `inf`（无穷大）。

第 3 条用 `torch.isfinite(t)`：每个元素是正常的数就是 True，是 nan 或 inf 就是 False。后面接 `.all()`，全部为 True 才返回 True。

nan 会传染：一个 nan 参与计算，结果就是 nan。所以 forward 里任何一处出了 nan，输出里都看得到。

写成工具函数时，用 `*input_shapes` 收「任意多个输入的 shape」：调用 `f((2, 4), (2, 3))` 时，函数里的 `input_shapes` 是 `((2, 4), (2, 3))`。反过来，`model(*xs)` 把列表 `xs` 拆开，一个元素当一个参数传进去。

检查不通过就 `raise AssertionError("说清是哪一条没过")`。
--- code
t = torch.tensor([1.0, float("nan"), float("inf"), -2.0])
print(torch.isfinite(t))
print("全部正常吗:", torch.isfinite(t).all().item())

def make_inputs(*input_shapes):
    print("收到的 shapes:", input_shapes)
    return [torch.randn(s) for s in input_shapes]

xs = make_inputs((2, 4))
out = nn.Linear(4, 3)(*xs)
print("输出 shape:", tuple(out.shape))
print("nan 会传染:", (out * float("nan")).sum().item())

@@ concept
title: 过拟合一个 batch：最快的查 bug 手段
--- body
模型写好了，能不能学？最快的检验：只拿一个小 batch，在它上面反复训练几百步。

一个 batch 只有十几个样本，任何写对了的模型都能把它「背下来」，loss 应该掉到接近 0。

- 掉到接近 0：forward、loss、反向传播、优化器这条链是通的，可以开始正式训练了。
- 掉不下去：代码里有 bug。这时候调学习率、加数据、换大模型都是浪费时间，先回去查代码。

每一步的顺序：算 loss → `opt.zero_grad(set_to_none=True)`（清掉上一步的梯度）→ `loss.backward()`（算这一步的梯度）→ `opt.step()`（更新参数）。优化器在循环外面只建一次。

记录 loss 时存 `loss.item()`（一个 Python float），别存 `loss` 本身：tensor 会连着整张计算图一起留在内存里。

分类任务一开始的 loss 大约是 ln(类别数)：模型还在瞎猜，每一类的概率差不多。5 类就是 ln 5 ≈ 1.609。起点差得很远，也说明哪里写错了。

loss 就是降不下去时，怎么一步步查？那是第 15 天的内容。今天先把这个检查做成随手能用的工具。
--- code
torch.manual_seed(0)
model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 5))
x, y = torch.randn(16, 8), torch.randint(0, 5, (16,))
opt = torch.optim.AdamW(model.parameters(), lr=1e-2)
print("ln 5 =", round(math.log(5), 3))
for step in range(201):
    loss = F.cross_entropy(model(x), y)
    opt.zero_grad(set_to_none=True)
    loss.backward()
    opt.step()
    if step % 50 == 0:
        print("step", step, "loss", round(loss.item(), 4))

@@ concept
title: 梯度裁剪：先记下范数，再裁剪
--- body
训练里偶尔会有一步的梯度特别大（碰上一个怪样本，或者学习率太高）。这一步的更新会把参数推得太远，loss 突然飙升，甚至变成 nan。

梯度裁剪（gradient clipping）的做法：

1. 把所有参数的所有梯度元素放在一起，算总范数：total_norm = sqrt(每个梯度元素的平方加起来)。
2. 如果 total_norm > max_norm，所有梯度一起乘上 max_norm / total_norm。方向不变，只把长度缩到 max_norm。
3. 如果没超过，什么都不做。

PyTorch 一行搞定：`torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)`。

- 名字最后的 `_` 表示「原地修改」：它直接改每个参数的 `.grad`。
- 它的返回值是**裁剪前**的总范数（一个 0 维 tensor）。把它记进日志：这个数突然变大，往往是 loss 变 nan 的前兆。
- 放在 `loss.backward()` 之后、`opt.step()` 之前。

例子：两个参数的梯度是 [6, 8] 和 [0]。总范数 = sqrt(36 + 64 + 0) = 10。max_norm = 2，所以都乘 2 / 10 = 0.2，变成 [1.2, 1.6] 和 [0]。
--- code
m = nn.Linear(2, 1)
m.weight.grad = torch.tensor([[6.0, 8.0]])
m.bias.grad = torch.tensor([0.0])
before = torch.nn.utils.clip_grad_norm_(m.parameters(), max_norm=2.0)
print("裁剪前的总范数:", before.item())
print("裁剪后的 weight.grad:", m.weight.grad)
print("裁剪后的总范数:", round(m.weight.grad.norm().item(), 4))

@@ concept
title: VQ（一）：最近邻量化和直通估计器
--- body
VQ（vector quantization，向量量化）前 13 天没出现过。今天把它当成「一篇新论文里的新模块」来写。它来自 VQ-VAE 论文；第 13 天音频 codec 输出的离散码，也是用这类方法得到的。

**码本**（codebook）：一个 (K, D) 的可学习矩阵，里面是 K 个「标准向量」，每个长 D。
**量化**：encoder 输出的每个向量 z（长 D），换成码本里离它最近的那一个 e，同时记下 e 的编号。

写成代码是三步：

1. `d = torch.cdist(z, codebook)`：z 是 (B, D)，codebook 是 (K, D)，d 是 (B, K)。d[i, k] 是第 i 个向量到第 k 个码的距离。
2. `idx = d.argmin(-1)`：每一行最小距离的位置，shape (B,)，类型 int64。
3. `e = codebook[idx]`：按编号取出码本向量，shape (B, D)。

问题来了：argmin 是「挑一个」，没法求导。梯度到这里就断了，encoder 什么也学不到。

解决办法叫**直通估计器**（straight-through estimator）：`z_q = z + (e - z).detach()`

- 前向：z + e − z = e，数值上就是码本向量。
- 反向：`.detach()` 的部分被当成常数，所以 z_q 对 z 的导数是 1。梯度原样「直通」回 z，就像量化这一步不存在。

论文里写的 sg[·]（stop-gradient，停止梯度）就是 PyTorch 的 `.detach()`：数值不变，梯度到这里停下。
--- code
codebook = torch.tensor([[0.0, 0.0], [2.0, 2.0]])   # K=2 个码，每个 D=2
z = torch.tensor([[0.3, -0.2], [1.5, 2.5], [1.2, 0.9]], requires_grad=True)
d = torch.cdist(z, codebook)
print("距离 d，shape", tuple(d.shape))
print(d.detach().round(decimals=3))
idx = d.argmin(-1)
print("编号:", idx.tolist(), idx.dtype)
e = codebook[idx]
z_q = z + (e - z).detach()
print("z_q 的数值（等于 e）:")
print(z_q.detach())
z_q.sum().backward()
print("z.grad（梯度直通回来，全是 1）:")
print(z.grad)

@@ concept
title: VQ（二）：两个 stop-gradient 项
--- body
直通估计器有个副作用：在 `z + (e - z).detach()` 里，码本向量 e 整个待在 detach 里面。所以后面不管接什么 loss（比如重建误差），梯度都**到不了码本**。码本自己不会动。

所以 VQ-VAE 论文在 loss 里专门加了两项。公式里的 sg[·] 就是 `.detach()`：

- **codebook 项**：‖sg[z] − e‖²。z 被挡住，只有 e 有梯度。作用：把码本向量拉向 encoder 的输出。
- **commitment 项**：β‖z − sg[e]‖²。e 被挡住，只有 z 有梯度。作用：让 encoder 的输出别离自己选中的码太远（「承诺」用这个码）。论文里 β = 0.25。

在代码里，‖a − b‖² 写成 `F.mse_loss(a, b)`，它默认对所有元素求平均。

加上重建误差，VQ-VAE 的 loss 一共三项。梯度流向：

- 重建项 → decoder，再经过直通到 encoder；**到不了码本**
- codebook 项 → 只到码本
- commitment 项 → 只到 encoder

判断一个 loss 项会更新谁：看公式里哪些量**没有**被 sg 包住。

下面的例子：z = [3, 2]，e = [1, 1]。codebook 项 = mean(2², 1²) = 2.5，commitment 项 = 0.25 × 2.5 = 0.625。
--- code
z = torch.tensor([[3.0, 2.0]], requires_grad=True)   # 当作 encoder 的输出
e = torch.tensor([[1.0, 1.0]], requires_grad=True)   # 当作选中的码本向量

codebook_term = F.mse_loss(z.detach(), e)
codebook_term.backward()
print("codebook 项:", codebook_term.item(), " e.grad:", e.grad.tolist(), " z.grad:", z.grad)

e.grad = None
commit_term = 0.25 * F.mse_loss(z, e.detach())
commit_term.backward()
print("commitment 项:", commit_term.item(), " z.grad:", z.grad.tolist(), " e.grad:", e.grad)

--- body
新模块写成函数、单独测过以后，接进训练循环前先做一个小实验：数据简单到你知道正确答案，看它能不能学出来。

今天的小实验用 `_toy_data()`：64 个一维的点，围着 -3、-1、1、3 四个中心，每个中心 16 个点，噪声的标准差是 0.1。shape (64, 1)。

码本有 4 个码，一开始故意挤在 0 附近：[-0.3, -0.1, 0.1, 0.3]。VQ 写对了的话，训练后 4 个码应该各自跑到一个中心附近。

这里没有 encoder 和 decoder，数据直接当成 z。loss = 重建项 + `vq_loss(..., beta=0.0)`（没有 encoder，也就不需要 commitment 项）。优化器只管码本。

**反直觉的地方**：重建项 `F.mse_loss(z_q, data)` 对码本**没有梯度**。data 本身不需要梯度，码本又被直通估计器的 detach 挡住，所以这一项的 `requires_grad` 是 False。它只是一个拿来看的数字。真正推着码本走的，是 vq_loss 里的 codebook 项。下面的例子里，两项的数值一模一样（z_q 的值就是 e），可只有 codebook 项带梯度。

还有一个细节：一开始所有点都选最外面的两个码（-0.3 和 0.3），中间两个码没人选，梯度是 0。等外面的码往外走，中间的码才开始被选中。

想知道一个 loss 能不能训练某个参数，直接查：`loss.requires_grad`、`loss.grad_fn`，或者 backward 之后看参数的 `.grad`。
--- code
data = _toy_data()
cb = nn.Parameter(torch.linspace(-0.3, 0.3, 4).reshape(4, 1))
print("data:", tuple(data.shape), " 码本:", cb.detach().flatten())

zq, idx = vq_quantize(data, cb)
print("每个码被选了几次:", torch.bincount(idx, minlength=4).tolist())
recon = F.mse_loss(zq, data)
print("重建项:", round(recon.item(), 3), " requires_grad:", recon.requires_grad)

book = F.mse_loss(data.detach(), cb[idx])     # codebook 项
book.backward()
print("codebook 项:", round(book.item(), 3))
print("码本的梯度:", cb.grad.flatten())

@@ concept
title: 症状 → 病因：先认得五种情况
--- body
新模块接进去以后，训练多半不会一次就顺。有经验的人看一眼症状，就能猜到大概哪里坏了。先认得下面五种；第 15–17 天会专门讲怎么一步步排查。

- **模型没学到东西**：模型给每个 token 的概率都差不多。V 个词平均猜，交叉熵正好是 ln V，所以 loss 一直停在 ln(词表大小)。常见原因：梯度没传到参数、学习率太小、忘了 `opt.step()`。
- **lr 过大或 fp16 溢出**：一步更新太猛；或者半精度 fp16（最大只能表示 65504）装不下某个中间值，变成 inf，下一步就是 nan。通常开训几步之内就出现。
- **标签泄漏**：训练时模型偷看到了答案。比如 causal mask 写反了或者忘了加，或者输入和标签没有错开一位。训练 loss 低得离谱，可一到真正生成（看不到答案了），输出全是乱码。
- **忘了 model.eval()**：推理时 dropout 还开着，每次随机关掉一部分神经元。贪心解码（每一步都选概率最大的 token）本来每次结果都一样，现在同一个输入每次输出都不同。
- **循环里存了带计算图的 tensor**：比如写成 `total += loss`，而不是 `total += loss.item()`。每一步的计算图都留在内存里，越积越多，跑到后面显存不够（OOM，out of memory）。
--- code
for name, V in [("字符级莎士比亚", 65), ("GPT-2 的词表", 50257), ("5 分类", 5)]:
    print(f"{name}: V = {V}, 瞎猜时的 loss = ln V = {math.log(V):.3f}")
print("fp16 能表示的最大数:", torch.finfo(torch.float16).max)
print("超过它就变成:", torch.tensor(70000.0).half())

def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    """反复在同一个 (x, y) 上训练。返回 loss 列表（float）。
    用 AdamW + F.cross_entropy。这一步跑不到接近 0，说明模型/loss 写错了，
    别去调数据、别去调超参 —— 先回来改代码。

--- solution
def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    losses = []
    for _ in range(steps):
        loss = F.cross_entropy(model(x), y)
        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return losses

--- starter
def vq_quantize(z, codebook):
    """z: (B, D)   codebook: (K, D)
    返回 (z_q, indices)：z_q 是 (B, D)，indices 是 (B,) int64。
    z_q 必须用直通估计器，让梯度能传回 z。
    """
    raise todo()
--- solution
def vq_quantize(z, codebook):
    d = torch.cdist(z, codebook)             # (B, K)
    idx = d.argmin(-1)
    e = codebook[idx]
    return z + (e - z).detach(), idx         # 直通：前向是 e，反向绕过量化

--- prompt
写 `vq_loss(z, z_q_hard, beta=0.25)`，返回下面两项之和：

- codebook 项：‖sg[z] − e‖²，只更新码本（z 被挡住）
- commitment 项：β‖z − sg[e]‖²，只更新 encoder（e 被挡住）

`z` 是 encoder 的输出 (B, D)，带梯度。`z_q_hard` 就是公式里的 e：选中的码本向量 (B, D)，**没有**经过直通。sg[x] 写成 `x.detach()`，‖a − b‖² 写成 `F.mse_loss(a, b)`（默认求平均）。

例：z = [[1, 0]]，e = [[0, 0]]，β = 0.25。codebook 项 = mean(1², 0²) = 0.5，commitment 项 = 0.25 × 0.5 = 0.125，合计 0.625。

判题还会检查梯度的流向，以及一个反直觉的事实：经过直通以后，重建误差对码本没有梯度。这正是需要 codebook 项的原因。
--- starter
def vq_loss(z, z_q_hard, beta=0.25):
    """z: encoder 输出 (B, D)（带梯度）   z_q_hard: 量化后的码本向量 (B, D)
    codebook loss  = ||sg[z] - e||²        （只更新码本）
    commitment loss= beta * ||z - sg[e]||²  （只更新 encoder）
    返回两项之和（都用 mse_loss 的默认 mean）。
    """
    raise todo()
--- solution
def vq_loss(z, z_q_hard, beta=0.25):
    codebook = F.mse_loss(z.detach(), z_q_hard)
    commit = beta * F.mse_loss(z, z_q_hard.detach())
    return codebook + commit
--- tests

def train_vq_toy(steps=300, lr=1e-1):
    data = _toy_data()
    codebook = nn.Parameter(torch.linspace(-0.3, 0.3, 4).reshape(4, 1))
    opt = torch.optim.AdamW([codebook], lr=lr)
    losses = []
    for _ in range(steps):
        zq, idx = vq_quantize(data, codebook)
        # 第一项有数值，但对码本没有梯度（见 d14-06 的第 3 个检查），
        # 真正推着码本走的是第二项
        loss = F.mse_loss(zq, data) + vq_loss(data, codebook[idx], beta=0.0)
        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return losses

--- explain

def vq_quantize(z, codebook):
    d = torch.cdist(z, codebook)             # (B, K)
    idx = d.argmin(-1)
    e = codebook[idx]
    return z + (e - z).detach(), idx         # 直通：前向是 e，反向绕过量化

def overfit_one_batch(model, x, y, steps=300, lr=1e-2):
    opt = torch.optim.AdamW(model.parameters(), lr=lr)
    losses = []
    for _ in range(steps):
        loss = F.cross_entropy(model(x), y)
        opt.zero_grad(set_to_none=True)
        loss.backward()
        opt.step()
        losses.append(loss.item())
    return losses
